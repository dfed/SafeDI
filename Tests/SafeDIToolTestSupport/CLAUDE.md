# SafeDIToolTestSupport

The helpers the five `SafeDITool` test targets share. `SafeDIToolTestExecution.swift` (`executeSafeDIToolTest`) and `SafeDIToolMultiModuleTestExecution.swift` run fixtures through the whole pipeline; `SafeDICompileVerifier.swift` compiles each test's fixtures and generated code, skipping a check that `PassedCompileCheckCache.swift`'s file lists as passed in an earlier run. A helper launches a compiler or any other process through `runProcess`, which is `async`: a thread of its own launches and waits for the process while the caller is suspended, at most one process per core at once, serving first the test that began first. A test or helper never waits for a process with `waitUntilExit()` or another blocking call on a cooperative pool thread: that holds one of the pool's few threads, so other tests and `generate`'s detached work wait behind the compiles. A new entry point that tests call before their first compile takes the test's place in that line first (`ProcessSlots.takePlaceInLine(for:)`), and work several tests share is a `SharedTestWork`, not a `Task`, so that a test waiting for it keeps its place. The graph fuzzer's rules load as you read its files: `.claude/rules/fuzzer-overview.md`, `fuzzer-seam-draws.md`, `fuzzer-seam-oracles.md`, `fuzzer-corpora.md` and `fuzzer-value-oracles.md`. Which target a test goes in, fixture naming and the rest of the testing rules are in the root `CLAUDE.md`.
