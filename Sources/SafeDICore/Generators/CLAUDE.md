# Generators

`DependencyTreeGenerator.swift` and its `DependencyTreeGenerator+*.swift` files, one per concern, build and validate the production trees and the mock roots; `ScopeGenerator.swift` emits the code. By file: `+ScopeMapping` (`createTypeDescriptionToScopeMapping`), `+FulfillmentValidation` (`validatePropertiesAreFulfillable`), `+CycleValidation`, `+DeclarationValidation`, `+Errors` (`DependencyTreeGeneratorError`), `+MockOrchestration` (`generateMockCode`), `+MockRootPromotion` (`createMockRootScopeGenerator`), `+PublicMockCalls`, `+SeamDriver`, `+Constructions`, and `+Requirements` (`query needs`). The rules in `.claude/rules/` load as you read files here: cycle mechanisms (`cycle-generation.md`, `cycle-validation.md`), mocks (`mock-generation.md`, `mock-root-promotion.md`, `lazily-instantiated.md`, `public-mocks.md`), seams (`seams.md`, `seam-access-proof.md`, `seam-generation.md`, `seam-builder-structs.md`, `seam-holes.md`, `seam-hole-fills.md`), the contract for seams and public mocks (`seam-and-mock-contract.md`), `generator-design.md`, the decisions made while code is emitted (`emission-decisions.md`), `validation-boundaries.md` and `reserved-names-and-spelling.md`. Grep loads none of them: when you change a generator from a file elsewhere, read the ones for its topic first.
