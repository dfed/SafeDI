# SafeDIMacros

The macros validate what one declaration can show and give fix-its; the tool trusts them. Rules: `.claude/rules/validation-boundaries.md`, `.claude/rules/reserved-names-and-spelling.md`, and `.claude/rules/public-mocks.md` for the `generateMock` and `mockAttributes` arguments.

The target compiles SafeDICore through the `SafeDICore` symbolic link, leaving out what only SafeDITool uses: `Generators/`, `Utilities/` and the files the target's `exclude` in `Package.swift` lists, which the `SafeDICoreSources` filegroup in `Sources/SafeDICore/BUILD.bazel` repeats. `MacroTargetSourceTests` fails when the two lists disagree, when an exclusion names no file, or when a SafeDICore file is neither excluded nor in its list of the files the macros use, so a new file is a decision. Macro code that needs a declaration from an excluded file fails to build: move the declaration into a file the macros compile, as `Dependency.receivableProperties` and `AccessLevel.normalized(_:)` were, rather than compiling the file. `TypeDescription.swift`, `Initializer.swift` and `IdentifierSpellingExtensions.swift` import Foundation, which no other file the macros compile does; without it their `String.contains` calls bind to other overloads than in SafeDITool, one of them unavailable before macOS 13.
