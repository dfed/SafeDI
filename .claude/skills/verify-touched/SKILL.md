# Run the suites a branch touches

`verify-touched.py`, beside this file, works out which suites a branch's changes reach, runs them with `swift test`, and prints each failed test with its issues and the run's last line. Run it from the repository root; `S` below is `.claude/skills/verify-touched/verify-touched.py`. Its `--help` is the full contract.

1. `python3 -I S [BASE] --list` prints the filters and why each is there, and each changed path that reaches no test, and runs nothing. `BASE` is what the branch is measured from (default `origin/main`); in a stack, name the branch below. Uncommitted and untracked files count.
2. `python3 -I S [BASE]` runs them; start it in the background, since a run that reaches the tool's test targets takes minutes. Each test's generated code is compiled in a debug build; `--skip-compile-checks` is for a first pass only, and an inherited `SAFEDI_SKIP_COMPILE_CHECK` is dropped without it. It prints each failed test and its issues; the expected and actual text of a failed comparison, and the whole output, are in the log the script names, one per run.
3. Fix what it prints and run it again. Dispatch a full Verify (`gh workflow run verify.yml --ref <branch>`) only once it passes: the full run is still what counts, since this is a debug build of a selection, and CI's release build rejects code a debug build accepts.

Every changed path matches a rule or runs the whole suite. A Swift file of a test target selects the top-level types it declares, or its whole target when it declares no test, was deleted, or contains `#if`; any other file of a test target selects the target. A file under `Sources/` or `Plugins/` selects the test targets of its directory: every source directory reaches the plugin's tests, which read the sources, and every one but `Plugins/` reaches the five `SafeDITool` test targets, which is nearly the whole suite, so when the change is to one area (seams, mocks), read `--list` and expect a run of that size; `--also FILTER` only adds suites, it never narrows a source change. A path a test reads (`Documentation/Manual.md`, `TuistPlugins/`, `.github/scripts/`, `bazel/`) selects those tests' targets. `Tests/SafeDIToolTestSupport`, `Package.swift`, `Package.resolved` and any path no rule names run the whole suite. The script lists the paths that reach no test (instructions, workflows, scripts, examples, other Markdown). `--also FILTER` adds suites the diff does not show, for example those a regenerated expectation lives in.

`--runner COMMAND` (or `SAFEDI_VERIFY_RUNNER`) puts a command before `swift test`, for a machine that queues heavy work. The script makes a `TMPDIR` of the run's own, inside the inherited `TMPDIR` when that is outside the system temporary directory and the checkout, else inside the SwiftPM folder `CLAUDE.md` names, and removes only that folder when it ends or is terminated; terminating it ends `swift test` too. It exits with `swift test`'s status, 0 without a run when no changed path reaches a test, 1 when the run passed and ran no test, and 2 for wrong arguments or a base git cannot find.

After changing the script, a test target, a source directory or a path a test reads, run `python3 -I S --self-test`, which also checks that every tracked file matches a rule. "Check Line Coverage on Linux" runs the same.
