# Graph fuzzer: modules beneath the seam's module

Continues `fuzzer-corpora.md`.

In the seam and public mock corpora, `GraphFuzzerSeamDependencyDraw` (`Tests/SafeDIToolTestSupport/GraphFuzzerSeamDependencies.swift`) draws, after every other pass and from streams of its own (`seamRandomSeedMask`, `publicMockRandomSeedMask`), so that a graph without it is the graph it was, the modules beneath a split graph's seam's module that only `.safedi` views carry to its callers under the module-info flow: `FuzzSession` (`GraphFuzzerModule.seamDependency`), which only the seam's module lists, `FuzzCore` (package `core`), which only `FuzzSession` lists, and `FuzzBase` (package `base`), which only `FuzzCore` lists; callers still list the seam's module alone, and under the module-info flow a module also lists each module beneath it whose types its mocks build (`GraphFuzzerSeamDependencyDraw.moduleInfoDependencies(of:modules:)`), as the Manual's "Which modules to list" tells adopters (seeds 4749 and 4867). In three eligible graphs in ten of the public mock corpus, and forty-five in a hundred of the seam corpus (`seamCorpusDrawPercent`, raised so that enough accepted graphs read a move through the view, below), half the declarations of the seam's module that can move go into `FuzzSession` (`destinations(of:typeNamePrefix:percent:random:)`): a declaration moves only when it spells `public` or `package` on everything another module of its package needs, names only what moves with it, and no caller, configuration, hand-written caller comment, caller's mock, or caller's inline build of a seam or public mock it can construct names or builds it (`Analysis`: `pinnedNames`, `inlineNames`), since under the module-info flow a caller reads no type a view alone carries while the plugin flow reads every module beneath it; a declaration never moves two modules down, since the seam's module builds its seams' and public mocks' trees and lists only `FuzzSession`. Two in ten eligible graphs gain a chain (`chainPercent`): a seam the callers call and no other type's mock builds (a seam's own mock builds the chain beneath it, two modules beneath what its module imports), or a `.public` leaf a consumer calls and cannot construct (its initializer `internal`, or `package` and reached only from `FuzzOther`), instantiates `ChainLink` (`FuzzSession`), which instantiates `ChainBase` (`FuzzCore`) – seams in the seam corpus, public mocks with an `internal` initializer in the public mock corpus – which instantiates `ChainLeaf` (`FuzzBase`), whose tree receives `ChainToken` only if available; its bottom level reads a module the level above does not list, the shape of cell 5b, whose defect (a nested public mock plan computed from the calling module's filtered map) the drawn chains report as `integrationsDisagree` when its fix is removed, while a chain one module shorter passes with or without it.
