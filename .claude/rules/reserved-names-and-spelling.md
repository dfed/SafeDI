# Reserved names, nested types, and spelling

- **Names generated code introduces are reserved** (`ReservedName`, the one place they are spelled: `ScopeGenerator` emits them from its constants, and the macro checks against them). The enums nested by type in a plain root (`<Type>_Scope`, the type as the seam's module spells it) and payload structs (`<case>_Values`, `<label>_Values` nested by type) take a trailing `_` where a field's type would resolve to the struct; a seam's root enums (`SafeDIScope_<Stem>`, `SafeDISendableScope_<Stem>`) and its builder structs (`__safeDI_Builder`) are never named apart, since a type named with one of their prefixes is rejected (below); every type nested in a root nested by type also takes `_` while a case, another generated type, or any type spelled inside the root has its name (`scopeEnumsByType`); a wrapping case's payload is bound in the seam's body as `__safeDI_<stem>Values_<label>`; a stem is the instantiated type's `simplified.asIdentifier`, followed by `_` and the returned type's where the two differ (`seam-holes.md`), its label lowered at the leading capitals. Generated bodies declare builder functions `__safeDI_<label>` (and `@Sendable`-extracted locals `__safeDI_<label>__…`) next to the `let <label>` they build, and a seam initializer only generated code calls labels its parameters `__safeDI_<label>` (`ReservedName.seamGeneratedOnlyArgumentLabel(of:)`, joined through `spelledAsJoinedIdentifier`, so a keyword needs no backticks and a raw identifier keeps them); the prefix keeps them out of the namespace of user labels, and it stays: any other scheme is more collision-prone and rewrites every generated file. Three kinds of exact name are reserved too, because generated code puts them in a scope with user names and cannot rename them: `safeDIOverrides` (the `mock()` parameter callers spell, which a mock parameter of that label redeclares and a body binding hides), `safeDIBuilder` (the property and initializer parameter of every `SafeDIMockConfiguration`, which a configured type's instantiated or default-parameter label redeclares, and the `if let safeDIBuilder` override binding in each construction expression, which therefore never shadows an argument), and the wrapper types generated code constructs by name (`Instantiator<T>(…)` and the other five, `Property.PropertyType.wrapperTypeName`), which a binding of that name hides. The macro tests pin that each is rejected; the evidence that each collides is in PR 410's description, because a fixture that declares one is macro-invalid and so cannot be a pipeline test. `SafeDIToolReservedNameTests` shows, with macro-valid fixtures, that the other names generated code introduces do not collide, which is what stops anyone reserving more than is needed: the `instance` closure parameter, and the generated members `SafeDIOverrides`, `SafeDIMockConfiguration`, `ForwardedProperties`, and `mock`, which a same-named property does not redeclare and which generated code never names where a binding could hide them. A new generated identifier in a scope with user names must be added to `ReservedName`, with such a test. The `@Instantiable` macro rejects every name it can see that generated code binds or refers to: property labels and `fulfilledByDependencyNamed:` names (`InstantiableVisitor`), the names of `instantiate(…)` parameters without a default value (also the visitor), and the argument labels of labeled, default-valued, non-dependency parameters of the construction initializer, `instantiate(…)` methods, and mock methods, which a mock root takes as `mock()` parameters (`validateReservedParameterLabels`, the same parameters `validateDefaultExpressions` checks). Backticks only quote a name, so `ReservedName(reserving:)` reads each without them and the message names it without them: `` `__safeDI_editor` `` is rejected as `__safeDI_editor` is. The property macros do not check, so nothing is reported twice. Only a prefixed parameter label gets a fix-it (rename the argument label to the label without the prefix, keep the parameter's name): renaming a dependency can change which dependency it fulfills or receives, because SafeDI matches by label, with no error, and an exactly reserved label has no evident replacement. `generate` does not check: SafeDI is upgraded per project at once, so every module's names have passed the macro.
- **A person's type named like a generated type.** `SafeDIToolSeamGeneratedTypeNameTests` shows the names that compile: a payload struct takes `_` where a field spells a person's type of its name (`detailBuilder_Values_` holds the `detailBuilder_Values` a seam binds), a type of the tree named like another type's nested enum gets an enum of its own named apart (`Detail_Scope_Scope` beside `Detail`'s `Detail_Scope`) and is spelled outside the root enum, a calling module's own type named like a seam's root enum is spelled bare in its fill, since the caller spells the seam's enums qualified (`Home.SafeDIScope_Api`), and a person's type named `Built` that a place forwards, alone or in a tuple, is spelled inside the builder struct beside its generic parameter, which the prefix keeps apart (`__safeDI_Built`); an `@Instantiable` type of a calling module named like the seam is the duplicate-name error (`types-a-module-cannot-name.md`). The fuzzer draws no such name: its type names never equal a generated one.
- **Nested-type qualification.** `normalizingInstantiableTypes(of:plainTypeDeclarations:)` qualifies every type a declaration spells – each dependency's property type and alias `ofType:` type, every argument of its initializer, other initializers, and hand-written mock (dependency or default-valued alike, each by itself, so a dependency's argument is qualified as its property), and the mock's return type – in two steps. First `TypeDescription.qualifyingInstantiatedType(within:amongInstantiableTypes:searchingTypesEnclosingIt:namesOfNestedInstantiableTypes:)` qualifies the type `asInstantiatedType` returns (`Instantiator<Service>?` → `Instantiator<Feature.Service>?`, `LazilyInstantiated<any Service>` → `LazilyInstantiated<any Feature.Service>`, so a by-value receiver of `any Service`, qualified the same way, still matches `lazilyInstantiatedInstanceType`), choosing the most qualified of `nestedOptions` that an `@Instantiable` fulfills, so a nested type wins over a top-level type of the same name, as the compiler resolves it; `fulfilledByType:` gets only this step, restricted, on an extension-based declaration, to the extended type's own nested types and the name as written. Then `TypeAccessProof.NestedTypeQualifier` nests each outermost name the type spells, anywhere in it (generic arguments, closures, tuples, optionals), as Swift resolves it where the declaration is written: the most qualified option of `nestedOptions` that is an instantiable type or a plain declaration (`PlainTypeDeclaration`) the declaration's module can name, else the name as written; a declaration another module nests in a type whose name the mentioning module itself declares is no option, since the module's own type shadows the other's (`PlainTypeDeclarations.candidates`). A member of an extension-based declaration is written at file scope, so only the extended type's own nested types are options there, in both steps; `fulfillingAdditionalTypes:` is written outside the type, so it is qualified within the type enclosing it, and on an extension by neither step. The generated code is outside the declaration – another type's tree, a mock or `SafeDIMockConfiguration` in an extension of the nested type, a seam's initializer, a public mock's module-level configuration – and there `Mode`, declared in `Feature` beside `Feature.Child`, does not resolve; so every generator reads the qualified types and qualifies nothing itself. A module keeps the plain declarations nested in the outermost type enclosing each `@Instantiable` type of any clause and those its declarations mention (`keptPlainTypeNames(of:)`), so every run that reads the type's file, and every `.safedi`, holds what the qualifier reads. A declaration SafeDI knows no module of counts as the mentioning declaration's module's (normalization runs before the run knows its own files). Most names name no nested type, so the qualifier searches a name's options only when a nested instantiable type or a nested plain declaration a mention can find has that name (`namesOfNestedTypes`, backticks dropped), or when the enclosing type's outermost name is a module's, whose top-level declarations a mention spelled with it names; the instantiated-type step likewise searches the nested options only for a name a nested instantiable type has. Any new way `PlainTypeDeclarations.candidates` can find a declaration must keep that check a superset of it. Both steps return `nil` when they change nothing, and normalization keeps a dependency, argument or type they leave unchanged rather than rebuilding it. A type inherited from a superclass or a protocol, and a default *expression* (`= Mode.fast`, copied as written into the type's extension), are not qualified, and where an inherited nested type shadows one of the enclosing types', the qualified type is the enclosing type's and the generated code does not compile. Unqualified, `mockReturnTypeIsCompatible` fails against `Feature.Consumer`, and the hand-written mock is silently skipped; doing it while normalizing, before `resolveSafeDIFulfilledTypes`, keeps `mockInitializer`, `mockReturnType` and `mockDeclarationLocation` together through both mockOnly merge branches, and makes a provider and a receiver that spell one type differently (`Grandchild.NestedType` and, inside `Grandchild`, `NestedType`) match. `replacingInstantiatedType` walks the same path through a type as `asInstantiatedType`: both read `TypeDescription.builtGeneric`, which names the built generic of each wrapper and whether its own instantiated type is read through it (`LazilyInstantiated`, whose generic may be `any Service`), so a new wrapper type is added there once.
- **Identifier spelling.** Labels and parameter names are stored in `spelledAsIdentifier` spelling: backticks only where Swift requires them to declare or name a value. Every call-site label goes through `spelledAsArgumentLabel`. Every name joined from a label (`__safeDI_` + label, `label_lazilyInstantiated`, sibling, alias, and override-local suffixes) goes through `spelledAsJoinedIdentifier`. Tuple element labels follow the same spelling. A member a generated type declares from a label (a scope enum's case, which Swift rejects named `Type` or `Protocol` bare where it carries no values, a builder struct's member, a payload struct's field, a configuration's field, an override of what a mock receives only if available, a configuration storage's field) is declared through `spelledAsMemberDeclarationName`, which escapes `Type` and `Protocol`. A read of such a member spells the label as it is stored (`safeDIOverrides.Type`), in the mock’s walk and in the node records alike: after a value, neither name spells a metatype, so only the declaration takes the backticks. A configuration's initializer and its storage's take each field through `spelledAsAssigningParameter(labeled:)` and read it through `spelledAsAssigningParameterName`, which name a parameter labeled `self` apart (`ReservedName.selfParameterName`), since one named `self` hides the instance the initializer assigns to: a mock promotes a dependency an extension's `instantiate(self:)` receives, so its overrides take a `self` field. No property is labeled `self` (the macro requires an initializer parameter named as each dependency, and no initializer assigns a property from a parameter named `self`), so a builder struct's member or a payload struct's field never is. `SafeDIToolSeamKeywordLabelTests` and `SafeDIToolMockKeywordLabelTests` compile each site for `Type`, `Protocol`, `Self`, `init`, `default` and a raw identifier, and the overrides for `self`; the seam and public mock corpora draw keyword labels on a hole's level and on configuration members ("Keyword labels" in `fuzzer-corpora.md`). A new emission site that interpolates a label directly compiles for every label the fuzzer draws and breaks only for a keyword or a raw identifier, which the fuzzer never draws, so only a keyword-label test catches it.
- **`TypeDescription ==`/`hash` ignore `any` at every depth.** `any P` equals `P`, `(any P)?` equals `P?`, `Instantiator<any P>` equals `Instantiator<P>`, and `(any P).Type` is treated as `P.Protocol` (not `P.Type`, which is `any P.Type`). `some P` stays distinct. Sets and dictionaries keyed by `TypeDescription` or `Property` therefore merge the two spellings, keeping whichever was inserted first, while `asSource`/`asIdentifier` keep each declaration's own spelling. `<` compares the spelling without `any` first, then the full spelling as a deterministic tiebreak, so two spellings of one type are equal under `==` but ordered under `<` (determinism was chosen over the Comparable contract). Any new map or set keyed by a type's spelling string (`asSource`) instead of `TypeDescription` must normalize `any` the same way, or it will miss matches `==` makes.
- **A type named with a generated type’s prefix is rejected.** A seam’s root enums (`SafeDIScope_<Stem>`, `SafeDISendableScope_<Stem>`), a public mock’s (`SafeDIMockScope_<Stem>`, `SafeDISendableMockScope_<Stem>`) and the builder structs inside a seam’s (`__safeDI_Builder`) are not named apart from a person’s types. Not every name with these prefixes collides with one SafeDI generates, and which ones do changes with the generator, so SafeDI reserves each whole prefix: then no generated name can collide with a person’s type, and nothing needs generating around a collision. No one names a type with SafeDI’s prefixes. The `@Instantiable` macro reports, at the name and without a fix-it (renaming the declaration leaves every use of the old name), each type whose name begins with `SafeDIScope_`, `SafeDISendableScope_`, `SafeDIMockScope_`, `SafeDISendableMockScope_` or `__safeDI_` among the declarations it sees: the decorated type, the type an `@Instantiable` extension extends (its last name when qualified), and every type declared inside either, at any depth and in every `#if` clause, except that a nested `@Instantiable` type reports its own name and members in its own expansion, so none is reported twice (`InstantiableMacro.diagnoseReservedTypeNames`, `InstantiableMacroTypeReservedNameTests`); a backticked name is read without its backticks. It also reports a name spelled by a declaration it reads, at the spelling: the first name of each type spelling, wherever it nests (a generic argument, a tuple, a closure, an optional, `any`, an attribute), in each dependency’s property type, an alias’s `ofType:`, `fulfilledByType:` (reported at the string), the parameters of every initializer, `instantiate(…)` and hand-written mock, and the return types of `instantiate(…)` and the mock, in every `#if` clause (`InstantiableMacro.diagnoseReservedTypeNamesSpelled`). Generated code spells those types in scopes where a generated type can hide one of such a name, wherever the type is declared – in another module, or in one SafeDI never reads – so this check covers what no module’s run could. A name another qualifies (`Feature.SafeDIScope_Api`) resolves as a member of the type before it, which no generated type hides, so it is not reported; the first name of `SafeDIScope_Mode.Kind` is. `generate` reports every other declaration of such a name in the module’s own files (`isOwnFile`’s: the manifest’s `mockScopedFilePaths`, else the input files) – in a plain extension of the seam or mocked type, a plain type, a type nested in one, a protocol’s type alias or associated type – that is neither `@Instantiable` nor inside an `@Instantiable` type or extension at any depth, in every clause of every `#if` block, before it builds any tree, with the macro’s message (`ReservedName.reservedTypeNameMessage`), at the name, in source order (`ReservedTypeNameError`, `SafeDIToolReservedTypeNameTests`). `FileVisitor` records them (`reservedTypeNameDeclarations`): the declarations outside every block itself, and those of each outermost block’s clauses through `SafeDIContentDetector`’s walk of them, so the records depend on no condition. A file without a SafeDI marker is parsed for them when a word after a type keyword (`associatedtype` among them) begins with a reserved prefix, and contributes nothing else it was not parsed for. Only the module’s own run reports its declarations: the records stay out of `ModuleInfo` and the `.safedi`, and a run that reads another module’s files (the SwiftPM plugin’s) drops theirs. Under the SwiftPM plugin a module whose files plan no output runs no `generate`, so its declarations go unreported; no generated code compiles in it, and the macro reports a mention of one in a module that runs. The prefixes are spelled once, in `ReservedName.reservedTypeNamePrefixes`, from which `ScopeTypeNames.seam` and `ScopeTypeNames.publicMock` take theirs.

## Types the expression parser cannot read

`TypeDescription` keeps everything a type's spelling carries, so `asSource` gives back a type Swift reads as the same one: a closure's `throws(E)` (`thrownType`; `==` and `hash` read `throws(any Error)` as `throws`, as Swift does), a variadic parameter (`.variadic`), an attribute's qualifier and arguments, as text without the `@` (`Space.Act`, `convention(c)`), a specifier that follows the attributes (`lateSpecifiers`, kept in `specifiers`, which `asSource` spells first because Swift reads `nonisolated(nonsending)` only there), and a value generic argument (`.unknown`). Swift's expression parser does not read `nonisolated(nonsending)` in a generic argument (6.4 reports "consecutive statements on a line"), so a wrapper of such a type is constructed by its bare name under a type annotation (`spelledForConstruction`, `isConstructedByAnnotation`).
