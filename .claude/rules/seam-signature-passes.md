# Seams: skipping the confirming signature pass

Only the seam driver applies this rule, so it loads for the driver and its tests, not for every generator file; `seams.md` holds the fixed point it shortens.

- **Skipping the confirming pass.** A component of one seam that does not reach itself (`SeamComponents.seamsReachingThemselves`, from the walk that builds the components, since Tarjan returns a self-loop as a component of one) settles after its first pass, without the pass that would confirm it, when that pass threw nothing, added no parameter (same count and order, each by label, type spelling, `deferral` and `internalName`; a `nil` root is computed again from `initialSeamRoot` anyway), and its tree holds no generator with `seamCall`, `publicMockCall`, `fillKey` or `passedUpHoles` (`confirmingPassFindsNothingNew`): the second pass would read the same parameters, and of the holes, builders and call routes it adds (`SeamHoles`) only code generation, the memo's sharing, and reads behind calls, fills and passed-up holes read anything, so it finds the same root, byte for byte, not just the same `settledContent`. Such a seam's signature comes from a tree built with the construction memo on (`construction-memo.md`). The skip runs the settled pass's bookkeeping. The test executors run the skipped pass anyway and compare encoded signatures (`SeamSignatureObservation.confirmsSkippedPasses`, `SkippedConfirmingPassChecks`).
- **Reusing the settled pass's tree.** Emission does not build such a seam's tree again when it is one of this module's own seams with a signature (`SignatureConstruction.ownSeams`, never the callers' view or another module's): the pass keeps its tree (`firstPassTrees`, released at once for a `nil` root or an error), and emission makes it again from the final seam root (`ScopeGenerator.reseating(treeRootedAt:of:seamRoot:)`), bottom-up, children in index order, a generator the memo shares made again once. A new generator copies what construction read from the scopes and the parameters, and finds again, from the final `SeamHoles` and its path, what construction reads of them (each hole's `site` and `carrierSite`, `valuesBindings`, `memberCallsInsideFunction`, the tree-wide `namesBoundBySeam`) and what it works out from its children's (`boxedLoops`, `loopLevelsTypesInTree`, `fieldsCarriedBySites`); the root takes the final seam root. `ScopeGenerator.ReseatedField` classifies every stored property and every `SeamAndFillFields` field, which a test checks against reflection: a new one is classified and set in `init(reseating:…)`. The tree reads the same scopes, since the base and pass maps of the module's own seams take the inline seam comment the seam world's map does. The test executors build the tree anew beside the reused one and compare the code (`SeamTreeReuseObservation.comparesBuiltTrees`, `ReusedSeamTreeChecks`).
- **Computing the callers' view again.** Where a run computes each seam it generates over the declarations its callers see (`seam-generation.md`), it hands the test executors what it decided of each seam – whether the callers can compute it, the callers' signature, the error reported at the seam – and a function that computes the view again from the same declarations, outside the generation layer observer and in an interner space of its own copied from the run's (`SeamCallersViewObservation.comparesProducers`, `DependencyTreeGenerator.CallersView`). The executors call it after generation and record an issue where the two decide otherwise: the signature by its encoded bytes, the error by its diagnostics (`SeamCallersViewChecks`). Today both computations read the tree, so the check holds the view to determinism; under the facts producer it compares the producers, and a callers' signature that differs is a failed test. Only the seam corpus's `addingCallersViewShapes` draws an added directory (`fuzzer-seam-oracles.md`).
