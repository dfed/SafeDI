# Remedy oracle

Every error SafeDI reports names its fix. The remedy oracle (`Tests/SafeDIToolTestSupport/GraphFuzzerRemedies.swift`) follows that advice on the graphs the base corpus rejects, about half of it, which no other oracle judges beyond determinism and renaming: for each error of the three families users see most, it applies the remedy the error states to the graph's declarations, runs the tool again, and requires that no error is left at the declaration the error was at (`GraphFuzzerToolRuns.remedyFailure`, `remedyLeavesErrorAtSite`). An error elsewhere is allowed: a remedy can expose an error the tool's walk stopped before, or change what another type receives. It runs only the tool, never the compiler, so it adds about one tool run per remedied site.

- **Which graphs.** A rejected graph of the base corpus in one module (`GraphFuzzerOracle.remedyRuns(of:outcome:)`): the seam and public mock corpora's graphs spell declarations (holes, nested types, extensions) the remedies do not edit. So a known issue whose every signature is `remedyLeavesErrorAtSite` is not inherited by the seam corpus (`isBaseCorpusValueOracleShape`).
- **What it reads.** An error's site is the property declaration its location names, as a file, the `final class` around that line, and the property's label (`GraphFuzzerRemedy.Site`), so a remedy that adds or removes lines elsewhere in the file moves no site. All the errors at a site must state the same remedy, or, for a receive no type in its chain fulfills, the same declaration on their own roots, which every named root then gets; a site whose errors state other remedies gets none.
- **The remedies** (`GraphFuzzerRemedyKind`), each read from the error's text (`GraphFuzzerRemedies.StatedRemedy`):
  - an unfulfilled receive's "Declare `@Instantiated let x: X` on `Root` …": `Root` declares it (`instantiateOnRoot`), and where the hint goes on "and add `onlyIfAvailable: true` to this property’s `@Received`", for a required receive of `x: X?`, the receive gets it too (`instantiateOnRootAndReceiveOnlyIfAvailable`);
  - "Did you mean to decorate this property with `@Received(onlyIfAvailable: true)`?": the bare `@Received` gets it (`receiveOnlyIfAvailable`);
  - "Did you mean `y: Y`?" and "Did you mean one of …?": the bare `@Received` takes each suggestion's label and type in turn, a remedy each (`receiveSuggestedProperty`);
  - a cycle's "Change … to an instantiator.": the dependency at the site, which closes the cycle, becomes `Instantiator<T>`, `ErasedInstantiator<(), AnyT>` for an erased one, `Sendable` when its lazy wrapper was (`instantiateAsInstantiator`);
  - a receive of a property still being built, or an unfulfilled receive whose declaration would be ("Declaring `@Instantiated let x: X` would close a dependency cycle …"), "Remove this @Received property, or receive it with `onlyIfAvailable: true` and an optional type": two remedies, the removal (`removeReceive`) and the optional receive (`receiveOptionallyIfAvailable`).
- **What it leaves out.** Advice it cannot apply as stated: an erased instantiator's "naming the type it builds" (the macro rejects a declaration that names none), a type built only through an `Instantiator` ("Declare `@Forwarded` …"), a type no declaration fulfills, a cycle an alias received only if available closes, a suggestion or receive on an alias, a property the type already declares under the new label, a root declared by an extension. The long run's report counts these sites (`unremedied=` on its `remedies` line).
- **How it edits.** On the fixture's text, as the fuzzer writes a type (`GraphFuzzerRemedies.Files`): property lines `@Attribute let label: Type` in a `final class`'s body and a one-line initializer that takes each property in order, before its default-valued parameters, and assigns each. An edit rewrites the initializer and its body with the properties, so the remedied graph stays one the macro accepts.
- **Pins and tests.** The long run reports `remedies <corpus> <kind>=<judged>/<failed>,… unremedied=<n>`, which no pin checks. `smokeSeeds_applyRemedies_inGraphsTheToolRejects` pins the kinds the smoke batch applies (`smokeRemedyKinds`). `SafeDIToolGraphFuzzerRemedyTests` holds one handwritten graph per kind, each written as the fuzzer writes one, with its remedied file in full and no error left at its site, and the oracle's verdict on a remedy that leaves one.
- **A finding** is advice that does not fix its error, or trades it for another at the same declaration. It is a defect of the diagnostic, not of generated code: record it as a known issue with `.remedyLeavesErrorAtSite(_:containing:)`, a signature for each remedy kind that shows the shape, each naming the error the remedy leaves, which tells the shapes of one kind apart (every remedy line of the failure must match one of the entry's signatures, `GraphFuzzerFailure.remedyFailures`), with its minimal graph in the entry's reason and as a test in `SafeDIToolGraphFuzzerRemedyTests` that expects the advice to work inside `withKnownIssue`, and fix the diagnostic in a change of its own. Five shapes are recorded today: advice inside a `@Sendable` builder to receive or declare what it cannot capture; advice to receive only if available, or a suggested property, beneath a type that declares the label with another type, where the receive is then hidden; a suggestion whose receive closes a cycle; suggestions that alternate between two paths to one receiver, since each error reports one; and advice to declare on a root whose own properties the declared tree receives and require the declaration.
