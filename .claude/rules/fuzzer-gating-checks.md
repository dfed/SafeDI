# Graph fuzzer: the gating checks

Continues `fuzzer-seam-oracles.md`. These checks gate seam and public mock generator changes: the retention oracle, and the draws of fixed defects' shapes.

## The retention oracle

The retention oracle (rule 3 of the seam contract: nothing is retained that inline frees) judges each graph with a hole (`GraphFuzzerOracle.holdsHole`: the graph draws a hole's fill, or its generated code takes a builder over a `SafeDIScope_`, `SafeDISendableScope_` or `MockScope_` enum) that the comparator compares, of the seam corpus against its inline build and of the public mock corpus against its known-right path (`DifferentialValueGraph.judgesRetention`). After describing each probe, the describer builds the probe's value again for each experiment – holding nothing, then holding one of the SafeDI wrappers the value holds through stored properties, at most 24, in the order a walk of those properties meets them, once along each way to them (the walk ends a way only at an instance it is already inside, and stops after 4,096 visits), each named by the labels on that way, so that two paths whose values agree pair every experiment whichever instances either shares – holds that wrapper with what one call of it builds, or its instance, releases the value, and prints how many class instances of each type that the value and what is held hold through stored properties are still alive though what is held does not reach them through stored properties (`retained holding <labels>: <Type> (2); …`, `DifferentialValueRetention`), so that a held value holding more instances on one path, a value difference, keeps no more alive; instances only a closure holds are not walked. A type of which the seam build keeps more alive than the inline build in an experiment both paths ran fails the graph as `seamRetainsWhatInlineFrees` (`publicMockRetainsWhatKnownRightFrees` in the public mock corpus), one `DifferentialValueRetentionDifference` per type, written ``probe `P` keeps <Type> alive holding <labels> once the probe's value is released: <n> on the feature path, <m> on the known-right path``, so that a signature names the type, the labels and both counts in one run of text; keeping fewer is no failure. It judges last in the oracle's chain, and no known failure masks it, as none masks a renamed graph's difference, so a known failure never hides a leak; a known issue documents it only when every difference matches one of its retention signatures, so a seed that also fails otherwise lists both. Each entry a seed's issue combines is judged on its own: where the retention oracle judged a graph that still fails what the seed's other entries list, such as the builder surface, but no longer finds the leak its leak's entry lists, the long run reports that entry stale for the seed (`GraphFuzzerFinding.staleLeakEntry`, a `stale` line), so the leak fix sees each seed it fixes though the seed still fails otherwise. A graph counts as judged only when both paths ran an experiment holding a wrapper; each corpus pins what the oracle judged (`retentionCounts`, the `retention` line: the judged graphs, those that draw its own shape, those whose hand-written builder's probe it judged, and the experiments only one path ran), each count but the last at least ten (`retentionCounts_holdAtLeastTenGraphs_whereTheRetentionOracleGates`); each smoke batch must judge one, and a run that judges no graph's retention (without compile verification) calls no known issue of leaks only stale (`documentsOnlyRetention`). A graph that fails only the retention oracle, as a known issue lists, and the builder surface's known kinds, listed or not, counts as passing where the long run counts the spellings passing graphs draw and the seam smoke batch the shapes of passing graphs (`GraphFuzzerResult.passes(butForRetentionDocumentedBy:)`; the public mock corpus counts its output features over every accepted graph, failing or not), since every other oracle judged it first; the seam smoke batch consults the known issues, with `seamSmokeKnownIssuesBeyondTheCorpus` for its seeds past the corpus. Its shape is the gating draw `addingRetentionShapes` (below): the adopter's Navigator and Detail, and, where `RetainDetail` is `RetainInnerDetail`, a seam that passes its place up, the shape #703 fixed across seams; 35 in 100 draws make the fill read `retainNavigator`, which inline then keeps too, and `Sendable` instantiators put the place in the `@Sendable` family, whose cases carry no values, so there the fill reads nothing (the tool rejects the read, and with it the graph's other shapes). Where the fill reads nothing, the graph also gets a probe that builds `RetainHome` through a builder written by hand, `{ _ in RetainLive() }`, beside `RetainRoot().retainHome` (`handWrittenRetentionProbe`), handed to the initializer only generated code calls, which takes the builder the readable initializer forwards unchanged; should that initializer take another builder type, the probe stops compiling rather than dropping out. On main the oracle fails such graphs whose instantiators are plain and whose `RetainDetail` is built in `RetainHome`'s own seam (seed 15, `S15_RetainNavigator` kept alive where inline frees it), but not seed 69, across seams, since an inner seam's call hands its places no values of the calling seam, and it fails graphs of the hole draws too (68's and 990's tangle, 15's and 94's cycle): the in-seam leak, listed as known issues that the leak fix removes (`inSeamLeakReason`), so the check gates that fix on their going stale and every other change on matching their signatures. Its written exceptions are known issues too: a hand-written builder until the in-seam leak fix (`handWrittenBuilderRetentionReason`), and a public mock's fill until the leak fix gives public mocks builders that keep only what their fill reads (a calling mock's fill of `RetainHome`'s place, and of `PlaceInFillInner`'s inside `PlaceInFillOuter`'s mock, keep the levels' values on the way to the place alive).

## Gating draws

Three draws, each on a stream of its own and drawn after every other draw of its corpus, so that a graph without them is drawn as before, reproduce the shapes of fixed defects and gate generator changes: the seam corpus's `addingForwardedLabelAcrossSeamCallShapes` (`forwardedLabelRandom`, three in four split graphs), the shape #703 fixed – `ForwardedInner`, a seam with a place of `ForwardedService` that `ForwardedImpl` fills from the roots' module, forwards a label, and `ForwardedOuter`, a seam or a type the seam `ForwardedHome` builds, calls it through an instantiator while forwarding the same label as another type, as the optional's wrapped type, or as the same type, or builds `ForwardedReader`, which receives it from `ForwardedRoot`; and the public mock corpus's `drawSelfBuildingPublicMock` (`publicMockSelfBuildRandomSeedMask`), the shape #702 fixed – `SelfNode`, a `.public` type with a place, builds itself again through an instantiator, through `SelfStep`, or through a `SendableInstantiator` – and `drawPlaceInsidePublicMockFill` (`publicMockPlaceInFillRandomSeedMask`), a place inside a public mock's fill – `PlaceInFillOuter`, `.public`, builds `PlaceInFillInner`, a `.public` type of `FuzzSession`, and fills its place with `PlaceInFillDefault`, whose own place only a consumer module fills or passes up (the comparator calls `PlaceInFillInnerScreen`'s instantiator with a sample `placeInFillId`, `placeInFillInnerScreenSamples`, as it calls `ForwardedOuter`'s and `ForwardedInner`'s with `forwardedLabelAcrossSeamCallSamples`); a variant whose place is passed up (`placeInsidePublicMockFillPassedUp`, `selfBuildingPublicMockPassedUp`) leaves the calling mock a required builder, so no probe builds it and it is gated by acceptance and compilation only; neither public mock draw lands in a graph with a module that sets `mockConditionalCompilation: nil`, where it would reject a graph the rest of the draw has the tool accept. That shape's route through `SelfStep` is a two-type lazy cycle, whose names the move across wrapper names now and then puts on either side of `Instantiator`, so its seeds that show it are listed under the lazy cycle's configuration-field known issue. Each shape is a draw feature whose drawn count and accepted count are pinned (`seamCorpusAcceptedDrawFeatureCounts`, `publicMockCorpusAcceptedDrawFeatureCounts`, reported on the `draws` line), and every accepted pin is at least ten (`acceptedDrawFeatureCounts_holdAtLeastTenGraphs_forEachGatingDraw`). An accepted graph gates only where an oracle after acceptance judged it, so the long run also counts, per gating draw, the accepted graphs the value comparator compared (for a retention draw, that the retention oracle judged) and that no known issue masks, one whose shapes are all value or retention differences masking nothing (`GraphFuzzerKnownIssue.masksNoLaterFailure`, `Corpus.gatingDrawsJudged(by:knownIssue:)`); the `gating` line reports them for each draw, and the combine job fails a draw below `gatingDrawJudgedGraphFloor`, ten graphs per draw (a draw's own name, `Corpus.flooredGatingDrawNames`); the `gating-shapes` line reports the shapes each draw rolls, against no floor. Without its fix, a non-`Sendable` draw of the shape #703 fixed whose types differ, whose inner label is optional, or whose caller defers the label fails to compile (seeds 59, 78, 80, 83, 98, 108, 215), and every draw of the shape #702 fixed does (seeds 3, 4, 8, 15 of the public mock corpus). Without the fix, draws whose two labels have one type, and `Sendable` draws, compiled and built the inline build's values (seeds 18, 19, 25, 30, 56), so the fuzzer does not gate the wrong value that defect handed a hand-written builder. Two more draw the retention oracle's shape, counted and pinned the same way: the seam corpus's `addingRetentionShapes` (`retentionRandom`, three in four split graphs, after `addingForwardedLabelAcrossSeamCallShapes`) and the public mock corpus's `drawRetentionPublicMock` (`publicMockRetentionRandomSeedMask`, three graphs in twenty): `RetainHome`, a seam or a `.public` type with an `internal` initializer, binds `retainNavigator` and then builds `RetainDetail` through an instantiator, beneath which `RetainLeaf` holds a place of `RetainApi` that `RetainLive` fills from a caller's module (`RetainRoot`'s, or the mocked consumer `RetainApp`'s).

Every seam module the seam corpus draws sets `generatePlainDependencyTreeInitializers: true` (`GraphFuzzerFixture.init`). The builder surface reads each tier's readable initializer where the module generates one (`GraphFuzzerOracle.seamInitializers`), so a builder that takes a builder struct is read as the `() -> T` a person passes, and the hand-written retention probe calls the readable initializer with `{ RetainLive() }` there, `{ _ in RetainLive() }` where the builder keeps the closure over its enum. The readers of a seam's scope types admit `nonisolated`, and leave `__safeDI_Builder` and the empty struct a `@Sendable` member takes out of the payload structs. The retention oracle holds one wrapper and one call's build (`retentionExperiment(holdingWrapperAt:)`), and `addingRetentionShapes` draws no type that builds itself again, so retention that grows with the depth of a self-building shape is judged only by hand-written tests (`SafeDIToolSeamBuilderStructTests`).
