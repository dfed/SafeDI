# Graph fuzzer: the gating checks

Continues `fuzzer-seam-oracles.md`. These checks gate seam and public mock generator changes: the retention oracle, the compile of the call a person writes, and the draws of fixed defects' shapes; and mock generator changes: the configuration storage oracle.

## The retention oracle

The retention oracle (rule 3 of the seam contract: nothing is retained that inline frees) judges each graph with a hole (`GraphFuzzerOracle.holdsHole`: the graph draws a hole's fill, or its generated code takes a builder over a `SafeDIScope_`, `SafeDISendableScope_` or `MockScope_` enum) that the comparator compares, of the seam corpus against its inline build and of the public mock corpus against its known-right path (`DifferentialValueGraph.judgesRetention`). After describing each probe, the describer builds the probe's value again for each experiment – holding nothing, then holding one of the SafeDI wrappers the value holds through stored properties, at most 24, in the order a walk of those properties meets them, once along each way to them (the walk ends a way only at an instance it is already inside, and stops after 4,096 visits), each named by the labels on that way, so that two paths whose values agree pair every experiment whichever instances either shares – holds that wrapper with what one call of it builds, or its instance, releases the value, and prints how many class instances of each type that the value and what is held hold through stored properties are still alive though what is held does not reach them through stored properties (`retained holding <labels>: <Type> (2); …`, `DifferentialValueRetention`), so that a held value holding more instances on one path, a value difference, keeps no more alive; instances only a closure holds are not walked. A type of which the seam build keeps more alive than the inline build in an experiment both paths ran fails the graph as `seamRetainsWhatInlineFrees` (`publicMockRetainsWhatKnownRightFrees` in the public mock corpus), one `DifferentialValueRetentionDifference` per type, written ``probe `P` keeps <Type> alive holding <labels> once the probe's value is released: <n> on the feature path, <m> on the known-right path``, so that a signature names the type, the labels and both counts in one run of text; keeping fewer is no failure. It judges last in the oracle's chain, and no known failure masks it, as none masks a renamed graph's difference, so a known failure never hides a leak; a known issue documents it only when every difference matches one of its retention signatures, so a seed that also fails otherwise lists both. Each entry a seed's issue combines is judged on its own: where the retention oracle judged a graph that still fails what the seed's other entries list, such as the builder surface, but no longer finds the leak its leak's entry lists, the long run reports that entry stale for the seed (`GraphFuzzerFinding.staleLeakEntry`, a `stale` line), so the leak fix sees each seed it fixes though the seed still fails otherwise. A graph counts as judged only when both paths ran an experiment holding a wrapper; each corpus pins what the oracle judged (`retentionCounts`, the `retention` line: the judged graphs, those that draw its own shape, those whose hand-written builder's probe it judged, and the experiments only one path ran), each count but the last at least ten (`retentionCounts_holdAtLeastTenGraphs_whereTheRetentionOracleGates`); each smoke batch must judge one, and a run that judges no graph's retention (without compile verification) calls no known issue of leaks only stale (`documentsOnlyRetention`). A graph that fails only the retention oracle, as a known issue lists, and the builder surface's known kinds, listed or not, counts as passing where the long run counts the spellings passing graphs draw and the seam smoke batch the shapes of passing graphs (`GraphFuzzerResult.passes(butForRetentionDocumentedBy:butForBuilderOrderDocumentedBy:)`, which also passes a renamed graph's difference by the builder label sort its entry lists, a sanctioned order, and by no other reason: the order-only aspect `dependencyTreeListOrder`, which a dependency tree file's difference takes only under a renaming that reorders type names or labels and only when the two files match with the items of each `(…)`, `[…]` and generic `<…>` list (split at its own commas) and of each `{…}` block (split at its own newlines and semicolons, an `#if` region one item) sorted, recursively (`GraphFuzzerOutcomeDifference.listsInCanonicalOrder(of:)`), so that only sibling order within one list or one block is forgiven, and an item moved to another list or block, a value swapped between calls, a changed nesting, a respelled type or a value moved to another label stays the file's code (and only while the renamed graph's code, with its renaming undone, compiles with the graph and ends its value comparison against the same inline build as the graph's own does, with the same differences or the same failure at the same stage of the same path, which `GraphFuzzerOracle.valueComparisons(of:isolatingValueGraphsOf:)` checks for each such renamed graph, in rounds that hold one per seed (`GraphFuzzerOracle.listOrderRefutation(of:by:)`); a use before a declaration or a move that changes what is built makes the difference the file's code, `GraphFuzzerToolRuns.renamedGraphFailures(refutingOrderOf:)`. That check alone judges two moves the sorted form also finds equal, which are not sibling order: a statement moved between two `case` bodies of one `switch`, and swapped unlabeled arguments or case bindings), `seamBuilderOrderShape(listedBy:)`; the public mock corpus counts its output features over every accepted graph, failing or not), since every other oracle judged it first; the seam smoke batch consults the known issues, with `seamSmokeKnownIssuesBeyondTheCorpus` for its seeds past the corpus. Its shape is the gating draw `addingRetentionShapes` (below): the adopter's Navigator and Detail, and, where `RetainDetail` is `RetainInnerDetail`, a seam that passes its place up, the shape #703 fixed across seams; 35 in 100 draws make the fill read `retainNavigator`, which inline then keeps too, and `Sendable` instantiators put the place in the `@Sendable` family, whose cases carry no values, so there the fill reads nothing (the tool rejects the read, and with it the graph's other shapes). Where the fill reads nothing, the graph also gets a probe that builds `RetainHome` through a builder written by hand, `{ _ in RetainLive() }`, beside `RetainRoot().retainHome` (`handWrittenRetentionProbe`), handed to the initializer only generated code calls, which takes the builder the readable initializer forwards unchanged; should that initializer take another builder type, the probe stops compiling rather than dropping out. On main the oracle fails such graphs whose instantiators are plain and whose `RetainDetail` is built in `RetainHome`'s own seam (seed 15, `S15_RetainNavigator` kept alive where inline frees it), but not seed 69, across seams, since an inner seam's call hands its places no values of the calling seam, and it fails graphs of the hole draws too (68's and 990's tangle, 15's and 94's cycle): the in-seam leak, listed as known issues that the leak fix removes (`inSeamLeakReason`), so the check gates that fix on their going stale and every other change on matching their signatures. Its written exceptions are known issues too: a hand-written builder until the in-seam leak fix (`handWrittenBuilderRetentionReason`), and a public mock's fill until the leak fix gives public mocks builders that keep only what their fill reads (a calling mock's fill of `RetainHome`'s place, and of `PlaceInFillInner`'s inside `PlaceInFillOuter`'s mock, keep the levels' values on the way to the place alive).

## The compile of the call a person writes

The builder surface's base, label and pair checks read the readable initializer's text; the compile of `C` compiles the call a person writes against it. For every seam whose readable initializer takes a builder that takes a builder struct – one whose generated-only parameter is `SafeDIScope_….__safeDI_Builder<T>` or `SafeDISendableScope_….__safeDI_Builder<T>`, a switched builder – `GraphFuzzerBuilderSurface.addingBuilderCalls(to:seamTypeAccess:modules:)` writes `<Seam>+SafeDIBuilderCall.swift`: for each tier that takes one, a function passing each switched builder a closure, `{ make() }`, and another passing the stored closure `make` itself, where `make` is `@escaping () -> T`, or `@escaping @Sendable () -> T` in the `@Sendable` family. The family and `T` are read from the builder struct, which the drawn graph decides, never from the readable parameter judged, so a readable parameter of the wrong family fails rather than being called in its own. A builder whose places are all held in instantiators takes the value they forward, read from the members of the struct and its levels (`forwardedValue(ofBuilderStruct:membersByStruct:)`: nothing where a place is plain or lazy, `()` where one forwards nothing, otherwise the first place's value): `make` is `@escaping (F) -> T`, passed as `{ value in make(value) }` (`{ make(()) }` for `()`) and stored, and, for a labeled tuple, through two more functions that destructure it and read it by label; a graph whose code compiled and whose calls judged such a builder counts toward the `wrapperBuilderCall` floor, whether they compiled or not. So `C` covers escaping, `@Sendable` and isolation, and existential spelling; a kept builder, which takes a closure over its scope enum, is passed a value of its own type and judged by the base check alone, since no form of `C` compiles against it. As the seam callers do, the calls in the seam's module call every tier, and a call in each other module of a split graph calls the narrowest tier its package reaches. `compilationFailures(of:definesDebug:)` compiles them with the graph's generated code, never with the outcomes the other oracles compare; a graph whose every error is in them is compiled again without them, and fails as `builderCallDoesNotCompile` only where its own code then compiles and draws no warning (`SafeDIToolGraphFuzzerBuilderCallTests`). Such a graph is still value-compared and retention-judged; the kind is in no known-issue list and in both never-masked expressions of `GraphFuzzerFinding`, so no known failure hides it.

`accepts(parameterType:facts:form:)` still judges the differential pairs and kept builders. Where it and the compiler disagree on a switched builder, the compiler is right and `accepts` is corrected. The hand mutation only this oracle catches: the readable parameter of a switched builder spelled `@autoclosure @escaping () -> T`, which the seam's module compiles, since the initializer passes the autoclosure on as a closure, and no person's closure converts to. Spelling the plain family's readable parameter `@escaping @Sendable () -> T` fails the compile of `C` too, and the label check as well, since it reads the family from that parameter. For a wrapper's `Builder`, spelling the plain family's with the `Sendable` twin fails only the compile of `C` (seed 454, whose plain `retainApiBuilder` C stores as a closure that is not `@Sendable`).

## The configuration storage oracle

`GraphFuzzerToolRuns.configurationStorageFailure` (`Tests/SafeDIToolTestSupport/GraphFuzzerConfigurationStorage.swift`) judges every accepted graph of every corpus: no generated `SafeDIOverrides`, `SafeDIMockConfiguration` or public mock's module-level configuration stores a property whose type is a configuration (`configurationStoresAnotherByValue`), since each keeps its fields behind one reference (`mock-generation.md`, "Configuration fields are behind one reference"). It reads every generated file with SwiftParser, so a computed property is never a stored one. With the generator reverted to stored fields it fails 41 smoke graphs, 13, 14 and 14 of the base, seam and public mock smoke batches (base seed 12 among them). Its floor is the base smoke batch's: at least ten of its graphs generate a configuration (`smokeSeeds_judgeConfigurationStorage_inGraphsTheToolAccepts`).
