# Graph fuzzer: the query oracle

`query graph` exports, for each received dependency and alias, the declarations whose values generated code hands it, and whether and why it hands `nil` (`provenance`; `query-needs.md`). The query oracle (`GraphFuzzerToolRuns.querySuppliersFailure`, `Tests/SafeDIToolTestSupport/GraphFuzzerQuerySuppliers.swift`) checks that claim on every graph in one module the tool accepts, base corpus and seam corpus alike, but a public mock's graph: `toolRuns(of:)` exports the fixture's files with `QueryGraph` (`GraphFuzzerQuerySupplies.export(of:)`), reading an export whose `completeness` is `trees`, each `nil` entry as `nil` whatever its reason, and each dependency's kind from its `source`, `lifetime` and `aliasOf` (`kindsByLabelByType(exportedJSON:)`), and the oracle reads the generated production code's syntax (`GraphFuzzerQuerySupplies(generatedFiles:kindsByLabelByType:)`), never SafeDI's own resolution. For each construction of a type the export lists (`T(…)`, `T.instantiate(…)`, a root's `self.init(…)`, a nested type by its qualified or bare name), each argument of a received or aliased dependency is resolved as Swift scopes its name: the nearest `let` before it in an enclosing block, or a parameter of an enclosing function. A `let` of a label its function's type instantiates, forwards or aliases is that supplier (the type a builder function returns, or the root an `init` extends); the receive's own alias is followed to what it renames, through an erasing wrapper (`AnyT(x)`, or `(x as T?).map { AnyT($0) }` for an erased rename of an optional), and `.instance`; a `let` its type does not declare is a builder loop's rebinding, read where the function is declared; a function parameter its type forwards is that supplier, and any other is a lazy cycle's parameter, followed to the argument of every call of that function; `nil` is `nil`. Mock code (`#if DEBUG`, `…Mock…` files) is skipped. The two sets must be equal for every receive, and every read must resolve (`querySuppliersDifferFromGeneratedCode`). At least ten smoke graphs must be judged (`smokeSeeds_judgeQuerySuppliers_inGraphsTheToolAccepts`). A graph with a seam is judged on its build with no seam (`inlineOutcome`): the export builds every seam inline, and `seamBuildsOtherValuesThanInline` equates the seam build's values with the inline build's. With the walk handing every receive its nearest declaration whatever `unavailableProperties` says, base corpus seed 2 fails (`S2_T1.t2Builder`); with no call passing `nil` judged (`OmissionFindings.passedNothing`), `SafeDIToolQueryGraphTests.graph_recordsNilProvenance_whenLazyCyclePassesNilFromOneCall` fails.

A dependency instantiated only if available that the export shows no `fulfilledBy` for is read as `absent`, whose generated `let` is `nil` (`kindsByLabelByType(exportedJSON:)`), as the export's `declarationNotInstantiated` reason says.

**The unfulfilled marks.** Every one-module graph the tool rejects (but a public mock's) is exported too (`GraphFuzzerToolRuns.rejectedQueryExport`), and `queryUnfulfilledFailure` (`GraphFuzzerUnfulfilledDependencies`) checks its marks against what `generate` reports, by file and line. Where `completeness` is `partialTrees`, at least one dependency is `isUnfulfilled`; every error of the graph is at a marked dependency, but one at a dependency instantiated only if available, which the error lists beside a required one and the export leaves `nil`; and every further mark is at an error of the graph with each type no declaration fulfills declared, which the oracle runs `generate` on (`missingTypesDeclaredOutcome`), with an empty declaration of each type in a last file so that no line moves (`fixtureDeclaringMissingTypes(of:)`). Otherwise no dependency is marked (`queryMarksOtherDependenciesUnfulfilled`). The smoke batches hold too few exports with partial trees for a floor, so `queryGraph_marksDependenciesGenerateReports_inTenBaseCorpusGraphsWithPartialTrees` judges the first 120 base corpus graphs itself, compiling nothing, and requires ten with partial trees; a graph with both a missing type and a receive nothing provides is rarer (eleven of the first 1,500), so `queryGraph_marksReceivesGenerateReportsOnceMissingTypesAreDeclared_inBaseCorpusGraphThatHoldsBoth` names them. Hand mutations of `QueryGraphCommand`: with no dependency marked, or every dependency of a partial export marked, seeds 5, 10, 17, 29 and 40 fail; with no build around the receives the second build reports (`for _ in 0..<1`), the named graphs’ exports are `fulfillment` and that test fails.

**The deletions.** The marks say nothing of provenance, so `queryDeletionFailure` deletes from every one-module graph the tool accepts and exports it again (`queryProvenanceMovesWhenDeclarationIsDeleted`). `GraphFuzzerQueryDeletion` blanks the `@Instantiable` line of a declaration with no dependencies that a reached declaration instantiates: the export must be the graph's own, with the dependencies that instantiated it marked where one a root reaches requires it (`partialTrees`) and each receive of one handed `unfulfilled` naming it, or `nil` (`declarationNotInstantiated`) where it is instantiated only if available, in place of the declaration. `GraphFuzzerQueryProviderDeletion` removes an instantiated property a leaf fulfills, preferring one a receive beneath another receive of it reads: every dependency that reads another label keeps its marks and provenance whole; a reader keeps every other declaration it was handed, is marked exactly where a value of it is `unfulfilled` naming nothing, names only a marked receive of the label, and, required, is never `nil` for want of a declaration. An export without trees (the deletion left another error) is not judged. `queryGraph_handsEveryOtherReceiveItsValue_whenDeclarationIsDeletedFromTenBaseCorpusGraphs` floors both at ten graphs left with partial trees, and `queryGraph_namesMarkedReceiveOfDeletedProperty_inBaseCorpusGraphWithReceiveBeneathIt` names twelve graphs with a receive beneath a marked receive. Hand mutations, by base corpus seed: a marked instantiated supplier reported as a plain `declaration`, or the reported dependency stripped from its declaration in place of the absent leaf (the relaxing this method replaced), seeds 0, 3, 13, 16 and 18, as with every dependency that has an `unfulfilled` value marked; no absent declaration beneath a marked receive, seeds 2, 25, 33, 35 and 39; a marked receive handed `nil`, seeds 0, 2, 3, 13 and 16. The fuzzer does not catch a dependency instantiated only if available marked too (`graph_leavesDependencyInstantiatedOnlyIfAvailableUnmarked_whenAnotherDependencyRequiresItsType` does), nor an absent declaration read before a declaration of its label (`SafeDIToolQueryGraphTests` does).
