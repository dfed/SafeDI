# Public mocks and a seam's own mock: builders that take nothing

Continues `public-mocks.md`; a seam's builder struct is `seam-builder-structs.md`'s.

- **Which hole types take the struct.** Every hole type of a public mock takes the builder struct, as a seam's does (`SeamBuilderFamilies`): the `@Sendable` family, a forwarding place, a `LazilyInstantiated` on the route, and a case that holds another scope (a call's case, which returns another module's public mock's struct; a fill case, which returns the called mock's struct over the struct of the fill's own level; the mocked type's own root struct where its tree builds it again). A type that is a seam and a public mock takes the same struct in both. The mock's enums are namespaces with no case and no `@frozen`, as a seam's are (`seam-builder-structs.md`). A place beneath a received dependency the mock promotes to its root (`createMockRootScopeGenerator`) is a place like any other: the root's enum has a case for each promoted child whose tree leads to a place, after the cases of the mocked type's own properties (`scopeEnumsByType`, which drafts a type's cases from its declarations and, at the mock's root, from the children it builds besides them), so `mock()` takes a builder for it, never a flat value (`SafeDIToolPublicMockPromotedHoleTests`); a promoted instantiator of the mocked type returns the root struct, as a property of its own that builds it again does.
- **The pair.** A tier that takes at least one such builder declares `mock()` and `__safeDI_mock(…)` (`ReservedName.publicMockFunctionName`), both with the tier's access, attributes, `mockAttributes` and isolation, and the same parameters and defaults; a tier that takes none is unchanged. `mock()` takes each such builder as its readable type (`Builder.readableParameterType`: `@escaping () -> T`, or the erased wrapper's `Builder` where every place is an erased instantiator) and its body is one call of the tier's `__safeDI_mock`, passing `.init(__safeDI_noScope: <label>)`. `__safeDI_mock`, documented "Only code SafeDI generates calls this function", takes the root struct, `SafeDIMockScope_<Stem>.__safeDI_Builder<T>`, under the tier's label and the builder's internal name, and holds the body `mock()` holds elsewhere; a wider tier's forwards to the next narrower tier's `__safeDI_mock`, passing each struct by its internal name. The body calls one member per level, as a seam's tree does. A type whose tree builds it with its hand-written mock also declares the construction function `__safeDI_mock(verbose:…safeDIBuilder:)` (`publicConstructionFunctionName(of:)`); the two are overloads told apart by the required `safeDIBuilder:` label, also for a mock with no `SafeDIOverrides` (`SafeDIToolPublicMockBuilderStructTests`). The guard hashes the struct type, so a mock that takes one gets a new guard name. The hole type's enums, payload structs and structs are `nonisolated`.
- **Calls from generated code.** Every call of another module's public mock is static (`PublicMockLevelFunctions`): one level function per level of the called mock's tree and per set of values the routes to it bind, decided when the code is generated, each returning the level's struct. A route on which no level binds a value a fill reads hands the fill the caller's, which the root level function takes (`ScopeGenerator.FillCallerReads`), so a call fills every place of a builder its routes reach or passes the builder up whole: an internal caller `.init(__safeDI_noScope: <its builder parameter>)`, a `.public` caller its own struct's member for the call. On a route to a place inside a fill of the call, a level function also takes the struct of the caller's fill level its member returns (`FillDispatcher.carriedInnerScopes`), as a seam's caller does. A call inside a fill re-enters a level function an enclosing call declares: a call of the same builder the root level function, and a case of a call of another module's public mock that holds a builder of a type whose places the enclosing call fills (`.inner`) that type's level function (`PublicMockLevelFunctions.Member.reentry`). Each hands the function what it takes of the caller's scope, read of the re-entering call's own (`PublicMockLevelFunctions.Reentry`), and a fill whose trees hold such a call takes those values from the function (`Scope`'s `callsInsideFills(of:reenter:)`). The caller's scope holds nothing the called mock binds on its way to the builder it holds, which its copy of the place leaves uncarried, so a fill that reads such a label gets the twin's error: `validateFills` judges a public mock call's fills against those copies (`calledCopyDeclarations`), not against the declarations on the path to the re-entering call, which it reads (`SafeDIToolCallingMockCrossCallReentryTests`). A fill of an instantiator's place returns the wrapper's `Builder`. No call converts a closure over an enum, and nothing decides at run time whether to pass a place up. A call's override closure is handed what the called `mock()` takes, or is not generated (`public-mocks.md`, "An override closure for a call of another module's public mock"). Over a level that reopens in a loop, the reopened level re-enters the first opening's function; a fill that reads a label the loop declares again stays rejected (`declarationBoundOnCycleReentry`).
- **A lazy value a call hands over.** A known difference, not a deliberate gap: a called public mock takes its received values by value, so a call hands it a `LazilyInstantiated` origin's instance (`<label>.instance`, at `ScopeGenerator`'s construction of a public mock call), and the instance, its override and its hole builders run at the call, even when nothing in the called mock's tree reads it. Values are the same. The graph fuzzer's M8.32 (`isEarlyReadHeldInstance`) covers the early read; the value comparator compares the wrapper the called mock makes again by its instance, the caller's. It differs from a seam's call in production code, where an eager read was a regression and a seam's generated-only initializer takes the value deferred (`SeamSignature.Parameter.Deferral`). Closing it means every tier takes received values deferred from generated callers by the seam's rule, with `_Values` holding the memo, and without adding an availability requirement.
- **The caller's own value.** The called mock's root binds each received value a call hands it from the caller's scope (a parameter of `mock()`, or a dependency it builds where the caller passes `nil`; `SeamSignature.Hole.Field.isBoundByPublicMockRoot`), and that copy is the caller's own, as a seam's deferred parameter is: a fill whose nearest declaration of the label is that copy at every place of its case that carries a field of it reads the caller's declaration (a place that carries none has its fill read the caller's declaration already: no level on its route holds the label, or the place is inside a `@Sendable` function and the copy is bound outside it, `UncarriedDeclaration.isBoundFromCallersArgument`, whether the called type's tree receives the value outright or only if available), so its tree holds the caller's `LazilyInstantiated` itself, as inline and the twin do, and no level function takes the value (`Scope`'s `callersOwnLabels(amongLabelsOf:at:reading:handedFrom:by:)`). The caller's declaration is a scope of its tree, or its mock root's binding where that is the root's one declaration of the label, under the label: a dependency the mock promotes, as for a mocked type between the value's owner and the call (`NearestDeclarations.markBoundUnderLabelByRoot`). Any other label keeps its field, as does a label its case's payload carries, and the levels on each route hand the fill the field: a level of the called mock that declares the label again hands its own value, which inline reads there. Where no level on a route binds a form that provides the one the fill reads, the route passes the place up, and the calling mock names a builder it does not declare, since a level that holds only the called mock's by-value copy cannot hand a fill that reads the caller's `LazilyInstantiated`; `DependencyTreeGenerator.holeTypesTheFillGatesPassUp(of:in:)` passes two such shapes up whole, every place of the hole type, before any fill is generated, a difference contract rule 7 lists (`seam-and-mock-contract.md`): places of one hole type whose fills read different `LazilyInstantiated` or `SendableLazilyInstantiated` values beside their fields, as one beneath a level that declares the label again and another the copy reaches; and a called type whose fill's tree calls its public mock again, or one whose builders reach its places, where a fill of one of its places reads such a value beside its place's fields (`SafeDIToolCallingMockMirrorsProductionTests`' `generate_passesPlaceUpWhole_…` and `generate_passesBothPlacesUpWhole_…`). A fill whose tree calls a public mock that then passes a builder up is not filled either. Each gate decides per called type and hole type for the whole module, so every mock of the module that calls the type passes the place up. Two known defects, not deliberate gaps, remain: a caller whose mock binds the form the fill reads only under a name apart (`session_lazilyInstantiated` beside the instance `session` it takes, or a label it promotes in two forms or that a default-valued parameter of `mock()` keeps; `NearestDeclaration.isBoundByMockRoot`); and a place on the called mock's root level whose fill reads both the caller's `LazilyInstantiated` and the value it holds, where the fill binds the payload's copy under the label, which hides the wrapper. Closing the first means the fill reads the name the caller's mock spells; closing the second means a label the payload carries is the caller's own where the copy does not provide every form the fill reads. Lifting the gates means each route of a re-entered call decides again whether it fills the place, with the builder declared wherever a route passes it up; a release that fills these places keeps `mock()`'s builder parameter, defaulted, so tests that pass one keep compiling. Where a call inside the fills re-enters the called mock's root level function, the label is the fill's field again (`Scope`'s re-entering call) and a parameter of the root level function, which each call hands its own nearest declaration (`PublicMockLevelFunctions.Reentry`), the one inline reads at the places that call reaches. The gates leave a call filled whose re-entering call is inside a fill of another call's place, as where the called type's fill builds a second called type whose own fill builds the first again (`SafeDIToolCallingMockMirrorsProductionTests`' `whenCallReadingCallersLazyValueIsReenteredOnlyThroughAnotherCallsFill`): there a fill whose tree makes that call takes each label the function takes in the field's form, non-optional where the function's form is, whatever its own tree reads of it (`Scope`'s `labelsHandedToReenteredFunctions(by:)`), and where a fill reads the label in a form the called mock's by-value copy does not provide, the caller's `LazilyInstantiated`, the root level function hands the level beneath its own parameter, past the copy its payload carries (`Scope.Fill.labelsHandedPastCalledMockCopy`); where the copy provides every form the fill reads, the levels hand the copy, which holds the same value.
- **A seam's own internal mock** (`MockRootParameters.SeamMockBuilder`, `ScopeGenerator.seamMockBuilders`) takes, for each hole type and family whose places its tree cannot build, the builder the seam's readable initializer takes, in place of those places' flat parameters: its type is the seam's (`DependencyTreeGenerator.builderForm(ofPlaceProperties:)`, `readableBuilderType`: `() -> T`, `@Sendable` for a place built in a `@Sendable` function or held in a `Sendable` wrapper, or the wrapper's `Builder` where every place is an instantiator), and it is labeled from what it builds as a seam's builder is (`DependencyTreeGenerator.stems(of:)`), with `_` appended while another parameter of `mock()` has the label, so the seam's own labels and guard never move; it is listed among the flat received parameters by label. Each type that instantiates a place calls it once per build and binds the value under the place's label, or builds the place's wrapper (`LazilyInstantiated`, an instantiator) around it (`SendableAutoclosureParameter.binding`); where a name the tree binds at any level has the builder's label, `mock()` first binds it to a name apart (`let <name> = <label>`). It has no struct and no `__safeDI_mock`: no generated code calls an internal mock. A place reached through another module's public mock is passed up as that mock's readable builder. An internal mock of a type that is not a seam keeps its flat parameters, which are API, but for a call of a switched public mock inside it, and its fills take builders for what they cannot build: each place inside a fill of a call of another module’s public mock that no declaration the module sees fulfills, spelled as a hole can be (`canBeHole`), is a place of a builder of its own (`ScopeGenerator.FillPlace`, `fillPlaces(insideSendableFunction:)`), joined by family with the type’s own places where it is a seam, labeled and named apart from the fills’ declarations in the same way, and bound by the type in the fill that instantiates it (`FillPlaceBindings`, through `prepareFillCode`), so the mock fills that call’s place where its twin does (`DependencyTreeGenerator.holesFilled`). A deliberate gap from the twin, which takes one builder per hole type: a type that is not a seam takes a flat parameter for the same type its own tree instantiates outside every fill, and a builder only for the places inside fills; and where it builds a seam itself whose hole nothing fulfills, a flat parameter for the hole, while a seam a fill builds takes a builder (comments at `seamMockBuilders`' call and `fillPlaces(insideSendableFunction:)`). A fill whose tree instantiates, with no declaration fulfilling it, a type spelled as no hole can be (a closure, tuple, array or dictionary) is production's error, `noInstantiableFound` at that property, which both kinds of calling mock report where a mock's tree reaches the call (`holesFilled`' `typesNoDeclarationCanFulfillByCalledType`, `validateFillsInstantiateOnlyWhatCanBeFulfilled`), in a build that compiles the generated mocks only (`compilesGeneratedMocks`, as for a hand-written mock's unfulfilled parameter in `validation-boundaries.md`): a release build compiles no mock, and generates the place passed up, with no error (`generate_generatesMockWithoutTwinsError_whenBuildLeavesMockConditionInactive`). A debug build whose integration does not report `DEBUG` (SwiftPM's native backend) compiles that mock, with the place passed up, where an integration that reports `DEBUG` gets production's error (the same test's debug cases, and the calling-mock draw's last block). `query needs` reports each builder as a required parameter (`DependencyTreeGenerator.requirements`).
- **Graph fuzzer.** The hand-written caller (`GraphFuzzerOracle.addingPublicMockCallers`) rewrites `{ _ in value }` to `{ value }` where `mock()` takes a builder that takes nothing, reading the type from the generated file, and the retention probe (`handWrittenRetentionProbe`) does the same for `RetainHome`. The output features `.generatedOnlyMockFunction`, `.consumerPassesLevelFunctionsStruct` and `.holeLoopBuilderOfBuilderStruct` count the new shapes; the seam corpus counts a seam's own mock that takes a builder (`GraphFuzzerSeamOutputFeature.seamOwnMockBuilder`, the `seam-mock-builders` report line, floor ten in the combine job).
