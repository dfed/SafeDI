# Graph fuzzer: the seam corpus's oracles

Continues `fuzzer-seam-draws.md`.

The seam corpus also runs a DIFFERENTIAL oracle: a graph the tool rejects with its seam is run again with no seam (`GraphFuzzerFixture.withoutSeams`), and when inline accepts it, the seam's rejection must be a seam's own error – one reported about the seam's generated initializer or a call of it (`GraphFuzzerOracle.isSeamOnlyRejection`: label collision, tier omission, redeclared initializer, a declaration the callers cannot see, a `@Sendable` builder inside the seam capturing a wrapper parameter, and a fill's own errors, among them a fill whose tree receives an instantiator the seam's tree is building where it calls the hole's builder, which inline hands a wrapper made again inside a loop of instantiators) – else the seed fails as `seamRejectsGraphInlineAccepts`: an inlined validation's error the seam world adds is a defect, not a rule. The converse is judged in one module, where the seam world is the inlined validation and the seam rules: a graph in one module the tool accepts with its seam and rejects without it fails as `seamAcceptsGraphInlineRejects` (`acceptanceDifferentialFailure`); a split graph is not judged so, since its inline build cannot construct another module's `internal` types. Every seam graph is run without its seam, and the graphs the tool accepts both ways (`isInspectedByValueOracle`, pinned as `seamCorpusValueOracleInspectedGraphCount`, reported per shard as `inspected` and added up by the combine job) are judged by value: the differential value comparator (`GraphFuzzerOracle.valueFailures`, one `DifferentialValueOracle.compare(graphs:)` batch per `results` call) compares each root and each generated mock without a required parameter between the seam build and the inline build of the graph drawn storing every parameter, which changes nothing the tool generates, and a difference is `seamBuildsOtherValuesThanInline` (a build the comparator cannot describe is `valueComparatorCouldNotDescribeGraph`). A known issue documents a value failure only when every difference matches one of its value signatures (`GraphFuzzerKnownIssue.matches`), and a known value failure masks no later failure of the oracle's chain that the known issue does not document (`GraphFuzzerFinding`). A seam graph is passed no exemptions (`DifferentialValueGraph.exemptions` is empty; only a public mock graph's stated divergences are filtered, `statedPublicMockValueDivergences`), and nothing is exempted by its shape: a seam hands a hole's struct the memo of each value it defers and a generated fill reads the caller's declaration, so a seam with holes is held to exact parity; the one early read left, in a fill re-entered beneath another declaration of a deferred label (see `seam-holes.md`), is in no shape the seam generator draws. Beside the comparator, a literal-nil count (`GraphFuzzerToolRuns.nilArgumentFailure`) counts, over the whole module's generated code, per constructed type and argument label, the literal `nil` arguments (`GraphFuzzerOracle.nilArgumentCounts`), and a count higher with the seam is `seamPassesNilWhereInlinePassesValue`; it still reaches the non-seam constructions beneath what the comparator does not traverse – an instantiator with forwarded properties other than the three probed below, or an erased instantiator – while a seam type's own constructions are not counted, since a wider tier passes `nil` for what it omits; mocks are generated the same with and without a seam, so the count says nothing about them. The comparator does not traverse an instantiator whose type forwards a property, so each root's `spellSeamBuilder`, `spellHostBuilder` and `aliasSeamBuilder` gets a probe calling it with a sample value (`GraphFuzzerSpelling.sampleExpression`, with a `SpellConformer` declared for the existential spellings), which judges the seam's tree beneath and the seam call's arguments; the graph accepted both ways that draws a known compiler warning (seed 916) is counted as inspected but never compared, since `results(of:)` compares only graphs without a compilation failure (the long run reports the graphs compared as `compared`, beside `inspected`), and the documented divergences only lower the count. The oracle compiles, for each generated seam initializer, a hand-written call of every tier passing every parameter, one file per seam, each function spelled at the narrower of its tier's access and the seam type's – and, for a split graph's seam, a caller in each other module calling the narrowest tier its package reaches; a warning in any of them fails the graph as one in generated code does – and reduces the guard enum's hash to a placeholder when it compares a renamed graph's output, since the hash names the signature's types. Two oracles judge the access a seam's tiers prove. The ground truth (`GraphFuzzerToolRuns.tierAccessFailure`) requires every generated tier to be no wider than each type its parameters name, by the access the generator gave the types it drew (`GraphFuzzerGenerator.narrowerTypeAccess`, every other type `public`), which fails as `seamTierWiderThanParameterType`. In a split graph the tool accepts inline, the omitted-value oracle (`GraphFuzzerToolRuns.omittedValueFailure`) requires an error that a caller holds a value its tier omits exactly where the caller's module's inline build passes some receiver of that parameter a value: a call omitting a parameter the inline build passes a receiver is `seamTierOmitsValueInlinePasses`, and such an error where the inline build passes every receiver `nil` is `seamTierOmitsProvidedValueReportedWhereInlinePassesNil`; an alias's receiver is not followed. In a split graph that error is a seam's own to the differential (`isSeamOnlyRejection(excusingOmittedValues:)`), never in a graph in one module, whose seams are called at their narrowest tier. So is an outer seam's error that it takes the value from its own callers ("`Outer` takes `theme: Theme?` from its callers, but …", `GraphFuzzerOracle.omittedValueLabel(of:)` reads both forms), which the inline build cannot judge, since no caller of the outer seam is known (`isOuterSeamOmittedValueError`). The graphs the tool rejects with it are pinned (`seamCorpusOmittedValueGraphCount`, reported per shard as `omitted-values` and added up by the combine job). The rename-invariance oracle compares the declarations a diagnostic lists as proving a type's access as a set, as it does a list of suggestions. A reproduction command names `SAFEDI_GRAPH_FUZZER_FEATURES` for a seam-corpus seed, and a stale entry's message names the corpus's list. `ci.yml` fuzzes each corpus in shards of its own (`matrix.corpus`, `matrix.features`), and the combine job checks each corpus's shards against its pins, that they cover it exactly once, and – from the `corpora` line every report carries – that no corpus is missing a report. `addingUnreadParameterTypes`, drawn after every other pass on streams of its own (`unreadTypeRandom`, three graphs in twenty; `unreadBoundaryRandom`, one in ten), adds `UnreadHost`, which the first root builds through an instantiator and which forwards `unreadValue` – a `StaticString`, which no declaration SafeDI reads declares and the list of standard types leaves out: by value, received only if available, in an array, a closure or a tuple, through `any CustomStringConvertible`, as `Unicode.Scalar`, or through a `public` typealias the seam's module declares – and instantiates the seam `UnreadSeam`, whose `UnreadChild` receives it, and a first-party type received only if available that SafeDI must read a declaration of – `public` inside a platform-conditioned `#if` block, every clause of which it reads (`recordedInsideConditionalBlock`), or narrower in a `package` extension in a file without a SafeDI marker, in an extension of a nested type, or as an `internal` typealias – which, misread as unread, would make the `public` tier fail to compile; half of those graphs, by one more roll of `unreadBoundaryRandom`, also receive a type declared `internal` in the clause of `FUZZ_FLAG` and `public` in its `#else`, spelled `#if FUZZ_FLAG` or `#if !FUZZ_FLAG` (`recordedInFlagClause`). `FUZZ_FLAG` is never defined, by the harness or the compile, so the `!FUZZ_FLAG` spelling selects the narrower clause, which the oracle expects at `internal`, and the other the `public` one: a deviation from drawing the flag reported in half the draws, which would have to thread conditions through the batch compiles, and which a smoke seed with the flag among its conditions could add later. `addingMockOnlyBlockParameterTypes`, drawn after it on a stream of its own (`mockOnlyBlockRandom`, one graph in ten), adds `DebugHost`, which the first root builds through an instantiator and which forwards `debugValue` and instantiates the seam `DebugSeam`, whose `DebugChild` receives it, required or only if available: a plain `DebugValue` declared in an `#if DEBUG` block beside a `mockOnly` extension, whose `#else` declares it at the same level, wider or narrower (`mockOnlyBlockTypeElseSameLevel`, `…Wider`, `…Narrower`), or which has none while `DebugChild`'s file declares it under `#if !DEBUG` with a `mockOnly` extension in that block's `#else` (`mockOnlyBlockTypeRedeclaredWhereMockConditionIsInactive`); the narrowest level goes into `proofTypeAccess`, with `DebugHost`, whose `ForwardedProperties` names the value. The harness gives the tool no `DEBUG` while it compiles with it, so the fuzzer cannot draw a plain-only `#if !DEBUG` redeclaration, which SafeDI asserts; the pipeline cells cover it. The oracle compiles these graphs a second time as a release build, without `DEBUG` (`GraphFuzzerFixture.compilesAsReleaseBuildToo`, `compilationFailures(of:definesDebug:)`), a failure there reported only when the debug build passed. A file a pass draws without a SafeDI marker is named after the type it declares first, as `executeSafeDIToolTest` names a file, or the harness writes no file of the name the fuzzer looks up, which is an infrastructure error (`fixtureDirectory(of:in:seed:)`), as is a fixture written outside a directory of its own under `TestTemporaryDirectory.root`, so nothing outside it is ever deleted. A graph whose generated code carries the comment of a run without a target graph shows `GraphFuzzerSeamOutputFeature.unreadTypeComment`. Every graph of this corpus or the public mock corpus that names a type no declaration SafeDI reads declares is also run as its read twin (`GraphFuzzerFixture.readTwin`), under each flow the graph runs under: each such type (`GraphFuzzerReadTwin.UnreadType.all`) is renamed to its twin – its name with the case of its last letter flipped, which keeps every column and every order of names – and declared `public` at the end of the first file naming it of the lowest module whose files name it. Decision 54 counts the type as `public`, so with the rename undone the twin must get the graph's verdict, diagnostics and generated code byte for byte, but for the comment of a run without a target graph, compared by the types it names in each module: in every module it names none of the twinned types and every other type the graph's names, since the twin's module names the twin in a declaration, so its `.safedi` keeps the twin's `public` record even when written without a target graph, which keeps no other; the SwiftPM plugin writes no comment (`readTwinDiffers`). The graphs that run as a read twin are pinned per corpus (`seamCorpusReadTwinGraphCount`, `publicMockCorpusReadTwinGraphCount`, none in the base corpus), reported per shard as `read-twins` and added up by the combine job, so a run that stops twinning fails.

The renaming oracle's `GraphFuzzerRenaming.restore` also undoes a lowered type name (`s12_Missing3Builder`, and the `a12_`/`z12_` prefix move), since a builder's label is its hole type's stem with its leading capitals lowered. Builder order follows type names, so moving type names across wrapper names reorders the builders of a graph with two hole types, and a mock's builder among its label-sorted parameters: known-issue shapes of `seamKnownIssues` and `publicMockKnownIssues`, combined with a seed's other shapes in entries of their own, since a seed is listed once. `seamOnlyErrorMarkers` read `` the builder for ` `` and `` but that call passes the builder ` ``, and `holeOutputFeatures` tells a fill (a case's `_Values` payload, nested by type in a `<Type>_Scope` or not, or a case of a `@Sendable` enum that carries none) from a dispatcher (the enum, root or nested, taking the values a nested enum's dispatcher passes on after it), and reads an inner seam's enum held in a case alone or, in the case of a builder a call fills, after that case's payload.

The name-stability oracle (`GraphFuzzerToolRuns.holeNameStabilityFailure`) runs every accepted graph that has a second place of a hole – the seam corpus's (`fuzzer-seam-draws.md`) and the public mock corpus's `t6Twin`, else its second call of `T6`, `t6Second` (`fuzzer-corpora.md`) – again without it (`GraphFuzzerGenerator.fixtureWithoutSecondHolePlace`), and fails as `holeNamesChangeWithSecondPlace` when a name the tool generates without the place is gone with it (`GraphFuzzerOracle.holeBuilderNames(in:)`: each parameter typed by a scope of places of a mock or of the seam initializer only generated code calls, which every module generates, read without its `__safeDI_` prefix as the plain initializer spells it, each `SafeDI…Scope_…` an extension declares, and each case of one), since a hand-written caller spells them. The design's accepted breaks of output stability are known issues with the signature `holeNamesChangeWithSecondPlace(containing:)`, which reads the place's label: two hole types of one instantiated type, whose builders are named apart (`holeGadgetOther`), and an internal consumer that passes up the places of two public mocks of one hole type, which names the builders it takes for them apart after each called type (`t6Twin`). Two calls of one public mock (`t6Second`) share one builder, so the second only adds a case. The smoke batch must compare one graph so (`isComparedWithoutSecondHolePlace`).

The place-level oracle (`GraphFuzzerToolRuns.placeLevelsFailure`) reads the levels of every place the first run computes (`SeamPlaceLevels`, through `collectingPlaceLevelDisagreements(during:)`) and fails a graph as `placeLevelsDifferBetweenBuildsOfType` when two builds of one type, inside a fill or not, bind other values before the same property – a builder function's cycle parameters left out, a fact of the function (`Level.fieldsOfType`) – or the seam's root binds other values before one property on two paths (`SeamPlaceLevels.levelDisagreements()`): a scope enum nested by type holds one level per type. A fill's tree starts each type's children in the type's order, as the rest of the tree does, so a tangle of cycles inside a fill gives no disagreement (`SafeDIToolSeamPlaceLevelTests`).

The oracles of a scope nested by type read the facts of the places the first run computes (`GraphFuzzerPlaceFacts`, from the same `SeamPlaceLevels` observer, through `collectingPlaceFacts(during:)`), outside every fill: each case a place's path produces, by the type that binds the level and the property after it; each level's fields; and the labels each type declares. A place's path that repeats a declaration, keyed as the cycle check keys it, fails as `placeChainRepeatsDeclaration` (`placeChainFailure`): a build that closes a cycle is the first build, so a scope value's chain never repeats one, which the per-path bodies 2.3.0 generates build from the path; a body with one function per type, after the tag, needs a run of its generated code to judge. A graph with a second path to a type that holds a place (`fixtureWithoutSecondPath`, the shared types' draw) is run again without it, and fails as `secondPathChangesScope` (`secondPathFailure`) when a level other than the path's own is added, removed or holds other fields. In a graph whose scopes the generator nests by type (`GraphFuzzerToolRuns.nestsEveryScopeByType`: every graph that holds no place inside a fill, whose call's case for the builder filled they do not model yet, `GraphFuzzerPlaceFacts.holdsPlaceInsideFill`), the generated scope enums are read from the generated files' syntax (`GraphFuzzerScopeDeclarations`: each root enum a seam's extension declares, the enums nested in it, their cases, and their `_Values` structs' fields), and the second-path oracle also requires every enum, case, struct and field but the path's own case and its struct to be the same; a produced case no enum declares fails as `producedCaseUndeclared`; in a graph without the tangle draw, an enum of no type a path builds, or a case of its own no path produces, fails as `declaredCaseNeverProduced` (a case that holds another seam's enum, an inner seam's wrapping case or a place inside a fill, is not its own, nor one whose nested enum has none: the places an inner seam passes up have no levels, as `seam-holes.md` states); and a case whose label is not `p`, `p_Sendable`, or, holding another seam's enum, `p_<builder>`, for a label `p` its type declares, fails as `scopeCaseNamesNoProperty` (a seam's root declares the labels of its `@Received`, `@Forwarded` and `@Instantiated` properties, read from the fixture's syntax, `addingSeamRootLabels(declaredIn:)`, since a seam whose every place an inner seam passes up has no levels; a case that holds a seam's root enum, the seam's own where its tree calls it again included, wraps that call's enum and is no case of its own), which bounds an enum's cases by its type's properties. A public mock's enums are left out of the case oracles until they nest by type.
