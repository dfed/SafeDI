# Graph fuzzer: the seam corpus's oracles

Continues `fuzzer-seam-draws.md`.

The seam corpus also runs a DIFFERENTIAL oracle: a graph the tool rejects with its seam is run again with no seam (`GraphFuzzerFixture.withoutSeams`), and when inline accepts it, the seam's rejection must be a seam's own error – one reported about the seam's generated initializer or a call of it (`GraphFuzzerOracle.isSeamOnlyRejection`: label collision, tier omission, redeclared initializer, a declaration the callers cannot see, a `@Sendable` builder inside the seam capturing a wrapper parameter, and a fill's own errors, among them a fill whose tree receives an instantiator the seam's tree is building where it calls the hole's builder, which inline hands a wrapper made again inside a loop of instantiators) – else the seed fails as `seamRejectsGraphInlineAccepts`: an inlined validation's error the seam world adds is a defect, not a rule. The converse is judged in one module, where the seam world is the inlined validation and the seam rules: a graph in one module the tool accepts with its seam and rejects without it fails as `seamAcceptsGraphInlineRejects` (`acceptanceDifferentialFailure`); a split graph is not judged so, since its inline build cannot construct another module's `internal` types. Every seam graph is run without its seam, and the graphs the tool accepts both ways (`isInspectedByValueOracle`, pinned as `seamCorpusValueOracleInspectedGraphCount`, reported per shard as `inspected` and added up by the combine job) are judged by value: the differential value comparator (`GraphFuzzerOracle.valueFailures`, one `DifferentialValueOracle.compare(graphs:)` batch per `results` call) compares each root and each generated mock without a required parameter between the seam build and the inline build of the graph drawn storing every parameter, which changes nothing the tool generates, and a difference is `seamBuildsOtherValuesThanInline` (a build the comparator cannot describe is `valueComparatorCouldNotDescribeGraph`). A known issue documents a value failure only when every difference matches one of its value signatures of the failure's kind (`GraphFuzzerKnownIssue.matches`; a difference from a hole's visible build by `holeBuildsOtherValuesThanVisibleBuild(containing:)`), and a known value failure masks no later failure of the oracle's chain that the known issue does not document (`GraphFuzzerFinding`). A graph with a hole puts both of its comparisons in that chain, its visible build's failure first and its inline build's after it (`valueComparisons`), so a known issue lists a signature for each comparison that differs. A seam graph is passed no exemptions (`DifferentialValueGraph.exemptions` is empty; only a public mock graph's stated divergences are filtered, `statedPublicMockValueDivergences`), and nothing is exempted by its shape: a seam hands a hole's struct the memo of each value it defers and a generated fill reads the caller's declaration, so a seam with holes is held to exact parity; the one early read left, in a fill re-entered beneath another declaration of a deferred label (see `seam-holes.md`), is in no shape the seam generator draws. Beside the comparator, a literal-nil count (`GraphFuzzerToolRuns.nilArgumentFailure`) counts, over the whole module's generated code, per constructed type and argument label, the literal `nil` arguments (`GraphFuzzerOracle.nilArgumentCounts`), and a count higher with the seam is `seamPassesNilWhereInlinePassesValue`; it still reaches the non-seam constructions beneath what the comparator does not traverse – an instantiator with forwarded properties other than the three probed below, or an erased instantiator – while a seam type's own constructions are not counted, since a wider tier passes `nil` for what it omits; mocks are generated the same with and without a seam, so the count says nothing about them. A literal `nil` a call of a builder function passes for a label – a cycle parameter of a function a lazy cycle closes on – counts, on both sides, at each construction in that function's body that passes the parameter on by name (`nilArgumentCountsThroughBuilderFunctions`), since inline's `nil` reaches those constructions through the parameter where a seam's fill can write it at each. The comparator does not traverse an instantiator whose type forwards a property, so `HoleNestScreen`'s forwarded `holeNestId` gets a registered sample (`GraphFuzzerFixture.holeDrawForwardedPropertiesSamples`, which every instantiator forwarding an `Int` in the graph is called with), and each root's `spellSeamBuilder`, `spellHostBuilder` and `aliasSeamBuilder` gets a probe calling it with a sample value (`GraphFuzzerSpelling.sampleExpression`, with a `SpellConformer` declared for the existential spellings), which judges the seam's tree beneath and the seam call's arguments; the graph accepted both ways that draws a known compiler warning (seed 916) is counted as inspected but never compared, since `results(of:)` compares only graphs without a compilation failure (the long run reports the graphs compared as `compared`, beside `inspected`), and the documented divergences only lower the count. The oracle compiles, for each generated seam initializer, a hand-written call of every tier passing every parameter, one file per seam, each function spelled at the narrower of its tier's access and the seam type's – and, for a split graph's seam, a caller in each other module calling the narrowest tier its package reaches; a warning in any of them fails the graph as one in generated code does – and reduces the guard enum's hash to a placeholder when it compares a renamed graph's output, since the hash names the signature's types. Two oracles judge the access a seam's tiers prove. The ground truth (`GraphFuzzerToolRuns.tierAccessFailure`) requires every generated tier to be no wider than each type its parameters name, by the access the generator gave the types it drew (`GraphFuzzerGenerator.narrowerTypeAccess`, every other type `public`), which fails as `seamTierWiderThanParameterType`. In a split graph the tool accepts inline, the omitted-value oracle (`GraphFuzzerToolRuns.omittedValueFailure`) requires an error that a caller holds a value its tier omits exactly where the caller's module's inline build passes some receiver of that parameter a value: a call omitting a parameter the inline build passes a receiver is `seamTierOmitsValueInlinePasses`, and such an error where the inline build passes every receiver `nil` is `seamTierOmitsProvidedValueReportedWhereInlinePassesNil`; an alias's receiver is not followed. In a split graph that error is a seam's own to the differential (`isSeamOnlyRejection(excusingOmittedValues:)`), never in a graph in one module, whose seams are called at their narrowest tier. So is an outer seam's error that it takes the value from its own callers ("`Outer` takes `theme: Theme?` from its callers, but …", `GraphFuzzerOracle.omittedValueLabel(of:)` reads both forms), which the inline build cannot judge, since no caller of the outer seam is known (`isOuterSeamOmittedValueError`). The graphs the tool rejects with it are pinned (`seamCorpusOmittedValueGraphCount`, reported per shard as `omitted-values` and added up by the combine job). The rename-invariance oracle compares the declarations a diagnostic lists as proving a type's access as a set, as it does a list of suggestions. `unreadBoundaryRandom`, one in ten), adds `UnreadHost`, which the first root builds through an instantiator and which forwards `unreadValue` – a `StaticString`, which no declaration SafeDI reads declares and the list of standard types leaves out: by value, received only if available, in an array, a closure or a tuple, through `any CustomStringConvertible`, as `Unicode.Scalar`, or through a `public` typealias the seam's module declares – and instantiates the seam `UnreadSeam`, whose `UnreadChild` receives it, and a first-party type received only if available that SafeDI must read a declaration of – `public` inside a platform-conditioned `#if` block, every clause of which it reads (`recordedInsideConditionalBlock`), or narrower in a `package` extension in a file without a SafeDI marker, in an extension of a nested type, or as an `internal` typealias – which, misread as unread, would make the `public` tier fail to compile; The oracle compiles these graphs a second time as a release build, without `DEBUG` (`GraphFuzzerFixture.compilesAsReleaseBuildToo`, `compilationFailures(of:definesDebug:)`), a failure there reported only when the debug build passed. A file a pass draws without a SafeDI marker is named after the type it declares first, as `executeSafeDIToolTest` names a file, or the harness writes no file of the name the fuzzer looks up, which is an infrastructure error (`fixtureDirectory(of:in:seed:)`), as is a fixture written outside a directory of its own under `TestTemporaryDirectory.root`, so nothing outside it is ever deleted. A graph whose generated code carries the comment of a run without a target graph shows `GraphFuzzerSeamOutputFeature.unreadTypeComment`. Every graph of this corpus or the public mock corpus that names a type no declaration SafeDI reads declares is also run as its read twin (`GraphFuzzerFixture.readTwin`), under each flow the graph runs under: each such type (`GraphFuzzerReadTwin.UnreadType.all`) is renamed to its twin – its name with the case of its last letter flipped, which keeps every column and every order of names – and declared `public` at the end of the first file naming it of the lowest module whose files name it. The retention oracle (rule 3 of the seam contract: nothing is retained that inline frees) judges each graph with a hole (`GraphFuzzerOracle.holdsHole`: the graph draws a hole's fill, or its generated code takes a builder over a `SafeDIScope_`, `SafeDISendableScope_` or `MockScope_` enum) that the comparator compares, of the seam corpus against its inline build and of the public mock corpus against its known-right path (`DifferentialValueGraph.judgesRetention`). After describing each probe, the describer builds the probe's value again for each experiment – holding nothing, then holding one of the SafeDI wrappers the value holds through stored properties, at most 24, in the order a walk of those properties meets them, once along each way to them (the walk ends a way only at an instance it is already inside, and stops after 4,096 visits), each named by the labels on that way, so that two paths whose values agree pair every experiment whichever instances either shares – holds that wrapper with what one call of it builds, or its instance, releases the value, and prints how many class instances of each type that the value and what is held hold through stored properties are still alive though what is held does not reach them through stored properties (`retained holding <labels>: <Type> (2); …`, `DifferentialValueRetention`), so that a held value holding more instances on one path, a value difference, keeps no more alive; instances only a closure holds are not walked. A type of which the seam build keeps more alive than the inline build in an experiment both paths ran fails the graph as `seamRetainsWhatInlineFrees` (`publicMockRetainsWhatKnownRightFrees` in the public mock corpus), one `DifferentialValueRetentionDifference` per type, written ``probe `P` keeps <Type> alive holding <labels> once the probe's value is released: <n> on the feature path, <m> on the known-right path``, so that a signature names the type, the labels and both counts in one run of text; keeping fewer is no failure. It judges last in the oracle's chain, and no known failure masks it, as none masks a renamed graph's difference, so a known failure never hides a leak; a known issue documents it only when every difference matches one of its retention signatures, so a seed that also fails otherwise lists both. A graph counts as judged only when both paths ran an experiment holding a wrapper; each corpus pins what the oracle judged (`retentionCounts`, the `retention` line: the judged graphs, those that draw its own shape, those whose hand-written builder's probe it judged, and the experiments only one path ran), each count but the last at least ten (`retentionCounts_holdAtLeastTenGraphs_whereTheRetentionOracleGates`); each smoke batch must judge one, and a run that judges no graph's retention (without compile verification) calls no known issue of leaks only stale (`documentsOnlyRetention`). The builder-surface oracle (`Tests/SafeDIToolTestSupport/GraphFuzzerBuilderSurface.swift`) judges what a person writes against the seam and public mock corpora's accepted graphs, by "Builders a person writes" in `seam-and-mock-contract.md`, from the tool's output alone, without a compile. (ii) A new builder of an existing filling type keeps every existing builder's label, type and order (`addedBuilderChangesExistingBuilder`): the public mock corpus's second erasure and the seam corpus's `holeGadgetOther` and a new builder in the inner seam, judged against the graph with its second place. (iii) A second place forwarding other values is rejected in the module where the places meet, (`placesForwardingOtherValuesAccepted`), in both corpora and, in the seam corpus, from the inner seam; its remedy must be accepted (`remedyOfPlacesForwardingOtherValuesRejected`) with exactly the drawn graph's builders (`remedyAddsBuilder`), kinds of their own that no known issue lists. (iv) The public mock corpus's second call of a public mock keeps the first's builder (`callingMockChangesBuilder`). An edit the tool rejects is a failure ("The tool rejects the edited graph"; `sameSupplyEditRejected` for part (i), the part's own kind for part (ii)), so a legitimate rejection is a known issue with its reason; its pair, whose calls were never judged, counts toward no floor. Each judged pair counts toward its kind's floor of ten whether it passes or fails, as does each hole kind the base check judges (`builderSurfaceFloorKinds`); the long run reports them as `builder-surface`, which the combine job adds up and checks against the kinds each corpus floors (`Corpus.builderSurfaceFlooredKinds`, `base-forwarding` among them). A known builder-surface failure masks no later failure the entry does not list, and a listed kind the graph does not show is a misfiled seed (`staleBuilderSurfaceSignature`). On main every graph with a hole fails the base check, so the parts' seeds are known issues of their own, each part's list apart (`seamBuilderSurfaceSeeds`, `publicMockBuilderSurfaceSeeds`, and `seamSmokeKnownIssues` for the smoke seeds beyond the corpus), which the builder-struct work empties.
