# Graph fuzzer: release acceptance

SafeDI measures breaking changes from its last stable release (`releases-and-packaging.md`). Release acceptance checks that for the base, seam and public mock corpora: every graph the older release accepts must still be accepted, compile cleanly and build the same values. The harness is `GraphFuzzerReleaseAcceptance` (`Tests/SafeDIToolTestSupport/GraphFuzzerReleaseAcceptance.swift`), its tests and long run `SafeDIToolReleaseAcceptanceTests` (`Tests/SafeDIToolFuzzerTests`).

- **Both sides.** Each seed's graph is its corpus's (`GraphFuzzerReleaseAcceptanceCorpus`: `base`, `seam`, `public-mock`), drawn by this tree's generator storing every parameter (`GraphFuzzerGenerator.fixture(forSeed:features:storingEveryParameter: true)`), so the comparator can judge it. This tree runs in the test process as the corpus runs (`GraphFuzzerOracle.toolOutcome(of:)`: a graph in one module through `scan` then `generate --swift-manifest`, a graph split across modules through one `generate` per module as Bazel runs it, `.moduleInfo`); the older release runs through its built `SafeDITool` the same way (`executableToolOutcome`: `scan` over a CSV of the fixture's files, every file mock-scoped, then `generate` with the manifest; `executableSplitToolOutcome`: per module in dependency order, `--combined-output`, `--module-info-output`, `--module-name`, `--package-name` unless the module has none, and the `.safedi` of each module `GraphFuzzerFixture.dependencyLists` lists), never through its test suite, which writes into the system temporary directory. Both sides' outputs get the hand-written callers the corpus adds (`addingSeamCallers`, `addingPublicMockCallers`, `addingOverrideClosureCallers`), so each side compiles the calls a person writes against its own signatures. Each side's generated files compile with the fixture against that side's runtime and macros, module by module as the value comparator compiles them (`DifferentialValuePath(fixture:generatedFiles:)`), until one fails: the runtime the value comparator compiles from the release's `Sources/SafeDI` (`DifferentialValueOracle.runtimeArtifacts(for:)`), with the release's `SafeDIMacros-tool`. A tool warning is compared by its message, whether the executable printed it or this tree's run describes a `SourceDiagnostic` (`warningMessage(of:)`). The older release is a parameter (`GraphFuzzerRelease`: its name, tool and `DifferentialValueRuntimeSource`), so a later release candidate can be compared with a beta the same way.
- **Classes**, first match in this order (`GraphFuzzerReleaseAcceptance.classify`):
  - A, the older release rejects the graph: its tool reports an error (`tool`), its macros reject the fixture, an error located in a fixture file (`macro`), or its generated code does not compile (`compile`). A graph the older release rejects cannot be a break.
  - C, this tree's tool rejects it.
  - D, this tree's generated code, or the fixture under its macros, does not compile.
  - E, this tree's generated code draws a warning, by message, that the older release's does not; generated code a `#sourceLocation` directive attributes to a fixture's line counts as generated (the compile spells those directives under a directory of its own, `GraphFuzzerReleaseCompilation.sourceLocationDirectoryName`, and prefixes each fixture file's name, so no two paths share a `#fileID`).
  - F, a probe both releases generate builds other values (`DifferentialValueOracle.compare`, this tree as the feature path, the older release as the known-right path); B, every probe agrees. The probes are each root and each generated mock without a required parameter (`differentialValueProbes(generatedFiles:)`); a probe only one release generates is skipped and counted by which (`GraphFuzzerReleaseProbeSkip`). Each instantiator with forwarded properties is called with the samples its corpus's value oracle registers (`GraphFuzzerReleaseAcceptanceCorpus.forwardedPropertiesSamples(of:)`: the base corpus value oracle's, `GraphFuzzerSampleValues`; the seam corpus's hole and forwarded-label samples; the public mock corpus's `placeInFillInnerScreenSamples`). The seam corpus's inline build and visible build and the public mock corpus's known-right path are not run: release acceptance compares the graph as drawn under two releases, and the corpus's own oracles compare it with those paths.
  - X, the comparator could not describe a path: a harness failure, never a verdict. A graph whose probe spends the batch's traversals is compared again on its own under `DifferentialValueLimits.isolatedFuzzerGraph`, as the corpora compare the seeds they isolate, so that it gets a verdict (`verdicts_compareGraphOnItsOwnWithIsolatedBudget_whenItsProbeSpendsTheBatchsTraversals` fails without it; seam seeds 277, 391, 883, 967, 1311 and 1890 were X before it). A graph whose probe spends even that budget on both releases stays X and is listed as `beyond-comparator`, as the corpus's own known issue lists it: seam seeds 391 and 1311.
- **Annotations**, which break nothing: `new-source-diagnostic`, a warning about the fixture this tree's tool or macros report and the older release's do not (a deprecation is one); `shared-generated-warning`, a warning both releases' generated code draws.
- **Listed seeds.** A break (C, D, E or F) fails the run unless `listedSeedsByRelease` lists the seed, with its corpus, under the older release with that class: a known break, a release-noted behavior change (an intended difference, listed with its release-note line), or an exemption, a defect of the older release this tree fixed. An unintended difference is a bug, fixed before the release, never listed. A listed seed of another class fails as stale. The older release is 2.3.0; 2.2.0's list left with it. Against 2.3.0 the base corpus lists the 32 `WrapKindsHost` mocks #892 fixed, which pass `nil` where 2.3.0 built a wrapper of the other kind (`mockPassesNilAsProductionDoesReason`, class F, release-noted) and, as exemptions, the 85 graphs whose `NestRoot` builds a type again through a second lazy cycle, where 2.3.0 passed the outer declaration of a label (`nearestDeclarationInNestedCycleReason`, class F; a seed joins that group only when its one difference is `nestLabel` beneath its `NestRoot`), the seam corpus lists only seeds 391 and 1311, as `beyond-comparator`, and the public mock corpus lists none. A change that breaks a seed lists it, with its reason, in the same pull request.
- **Drawn without what 2.3.0 rejects.** Each graph is drawn as its corpus draws it but without the draws of features 2.3.0 rejects – `@Instantiated(onlyIfAvailable: true)` (`addingDependencyInstantiatedOnlyIfAvailable`, `addingOptionalPlaceShapes`, `drawOptionalPlacePublicMock`) and `@Instantiable` actors (`addingActorArgumentShapes`), and `nestedFillHoleUnfilled` – which would make it class A (`GraphFuzzerGenerator.releaseAcceptanceFixture(forSeed:features:)`). Each of those draws has a stream of its own, so a graph that draws none of them is the corpus's graph, byte for byte, and no corpus pin moves; `releaseAcceptanceFixture_drawsTheCorpusGraphWithoutFeaturesOlderReleaseRejects_whenDrawnForComparison` checks both over 300 seeds of each corpus. Drawn as the corpus draws them, 1,390 base, 660 seam and 178 public mock graphs were class A.
- **What it does not compare.** A graph 2.3.0 rejects, or whose 2.3.0 code does not compile, is class A and cannot break. Nor what the comparator does not see (`fuzzer-value-oracles.md`), nor the SwiftPM plugin's flow for a split graph, which the corpus's own `integrationsDisagree` holds to the module-info flow's output. A unit test cannot run the older release, so the executable side is exercised only by the workflow's run, or locally with this tree's built `SafeDITool` as the older release, which must find no break: a broken runner makes every graph class A, which each corpus's compared-graph floor fails.
- **Tests.** The unit suite judges this tree against itself over seeds 0 to 3 (no break, three graphs compared) and over two split graphs each of the seam and public mock corpora (every one class B), one hand-written graph whose two generated files pass one value differently (exactly that difference, class F), and the classifier once per class, rejection reason and annotation, from hand-written runs. The hand mutation that passes `nil` for every receive only if available fails seed 24 by value (F) and seeds 1, 107 and 114 by a new generated warning (E) over seeds 0 to 199.
- **Running it.** `release-acceptance.yml`, a workflow that is only called: one job builds 2.3.0's tool and macros, at the commit its tag names, and packages them with its `Sources/SafeDI`, cached under a key that names the release, the commit, the runner's operating system, the container and a hash of `swift --version`; one builds this commit's test bundle; shards of each corpus run the long run (four of the base corpus, four of the seam corpus, two of the public mock corpus; `SAFEDI_RELEASE_ACCEPTANCE_RELEASE`, `…_TOOL`, `…_MACROS_TOOL`, `…_RUNTIME_SOURCES`, `…_REPORT`, `…_CORPUS`, `…_SHARD`); and "Check Release Acceptance on Linux" combines their reports (`combine-release-acceptance-reports.py reports base=4 seam=4 public-mock=2`, each corpus with its shard count). A requested run with a missing input fails rather than skips, a shard without a complete report fails, and the combine job fails on a missing shard, a corpus's seeds not covered exactly once, a failure, a stale seed, a problem, or fewer of a corpus's graphs compared by value than its `COMPARED_GRAPH_FLOORS` entry. `ci.yml`'s "Release Acceptance" job calls it on every pull request and push to main that changes more than Markdown, from the bundle "Build Tests on Linux" uploaded, so the build job is skipped and the run that lands a change is the check before a release candidate; a dispatch of `graph-fuzzer.yml` with `release_acceptance` (the other inputs ignored) calls it for a branch and builds its own bundle. It is a workflow of its own so that `ci.yml` calls one whose every job asks for `contents: read` only. It is no required check. Locally, set the variables above (the shard optional) and run `swift test --traits sourceBuild --filter SafeDIToolReleaseAcceptanceTests/longRun`.
- **Pins.** The compared-graph floors and the listed seeds are derived from a dispatched run, never edited by hand to make a run pass: a new break is attributed (release-noted, or an older release's defect) or fixed.
