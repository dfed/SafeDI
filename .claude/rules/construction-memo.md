# The construction memo

`ConstructionMemo` lets a place reuse a generator another place built: a hit needs an equal key and a read log that the new place's context answers alike (`ConstructionMemo.swift`'s header has the argument). A log matches as a set: every read it holds answered alike, in any order. Two entries of one key can hold alike reads in different orders (a child's reads taken from a reuse come cycle reads first; the mock roots' shared memo shows it), so a lookup never accepts on a matching prefix nor compares logs read by read. Production trees keep a memo per tree; the mock roots share one, a local of `generateMockCode`'s loop, carrying every pass: each pass starts from the prior pass's memo, and the tree keeps its own last (`memo(forPassAfter:)`, `keepEntries(ofLastPass:)`), so a later pass reuses an earlier root's later pass built from one generator (`mock_reusesLaterPassOfEarlierMockRoot_…`). A tree with a seam root or a mock root's builders keeps a memo of its own, for one pass, because it reads its own `SeamHoles`.

A memo that only one tree reads, every memo but the one the mock roots share, neither keys, looks up nor stores a place of a scope the tree builds at one place only (`ScopesBuiltAtOnePlace`, which `createdTree` decides once per tree, by how many references reach each record): no other place of a pass has that place's key, and the pass after builds the place again rather than reusing it settled. The sharing oracle's build that offers each place what a later place built keys every place, so it still judges the reuse a place at one place could make. A place records its subtree's reads (`ScopeGeneratorUnderConstruction.recordsReads`) only where it has a key or is beneath a place that has one: only a place with a key is stored, and every place beneath it records, so an entry's log holds every read its subtree made, while the reads of a place beneath no keyed place reach no entry. `SafeDIToolConstructionMemoTests`' `generate_keys…` tests and `SafeDIToolMockConstructionMemoTests`' `mock_keysPlacesBuiltAtOnePlaceInMemo_whenMockRootsShareMemo` count the places keyed.

**A place's log refers to its children's logs; it never copies them.** A place keeps the reads answered above it (`ConstructionLog.reads(answeredAbove:)`) as its log frozen into an immutable `Segment` with that depth as a cutoff, which every place above it and its memo entry refer to, and a lookup applies the cutoffs as it walks (`forEachRead`), in the order the reads were added, each read and depth once with its first answer, as the dictionary that copied them kept them; `answeredAlike(in:)` asks every read of the cycle kinds first, then the rest. Copying them all made a chain of n places keep n²/2 reads (`SafeDIToolDeepTreeTests`' `run_keepsReadLogsGrowingWithTheChain_…` counts them, `ConstructionLogStorage`). A segment holds values only, and the walk keeps a stack of its own, since a chain of segments is as deep as the tree. The one exception is a short log: a place whose reads above it number at most `copiedReadLimit` (32) keeps them as one copied run, which a lookup reads in place, with no stack and no set of the reads visited. A copy costs at most that many reads per place, so a chain still keeps reads in proportion to its depth. Mock roots ask each memo entry to tell apart many candidates, most of them set aside after a read or two, and the walk's set and stack cost more than those reads: on a benchmark module of twelve mocks that share one memo, segments alone added 1.1 s of CPU to its 226,000 lookups.

**Every input a place's build takes, and every value a generator stores without querying the context, is in the key, in the log, excluded, or constant for a stated reason, and is listed here.** A new one is added here in the change that adds it. The memo oracle (`ConstructionMemoOracle`, which the test executors install) compares every tree built with and without the memo by reflection, so a miss fails the first test or fuzzer graph whose places differ in it; dropping the cycle parameter context read from the log fails base-corpus seeds 35 and 168. Its build with the memo shares one memo across trees whatever the tree's own sharing, so under a production root it keys every place, and it takes the one-place skip only in a tree with a seam root or a mock root's builders, outside the sharing oracle's build that offers later places' candidates. A production tree's own build reuses at a subset of the places the oracle's reuses, and each of its stored entries holds a whole log because every place beneath a keyed place records, so the oracle's judgment still covers it.

"Excluded" means only places the memo neither stores nor reuses hold the value in a non-trivial form: `memoKey` is `nil` inside a fill and in a tree with seam holes, and `isMemoizable` is cleared up through every ancestor by non-empty `seamHoles`, a call with non-empty `holeArguments` outside a mock's tree, and `addHoleGenerator` (`subtreeIsShareable`). A fill and a scope inside one are never stored alone; in a mock's tree the call that passes the fill is stored whole, and "derived from the call" below means a function of the call's key and of reads its subtree logs (`construction-memo-calls.md`).

Construction reads the scopes through `ConstructionScope`, a record of a frozen `ScopeTable` with its table, never through `Scope` itself: each scope map is frozen once (`FrozenScopeMap`), and a root in no map is frozen against its map's table (`freezing(rootScope:)`). A scope's key is its `ScopeRecord`, which the memo keeps alive: every table made from one frozen map shares the map's records, so the mock roots, which share one memo, key one scope alike, and a record a table appends for a root names that root's scope alone, where a `ScopeID` of one table could name another table's scope. A new read of a scope during construction goes into `ScopeRecord`, in the same change. The record's identity (`ObjectIdentifier`, `ConstructionMemo.Key.scope`) is used for equality and hashing alone: nothing orders, sorts, iterates into output or emits it, so an address reaches no byte, and which of two alike candidates a place takes is the sharing oracle's subject. Every key keeps its record alive (`keyedScopes`), so no other record takes its address while the memo lives. Today one `ConstructionMemo` serves every mock root, and a mock root's table comes from one of two frozen maps, the internal mocks' or the public mocks' (`MockScopes.forMockRoot`): the memo spans both. That is safe because each map's records are its own objects, so a key built over one map never equals a key built over the other, and no entry crosses between them; it only shares nothing across them. A tree with a seam root or a mock root's builders, which reads a signature pass's overlaid table, keeps a memo of its own. No change may rely on a memo serving one frozen map until PR 7b makes it so by construction.

## Inputs a place passes to its children, and values a generator stores without querying them

| Input or stored value | Classification |
|---|---|
| `scope`, `property`, `erasedToConcreteExistential`, `forMockGeneration`, `validatesForwardedProperties`, `buildsWithHandWrittenMocks` | Key; `property` by its exact `PropertyID`, which tells every two spellings apart, so it needs no spelling of its own. |
| `lazilyInstantiatedInstanceProperties`, `reboundProperties` | Key, with the spellings of each set, one entry per set, compared by UTF-8 bytes, since `String`'s `==` reads canonically equivalent labels as one. |
| `previousPassGenerator` and everything read from it (`foundCycleParameters`, `receivedBuilderLoops`, the child taken by index, and the fill findings `fillDeferredLabelsHiddenByReenteringCalls`, `fillDeferredLabelsReadInsideSendableFunction`, `fillSendableWrapperReads`, `fillLabelsReadOnlyAsPlaceField` and `publicMockLevelReentries`) | Key (its identity), kept alive where the memo is shared across trees (`keepAlive(passTree:seed:)` holds each pass's tree), so no other generator takes its address. Two trees' later-pass keys are equal only where they name one generator their first passes shared. The fill findings are non-empty only on a call with non-empty `holeArguments`, which is never settled, nor is any scope above it (`isSettled(building:)`), so settling (below) need not compare them. |
| Across passes: a place whose previous-pass generator `G` the pass before built settled (`ConstructionMemo.settledReuse`) | Reuses `G` itself, when the key equals `G`'s but for `previousPassGenerator` and `G`'s reads are answered alike. Settled (`Entry.isSettled`, `ConstructionMemo.foundAlike`) means every scope of `G`'s subtree found the cycle parameters and loops of builders its previous-pass generator found, by `==` and spelling, so a build from `G` reads what `G`'s build read from its own pass before. Only while both passes read the same `placeHoldingPropertiesByType`, and only where the place takes no cycle parameter seed. |
| A place's cycle parameter seed (`CycleParameterSeed`, from `CycleParameterPlan`) | Key (its identity), per child, kept alive as `previousPassGenerator` is; a seeded place's own parameters are the seed's, and settling compares what the place found with what it was built with. Settled reuse needs a nil seed. The memo oracle's reference build takes no seed, so every graph compares the seeded tree with the plain passes. |
| `contextStack` (`ContextStack`: each entry's property and concrete type by ID, with their classes, depth and whether it is a lazily instantiated declaration's instance) | Logged: read only through `declarationClosedOn`, keyed by the IDs of the property and concrete type, whose answer is the ID of the declaration closed on; equal IDs are one spelling, so an answer needs no spelling check. Every ID is the generator's (`ConstructionInternerSpace`), which every map and table it freezes interns into and never renumbers, so a memo that spans tables compares IDs alike. `closesCycleOnFillPath` reads the stack unlogged, only where `fillPathStackCount > 0`: inside a fill, whose stack is the fill path, derived from the call, and what the fill's own scopes push. Inside a fill a miss and a fill path entry are logged at the call's depth (`fillCallDepth`). |
| `nearestDeclarations` | Logged: `nearestDeclaration`, `binding`, `cycleArgumentBinding` (as `binding`), `passesNil`. A `ConstructionLog.Read` key hashes its label as `String` does, canonically, as `NearestDeclarations` matches labels; a change that makes label matching byte-based updates those keys in the same change. A logged `nearestDeclaration` answer compares every field of `NearestDeclaration` (`bindings`, `formsBeingBuilt`, `receivesPassedNil`, `judgesPlacesPinnedFromAbove`, `propertiesReadByRequiredReceivesAbove`, `isBoundByMockRoot`), so a declaration a scope of the subtree changes (`build(_:)`) carries nothing the log does not hold. |
| `NearestDeclarations.resolvingPassesNil`'s reads: `holdsReceivesPassedNil` (`mayPassNil`), each declaration's `receivesPassedNil` and `propertiesReadByRequiredReceivesAbove`, and the receiving dependency | `mayPassNil` is in the key: `false` in every tree but a mock root's, where every `passesNil` answer is `false` and nothing is logged. Where it holds, each receive only if available of a property its scope does not create logs its `passesNil` read, keyed by property, dependency and receiving type, with its answer, `false` included, at the depth of the declaration that answers it, which reads that declaration alone: two mock roots can reach one place and differ only in a receive the one passes `nil` and the other binds (`SafeDIToolMockConstructionMemoTests`' `mock_buildsEachMockRootsOwnPlace_…` tests: dropping the logged read fails the first, and leaving `mayPassNil` out of the key fails both). The dependency in the read's key adds nothing: a type declares one dependency per label, so the property and the receiving type name it. |
| `NearestDeclarations.judgesPlacesPinnedFromAbove`, and `recordRequiredReceives(of:reading:)`'s reads and changes | The tree-wide flag is `false` in every tree but a mock root's whose receives a required receive above pins, where no scope records anything. Where it holds, each scope records what its type's required receives read into the nearest declaration of each such label, a change made at its own depth from a declaration above it, so it logs every `nearestDeclaration` read it makes, at the depth that answers it, before any change: a declaration a recording changed would otherwise answer the places beneath from inside the subtree (`mock_buildsEachMockRootsOwnPlace_whenPlaceRecordsItsRequiredReceiveIntoDeclarationOnlyOneMockRootPins`: dropping the log fails it). What a recording reads into a declaration is compared with it (`mock_buildsEachPlaceOfTypeOnItsOwn_whenDeclarationsAbovePlacesDifferOnlyInRequiredReceivesRecordedIntoThem`: leaving `propertiesReadByRequiredReceivesAbove` out of `==` fails it), and a promoted child is looked up beneath the declarations it is built beneath (`mock_buildsPromotedPlaceBeneathDeclarationsBeforeMockedTypesReceivesPin_whenMockedTypeBuildsSameTypeBeneathThem`: looking it up in the root's own context fails it). The flag is not in the key, which needs it nowhere: a recording changes what a place beneath reads only where the place's subtree holds a required receive and, beneath it, a receive only if available that it pins, both of a label whose nearest declaration is the mock root's binding; the walk that sets the flag (`receivesPassedNilInMockTree`) meets that same pair in every mock root whose tree reaches the place beneath that binding, so that root's binding of the label is judged too, which a logged `nearestDeclaration` answer compares. Two roots that differ in the flag alone differ only in labels the place's subtree pins nothing of, whose recordings change nothing beneath. |
| `promotedChildNearestDeclarations`, `mockRootPromotedProperties` | The root place only, which is never stored; its children are each looked up in the context they are built in (`childContext(ofChildBuilding:)`), a promoted child's being the declarations before the root's own receives were recorded. |
| `isBoundByMockRoot` | Set by the mock root's binding of what its tree receives and cleared at the root (`markBoundUnderLabelByRoot`), a root place, never stored; compared in every logged `nearestDeclaration` answer; read by `callersOwnLabels`, under a public mock call's non-empty `holeArguments`, as a logged `nearestDeclaration` read. |
| `enclosingCarriedInnerScopes`, `enclosingLevelReentries` | A child inherits its parent's, and only a fill is handed a call's own, so both are empty outside a fill; inside one, derived from the enclosing call and its pass before. |
| `cycleParameterContexts` | Logged: `cycleParameterContext`, keyed by the resolved closed-on declaration, misses included. Its depths are used only as the depths the log records. |
| `depth` | Stored by no generator; used only for the log's answering depths, which a hit asks again at the new place. |
| `placeHoldingPropertiesByType` | Constant within a pass of one tree; `nil` on every first pass; non-nil only in a tree with a build site, excluded, so every entry crossing trees was built with `nil`. |
| `declaredTypeNames` | Constant for the run: `DependencyTreeGenerator`'s `let`. |
| `fill`, `enclosingFills` | Derived from the call. |
| `fillPathStackCount`, `fillCallDepth` | 0 and `nil` outside a fill; derived from the call inside one. |
| `enclosingFillNames` | Read only under non-empty `holeArguments`; empty outside a fill, derived from the enclosing call inside one. |
| `seamHoles`, `sitePath` | Excluded when `seamHoles` is non-empty. Otherwise `sitePath` is `[]` at every place, so the four reads of `SeamHoles` a generator stores – `valuesBindings(at: sitePath)`, `memberCallsInsideFunction(at: sitePath)`, `holdsLoopPayloadsInBoxes` (set only for a seam root's tree) and `namesBoundBySeam` – are the same at every place of the tree; `innerScopes`, `carriesStruct` and `carriedStruct` are read only under non-empty `holeArguments`. They are not the same across trees, which is why a tree with a seam root or a mock root's builders never shares its memo across trees or keeps it past a pass. A seam's first signature pass has empty `seamHoles`, so its tree memoizes, and a seam that settles there without a confirming pass (`seams.md`) takes its final signature, holes included, from that tree: the memo oracle runs over signature-pass trees too. |
| `seamRoot`, `mockBuilders` | The root place only (children get `seamRoot: nil`), and a root place is never stored. A tree with either keeps its memo to itself (`sharesMemo` in `Scope.createScopeGenerator`). |
| `holeArguments`, for `holeCallArguments`, `builderCallArguments`, `fillDispatchers`, `passedUpHoles`, `fillsStoodFor`, `buildsFillOfEveryPlace` | In the key, from `scope`; unset where it is. Outside a mock's tree a call with holes is excluded. |
| `closesCycleOnFillPath` | `true` only inside a fill. Derived from the call. |
| A hole generator's `ownerPropertyStack`, `ownerConcreteTypeStack`, `siteCarrierUse` | Excluded by `addHoleGenerator`: the creating scope and every ancestor are not memoizable. |
| `isBuiltByFill`, `fillReturnsWrapperBuilder`, and a fill generator's own fields, `fillCarrierUse` among them | Derived from the call. |
| `constructsWithHandWrittenMock` | Key (flag, scope, property). |
| `cycleParameters`, `builtCycleParameters`, `cycleParameterUnavailableProperties`, `callSiteLazilyInstantiatedInstanceProperties` | From the key and logged reads (cycle context, bindings). |
| `unavailableOptionalProperties`, `lazilyInstantiatedInstanceProperties`, `receivesPassedNil` | From the key's sets and logged `binding` and `passesNil` reads. |
| `instantiable`, `propertiesToDeclare`, `instantiatedDependenciesNotGenerated`, `forwardedLazilyInstantiatedInstanceProperties`, `fillLabelsReadOnlyIfAvailable`, `builtInlineSeamComment`, `isUnavailableDependency`, `seamCall`, `publicMockCall` | Read from `scope`, in the key. |
| `placeHoldingProperties` | From `placeHoldingPropertiesByType`, above. |
| Children and everything aggregated from them | Built from the same inputs, or reused under the same rule at the child's own place. |

Walks of a finished tree that key by a generator's identity rely on a shared generator having the same subtree at each place: `SeamBuilderParameters`' nested cycle parameter bindings (the first place's binding is each place's) and its declarations between a closed-on scope and its closers (a closed-on scope on a site's path holds a hole and is never shared). So do three walks of a seam's tree in its own module, which visit a generator once, or once per frame, by its identity: `builderFunctionNamesOfProperties(in:)`, whose names a shared generator's subtree gives alike at each place; `receivers(in:)`, once per frame projected to what its subtree reads (`ReceiversVisit`); and `generatorsLeadingToSeamTierOmissions`, whose answer is a fact of the subtree. Each set dies with its walk. `SeamBuilderParameters`' `placesByTreePath` keys each place by its tree path, never by a generator, so two places one generator holds are two entries. A scope tells its children apart by their index in `propertiesToGenerate` (`OrderedChild.index`, `ReceivedBuilderLoops.loopByChildIndex`), never by generator, so siblings may share one generator: a mock root that lists a property twice generates only the first.

## The sharing oracle

Which alike candidate a place takes reaches no output, and neither does whether it shares at all. `ConstructionSharingSchedule` (test only, a task-local) makes both an input: per memo lookup of a pass, in walk order, a seeded draw builds the place again or asks the candidates in a permuted order, and `offersLaterPlacesCandidates` first fills the pass's memo with a discarded build of the same pass and asks newest first, so a place is offered what a place after it built. The graph fuzzer's second run of every graph follows a schedule its seed picks (`sharingOracleSchedule(forGraphSeed:)`; `SAFEDI_SHARING_ORACLE_SCHEDULE=<n>` picks another, for sweeps) and must equal the first run (`runsDiffer`). A new identity-keyed map over generators fails it.

## State a mock emission writes to a non-root generator

These are every `var` `ScopeGenerator` stores; everything else is a `let` set at construction.

| State | Why it does not depend on the root or the place |
|---|---|
| `unavailablePropertiesToGenerateCodeTask`, `unavailablePropertiesToGeneratedCode` | Keyed by `UnavailablePropertiesCacheKey`, every argument of `generatePropertyCode` but the constant `codeGeneration`. Several places can share one generator, and the oracle compares construction only, so a new emission argument goes in the key. |

A construction error ends the mock pass (`ErasedInstantiatorForwardedPropertiesMismatchError`, the only one), so no mock root reads the shared memo after a root that failed. A construction error the mock pass catches would owe a test that a root failing first, in the middle and last reports the same errors, and leaves the other roots the same mocks, with the memo shared and without it.
