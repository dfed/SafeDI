# Decisions made while code is emitted

The emitter is being rewritten in two steps per body: a plan of builder functions and statements that kept code decides, then a spelling of that plan. The rewrite keeps every generated byte only if no output decision is taken while text is written, or from text already written. This file lists every such decision in today's emitter, what it reads, and how it is carried as a fact instead. A new decision that reads emitted text, or is made inside a body emitter, goes in this table, with its port, in the change that adds it.

The audit behind the table searched every emitter file under `Generators/` (`ScopeGenerator`, `PublicMockGeneration`, `PublicMockLevelFunctions`, the `Seam*` files, `GeneratedImportAccess`, `UnreadTypeComment`, `GeneratedCodeText`), `Models/Scope.swift` and `Models/Initializer.swift` for every `.split(`, `components(separatedBy:)`, `.contains("…")`, `hasPrefix` and `hasSuffix`; every `.isEmpty` on emitted text or on an array of emitted lines; every `min()` or `max()` over spelled text; and every branch on a body's generated lines. Diagnostics and access computations are left out: they decide no generated byte.

## Decisions, and their ports

| Decision | Today's site | What it reads | Port |
|---|---|---|---|
| Whether a constant has a builder function, with its annotation and call form | `generatePropertyCode`, the `.constant` branch | Whether the body has a statement: member calls, the seam guard line, fill place bindings, an emitting child | A fact of the body's statements, never of their text |
| Whether a body writes `return` before its last line | The instantiator, lazy, constant and `_received` builder functions; the mock's builder functions | Whether arrays of emitted lines are empty, under two counting rules: an instantiator's or a lazy function's body counts every statement, guard lines included; a constant's always writes it; a `_received` function's counts its rebinding lines | One named rule per kind of body |
| `_received` names, and the box of a boxed loop | `generateProperties` | Loop membership and the children's builder function names | One policy: the box name is claimed before each member's `_received` name, from one allocator seeded as today, or the names move |
| The caller's argument for each label a seam call's fills read | `generateProperties`, before the dispatchers | The caller's declaration per parameter form the fills take, and per `SendableLazilyInstantiated` memo | None: each form is handed as the caller declares it ("A caller's argument per form") |
| What a public mock's root level functions read of the caller | `ScopeGenerator.init`, the caller reads of a public mock call | The first non-optional form per label, then that form's argument | The caller's declaration in that form |
| The root's extension, attributes, `convenience`, and "no dependencies emits nothing" | `generatePropertyCode`, the `.root` branch | `dependencies.isEmpty`, `generatedInitializerAttributes`, `declarationType` | Facts of the root's initializer |
| A public mock call's argument per parameter | `generatePropertyCode`, the `.property` branch | The builder struct value, then the hole argument, then the dependency, whose lazily instantiated receive passes its instance | An argument source, chosen in that order |
| Whether a public mock's construction is wrapped in braces | `PublicMockGeneration.passing(_:orBuilding:)` | Whether the spelled construction starts with `if ` | The construction says whether it is an `if` expression |
| Whether a mock struct's default parameter closure gets `@Sendable` | The default parameters of a mock's configuration struct | Whether the spelled type contains `@Sendable` | Read from the `TypeDescription`, anywhere in it, as the text test does |
| What an inlined fill case binds | `inlinedFill`, called from `generateProperties` | The fill's emitted lines (`(_ scope: `, ` = scope.`), and a scan of its body for the forwarded value's name | Text, until fills are planned as builder functions. The three conditions that are not text (a public mock's inlinable fills, the fills an override closure calls, and a fill that declares a function under a dispatcher that returns a builder struct) become one fact |
| The bindings of a caller's mock root names in a wrapper-builder fill | `generateFillCode` | The fill's mock root bindings and the root's binding names, in sorted label order | A fact of the fill |
| Whether a dispatcher's case targets a fill or another dispatcher | `FillDispatcher` | A key that is a string | An enum key, when seam bodies are planned |
| How a dispatcher hands each value, and the dispatcher-parameter fixed point | `FillDispatcher.dispatcherParameters(of:fillReads:)`, `HandedSource` | Each field's `bindsMemo`, `deferral` and `memoType` | Already structural; moves with `FillDispatcher` when seam bodies are planned |
| Which types a generated file's declarations name | `GeneratedImportAccess.namedTypes(inGeneratedCode:)` | The whole emitted file | Text after emission; safe while the same file is spelled |
| The unread-type comment | `UnreadTypeComment.resolvingMarkers(in:)` | Markers in the emitted file | Text after emission; safe while markers are spelled the same |

Spelling only, with no decision: a mock call preamble's splice of fill code, the blank lines between a seam body's scope enums and builder structs, per-level re-indentation (`GeneratedCodeText.indentingNonEmptyLines`), the text a wrapper-builder fill re-splits into lines, and the seam root's narrowest tier body. Errors thrown while text is written (`Initializer.createInitializerArgumentList`'s `unexpectedArgument`) are reported in emission order, the first one the walk reaches; a speculative code task discards its error.

## A caller's argument per form

A seam call's root dispatcher and a public mock call's root level functions hand each value a fill reads of the caller's scope as the caller declares it (an `ArgumentSource`): the label itself, its `instance` where the caller holds it lazily, a wrapper made of the caller's value where the fill reads a `LazilyInstantiated` the caller does not declare (`LazilyInstantiated<X>({ x })`, or `x.map { value in … }` for an optional), or `nil`. Every fill of one call reads the one scope enclosing the call (`Scope.Fill.callerNearestDeclarations`), so the caller's declaration in one form is the same for every fill, and nothing is chosen among spellings: two fills that take one label in different forms are each handed their own form, a form is passed as the declaration where any fill that takes it finds it available, and as `nil` where none does. `SafeDIToolSeamCallerArgumentFormTests` holds those shapes.

## Empty chunks

No body's statements include an empty chunk of text: every child scope a body emits writes at least one line. The only scope that writes nothing is a hole without a site, which exists only in a tree built to compute a seam's signature (`SeamHoles.site(at:)`), and such a tree generates no code. So a constant's body counts its statements without filtering empty strings, as the instantiator and lazy bodies do.
