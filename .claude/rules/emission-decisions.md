# Decisions made while code is emitted

The emitter is being rewritten in two steps per body: a plan of builder functions and statements that kept code decides, then a spelling of that plan. The rewrite keeps every generated byte only if no output decision is taken while text is written, or from text already written. This file lists every such decision in today's emitter, what it reads, and how it is carried as a fact instead. A new decision that reads emitted text, or is made inside a body emitter, goes in this table, with its port, in the change that adds it.

The audit behind the table searched every emitter file under `Generators/` (`ScopeGenerator`, `PublicMockGeneration`, `PublicMockLevelFunctions`, the `Seam*` files, `GeneratedImportAccess`, `UnreadTypeComment`, `GeneratedCodeText`), `Models/Scope.swift` and `Models/Initializer.swift` for every `.split(`, `components(separatedBy:)`, `.contains("…")`, `hasPrefix` and `hasSuffix`; every `.isEmpty` on emitted text or on an array of emitted lines; every `min()` or `max()` over spelled text; and every branch on a body's generated lines. Diagnostics and access computations are left out: they decide no generated byte.

## Decisions, and their ports

Errors thrown while text is written (`Initializer.createInitializerArgumentList`'s `unexpectedArgument`) are reported in emission order, the first one the walk reaches; a speculative code task discards its error.

## One preference for a caller's argument

A seam call's root dispatcher and a public mock call's root level functions hand each value a fill reads of the caller's scope as the caller declares it: the label itself, its `instance` where the caller holds it lazily, a wrapper made of the caller's value where the fill reads a `LazilyInstantiated` the caller does not declare (`LazilyInstantiated<X>({ x })`, or `x.map { value in … }` for an optional), or `nil`. Both pick one argument per label from what their fills read, by one preference: an argument that is not `nil` before `nil`, then the spelling that sorts first. A wrapper made of the caller's value sorts before the plain label (`L` before `x`), so the preference is not "the label first".

Every fill of one call reads the same caller declarations, so within one form every fill spells the argument alike, and so do the `SendableLazilyInstantiated` memos; there the preference never chooses between two spellings. It chooses only where two fills of one call each take one label from the call in a different form, and there one fill is handed the other's form, which does not compile: a defect, whose fix hands each fill the caller's argument in the form that fill takes, and which the port keeps byte for byte. `SafeDIToolSeamCallerArgumentFormTests` holds the two neighbouring shapes that compile, where the second fill reads the label without taking it from the call, or takes it only from a level that binds it; reversing the spelling order changes neither.

## Empty chunks

No body's statements include an empty chunk of text: every child scope a body emits writes at least one line. The only scope that writes nothing is a hole without a site, which exists only in a tree built to compute a seam's signature (`SeamHoles.site(at:)`), and such a tree generates no code. So a constant's body counts its statements without filtering empty strings, as the instantiator and lazy bodies do.

## A spelling holds no subtree text longer

A scope's text holds its whole subtree, and every scope caches its own, so `generate`'s peak memory moves with how long each level keeps its children's text. A port spells what the inline text spelled with the same string operations: a block and the code around it in one interpolation (`BuilderNode.spelled(after:followedBy:)`), never a copy of the block with a line added; and a plan that holds a body's statements is consumed as it is joined (`RootInitializer.spelled(writing:)`), so the statements are released before the text around them is written, as the temporary they replaced was. Holding the root's children in its plan while its extension was written raised `generate`'s peak memory by 3 to 8% on deep inline graphs, such as issue #646's. Byte-identical output does not show it, so a port that changes how a body's text is built is measured against its base's peak memory.

## Where the ports live

In `Sources/SafeDICore/Generators/Emission/`:

- a construction's call and an erasure wrap: `ConstructionTarget`, `Expression`;
- a binding's annotation: `BindingDeclaration`, one rule per form;
- where an argument comes from, and the preference for a caller's argument: `ArgumentSource`, `CallArgument`;
- a builder function's statements, and whether it writes `return`: `BuilderBody`;
- a root's initializer: `RootInitializer`;
- the conditions of a fill's inlining that read no text: `FillInlining`;
- a fill's rebindings of the caller's mock root names: `FillCallerReads.mockRootRebindings(rootBindingNames:)`;
- a loop member's box and `_received` names: `LoopMemberNames`;
- the plan these spell into: `BuilderFunctionGraph`, `Statement`, `BuilderNode`, and `BuilderKey`, which nothing builds until the production emitter numbers its places.

A mock's builder functions keep their own `return` rule, and the two mock rows above keep their text tests, until the mock body is planned: the mock body is rewritten then, and its configuration structs before it.
