# Decisions made while code is emitted

The emitter is being rewritten in two steps per body: a plan of builder functions and statements that kept code decides, then a spelling of that plan. The rewrite keeps every generated byte only if no output decision is taken while text is written, or from text already written. This file lists every such decision in today's emitter, what it reads, and how it is carried as a fact instead. A new decision that reads emitted text, or is made inside a body emitter, goes in this table, with its port, in the change that adds it.

The audit behind the table searched every emitter file under `Generators/` (`ScopeGenerator`, `PublicMockGeneration`, `PublicMockLevelFunctions`, the `Seam*` files, `GeneratedImportAccess`, `UnreadTypeComment`, `GeneratedCodeText`), `Models/Scope.swift` and `Models/Initializer.swift` for every `.split(`, `components(separatedBy:)`, `.contains("…")`, `hasPrefix` and `hasSuffix`; every `.isEmpty` on emitted text or on an array of emitted lines; every `min()` or `max()` over spelled text; and every branch on a body's generated lines. Diagnostics and access computations are left out: they decide no generated byte.

Spelling only, with no decision: a mock call preamble's splice of fill code, the blank lines between a seam body's scope enums and builder structs, each level's indentation (`GeneratedCode.indented`), the text a wrapper-builder fill re-splits into lines, and the seam root's narrowest tier body. Errors thrown while text is written (`Initializer.createInitializerArgumentList`'s `unexpectedArgument`) are reported in emission order, the first one the walk reaches; a speculative code task discards its error.

## A caller's argument per form

A seam call's root dispatcher and a public mock call's root level functions hand each value a fill reads of the caller's scope as the caller declares it (an `ArgumentSource`): the label itself, its `instance` where the caller holds it lazily, a wrapper made of the caller's value where the fill reads a `LazilyInstantiated` the caller does not declare (`LazilyInstantiated<X>({ x })`, or `x.map { value in … }` for an optional), or `nil`. Every fill of one call reads the one scope enclosing the call (`Scope.Fill.callerNearestDeclarations`), so the caller's declaration in one form is the same for every fill, and nothing is chosen among spellings: two fills that take one label in different forms are each handed their own form, a form is passed as the declaration where any fill that takes it finds it available, and as `nil` where none does. `SafeDIToolSeamCallerArgumentFormTests` holds those shapes.

## Empty chunks

No body's statements include an empty chunk of text: every child scope a body emits writes at least one line. The only scope that writes nothing is a hole without a site, which exists only in a tree built to compute a seam's signature (`SeamHoles.site(at:)`), and such a tree generates no code. So a constant's body counts its statements without filtering empty strings, as the instantiator and lazy bodies do.

## A level holds its children's code, never a copy of their text

A production body is a plan (`GeneratedCode`): text, pieces written one after another or on lines of their own, a child's code a level indents. Each level holds its children's plans and wraps a child in its indentation without copying it (`.indented`), every scope caches its plan, which every place that builds the scope again shares, and the root's plan is spelled once, where `ScopeGenerator.generateCode(codeGeneration:)` returns the tree's text; a small subtree started early is spelled while the tree is still generated and cached as its text in place of its plan (`GeneratedCode.Node.spelled`), which that spelling copies. Re-indenting a subtree's text at every level above it cost CPU and memory that grew with the tree's size times its depth; the writer (`GeneratedCodeWriter`) keeps each level's line state instead and writes each line once, after the indentation of every level around it, the bytes `GeneratedCodeText.indentingNonEmptyLines` wrote at each level, `"\r\n"` kept inside its line (`GeneratedCodeTests`). A plan can be as deep as the module has types, so the writer keeps a stack of its own rather than recursing, and a level hands its children to `DeferredRelease` when it is released. Code that is not planned yet is hosted as text, flattened where it is read as text: a fill (`inlinedFill`, `generateFillCode`), a seam's root, a mock and the fills a mock's call splices (`prepareFillCode`). A change to how a plan is built or spelled is measured against its base's peak memory on deep inline graphs, such as issue #646's, as well as wide ones: byte-identical output does not show it.

An async function's frame holds a body's values too. A task keeps the frame of each call it is suspended in, and a large subtree starts each small subtree beneath it on a task of its own (`generator-design.md`, "A generator keeps finished code, never a finished task"), so at the peak of a wide tree every scope holds a `generatePropertyCode` and a `generateProperties` frame at once: on Linux, 1,801 of each at the peak of 600 independent seams built inline, 62 of its 79 MB of heap. A frame holds a slot for each value its function decides or spells, on every branch, and for each function inlined into it, so the ports' plan values, decided inside `generatePropertyCode`, raised that graph's peak memory by 4 to 9%. So both functions only await children's code: what a scope writes around it, and what a body decides of its children, is decided by synchronous functions kept out of them with `@inline(never)` (`propertyCode(around:…)`, `bodyChildren(propertiesGeneratedLater:enclosingFunctionNames:)`); `generatePropertyCode`, whose frame keeps a slot for each of its branches, is never inlined into the `generateCode` frame that every scope awaits each child's code in; and a value either holds across an `await` is one it needs after it. A change to either is measured on a wide graph (the generate benchmark's `E6d` shapes) as well as a deep one.

## Where the ports live

In `Sources/SafeDICore/Generators/Emission/`:

- a construction's call and an erasure wrap: `ConstructionTarget`, `Expression`;
- a binding's annotation: `BindingDeclaration`, one rule per form;
- where an argument comes from, and a caller's argument per form: `ArgumentSource`, `CallArgument`;
- a builder function's statements, and whether it writes `return`: `BuilderBody`;
- a root's initializer: `RootInitializer`;
- the conditions of a fill's inlining that read no text: `FillInlining`;
- a fill's rebindings of the caller's mock root names: `FillCallerReads.mockRootRebindings(rootBindingNames:)`;
- a loop member's box and `_received` names: `LoopMemberNames`;
- the plan these spell into: `GeneratedCode`, `BuilderFunctionGraph`, `Statement`, `BuilderNode`.

A mock's builder functions keep their own `return` rule, and the two mock rows above keep their text tests, until the mock body is planned: the mock body is rewritten then, and its configuration structs before it.
