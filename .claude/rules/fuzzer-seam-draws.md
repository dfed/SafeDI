# Graph fuzzer: generator features and seam draws

- **Generator features.** A `GraphFuzzerGeneratorFeature` (`generateDependencyTree`) is off by default and draws from a stream seeded from the seed and the feature (`seamRandom`), consumed only when the feature is on, so the base corpus is drawn as before and its pins do not move. `addingSeam` runs after the base passes, before `addingSpelledProperties` and `addingUncreatedAliasShapes`: it marks one type a root reaches that has an `@Instantiated` child as a seam (a leaf gains a `SeamChild` when none has) and gives its tree the shapes a seam's initializer must pass – a child's receive of a property provided above every path to that child, required or only if available; a rename on the seam or a child; a rename above the seam received by the new label beneath it, by a child the renaming type is on every path to, judged from the declarations as the sibling-alias pass judges (a root's extra property is not among `dominators`' edges), with a source provided above every path to the renaming type; the forms a tree can receive a `LazilyInstantiated` or `SendableLazilyInstantiated` property provided above in, under the rule that groups a label's forms by what provides them (every root instantiates `SeamShared` lazily under `seamLazy` when no wrapper is; the synthesized wrapper is `Sendable` in a mixed graph, whose `Sendable` builders could not read the other kind): the required wrapper, with a by-value form beneath it on a second child or, where the seam has one child, on a `SeamLink` only the receiver instantiates (`requiredWrapperProvidingByValueForm`, the rule's main support shape, pinned on its own); the instance by value, passed as `.instance`; the optional wrapper only if available, of the graph's kind or, in a mixed graph, of the other kind, which the caller passes `nil`; and, one lazy draw in five, a by-value form beside the optional wrapper on two children, the label collision the seam reports; a third of the time a child's `onlyIfAvailable` receive of a wrapper of `seamHeld`, a property of the draw's own that every root instantiates by value (`synthesizedHeldProvider`) and nothing else receives, which the caller passes `nil` (`instanceHeldByCaller` counts only a graph in which no child of the seam receives or aliases the label by value; a shared label made most such draws the collision); and, a quarter of the time, a second seam beneath the first. The next pass, with its own stream (`addingSpelledProperties`, `spellingRandom`, seven graphs in ten) adds a small seam tree of its own – `SpellSeam`, built through an instantiator by the first root or instantiated by `SpellHost`, which the first root builds so – whose one value, `spelled`, is drawn as a `GraphFuzzerSpelling`: a closure, a closure with a parameter and a return, a `@Sendable` closure, both optional closures, a tuple holding a closure, an existential (now and then received without `any`), a closure taking one, a nested type, an array, a `Result`, or a typealias of a type that is not a function. No `@Instantiable` type provides such a value, so it is `@Forwarded` by the seam or the host, and the seam's tree takes it as each kind of parameter a signature has – the seam's own `@Forwarded` or `@Received` property, a pass-through `SpellChild` requires or receives only if available, the optional form on a second child `SpellSibling` (`spelledOptionalFormOnSibling`), and a rename on the seam or the child – a graph whose wrappers are all `Sendable` drawing only `Sendable` values; now and then `SpellChild` or `SpellSeam` generates a mock (`spelledTreeMocked`); a fixture initializer spells a function-typed parameter `@escaping` (`GraphFuzzerSpelling.isFunctionType`). A function typealias and a third module's type are not drawn: the macro rejects the first, and the spelling's tree is in the roots' module or, moved there (below), the seam's. After it, a pass with its own stream (`addingUncreatedAliasShapes`, `uncreatedAliasRandom`, four graphs in ten) adds `AliasSeam`, a seam the first root instantiates, whose tree declares an `onlyIfAvailable` alias of `aliasToken` (`aliasAuth`, on `AliasDetail` beneath `AliasLeft`, or one graph in ten on the seam itself) in shapes whose seam binds the alias from a parameter: `aliasToken` is a pass-through received only if available or a required optional parameter – the seam's own receive, its own forwarded property, or a property `AliasLeft` requires – from which its exact-form alias (`ofType: AliasValue?.self`) and its unwrapped-form alias are both bound; a reader beneath the alias reads its property only if available or required, keeps the alias's label and retypes it to an existential, is built through a wrapper, sits inside a nested seam `AliasPanel` or beneath `AliasMid`; `AliasDetail` aliases the alias as `aliasBearer`, only if available or required; a declaration of the alias's label is placed beside its declaring type, above it, or as a parameter of the seam (the alias's property, another type, or an instantiator); the caller holds its label or its fulfilling property; and `AliasLeft` instantiates `aliasToken`, which creates the alias on that path (`AliasRight` beside it receives it only if available), or declares it so that the alias is always `nil` – `AliasDetail` built inside `aliasToken`'s builder, or `aliasToken` generated after `AliasA`, which builds `AliasDetail`. About half of the reader, alias-of-alias and same-property draws produce the accepted twin instead (the reader or the second alias reads the fulfilling property, or the alias is made required), so the rest of such a graph stays accepted and value-checked; each shape is a `GraphFuzzerSeamDrawFeature` with a pinned count, the three required-optional parameter kinds under one (`uncreatedAliasRequiredOptionalParameter`; the only-if-available pass-through is the rest), the three twins under one (`uncreatedAliasAcceptedTwin`), and the caller holding the fulfilling property under one that also counts every graph whose root must hold it (`uncreatedAliasFulfillingPropertyHeldByCaller`). The seam binds every such alias from its parameter as inline binds it from the caller's nearest declaration, so an error about `AliasSeam` in a graph inline accepts fails the graph (`seamRejectedWhereInlineAccepts`), and every graph accepted both ways is compared by value with its inline build. Then a pass with its own stream (`addingAccessProofShapes`, `proofRandom`, four graphs in five) adds `ProofSeam`, a seam the first root reaches through `ProofHost`, which holds the values its tree receives (forwarded plain types, or instantiated `@Instantiable` ones, now and then declared after the seam), whose parameters' types are narrower or wider than the access levels the declarations naming them spell: the seam type `package` or `internal`; its own initializer narrower than its type with no pass-through, with only optional narrower ones, or under two parameter levels; and, otherwise, a receiver whose initializer is narrower than its parameter's type, a receiver type narrower than its spelled initializer, a required parameter narrower than the seam, the seam's own only-if-available receive, a plain public type only package initializers mention, held by a caller or not, an alias of a plain type nothing proves or of a package `@Instantiable` type (now and then beside a declaration no tree reaches that mentions it), `@Instantiable` and plain types in an extension of a namespace enum (narrower than them or public; the extension spelled or not; reached by value or only through an existential), an `@Instantiable` extension of a narrower type with a public `instantiate(…)` and now and then a public mock, a public mock beside the `instantiate(…)` of an extension of a package type as the widest mention of what an internal receiver receives, a type declared in an unspelled extension of the seam or of a narrower recorded type, and a `Swift.`-qualified parameter type. An initializer is capped by the narrowest type it names, so the fixture compiles. Each shape is a `GraphFuzzerSeamDrawFeature`. Half of these graphs whose seam is not `internal` are split across modules – the seam's tree in `FuzzFeature`, every other file in `FuzzApp`, and, for a public seam, `ProofOtherRoot` and `ProofOtherHost` in `FuzzOther`, holding the public values – each file naming its module on its first line (`// module: <name>`), so every renaming and `withoutSeams` keep it. A split graph runs as Bazel runs the tool (`executeSafeDIToolMultiModuleTest`'s `.moduleInfo`, module and package names given), each module's combined output read back as per-type files (`GraphFuzzerOracle.decomposingCombinedOutput`), since a combined output declares its extensions in its files' path order, which a file-name reversal reverses. A sixth of the split graphs give their same-package caller, and another sixth their seam's module, no package (`ModuleFixture.omitsPackageName`, said on the module's first line), as Bazel builds a library without `package_name`: the tool is not told one, the oracle compiles the module without `-package-name`, and its files spell `public` wherever the draw chose `package` (`GraphFuzzerModule.droppingPackageAccess(from:)`), as do the seam's module's beside a caller without one, which names them; the graphs whose modules without a package differ compile apart. A seam's module without a package has no caller in another package, which keeps the other graphs' draws as they were. A split graph none of whose modules lacks a package also runs as the SwiftPM plugin runs the tool (`.swiftPackagePlugin`, which computes every seam signature, tier and public mock from source, with no `.safedi`; the plugin always knows the package, so a graph with a module without one models Tuist and Bazel alone), and the two flows must give one verdict, the same diagnostics, and the same generated declarations (`integrationsDisagree`): per module, the set of top-level blocks of its generated files once `#sourceLocation` directives, the header lines, and the comments only one flow writes – trailing ones (`integrationSpecificTrailingComments`) and whole lines, such as the unread type comment a run without a target graph writes (`integrationSpecificCommentLines`) – are dropped (`GraphFuzzerOracle.integrationComparedBlocks(of:)`). The compile-time assertions a reading module writes about another module's file are integration-specific too: the plugin reads a dependency's files under the reading module's conditions and asserts in the reading module the decisions it made about their blocks, as it asserts a dependency's `@Instantiable` decisions, where the module-info flow leaves them to the dependency, which asserts them under both flows. So a block only the plugin flow generates in a module is excused when it is the assertion of one decision whose condition the module's dependencies spell and the module does not (`GraphFuzzerFixture.conditionsSpelledOnlyInDependencies`, `GraphFuzzerOracle.compileTimeAssertionCondition(of:)`); any other block one flow alone generates still fails. The seam smoke batch must hold an accepted graph so compared, and every passing public mock smoke graph is one (`isComparedAcrossIntegrations`). Last, a pass with streams of its own (`addingHoleShapes`: `holeRandom`, a third of the graphs, and `holePassUpRandom`, `holeReentryRandom` and `holeSelfReentryRandom` for its further draws) splits the graph to add `HoleSeam` in `FuzzFeature`, whose tree instantiates `holeService: any HoleService`, which only `HoleImpl` in `FuzzApp` fulfills – a hole: the owner is the seam or `HoleOwner`, by value or through a wrapper the graph's sendability allows, now and then at a second site; `HoleImpl` reads a field and now and then the root's `holeLogger`; `HoleOuter`, a second seam of the seam's module, passes the builder up; where the seam builds the owner, at its one site, through an instantiator, at which the cycle then closes, `HoleImpl` re-enters the seam, a quarter of those through `HoleMiddle`, which declares `holeLogger` above the call (C1.27); and `HoleLoop` makes the seam's own tree reach the seam again, now and then binding `holeLogger` on the way (C8.14). Ten rolls more, each with a generator of its own (`HoleRolls`), each made whatever the base draw: the fillers and the root that reaches the seam (`HoleOtherRoot`) in `FuzzOther`, a fifth of those with `HoleImpl`'s initializer `package` (accepted: the fill is in `HoleImpl`'s module) and a tenth with `HoleImpl` instantiating `HoleCache`, whose initializer is `package` in the seam's package (rejected, as inline), never where the seam's module has no package; `HoleAnalytics` `package`, read by `HoleImpl` in the seam's package (a `package` field); `HoleImpl` reading the field through an alias or only if available, and `HoleOwner` aliasing it before its hole; `generateMock: true` on `HoleSeam` or `HoleOwner`; `HoleImpl` in an extension of `HoleNamespace`; the seam's module without a package (its files spell `public` for `package`, and the oracle compiles it without `-package-name`), the fillers in the roots' module and no caller in another; where a re-entry is drawn, half of the types that make it also instantiate `HoleRelay`, a seam that builds `HoleSeam` through an instantiator (by value, a walk from `HoleRelay`'s root would close a constant cycle) and passes its site up, so the fill is passed to another copy of its hole while every re-entry drawn before still draws, a quarter of those with `HoleRelay` binding `holeLogger` (rejected) and, in `Sendable` or mixed graphs, half through a `SendableInstantiator` (the fill `@Sendable`); a second hole, `holeTracker` on `HoleSettings`, filled by `HoleTrackerImpl`, which reads the root's `holeLogger` (rejected beside `HoleMiddle`); `HoleTop` calling `HoleOuter` and `HoleOuterS`, which builds `HoleSeam` in a `SendableInstantiator` (one `@Sendable` builder per site); and `HoleInner2`, a seam whose hole has `HoleSeam`'s hole's label, filled by `HoleTrackerImpl` inside `HoleSeam`'s fill, which re-enters `HoleSeam` (the inner fill named apart). Six rolls more, each on a generator of its own in `HoleRolls`, draw the nested builders' shapes: a second hole type, `HoleGadgetOwner` (built by value) instantiating `any HoleGadgetService`, which `HoleGadgetImpl` fills, or, four times in ten, two erasures of `HoleGadgetImpl`, whose stems are equal, so that their builders are named apart by the type each returns (`holeSecondHoleTypeCollidingStem`); `holeServiceLazy`, a `LazilyInstantiated` or `SendableLazilyInstantiated` of the hole beside its by-value place, also beside a mocked seam or owner, whose mock takes the wrapper as its parameter, as it takes every wrapper its tree instantiates and it cannot build; and, in graphs that hold `Sendable` wrappers, `HoleStager`, a seam `HoleSeam` builds in a `SendableInstantiator` whose own place is in one too (an inner staged place on a `@Sendable` route); `HolePing`, a seam `HoleSeam` builds that builds `HoleSeam` in a `SendableInstantiator` (a cycle of two seams with a `@Sendable` edge); `HoleBoth`, a seam the root builds that builds `HoleSeam` by value and in a `SendableInstantiator`, half the time beneath `HoleBothTop` (an inner seam with both enums); and `HoleDeep`, a seam in `FuzzSession` whose hole `HoleDeepImpl` fills in the seam's module with a place of `HoleService`, built by `HoleSeam` in a `SendableInstantiator`, so that the place is inside a `@Sendable` fill the seam generates (`GraphFuzzerSeamDependencyDraw.drawn(in:)` does not count it as a moved declaration). `HoleStager` and `HoleDeep` are not drawn where `HoleImpl` reads `HoleOwner`'s alias, which their scopes do not carry, nor `HoleDeep` where the seam's module has no package. The generator records the property that gives the graph its second place of a hole – the first of these draws' places or routes, else `holeSettings`, else `holeSecondOwner` – which `GraphFuzzerGenerator.fixtureWithoutSecondHolePlace` leaves out after every other draw, for the name-stability oracle (`fuzzer-seam-oracles.md`). Two more draws have streams of their own, so every other graph is drawn as before: a plain declaration the tree relies on, `ProofSpace` (the namespace) or `HoleService` (the hole's protocol), moves half the time to a file of its own that holds no SafeDI marker (`markerFreeFileRandom`; `namespaceInMarkerFreeFile`, `holeProtocolInMarkerFreeFile`), which `scan` reads only through its second parse – the moved graphs' verdicts and generated code equal those of the same graphs with the declaration in its owner's file, and with the second parse disabled some of them change, so reverting it or the word search turns the corpus red; and `HoleService` is declared `package` three times in ten, except with the fillers in another package, which could not conform to it, with every seam that takes its builder (`HoleSeam`, `HoleOuter`, `HoleRelay`, `HoleOuterS`, `HoleTop`) `package` and `HoleSeam`'s own initializer `internal`, so that only the protocol's own declaration lets the seam's `package` tier take its builder (`holeProtocolAccessRandom`; `holeProtocolPackage`). The files declaring `HoleImpl`, `HoleMiddle` and `HoleTrackerImpl` say on their first line that they fill a hole (`GraphFuzzerModule.holeFulfillerMarker`), and `GraphFuzzerFixture.withoutHoles`, the visible build, declares them in the seam's module. Every graph with a hole runs its visible build too: one the tool accepts while it rejects the visible build fails as `holeAcceptedWhereVisibleBuildRejects`, and one accepted both ways is compared by value with its visible build (`holeBuildsOtherValuesThanVisibleBuild`), and with the inline build, which passes the seam the hole draw re-enters (`holeSeamBuilder`) the nearest declarations as the seam's own call does. A fill's own errors are a seam's own to the differential. Each hole draw is a `GraphFuzzerSeamDrawFeature` with a pinned count, and the smoke batch must show every `GraphFuzzerHoleOutputFeature` – a builder parameter, a staged builder, a passed-up builder, a fill, a `@Sendable` fill, a fill passed to its seam, a passed-up builder's fill passed to the inner seam, a fill passed to a seam that passes its site up, and a fill named apart – and, in accepted graphs, every roll above with an accepted variant. The hand-written callers call each tier's initializer only generated code calls, the one every tier has, so the fuzzer's graphs need no `generatePlainDependencyTreeInitializers` (`seamInitializers` reads those initializers, and reports each parameter as the plain one spells it unless `keepsGeneratedOnlySpelling`, which the callers pass so a deferred parameter stays an `@autoclosure` they call), and spell a builder parameter with its scope struct qualified by the seam (`GraphFuzzerOracle.callerSpelling(ofParameter:of:)`). Four later passes, each with a stream of its own, draw the shapes the seam tests once pinned one by one: `addingUncreatedAliasExtensions` (`aliasExtensionRandom`, four alias trees in five) adds what `addingUncreatedAliasShapes` does not – a second declaration of `aliasAuth` where no other receive of it leaves the seam (instantiated as the alias's property, as `AliasLabel`, as an instantiator or a lazily instantiated wrapper, received only if available, or an alias of `aliasOther`) on `AliasLeft` before or after `AliasDetail`, on `AliasMid`, or on the seam, which may also require it; `AliasClient` receiving a wrapper of it; an alias of the seam's own alias; a reader of the alias of the alias; a required label-keeping reader; a reader redeclaring the alias; `AliasValue` receiving `aliasDetail` only if available, so that an `AliasValue` beside it is generated after it; the seam's own only-if-available receive of `aliasToken`; and `AliasNeed`, which requires it – none of which collides with another receive of the label, so the alias draw's oracle keeps its meaning; `addingAccessProofExtensions` (`proofExtensionRandom`) spells `ProofMeter`'s type `Foundation.`-qualified (whose probe sample is a fixed value), adds a `mockOnly` fake whose mock mentions `ProofBadge`'s plain theme at the theme's access or narrower, and has `ProofHost` or `ProofOtherHost` lazily instantiate a value, receive its plain values only if available, reach the seam through `ProofSeamHolder`, or be a seam itself, whose tree calls `ProofSeam`'s tier from the host's module; `addingLabelFormsSeam` (`formsRandom`, half the graphs) adds `FormsScreen`, whose tree receives `formsUser` in each form a lazily instantiated property can be received in, with a caller holding each form a tree can hold, mostly a mix the seam rules accept with a caller every required receive accepts; and `movingSelfContainedSeamsIntoSeamModule` (`crossModuleRandom`, last) moves `AliasSeam`'s, `FormsScreen`'s and `SpellSeam`'s trees, which name no other type of the graph, into `FuzzFeature` half the time in a split graph, so that their callers compute their signatures across modules. The oracle's seam callers repeat the imports of the generated file they call into. `SeamShared`'s four triggers are listed on `GraphFuzzerSeamDrawFeature.synthesizedSharedProvider`. `seamCorpus_drawsEachShapeInThePinnedNumberOfGraphs_whenFixturesAreGeneratedWithoutTheTool` reads each shape from the corpus's fixtures (`GraphFuzzerSeamDrawFeature`) and requires exactly the pinned count (`seamCorpusDrawFeatureCounts`, which every case must have: the draw is deterministic, so a change in a shape's share is a reviewed diff), so a draw that stops landing fails a test (one count per spelling and per holder kind, never their product); the smoke batch must also show every `GraphFuzzerSeamOutputFeature` in accepted graphs – both pass-through kinds, a call reading `.instance`, an `@escaping` closure parameter, an `@escaping @Sendable` one, and an optional closure – and the long run requires each spelling in some accepted corpus graph, which each shard reports (`spellings`) and the combine job unions. `seamCorpusSeedsOfOtherShapes` is observed from a corpus run, never derived: the inherited seeds the seam's draw moved to its own shape or cured. The seam corpus (`seamCorpus`, seeds `0..<seamCorpusSeedCount`) has pins of its own, a smoke batch (`seamSmokeSeeds`) whose accepted graphs must, by the generated code (`GraphFuzzerSeamOutputFeature`: a parameter received only if available, a required parameter the seam does not declare, a call reading `.instance`, and the closure parameters above, read from the seam's generated files, which spell a parameter received only if available as they spell a required one of optional type, so `GraphFuzzerSeamParameterKinds` tells the two apart by the graph's declarations), take every one, and a known-issue list (`seamKnownIssues`) that lists the base corpus's shapes from `knownIssues` below its size – the marking changes no mock; the draw's added receives can, which `seamCorpusSeedsOfOtherShapes` records – minus `seamCorpusSeedsOfOtherShapes`, plus the seeds `seamCorpusSeedsAddedToInheritedShapes` lists under an inherited shape the base corpus does not list them in, plus its own shape (the label-sorted pass-throughs). A stale seed's remedy is chosen by its shape and by the list that holds it (`Corpus.staleSeedRemedy`), written into the report line after the reason, which the summary script prints.
