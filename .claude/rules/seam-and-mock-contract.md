# The contract for seams and public mocks

Every design, change and review of a seam (`generateDependencyTree: true`) or a public mock (`generateMock: .public`) is judged against these seven rules, in this order; rules 1–4 outrank rules 5–7. The baseline is the inline build: the same types generated in one module, with no seam and no public mock call. How seams and public mocks are generated is in `seams.md`, `seam-holes.md` and `public-mocks.md`.

1. **Every valid combination of existing features compiles without warnings, at every position, across a module boundary.** A position is the seam or mocked type itself, a type beneath it, or a type inside a fill. "Reject" covers only what a confused user would write ("Reject nonsense shapes" in `CLAUDE.md`), and a shape an adopter asked for is required.
2. **Values equal the inline build's, or there is an error whose remedy works.**
3. **Nothing is retained that the inline build frees.**
4. **Generated size is linear when every axis grows together**: values, levels and hole types at once.
5. **A level carries only what its own type binds.** A field exists only where a generated read needs it.
6. **One case per property, and a shape that ignores type names, file names, module splits and labels that coincide.**
7. **A public mock differs from its seam only by this list:** a mock takes as parameters the received values its tree cannot build, where production reports an error; its levels follow the mock's tree; it passes one value per name and type to every type that creates it; `mock()` and `SafeDIOverrides` keep build order; a calling mock builds the called type inline, so where the called type's tree builds that type again, or a call inside a fill re-enters a level of the call (the called mock's root, or the level of a type whose places it fills that another module's public mock holds a builder of), its level functions hand the place the value nearest it, as inline reads (a value the called mock binds on its way to the builder it holds, which no scope of the caller holds, keeps the twin's error), where the seam passes its builder on unchanged and reports that its caller cannot hand that value (`Scope`'s re-entering call, `PublicMockLevelFunctions`; `fuzzer-calling-mocks.md`); and a calling mock passes up whole, every place of it, a hole type of a called type whose fill reads, beside its place's fields, a `LazilyInstantiated` or `SendableLazilyInstantiated` value where a fill re-enters the called type (its tree calls the called type's public mock, or one whose builders reach its places, itself or through the fills of the calls it makes), or whose places' fills read different such values, and then the hole type of each fill that calls a public mock passing a builder up so, where the twin fills them: `mock()` takes the builder, or a `.public` mock's own enum carries the case (`DependencyTreeGenerator.holeTypesTheFillGatesPassUp(of:in:)`, `public-mock-builders.md`). A calling mock, a generated `mock()` whose tree calls another module's public mock, does what its production twin (the caller declared a seam, calling the same types' seams) does: it fills a place where the twin fills it, each route reading the nearest value or the caller's, reports the twin's error where the twin reports one, and passes a place up only where the twin takes a builder for it, which is where its module sees no implementation of the place's type, or where this list passes it up. One deliberate gap: where a place's fill would construct a type the calling module cannot reach, such as an `internal` type of another package, the calling mock passes the place up and is accepted while the twin reports the access error (`DependencyTreeGenerator.holesFilled(byCallsOf:in:)` and `rootScopesThisModuleGenerates(from:checkingSeamTrees:)` say so); its plan is the calling-mock mirror work, 2.3.1.

Rules 5 and 6 govern generated code, not public shape: no hand-written code reads a level or names a case, so a breach of either is a defect any release can fix.

**How to use it.** A design states which rule each choice serves and which it costs. A rule gives way only when that yields a simpler API or a shorter path to the release, and the proposal names the rule that gives way and says why. A choice that costs one of rules 1–4 is the maintainer's decision. A field, case or error that no rule asks for is not built. An exception to rule 1 is a rejection: an error at the seam or mock for a shape that builds in one module, naming a remedy that works. The maintainer approves each exception, and lifting one later changes no public shape. What exists only in a prerelease is no public shape to protect: whether a change breaks is measured from the last stable release (`releases-and-packaging.md`).

## No retain cycles

- **No release ships a retain cycle**, prereleases included: not in a seam, a public mock, or anything else SafeDI generates. Rule 3 has no exception, and a known retention blocks the next publish.
- **Fix retention structurally.** Generated code captures only what it reads, so each closure SafeDI generates keeps alive only the values its body uses. Prefer the change that makes a capture unnecessary over a workaround that keeps the capture and breaks it later.

## Builders a person writes

These rules are the decided shape of the public interface of seams and public mocks. Generated code does not follow them everywhere yet; the planned no-scope work brings it in line. Until then, new code follows them, and generated code that differs from them is a shape to remove, not to extend.

- **A hand-written builder takes no scope.** A builder a person writes, whether passed to a seam's readable initializer or to `mock()`, is to take exactly what its place forwards and return the value: `() -> T` (or `@Sendable () -> T`) for a place that forwards nothing. Only generated code is to hand values between a seam's levels, so that no public parameter hands a person a value the seam builds.
  - A deliberate gap, owned by 3.0: a hand-written builder cannot read a value the seam or mock builds at its place (such as the `id` the place's own type forwards, or one a level above it holds), since the scope enums are generated-only. The ruling that made them so (NO-SCOPE-BUILDERS) leaves improving this to 3.0.0. No test pins the gap; the tests that read a place's own value through a hand-written builder's scope were removed with the enum's cases.
- **A forwarding place's builder type is its wrapper's nested `Builder`.** The readable initializer's and `mock()`'s parameter for a place that forwards values is to be the property's own wrapper type, spelled exactly as the property spells it, followed by `.Builder`: `Instantiator<T>.Builder`, `SendableInstantiator<T>.Builder`, `ErasedInstantiator<F, T>.Builder` or `SendableErasedInstantiator<F, T>.Builder`. Each is a typealias nested in its wrapper, and so bound to the property's own wrapper type, with no generic parameters of its own (`(T.ForwardedProperties) -> T`, and its `@Sendable` and erased forms): an alias with generic parameters of its own crashes Swift 6.2 and 6.4 wherever it is used unbound.
- **A seam's builder takes the type its places give it.** Its places held in instantiators, spelled alike: that wrapper's `Builder`, spelled through the wrapper's `Sendable` twin in the `@Sendable` family (`Instantiator<T>` inside a `@Sendable` function gives `SendableInstantiator<T>.Builder`, the same function type, `@Sendable`). Places that reach one forwarded value through other wrappers or spellings (`Int` beside `Swift.Int`, `Instantiator<T>` beside `ErasedInstantiator<T.ForwardedProperties, T>`): the erased wrapper's `Builder` over that value, spelled as the most explicit of the places' spellings, chosen by the spellings' shapes (`Swift.Int` over `Int`, `Optional<X>` over `X?`; `TypeDescription.mostExplicitSpelling(among:)`), never by where the places are, so renaming a file or a type never respells it. Places that all forward nothing, a plain or lazy place among them (an `Instantiator<T>` counts as forwarding nothing beside one, since a plain place of `T` says `T` forwards nothing): `() -> T`, so `{ T() }`, `T.init` and a stored `() -> T` keep compiling when a plain place joins (`DependencyTreeGenerator.builderForm(ofPlaces:)`). Places of one builder that forward different values are an error at the seam, naming both places and a remedy the calling module accepts (`validation-boundaries.md`). A builder that still takes a scope – one that carries an inner seam's scope or a fill's, or whose seam is built again – keeps the scope's form until the planned work removes it.
