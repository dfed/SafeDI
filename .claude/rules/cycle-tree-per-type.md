# A tree's plan by declaration

`Sources/SafeDICore/Generators/CycleTree/` holds a plan of a root's tree with one node per declaration (a scope's record and the property it is built as), where `Scope.createScopeGenerator` builds one generator per path. A tree whose screens open each other has a number of paths that grows with every cycle, and a number of declarations that does not.

- **A production root is laid out from its plan only where today's tree grows past a limit.** Each root's tree is built per path as before (`DependencyTreeGenerator.rootTrees`, which a module without seams and the seam world both call; a seam's own tree is always built per path), counting the places its passes build or reuse (`Scope.createScopeGenerator`'s `scopeGeneratorLimit`). A root within `DependencyTreeGenerator.scopeGeneratorLimitOfTodaysTree` (1,500 places) keeps that tree: its code, its errors and its cost are what they were before any root was planned, and nothing of this folder runs for it. At the limit the build asks (`ScopeGeneratorLimit.answer`) whether the root reaches a cycle and its whole tree holds none of the shapes `shapeOutsidePerTypePlan(inTreeOf:cache:)` names (`PerTypePlanShapes.swift`; each a `RootTreeChoiceObservation.PerPathReason`). If not, the same tree is built on with no limit and nothing is thrown away, so a large root the plan cannot take pays one walk of its scopes. If so, the tree must also hold `placesPerScopeOfTodaysTree` (8) places for each scope the root reaches, which that walk counts: a root of thousands of types that holds each a few times does not grow with its paths, so it is built on and asked again only at that count (a root of 4,000 services beside one screen that opens itself took 2.6 s and 2.5 GB abandoned, against 0.7 s and 113 MB kept). A limit a test sets (`scopeGeneratorLimitOverride`) is the whole criterion. Past both, the tree is abandoned (`ScopeGeneratorLimitExceeded`; the memo keeps nothing of it), `perTypePlan(ofRoot:…)` builds the root's bodies, the type key lays its code out of them (`TypeKeyBody.statements(ofPlan:)`), and `RootScopeInfo.Tree.perType` carries the code and the bodies. An abandoned root with no plan, one whose plan the layout cannot write, and one whose planning throws (the error is discarded, so the first error reported is today's) is built per path again with no limit. The limit is the largest whose build and abandon cost under 0.1 s and 20 MB in a release build on a 4-core Linux machine (0.08 to 0.09 s and 6 MB at 1,500 on layered screens with a back edge); a change to what a place costs measures it again. A run that draws the DOT graph decides alike and also keeps a tree per path to draw (`RootScopeInfo.drawnTree`); a run that generates no code (the graph alone, received values) sets no limit. A plan root may hold a `Sendable` instantiator, whose builder function is `@Sendable`, but no `SendableLazilyInstantiated` (`holdsLazilyInstantiated`) and no `@Sendable` function a type holds (`holdsSendableFunction`). Where the module names a wrapper that is not `Sendable` beside a `Sendable` builder (`namesNonSendableWrapperAndSendableBuilder`), the root choice walks the plan's bodies with the `@Sendable` capture walk (`WrittenVariantPlan.Unplanned.mayCaptureNonSendableWrapper()`, `ScopeGenerator.mayCaptureNonSendableWrapper(asBodyOf:answeredBy:)`), each body over its answers' declarations, and a root whose bodies may make a capture keeps its tree per path (`mayCaptureNonSendableWrapper`), whose walk reports today's error; the body walk is conservative, so it can keep a root per path that makes no capture, never lay one out that does. A lift that admits a `SendableLazilyInstantiated` or a `@Sendable` function keeps that walk reading what it builds in the same change; `PlanCaptureChecks`, which every test runs, records an issue where today's walk of a root laid out from its plan finds a capture (`PlanCaptureObservation`). The bar for a shape to leave the list is byte identity with today's code: `SafeDIToolPerTypePlanShapesTests` has a root per reason and per captured shape, each generated with the limit at 0 (`RootTreeChoiceObservation.scopeGeneratorLimitOverride`, which only tests set) and again within the limit, plus one root past the shipped limit. A function built inside a variant that captures a root statement reads that statement (`typeDeclaration(for:)`), as today's captures it. A rename (`fulfilledByDependencyNamed:`) is laid out like a receive of the label it renames; one received only if available or of a builder keeps its root per path through the reason of that shape. A parameter an initializer declares `@escaping` by a name is laid out as a call place carries it (`typesDeclaredEscaping`), so a function's parameter spells `@escaping` wherever today's does. A cycle member instantiated erased, through an `ErasedInstantiator` or to a concrete existential, is a call its edge wraps as today's tree wraps it. A received or renamed builder is a read like any other; one whose label's declaration builds a type that reaches the receiver closes a loop of builders, whose member the layout does not make again at the call yet, and keeps its root per path (`receivesBuilderThatClosesLoop`). A call of a seam's generated initializer that passes no builder is laid out as the leaf it is: the shadow's copy keeps the scope's `seamCall`, so the place's function writes the guard line and the `__safeDI_` labels as today's does, and a call that passes a builder keeps its root per path (`buildsSeam`); and a seam that receives a value only if available, as a tier that omits a parameter does, keeps its root per path through that reason, which is what keeps a root with a tier omission (`seamTierOmissions`) on the tree that walk reads: the lift that admits a value received only if available gives a planned root that check in the same change. A `LazilyInstantiated` is laid out (a `SendableLazilyInstantiated` keeps its root per path, `holdsLazilyInstantiated`): a function whose body reads the instance of a wrapper declared above its call takes the wrapper as its parameter (`Answer.parameter(labeled:)`), the call passes the binding, and the instance is created where it is first read, as today's type key body does; `SafeDIToolPerTypePlanValueTests`' `generate_buildsLazilyInstantiatedInstanceAtFirstRead_whenReaderIsBeneathDeclaringTypeOrAcrossCall` counts the instances built at each step on both paths. A stated change in generated code past the limit: the plan declares one function where today's tree declares copies of it named apart, and where today declares a capturing function beside a twin that takes the value, the plan declares the one that takes it. Where a test sets an observer of this folder, today's tree is built whatever its size and the plan is built for every root that reaches a cycle, and compared; the code emitted is still what the limit decides. The plan is no input to a place's build and has no entry in the construction memo's key or log.
- **A plan costs what it emits.** The bodies of the plan a root's code is laid out from share one construction memo (`VariantBodies(…sharesConstructionMemo: true)`), over a map with every copy of the shadow frozen once, so a tree beneath a type on a cycle built under several labels is built in one body and reused in the others; a test's comparison keeps a memo per body. A walk of a body for its calls follows only the scopes that lead to a call place (`CallPlaceShadow.scopesLeadingToCallPlaces`), and each scope's children share its declarations in one layer; the layout resolves calls only along the paths to them. Each body's answers, a called scope's labels and their order, and a closer's arguments by label are made once. `perTypePlan` builds no shadow for a root its shape refuses.
- **The core names no feature.** `OrderedGraph` is generic over its node and knows nothing of a scope: nodes in the order a depth-first walk first reaches them, edges in the order given, strongly connected components by Tarjan's algorithm in the same walk, all on an explicit stack. Positions are the only names, so no `Set` or `Dictionary` order reaches a result; its one dictionary only finds a node's position.
- **A declaration is a record and a property.** `Declaration` is equal by the scope's record, the property's ID and whether it is erased, never by a path. The graph has an edge for each property a scope instantiates (`ScopeRecord.PropertyToGenerate.instantiated`); an alias builds nothing and has none.
- **Twins.** Generation closes a cycle on the property as cycle validation sees it and the concrete type built (`CycleIdentity`, as `ContextStack.entryClosedOn(byPropertyID:concreteTypeID:interner:)` compares them). Two declarations of one component with one identity, such as a constant and a `LazilyInstantiated` of one label built for one type, are twins (`PerTypePlan.twins`): a path closes on whichever it built first, so what such a declaration builds differs between paths, and a plan cannot stand for both. The graph fuzzer draws twins over a shared screen in all three corpora (`addingTwinsOverSharedScreen`, `drawTwinsPublicMock`; `fuzzer-corpora.md`), with a parent label each twin reads, in one form or two.
- **Nothing crosses a module.** A plan is built from the frozen table of one run and dropped with its root's build. Nothing of it is written to a `.safedi` file, a manifest or a cache.
- **Labels read from above.** `LabelsReadFromAbove` gives each node the labels its subtree reads that it does not bind, the least sets that satisfy the rule, a component at a time. A node's order is its own labels, then each target's in edge order; inside a cycle, passes over the cycle's nodes in position order, so no order but the graph's reaches it. A node's bound labels hide a label from the nodes above whichever of its properties is built first, since the nearest declaration of a label answers a read even where it is built later.
- **The validation walk checks the labels.** Where a test sets `LabelsReadFromAboveObservation.observer`, `validatePropertiesAreFulfillable`'s `labelsReadFromAbove(by:)` also computes each scope's least set twice, with `LabelsReadFromAbove` and by passes until none changes, and hands both on with the answer the walk remembered; both test executors record an issue where the two differ (`LabelsReadFromAboveChecks`), so every test and fuzzer graph checks it. The walk's own answer is not compared: it is partial for a scope finished inside a cycle, and sharing `LabelsReadFromAbove` with the walk needs a fuzzer comparison showing no diagnostic moves.
- **Bodies.** `PlanVariants` gives each declaration one body per set of answers a path gives the labels it reads from above, by value: two parents that each declare `x: X` give one answer, a parent that declares none gives another (`nil`), and a declaration that reads the label it is built as is answered by that declaration, being built. It is a first model, built for `PerTypePlanObservation.variantsObserver` only, since its bodies still grow with the subsets of the labels a path around a cycle declares (2^n on a hub whose n members each declare a label it receives only if available); the labels each place may read come from the graph alone (`PlanVariants.placeReadLabels(of:)`), which every test reads: an answer is the nearest declaration by label alone, and does not yet judge the order a scope builds its children in, the form a reader takes a declaration in (`Answer.instance`), or the `@Sendable` family. Each of those joins the model with a test that fails without it, before any emitter reads a body.
- **A place reads only the labels its body is keyed by.** Where a test sets `PlaceReadsObservation.observer`, each place a pass finishes whose reads the construction memo logged hands on the labels its subtree asked the declarations above it for (`ConstructionLog.labelsOfReadsOfDeclarations`: the nearest declaration, a binding, whether a mock passes `nil`; never what a cycle closes on or passes) beside the labels `LabelsReadFromAbove` gives its declaration, and both test executors record an issue where a place read a label the plan lacks (`PlaceReadsChecks`): a body shared by the places whose paths answer its labels alike would read something its key does not hold. Left out, each stated at its site: the place's own property's label, which the scope that builds it declares, so the edge decides the answer; every place whose subtree holds a call or a fill, since a call reads the caller's declarations for its fills' trees and the plan has no edge for a fill, and every place inside a fill, which reads the fields of the place it fills and has no node (seam corpus seed 0 fails without it), so no tree with a call or a fill takes a body per declaration until the plan has that edge; and the binding a scope passes an optional parameter of the function a lazy cycle closes on (`ConstructionLog.Read.cycleArgumentBinding`), which today's tree asks for by the form the body receives, also where a declaration of the label inside the function that provides no such form hides the parameter from every reader, as a forwarded `mark: Mark?` above a receive of `mark: Stamp?` only if available does: the plan, which hides by label, keys the body by no such label and passes nothing (`SafeDIToolPlaceReadsTests`' hidden cycle parameter test, base corpus seed 2147). So this check no longer sees a plan that lacks the label of a parameter the body does read; the body comparison below does, where the body passes `nil` otherwise.
- **A body built beneath its answers passes `nil` where today's place does.** Where a test sets `VariantBodyObservation.observer`, each place of a production root's tree (`DependencyTreeGenerator.PlaceContextWalk`, driven by `compareBodies(ofRoot:todaysTree:frozenScopeMap:declaredTypeNames:cache:)`, the one function a world calls per root for this comparison and the next) has a body built from its scope's `CallPlaceShadow` copy, beneath only the declarations that answer the labels its tree receives and its own (`NearestDeclarations.keeping(labels:)`), one body per scope, property, answers and lazily instantiated instances; both test executors record an issue where the body's `unavailableOptionalProperties` differ from today's place's (`VariantBodyChecks`). It covers production roots, in a module without seams and in the seam world, never a seam's own tree, and compares nothing else of a body. A place inside a function a lazy cycle closes on is compared once for the call of the scope that declares the function and once for each scope that closes the cycle on it, with the declarations that call's path gives it: today one generator stands for the places of every call and reads the function's parameters, so where a call passes a parameter `nil` (`ScopeGenerator.labelsOfCycleParametersPassedNil`) today's side is every receive of the label, as in a body no declaration answers the label for. Calls of one function answered alike are compared once. Limits, each stated at its site: a call made inside the places a cycle-closing scope's call walks is not followed; a tree with a label no one parameter can pass (`unpassableCycleLabel`), which is rejected, is not compared, since a body beneath a call's own answers passes a value there that today's parameter cannot carry; and a member of a loop of builders has its rebindings seeded as its nearest declarations.
- **The plan builds every body today's places take.** Where a test sets `PlanBodiesObservation.observer`, a production root's bodies are also built with no tree of today's (`VariantBodies`): the root's copy, then the body of each call place a body holds, beneath the answers that body's path gives it (`CallPlaceShadow.scope(calledAt:)`), until no call is answered anew. Both test executors record an issue where a place of today's tree whose scope is on a cycle takes a body the plan did not build (`PlanBodiesChecks`). A call is of the function's property: where a path is building a twin of the value a call place builds (`CallPlaceShadow.twinValues`, `PlaceContext.twinsBeingBuilt`, the first of the two the path built), the plan's call is of that property beneath the calling scope's declarations, as today's cycle-closing scope calls that property's function, and each body is keyed by the twins its path is building (`VariantBodyKey.twinsBeingBuilt`). A root that holds a twin still stays per path; `TwinIdentityChecks` (below) checks its mapping of functions. A body is built as the property its place builds it as, the one child of a scope that declares nothing else (`VariantBodies.body(…builtBy:)`), so every child on a cycle is a call place, a repeat of the body's own declaration included; only the root's own body is built as a root. `VariantBodies.plan(ofRoot:shadow:cache:)` builds the plan and keeps what an emitter reads: `generator(of:)`, and `calls(of:)`, each call with the path of its call place among `propertiesToGenerate` from the body's scope down, the body called, and what answers each label that body is keyed by (`Body.planAnswers`), which `PlanCallsObservation` hands a test (`SafeDIToolVariantBodyTests`' `generate_listsEachBodysCallsWithTheirAnswers_…`).
- **A label the cycle declares again is one optional parameter.** A label a body's tree receives only if available, in forms one parameter provides, that another scope of the called scope's cycles declares (`CallPlaceShadow.parameterLabels(ofFunctionOf:)`, the labels today's function can take, `CycleParameter`) is taken as an optional parameter whatever each call answers it (`VariantBodies.OptionalParameter`, `calledBody(…)`): the body is built beneath the parameter, which hides every declaration of the label above, and each call passes its own declaration or `nil` (`VariantBodies.Call.arguments`, the parameter from the body's answer and the value from the call's in `ClosingPlaceRecord.init(callingVariant:…)`). Keyed by each answer, the hub of n members that each declare their own label built 2^n hubs and n·2^(n-1) members; it builds n + 1 bodies (`SafeDIToolVariantBodyTests`' hub test at 8 and 16 members), and today's places are compared with that body. A call keeps its own answer, so a body per answer, where a receive reads the declaration in another form than the parameter takes, through a lazily instantiated wrapper, or as a mock root's binding, and for a loop member made again at the call or a label required through an alias only if available. A loop member made again at the call is taken optionally too, and passed made again. Answers kept per call still multiply, so the plan stops where one key holds more than `VariantBodies.bodiesPerKeyLimit` bodies, and the root stays per path (`PerPathReason.bodiesOfOneDeclarationPassBound`, the `generate_keepsRootPerPath_whenBodiesOfOneDeclarationPassTheirBound` test). A body that declares the label itself in another form, called beneath the parameter, is keyed by the parameter like any other answer: hiding is by label, so a read is answered by the nearest declaration of its label, and a forward in a form the read does not take hides the parameter, as today (the `generate_buildsPlan_whenBodyCalledBeneathOptionalParameterDeclaresLabelInAnotherForm` test). The comparisons map each place of today's tree to the body the plan builds for it (`calledBody(…)`), so `PlanBodiesChecks` and `MockVariantBodyChecks` compare the merged bodies. A label no other scope of the cycles declares is answered alike by every call and takes no parameter, as today.
- **A body holds what its answers do not** (`VariantAnswers`, one test each in `SafeDIToolVariantAnswersTests`). Order: a label whose declaration a scope above builds after the call (`OrderedChild.propertiesGeneratedLater`, threaded through `PlaceContextWalk` as today's emission threads it) is answered `nil`, so a body is built with `nil` for it whatever declares it, and shares the body no declaration answers; a call of a function a lazy cycle closes on keeps a parameter the closing scope passes on as the `nil` its own function was passed, or passes `nil` as built after the call (`PlaceContext.answeringCall(of:by:passingOnNilFor:)`); today's side reads the ordered unavailable properties, so both test executors check the order on every test graph. A member of a loop of builders is the exception to the order: its function makes again the members its tree receives, and where it takes one as a parameter a lazy cycle needs, the scope that declares the loop calls it through `__safeDI_<label>_received`, which makes that member's wrapper again and passes it (`ScopeGenerator.loopMembersPassedByReceivedFunctions`), so a loop member built after the call still answers the label, at a call place and at today's place alike (`VariantAnswers.isPassedByReceivedFunction`, which matches a member by property, in the form the loop declares or its optional form, as today's `recordCalls` does; the two `…LoopMemberBuiltAfterCall…` tests, base corpus seeds 575 and 2103). The body's key holds the declaration, and the call's argument says the wrapper is made again at the call (`Answer.declaredMadeAgainAtCall`, from `VariantAnswers.labelsMadeAgainAtCall`; the two `generate_passesLoopMemberMadeAgain…` tests), since the call is made before the declaration; a deliberate gap while nothing emits from the plan: `Answer.argumentSource(labeled:)` still spells the binding, and the layout of a loop member's call owes the wrapper. The loops at a call place are those of the body's own generator, which no check compares with today's beyond the bodies and answers that follow from them. Family, a mark and no key: a call made inside a `@Sendable` function, or of a property held in a `Sendable` wrapper, is of the `@Sendable` family (`VariantBodies.Call.isInSendableFamily`; functions are declared in the root's body, so none encloses another and this is not `buildsInSendableFunction`), and a body is `@Sendable` where some call of it is, or a `@Sendable` body calls it (`VariantBodies.isSendable(_:)`). The type key's layout computes its own family of the same bodies (`WrittenVariantPlan`), and both test executors record an issue where the two mark other bodies (`PlanSendableChecks`). Calls of both families share one body, as today's tree writes one `@Sendable` function for every caller once a `@Sendable` function calls it: a plain caller can call it, so a plain body beside it would serve no call that compiles today. Twins: both test executors record an issue where a call of today's tree that a scope closing a cycle makes runs another function than the plan's call names (`TwinIdentityChecks`), so a body maps to one function. The two rules' twins are handed on, never compared: the order shadow's (`CallPlaceShadow.twinValues`) holds a constant whose lazy twin closes the cycle on it from another component, which the plan's (`PerTypePlan.twins`, one component) leaves out, and generation closes on the identity whichever names the twins.
- **A mock root's bodies are compared as a production root's.** Where a test sets `MockVariantBodyObservation`'s observers, each place of a mock root's tree that reaches a cycle has a body built as a place of a mock's tree (`VariantBodies(…forMockGeneration: true)`), and the plan's bodies are built from the root's copy (`compareMockBodies`, `MockVariantBodyChecks`): beneath the bindings the mock gives its tree, passing `nil` where `receivesPassedNil` says production does, kept by `NearestDeclarations.keeping(labels:)`; the root's declarations joined to those bindings (`PlaceContextWalk`'s `isMockRoot`); each place recording its required receives, and the promoted trees built beneath the bindings before the mocked type's own receives pin any. `SafeDIToolMockVariantBodyTests` has a test for each that fails without it. `buildsWithHandWrittenMocks` is no input: a mock's tree sets it only inside a fill, which no comparison reaches, and outside one the hand-written mock is the lowering's choice per declaration. Nor is the override a place reads: the places of one type read different `SafeDIOverrides` paths (at 12 screens opening each other, 66 of 2,956 places read their own path, none a nearest node's, the rest none, and one type reads up to 17 paths), so keying by the path gives a body per path. A body is handed its configuration by each call: the caller's field where the edge is not a pruned cycle edge, the nearest configuration of its type where the type repeats an ancestor's, else `.init()`, whose defaults are what reading none builds, with a parameter per declaration its subtree closes on; the kind of read (a configuration, a closure, a hand-written mock's) is the declaration's. Limits: no override path is compared yet, a tree that calls another module's public mock is not compared (the call reads the caller's declarations for its fills' trees, and a body has no edge for a fill), and the root's body is still built as a root.
- **A call place is ordered by today's rule.** A body will build each child on a cycle as a call place: a scope with no children whose type receives what the child's whole tree receives from above (`DependencyTreeGenerator.collectReceivedProperties`, least sets completed a strongly connected component at a time before any tree exists, so no sibling order feeds them). `ScopeGenerator`'s one ordering rule then orders it among its siblings; no second copy of the rule exists. `CallPlaceShadow` builds those copies only where a test sets an observer of this folder, and both test executors record an issue where a place of today's tree orders its children otherwise than its scope's copy does (`CallPlaceOrderChecks`). It covers production roots, in a module without seams and in the seam world, never a seam's own tree, and no tree with a label no one parameter can pass (`unpassableCycleLabel`), which is rejected: today's cycle-closing scope takes no parameter for such a label, so it waits for no sibling that declares it (`SafeDIToolLazyCycleNearestDeclarationTests`' `generate_throwsUnpassableLabelErrorAlone_…`, seam corpus seeds 480 and 505). A call place carries what its tree requires through an alias received only if available (`Scope.callPlaceRequiredAliasFulfillingProperties`, from `ReceivedProperties.requiredAliasFulfillingProperties`), so the sibling declaring the alias's source is built first, as today; and it declares `@escaping` each name the tree it stands for declares so (`ScopeGenerator.typesDeclaredEscaping(ownedBy:publicMockCall:seamCall:)`, unioned over every component its scope reaches), so a function that only passes a typealiased closure on spells its parameter `@escaping` (both in `SafeDIToolPlanCodeTests`). A loop of builders, where today's order and the receives left `nil` feed each other, is compared but not argued. A call place is a leaf kind of its own (`Scope.isCallPlace`, `ConstructionScope.isCallPlace`): it closes no cycle, whatever is being built above it, and no seam reader may take it for a seam's leaf.
- **A label no one parameter can pass keeps a root on today's tree.** A plan has no cycle-closing scope, so it cannot find such a label (`UnpassableCycleLabel`). `DependencyTreeGenerator.mayHaveUnpassableCycleLabel(inTreeOf:cache:)` decides from the scopes alone, before any tree: it fires where a scope on a cycle receives two or more forms of a label that a scope of its strongly connected component declares or forwards (`collectReceivedProperties`), and a root it fires for is built per path (`PerPathReason.unpassableCycleLabel`), so today's walk reports what it finds. It over-approximates: one form is always passable, and it counts forms rather than judging them, since a place can receive fewer forms than its scope and more forms can make a label passable. Both test executors record an issue where today's tree reports a label for a root the detector does not fire for (`UnpassableCycleLabelChecks`); `SafeDIToolUnpassableCycleLabelDetectorTests` has a root it catches that today accepts, and a cycle of screens that receive nothing, which it does not catch.
- **Shapes not built yet.** `Variant`, `PlanStatement` and `PerPathReason` (`PlanStatement.swift`) are the shapes the layout and the tree walks are written against. Nothing constructs them until an emitter reads the plan's bodies, but for the bound on a key's bodies (`VariantBodies.keptPerPathBecause`) (`Answer`, beside them, is what `Body.planAnswers` gives); a pull request of this folder either builds each or removes it.
