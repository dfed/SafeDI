# A tree's plan by declaration

`Sources/SafeDICore/Generators/CycleTree/` holds a plan of a root's tree with one node per declaration (a scope's record and the property it is built as), where `Scope.createScopeGenerator` builds one generator per path. A tree whose screens open each other has a number of paths that grows with every cycle, and a number of declarations that does not.

- **Nothing reads the plan to generate code.** `PerTypePlan` is built only where a test sets `PerTypePlanObservation.observer`, beside the tree each path builds, so that the two can be compared. A run with no observer does no work for it. Until a change makes an emitter read it, it is no input to a place's build and has no entry in the construction memo's key or log.
- **The core names no feature.** `OrderedGraph` is generic over its node and knows nothing of a scope: nodes in the order a depth-first walk first reaches them, edges in the order given, strongly connected components by Tarjan's algorithm in the same walk, all on an explicit stack. Positions are the only names, so no `Set` or `Dictionary` order reaches a result; its one dictionary only finds a node's position.
- **A declaration is a record and a property.** `Declaration` is equal by the scope's record, the property's ID and whether it is erased, never by a path. The graph has an edge for each property a scope instantiates (`ScopeRecord.PropertyToGenerate.instantiated`); an alias builds nothing and has none.
- **Twins.** Generation closes a cycle on the property as cycle validation sees it and the concrete type built (`CycleIdentity`, as `ContextStack.entryClosedOn(byPropertyID:concreteTypeID:interner:)` compares them). Two declarations of one component with one identity, such as a constant and a `LazilyInstantiated` of one label built for one type, are twins (`PerTypePlan.twins`): a path closes on whichever it built first, so what such a declaration builds differs between paths, and a plan cannot stand for both.
- **Nothing crosses a module.** A plan is built from the frozen table of one run and dropped with its root's build. Nothing of it is written to a `.safedi` file, a manifest or a cache.
- **Labels read from above.** `LabelsReadFromAbove` gives each node the labels its subtree reads that it does not bind, the least sets that satisfy the rule, a component at a time. A node's order is its own labels, then each target's in edge order; inside a cycle, passes over the cycle's nodes in position order, so no order but the graph's reaches it. A node's bound labels hide a label from the nodes above whichever of its properties is built first, since the nearest declaration of a label answers a read even where it is built later.
- **The validation walk checks the labels.** Where a test sets `LabelsReadFromAboveObservation.observer`, `validatePropertiesAreFulfillable`'s `labelsReadFromAbove(by:)` also computes each scope's least set twice, with `LabelsReadFromAbove` and by passes until none changes, and hands both on with the answer the walk remembered; both test executors record an issue where the two differ (`LabelsReadFromAboveChecks`), so every test and fuzzer graph checks it. The walk's own answer is not compared: it is partial for a scope finished inside a cycle, and sharing `LabelsReadFromAbove` with the walk needs a fuzzer comparison showing no diagnostic moves.
- **Bodies.** `PlanVariants` gives each declaration one body per set of answers a path gives the labels it reads from above, by value: two parents that each declare `x: X` give one answer, a parent that declares none gives another (`nil`), and a declaration that reads the label it is built as is answered by that declaration, being built. It is a first model, handed to `PerTypePlanObservation.variantsObserver` only: an answer is the nearest declaration by label alone, and does not yet judge the order a scope builds its children in, the form a reader takes a declaration in (`Answer.instance`), or the `@Sendable` family. Each of those joins the model with a test that fails without it, before any emitter reads a body.
- **A place reads only the labels its body is keyed by.** Where a test sets `PlaceReadsObservation.observer`, each place a pass finishes whose reads the construction memo logged hands on the labels its subtree asked the declarations above it for (`ConstructionLog.labelsOfReadsOfDeclarations`: the nearest declaration, a binding, whether a mock passes `nil`; never what a cycle closes on or passes) beside the labels `LabelsReadFromAbove` gives its declaration, and both test executors record an issue where a place read a label the plan lacks (`PlaceReadsChecks`): a body shared by the places whose paths answer its labels alike would read something its key does not hold. Left out, each stated at its site: the place's own property's label, which the scope that builds it declares, so the edge decides the answer; every place whose subtree holds a call or a fill, since a call reads the caller's declarations for its fills' trees and the plan has no edge for a fill, and every place inside a fill, which reads the fields of the place it fills and has no node (seam corpus seed 0 fails without it), so no tree with a call or a fill takes a body per declaration until the plan has that edge; and the binding a scope passes an optional parameter of the function a lazy cycle closes on (`ConstructionLog.Read.cycleArgumentBinding`), which today's tree asks for by the form the body receives, also where a declaration of the label inside the function that provides no such form hides the parameter from every reader, as a forwarded `mark: Mark?` above a receive of `mark: Stamp?` only if available does: the plan, which hides by label, keys the body by no such label and passes nothing (`SafeDIToolPlaceReadsTests`' hidden cycle parameter test, base corpus seed 2147). So this check no longer sees a plan that lacks the label of a parameter the body does read; the body comparison below does, where the body passes `nil` otherwise.
- **A body built beneath its answers passes `nil` where today's place does.** Where a test sets `VariantBodyObservation.observer`, each place of a production root's tree (`DependencyTreeGenerator.PlaceContextWalk`, driven by `compareBodies(ofRoot:todaysTree:frozenScopeMap:declaredTypeNames:cache:)`, the one function a world calls per root for this comparison and the next) has a body built from its scope's `CallPlaceShadow` copy, beneath only the declarations that answer the labels its tree receives and its own (`NearestDeclarations.keeping(labels:)`), one body per scope, property, answers and lazily instantiated instances; both test executors record an issue where the body's `unavailableOptionalProperties` differ from today's place's (`VariantBodyChecks`). It covers production roots of a module without seams, and compares nothing else of a body. A place inside a function a lazy cycle closes on is compared once for the call of the scope that declares the function and once for each scope that closes the cycle on it, with the declarations that call's path gives it: today one generator stands for the places of every call and reads the function's parameters, so where a call passes a parameter `nil` (`ScopeGenerator.labelsOfCycleParametersPassedNil`) today's side is every receive of the label, as in a body no declaration answers the label for. Calls of one function answered alike are compared once. Limits, each stated at its site: a call made inside the places a cycle-closing scope's call walks is not followed; a tree with a label no one parameter can pass (`unpassableCycleLabel`), which is rejected, is not compared, since a body beneath a call's own answers passes a value there that today's parameter cannot carry; and a member of a loop of builders has its rebindings seeded as its nearest declarations.
- **The plan builds every body today's places take.** Where a test sets `PlanBodiesObservation.observer`, a production root's bodies are also built with no tree of today's (`VariantBodies`): the root's copy, then the body of each call place a body holds, beneath the answers that body's path gives it (`CallPlaceShadow.scope(calledAt:)`), until no call is answered anew. Both test executors record an issue where a place of today's tree whose scope is on a cycle takes a body the plan did not build (`PlanBodiesChecks`). A call is of the function's property: where a path is building a twin of the value a call place builds (`CallPlaceShadow.twinValues`, `PlaceContext.twinsBeingBuilt`, the first of the two the path built), the plan's call is of that property beneath the calling scope's declarations, as today's cycle-closing scope calls that property's function, and each body is keyed by the twins its path is building (`VariantBodyKey.twinsBeingBuilt`). A root that holds a twin still stays per path; `TwinIdentityChecks` (below) checks its mapping of functions. A body is built as the property its place builds it as, the one child of a scope that declares nothing else (`VariantBodies.body(…builtBy:)`), so every child on a cycle is a call place, a repeat of the body's own declaration included; only the root's own body is built as a root. `VariantBodies.plan(ofRoot:shadow:cache:)` builds the plan and keeps what an emitter reads: `generator(of:)`, and `calls(of:)`, each call with the path of its call place among `propertiesToGenerate` from the body's scope down, the body called, and what answers each label that body is keyed by (`Body.planAnswers`), which `PlanCallsObservation` hands a test (`SafeDIToolVariantBodyTests`' `generate_listsEachBodysCallsWithTheirAnswers_…`).
- **A body holds what its answers do not** (`VariantAnswers`, one test each in `SafeDIToolVariantAnswersTests`). Order: a label whose declaration a scope above builds after the call (`OrderedChild.propertiesGeneratedLater`, threaded through `PlaceContextWalk` as today's emission threads it) is answered `nil`, so a body is built with `nil` for it whatever declares it, and shares the body no declaration answers; a call of a function a lazy cycle closes on keeps a parameter the closing scope passes on as the `nil` its own function was passed, or passes `nil` as built after the call (`PlaceContext.answeringCall(of:by:passingOnNilFor:)`); today's side reads the ordered unavailable properties, so both test executors check the order on every test graph. Family, a mark and no key: a call made inside a `@Sendable` function, or of a property held in a `Sendable` wrapper, is of the `@Sendable` family (`VariantBodies.Call.isInSendableFamily`; functions are declared in the root's body, so none encloses another and this is not `buildsInSendableFunction`), and a body is `@Sendable` where some call of it is, or a `@Sendable` body calls it (`VariantBodies.isSendable(_:)`). Calls of both families share one body, as today's tree writes one `@Sendable` function for every caller once a `@Sendable` function calls it: a plain caller can call it, so a plain body beside it would serve no call that compiles today. Twins: both test executors record an issue where a call of today's tree that a scope closing a cycle makes runs another function than the plan's call names (`TwinIdentityChecks`), so a body maps to one function. The two rules' twins are handed on, never compared: the order shadow's (`CallPlaceShadow.twinValues`) holds a constant whose lazy twin closes the cycle on it from another component, which the plan's (`PerTypePlan.twins`, one component) leaves out, and generation closes on the identity whichever names the twins.
- **A mock root's bodies are compared as a production root's.** Where a test sets `MockVariantBodyObservation`'s observers, each place of a mock root's tree that reaches a cycle has a body built as a place of a mock's tree (`VariantBodies(…forMockGeneration: true)`), and the plan's bodies are built from the root's copy (`compareMockBodies`, `MockVariantBodyChecks`): beneath the bindings the mock gives its tree, passing `nil` where `receivesPassedNil` says production does, kept by `NearestDeclarations.keeping(labels:)`; the root's declarations joined to those bindings (`PlaceContextWalk`'s `isMockRoot`); each place recording its required receives, and the promoted trees built beneath the bindings before the mocked type's own receives pin any. `SafeDIToolMockVariantBodyTests` has a test for each that fails without it. `buildsWithHandWrittenMocks` is no input: a mock's tree sets it only inside a fill, which no comparison reaches, and outside one the hand-written mock is the lowering's choice per declaration. Nor is the override a place reads: the places of one type read different `SafeDIOverrides` paths (at 12 screens opening each other, 66 of 2,956 places read their own path, none a nearest node's, the rest none, and one type reads up to 17 paths), so keying by the path gives a body per path. A body is handed its configuration by each call: the caller's field where the edge is not a pruned cycle edge, the nearest configuration of its type where the type repeats an ancestor's, else `.init()`, whose defaults are what reading none builds, with a parameter per declaration its subtree closes on; the kind of read (a configuration, a closure, a hand-written mock's) is the declaration's. Limits: no override path is compared yet, a tree that calls another module's public mock is not compared (the call reads the caller's declarations for its fills' trees, and a body has no edge for a fill), and the root's body is still built as a root.
- **A call place is ordered by today's rule.** A body will build each child on a cycle as a call place: a scope with no children whose type receives what the child's whole tree receives from above (`DependencyTreeGenerator.collectReceivedProperties`, least sets completed a strongly connected component at a time before any tree exists, so no sibling order feeds them). `ScopeGenerator`'s one ordering rule then orders it among its siblings; no second copy of the rule exists. `CallPlaceShadow` builds those copies only where a test sets an observer of this folder, and both test executors record an issue where a place of today's tree orders its children otherwise than its scope's copy does (`CallPlaceOrderChecks`). It covers production roots of a module without seams, and no tree with a label no one parameter can pass (`unpassableCycleLabel`), which is rejected: today's cycle-closing scope takes no parameter for such a label, so it waits for no sibling that declares it (`SafeDIToolLazyCycleNearestDeclarationTests`' `generate_throwsUnpassableLabelErrorAlone_…`, seam corpus seeds 480 and 505). A call place does not yet carry what its tree requires through an alias received only if available, and a loop of builders, where today's order and the receives left `nil` feed each other, is compared but not argued. A call place is a leaf kind of its own (`Scope.isCallPlace`, `ConstructionScope.isCallPlace`): it closes no cycle, whatever is being built above it, and no seam reader may take it for a seam's leaf.
- **Shapes not built yet.** `Variant`, `PlanStatement` and `PerPathReason` (`PlanStatement.swift`) are the shapes the layout and the tree walks are written against. Nothing constructs them until an emitter reads the plan's bodies (`Answer`, beside them, is what `Body.planAnswers` gives); a pull request of this folder either builds each or removes it.
