# Graph fuzzer: the override oracle

Continues "Base corpus value oracle" in `fuzzer-value-oracles.md`.

The value-oracle graph also holds, after the plan's pairs, one override pair per compared pair – each root's, then each mirrored mock's (`GraphFuzzerValueOraclePlan.overrideProbes`, `Tests/SafeDIToolTestSupport/GraphFuzzerMockOverrideProbes.swift`). Its candidates are the mock's `SafeDIOverrides` fields for a dependency built beside the mocked type: a root's own child, or a mirror's declaration (the mocked type's own child or a promoted dependency), of a type that is not a root, whose field is a builder closure returning the property's type or the built type's `SafeDIMockConfiguration` (`GraphFuzzerOverrideFieldKind`), of a kind the oracle judges (`GraphFuzzerOverrideCandidateKind`): a constant; a `LazilyInstantiated` or `SendableLazilyInstantiated`, whose instance production creates on its first read; an erased constant (`fulfilledByType:`, erased to a concrete existential or not), whose builder field returns the property's type, so the sentinel's builder erases what it builds as production does (`recording(_:erasedBy:)`), and whose configuration's builder returns the built type, which the mock erases, so the known-right side reads the instance the erasing type production holds stores (`known.<label>.value`; every erasing type of the base corpus stores it so); or a `SendableInstantiator` or `SendableErasedInstantiator` of a type that forwards nothing, which the mocked type stores and which is no actor, whose field the instantiator's `@Sendable` builder function reads once per instance, so each side records what one more call of the instantiator the mocked type holds builds (`value.<label>.instantiate()`, after resetting the record, against `known.<label>.instantiate()`), which the describer describes in full, each shared dependency where the rest of the probe first held it. A record of a type whose tree builds it again is described through that cycle again, so the seeds whose records traverse past a batch's budget are compared on their own (`corpusSeedsTraversingPastTheBatchBudget`: 512, 1136 and 1627). A mirrored mock's override of a value its tree receives only if available, `x: X?`, which production passes `nil` where nothing declares it, is a candidate too, after the mirror's declarations: the first such field of a non-wrapper type the harness has a sample of whose label the tree receives in no other form, which the variant would forward as that form (seed 126's wrapper), (field kind `value`), whose known-right side is the mirror's variant, `S<seed>_ZMirror<k>Available`, which forwards `x: X` beside the mock's required parameters and which its own root, `…AvailableHost`, builds with a sample of it, and which binds the mocked type's aliases of it from that value as the mock binds them from the override (seed 153) (`GraphFuzzerOnlyIfAvailableOverride`, in the value-oracle fixture beside the mirrors): the feature expression passes the override a sample and records it, and the known-right side records the variant's forwarded value, so each receiver the override reaches holds the sample where each holds the forwarded value. It takes the candidate at `(seed + the pair's position) % count`, so a seed judges one field per mock. The feature expression calls the mock, with the samples its own pair hands it, and that field given a builder that builds the type with its own initializer or `instantiate(…)` from the arguments the mock hands it (or, for the configuration of a property the tool builds with the type's hand-written mock because that mock returns the property's type, one of the type's additional types, with that mock: `handWrittenMocksReturningAdditionalTypes`, `overrideProbes_passSentinelThroughHandWrittenMock_whenConfigurationBuildsPropertyWithMockReturningAdditionalType`) and records the first instance it built since the probe began (`GraphFuzzerOverrideSentinel`; a node a cycle builds again beneath an instantiator reads the override of the nearest node of its type around it, so the builder builds again when the describer calls one, which for a lazily instantiated dependency is before its record is read: seed 209), in a file only the compiled fixture holds, which names itself and which the tool does not read), and returns the mock's value with the record. The known-right expression returns the pair's production build – the root, or the mirror's value, built through the mirror's root with the same samples when it forwards them – with the instance production holds under the label (`known.<label> as Any?`). For a lazily instantiated dependency each side's record is itself a `LazilyInstantiated<Any?>`, reading the sentinel or `known.<label>.instance`, so the describer reads it after the rest of the probe's value, where it reads the mock's and production's wrappers, which creates the instance; where the value reaches the wrapper only through another wrapper's instance, the record is read first, which makes the mock's record `nil` beside production's instance, and no corpus graph does so today. The sentinel is built from the arguments production passes, so the two agree only when it takes exactly the place of production's instance: an ignored override (`nil` beside the instance), one applied to another node (the record first seen elsewhere), or one that reaches some receivers and not others (two instances where production shares one) is a difference, a `mockBuildsOtherValuesThanProduction` whose probe is named `<T>.mock(safeDIOverrides: .init(<label>: sentinel))` (`sample` for a value received only if available). Since the mock's own pair compares the mock called without overrides with the same build, nothing else changes. The probe's value is a tuple, not a stamped class, so these pairs carry no creation-stamp marks. `corpusValueOracleCounts` pins the override pairs (`overridePairs`, a set sum over `<seed>:<type>:<label>`, the count per field kind, and the count per candidate kind), and the smoke batch must pass an override through each field kind and each candidate kind. The hand mutation that shows the lazily instantiated kind fires, a mock whose lazily instantiated node's builder function builds its construction without reading its override, fails seed 8. The one that shows the erased kind fires, a mock whose erased node builds its construction without reading its override, fails seed 0. The one that shows the `Sendable` instantiator kind fires, a mock whose `Sendable` instantiator's builder function builds its construction without reading its override, fails seed 41. The one that shows the only-if-available kind fires, a mock that binds its override of a value received only if available to `nil`, fails seed 14. Not judged: an `Instantiator`'s or `ErasedInstantiator`'s field, and a `Sendable` instantiator's the mocked type does not store or whose type forwards values; a lazily instantiated dependency the mocked type holds neither as the wrapper nor as its instance, whose instance the mock creates only where the value reads it and production's record would create anyway (seed 691); a nested configuration's field, so neither a constant built inside a `@Sendable` builder function beneath the mocked type's own nodes; an erased lazily instantiated dependency's field; a promoted dependency a mirror declares without `fulfilledByType:` that its mock's tree receives as a protocol, whose builder field returns the protocol; a root's `onlyIfAvailable` override, an override named apart from its label, and a mock's `onlyIfAvailable` overrides after its first; a flat parameter; and, where nothing the comparator traverses holds the instance, which node the override reached, since the record is then described in full on both sides.
