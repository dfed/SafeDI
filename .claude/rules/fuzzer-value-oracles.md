# Graph fuzzer: value oracles

- **Base corpus value oracle.** Every base corpus graph the tool accepts runs again as its value-oracle fixture (`GraphFuzzerValueOraclePlan`, `Tests/SafeDIToolTestSupport/GraphFuzzerMockMirrors.swift`): the graph with `generateMock: true` on every root and a mirror root, `S<seed>_ZMirror<k>`, in a file of its own, for each mocked type whose generated `mock()` takes no required parameter, or only required parameters the harness has a sample of. A mirror declares what the mock builds beside the mocked type – the type's own children and aliases in its declaration order, an own property its tree receives lazily rebuilt as that wrapper, then the dependencies the mock promotes, in the order its tree first receives them – and builds the mocked type from them by hand (`differentialMirrorValue`; an actor through a `nonisolated(unsafe)` local per argument, `GraphFuzzerMockMirror.argumentBindings`, since the mirror's values are in its initializer's region, which Swift 6 does not let it send to the actor, where production builds each argument in a function of its own), passing a wrapper's `.instance`, the non-optional declaration to an optional receive, and `nil` for an alias or a receive only if available that it does not declare. It copies the mocked type's aliases, but writes an alias of the optional form of a property the mock promotes and builds non-optional with the non-optional type (`ofType: X.self`), since the mirror declares that property itself and production reads a rename of a type's own property as a rename of exactly that property; the mock hands such an alias the non-optional value it binds. A model in the harness (`GraphFuzzerMockMirrorModel`) decides only which siblings exist and their base order, by the rules of `createMockRootScopeGenerator` and `inOrderTheMockTreeFirstReceives`; the production generator decides what each receiver is handed. A mock's required parameters – values the mocked type forwards, and dependencies its tree receives that the mock cannot build – are each handed a sample value (`GraphFuzzerSampleValues`), and its mirror forwards them (`@Forwarded`, before its other declarations), is no root, and is built by a root of its own, `S<seed>_ZMirror<k>Host`, through an instantiator called with a sample of the mirror's `ForwardedProperties`; a mock with a required parameter that is neither a value the mocked type forwards nor a dependency its tree receives by that label and type and the mocked type does not instantiate (an unbuildable instance the mocked type or its tree instantiates, the instance of a lazily instantiated receive, a parameter named apart from another of its label) is skipped as `requiredParameter`, as is one whose parameter has no sample. A sample is built by hand from the fixture's declarations – `nil` for an optional, a fixed value of a standard type, an empty collection, a closure that does nothing, a plain type's `init()`, an erasing type around a sample, a graph type through its initializer with a sample of each property, the type that fulfills a protocol for the protocol – and each class instance it is marked, so the describer shows it as `<4> T (sample)` without what it holds; a builder a sample holds is never called (`differentialValueUnreachableSample()`), except a forwarded `LazilyInstantiated`'s, whose instance generated code reads. The value graph also registers the sample of each type's `ForwardedProperties` that has one (`DifferentialValueGraph.samples`), so the describer calls each instantiator of a type that forwards values, in a root's tree or a mock's, with a fresh sample. A type has no sample when it or a property it takes by value is an existential no type of the graph fulfills, a type another module or package hides, or a type that takes itself by value; a graph split across modules gets none. The comparator compares, in one path (a graph of probe pairs, one compile and one link per batch), each root's `mock()` with `Root()` – a root receives nothing, so its mock builds its production tree – and each mirrored `mock()` with its mirror's `differentialMirrorValue`, never the mirror itself, with no exemption: a difference is `mockBuildsOtherValuesThanProduction`. Before the tool runs again, and before any mirror is skipped, since every skip reads the model, the model is cross-checked against every mocked type's generated `SafeDIOverrides` – what it builds beside the mocked type, as a multiset of concrete type names (`AnyT<n>` read as `T<n>`, as every erasure of the corpus erases), and how many `onlyIfAvailable` overrides it takes – and a disagreement is `mirrorModelDisagreesWithMock`, so a change to what `createMockRootScopeGenerator` promotes or to `inOrderTheMockTreeFirstReceives` changes the model in the same pull request; a model left behind on the promoted set or the override count fails at once, while one left behind on the base order, which the cross-check cannot read from generated code, shows only where the order decides a value (promoted siblings that receive each other only if available) or where production rejects the mirror. The tool's rejection of the fixture is `valueOracleFixtureRejected` (an error naming a mirror is judged against the model first; one naming a root or a drawn type is a finding), a fixture that does not compile or run is `valueOracleFixtureDoesNotCompile`, and a root's `mock()` taking any parameter but its overrides is `rootMockTakesParameter`. The oracle judges the corpus's mocks: each drawn type's `<T>+SafeDIMock.swift` must equal the corpus run's (`valueOracleFixtureChangesDrawnMocks`), but for its blocks that declare a type's configuration, which a root mock can need where no drawn mock did, and for a default-valued configuration field read through its `@Sendable` autoclosure, which a root mock that builds the type inside a `Sendable` builder makes of every read, and for the `Sendable` conformance of an overrides' storage that holds such a configuration (`GraphFuzzerMockOverrides.comparableWithAnotherRunsMocks`), and the drawn mock files that match only after that normalization are counted and pinned, so that the allowance stays visible when a generator change widens it; and each mirror's name must sort after every type name of the graph, so that `computeCycleEdges`, which walks types alphabetically, adds no back-edge. The tool runs the fixture as drawn and the comparator compiles it drawn storing every parameter, which changes nothing the tool generates; the fixture only feeds the oracle, so it is never renamed or run twice (the drawn graph already pins determinism and rename invariance). A mirror is skipped, by a counted reason (`GraphFuzzerMirrorSkip`), where the mock takes a required parameter the harness has no sample of, or where by a mock rule the Manual and this file state no production scope builds the mock root's tree as the mock does: two forms of one label in the mock root's scope; a required receive or required alias of an optional form whose closest declaration is the non-optional form, the mocked type's own aliases included, which production does not fulfill with it; and a required receive of an `onlyIfAvailable` alias production does not create, which a mock creates from the override it binds for the alias's fulfilling property. A receive whose closest declaration of its label has another type is no reason to skip: production passes `nil` for one received only if available, as the mock's override of its own type does, and a mirror production rejects is a finding. A seed whose known issue has a `valueOracleFixtureDoesNotCompile` signature is compared on its own, outside the value batch (`Corpus.isolatedValueGraphSeeds`), so that its known failure does not make the batch compile each graph again on its own. The long run reports per shard, and the combine job adds up and checks against `corpusValueOracleCounts`, the compared root pairs and mirrored pairs, each as a count and a set sum over `<seed>:<type>`, the skips by reason, the compared pairs that show each `GraphFuzzerValueOracleShape` (read from the model for mirrored pairs and from the root's tree for root pairs), and the drawn mock files R6's normalization alone makes match; the inspected graphs are `corpusValueOracleInspectedGraphCount`, every graph the tool accepts. The smoke batch must compare a root pair and a mirrored pair and show every shape. What it does not see, beyond the comparator's limits: an override passed to a mock, but for the override oracle's (`fuzzer-override-oracle.md`), a mock with a required parameter or the tree behind an instantiator with forwarded properties where a forwarded value has no sample, what a sample holds, a hand-written mock (production has none to compare with), what production and a mock share – sibling order, availability, alias creation – which a regression changes in both alike, and a change to the promoted set made in the generator and in `GraphFuzzerMockMirrorModel` together, which the cross-check and the mirror then both follow, so that the kept unit tests alone judge it (a transitive `onlyIfAvailable` receive left to an override is pinned by the model and by the direct form's kept tests).
- **Override oracle.** The value-oracle graph's override pairs, which pass a mock an override and compare what it builds with production, are in `fuzzer-override-oracle.md`.
- **Mock vocabulary.** The last base pass, with its own generator (`addingMockVocabulary`, `mockVocabularyRandom`, base corpus only, so every other draw of a graph is drawn as before), draws what apps write mocks with, each part independently: a `#SafeDIConfiguration` in `Root0`'s file listing a type without `generateMock: true` in `additionalMocksToGenerate` (a quarter of graphs); a member mock under `#if DEBUG` that takes every parameter of the initializer, with the same defaults, and passes each on, on a type another type instantiates (four graphs in ten), named `mock`, or `customMock` through `customMockName` on a type whose mock is generated, and the same on a second mocked type (three in ten); and `Service` (four in ten), a leaf `final class` or `struct` every root instantiates and one to three types receive, required or only if available, with a `mockOnly` extension under `#if DEBUG` before or after its production declaration, whose `mock()` builds it as production does, or whose `preview()` `customMockName` names when `Service` has `generateMock: true`. A listed type gets no member mock: the macro accepts `customMockName` only beside `generateMock: true` or `mockOnly: true`, and the tool rejects a `mock` on a listed type. Its features are `handWrittenMockUnderMockCondition`, `customMockNameBesideGeneratedMock`, `mockOnlyExtensionOfReceivedType`, `instantiableStruct` and `additionalMockToGenerate`. Every hand-written mock builds what production builds, so the value oracle sees the values a mock builds but cannot tell whether it built them with the hand-written mock or the initializer. A textual oracle sees that instead: no generated mock file of a base corpus graph may call the initializer, `T(` or `T.init`, of a type that has a hand-written mock, a static `mock` or `customMockName` method returning it (`GraphFuzzerToolRuns.handWrittenMockBypassFailure`, `generatedMockBypassesHandWrittenMock`). The mirror model counts a listed type as mocked, keeps a `mockOnly` declaration of a type that has a production declaration as only that type's mock, whichever it reads first, and a mirror builds a mocked type with the hand-written mock its `mock()` calls through to (`GraphFuzzerMockMirrorModel.HandWrittenMock`), passing what that mock takes. The model reads no `struct` (`GraphFuzzerSourceLine` reads `final class` and `extension`; reading `struct` would change the other corpora's models), so a mocked `struct` `Service` is not mirrored. A mocked type that forwards a value whose parameter defaults to its type's hand-written mock ("Flat parameters default to the mock the tree would build") is skipped as `requiredParameter`, since the mock is handed no sample of it and no production declaration builds it for the mirror.
- **Differential value comparator.** `DifferentialValueOracle` (`Tests/SafeDIToolTestSupport/DifferentialValueComparator.swift`) judges two paths that build one graph, a feature's and one known to be right, by the values they build, which a differential that compares acceptance alone and a full `==` pin of generated code both pass: `nil` for a declared value, a second instance where one was shared, an initializer's default where the mock's was due, an ignored field, an `Instantiator` that hands out one instance or captures one built outside its builder. Each path (`DifferentialValuePath`: modules in dependency order, each with its fixture files and generated files) is compiled with `-enable-testing` against the SafeDI runtime and the describer module, which the comparator compiles once per process (once per release for a path whose `runtimeSource` names another release's runtime sources and macros, as release acceptance's older side does, through the actor `ReleaseRuntimes`; graphs of other runtimes never share a batch), and linked into an executable of its own whose `main.swift` `@testable import`s every module and writes, with `write(2)` rather than through Glibc's `stdout`, which Swift 6 rejects as a mutable global, a canonical description of each probe (`DifferentialValueProbe`, a Swift expression such as `Root()` or `Feature.mock()`, with another for the known-right path where the two take one value through different declarations, such as a public mock's parameter and an inline mock's override): stored properties in declaration order, a superclass's first; class instances numbered by first visit within the probe (`<2> A`, then `<2> A (seen)`), with `(seen in probe …)` on an instance an earlier probe of the same graph held; leaves by dynamic type and `String(reflecting:)`, except an `AnyHashable`, described as the value it wraps, `Data`, by its bytes, and a pointer or `ObjectIdentifier`, as `(address)`; the values of a set or dictionary in the order of their own descriptions; types without a leading qualifier that names one of the path's modules or the `(extension in <module>):` of one, and with `(private)` where the runtime prints an address. An `Instantiator` with no forwarded properties is called twice (`instantiate()`, `instantiate() again`), each instantiator once beneath a second call, and one with forwarded properties likewise with a fresh sample each call when the graph registers a sample of its `ForwardedProperties` (`instantiate(sample)`; `DifferentialValueSample`, which only the base corpus's value oracle registers), a class instance a sample expression marks with `differentialValueSample(_:)` being described as `<4> T (sample)`, without what it holds; a `LazilyInstantiated` or `SendableLazilyInstantiated` is SafeDI's storage, whose value is its instance, so it is compared by its instance: it takes no identity and never says `(seen)`, and each meeting of it takes a number of its own and reads its instance after the rest of the probe, under the calls on the path where it was met, which the instance's identity numbers, `(seen)` on later meetings, so another wrapper around the same instance agrees with a shared one, and two wrappers around two instances where the other path shares one differ at the second instance (`DifferentialValueComparatorTests`' `compare_acceptsTwoLazyWrappersAroundOneInstance…` and `compare_rejectsTheSecondInstance…`); a wrapper's state is the one its first meeting in the probe found. Where the probe's value is a class that stores a creation stamp, that instance's line says `(built before the probe's value)` when it is a class instance stamped before the probe's value that the value does not hold through stored properties, which catches an instance a wrapper's closure captures, built up front, and an early read of either wrapper kind, wherever the description first showed the instance (the probe's own instantiator calls can read it first). Generated code stamps the probe's value after everything it builds for it, and the describer builds everything after the value. Otherwise, a `LazilyInstantiated`'s line says `already instantiated` when its instance was read before the describer met it (read from `Mirror`; a `SendableLazilyInstantiated`'s `Mutex` hides its state). Stamps follow `DifferentialValueCreationStamp`, the one contract fixtures follow: one counter per path, and every class storing `let differentialValueCreationStamp = <Counter>.next()`, which the describer never prints. Only the lazily built class instance itself is judged, never its dependencies or what a non-class lazy value holds: a mock builds the dependencies its tree receives up front and hands them to lazily built instances (`let x = X(); LazilyInstantiated { B(x: x) }`), so judging those would mark correct paths. Two lines that differ only by these marks still pair, so one early build is one difference at one line, and what lies beneath it and later references are compared; a wrapper whose owner type and property are on the path twice already is not traversed, so a cycle is unrolled once and its closing builder called. A probe traverses at most `DifferentialValueLimits.traversalsPerProbe` wrappers, so a description cannot grow exponentially with the builders each type holds, and the describer sets an alarm per probe, so a probe that runs past `probeTimeLimitInSeconds` fails its path, never hangs the test. A batch keeps the default, 10,000 traversals and 60 seconds, so a probe that runs away stays cheap. A fuzzer seed whose probes need more is listed by name (`Corpus.seedsTraversingPastTheBatchBudget`: seam corpus seed 391, 130,726 traversals), and its value graphs are compared on their own with `DifferentialValueLimits.isolatedFuzzerGraph`, 200,000 traversals and 300 seconds, so the rest of the corpus keeps the batch's budget and speed; the seed still gets every comparison, where a known issue would stop judging it. Stated limits: an `ErasedInstantiator`, or an instantiator with forwarded properties of which the graph registers no sample, is not traversed; a closure is described as `(Function)`, so closures compare only as present or `nil`; a set, or a dictionary whose keys or values hold class instances, is described as `(not compared: set of 3 class instances)` and compared by kind and count only, since which of several alike instances is described first would follow hash order; an instance an earlier probe held is identified by that probe alone; any other leaf whose debug description holds an address or a hash-ordered collection is not canonical; how often and in what order instances were built is not seen, so an instance built and discarded, or a reordering, passes; a lazily built instance's dependency built up front passes, as does an instance built early inside an instantiator the probe calls (stamped after the probe's value); and a fixture without stamps (a hand-written one that does not follow the contract), or a probe whose value is not a stamped class (a struct), gets no stamp marks, so there an instance a wrapper's closure captures, built up front, and a `SendableLazilyInstantiated` read early pass too, unless something else holds the instance, whose identity then shows it. `compare` reports every node whose line differs and nothing beneath it, pairing the identities the two paths number at the same node, so an added or missing instance renumbers nothing after it; an exemption is a `DifferentialValueDifference`, passed to `compare`, a `DifferentialValueGraph`, or `expectDifferentialValuesAgree`, and removes exactly the differences equal to it, each with everything beneath its node, such as the contents of a second instance. A compared node where a probe spent its traversals, on either path, fails the graph with a `DifferentialValueOracleError` (nothing beneath it is described), unless an exemption equal to that node's two lines accepts it; one beneath a difference is part of that difference. The comparator sees only stored properties, so a fixture it can judge stores every dependency and every default-valued parameter (what a closure determines, not the closure), and an extension's `instantiate(…)` passes its parameters to the type it returns, which stores them, and each class stores a creation stamp; `GraphFuzzerGenerator.fixture(forSeed:storingEveryParameter: true)` gives a fuzzer graph that shape (the counter at the end of its first file), and must compile wherever the default does, which is what the corpus and its pins are of. A feature wires it in by batch, not one compile per seed: for each accepted seed, a `DifferentialValueGraph` of its feature and known-right paths (`DifferentialValuePath(fixture:generatedFiles:)`) and `fixture.differentialValueProbes(generatedFiles:)` (each root, each generated mock without a required parameter, and each root's `spellSeamBuilder`, `spellHostBuilder` and `aliasSeamBuilder`, which only the seam corpus draws, called with a sample value), compared together by `DifferentialValueOracle.compare(graphs:filesToDelete:)`, which compiles the graphs of one layout into one executable per path, describes each graph's probes as on their own (numbering and every `(seen …)` mark start afresh at each graph), and, when a batch fails to compile or run, compares each of its graphs on its own; each graph's differences or `DifferentialValueOracleError` become a `GraphFuzzerFailure` of a `Kind` the feature adds. A graph may instead hold both ways in one path (`DifferentialValueGraph(name:path:probePairs:)`, each `DifferentialValueProbePair` a feature expression and a known-right expression described under one name): its batch compiles that path once and links one executable, which describes each pair's two expressions one after the other, and paired graphs batch only with paired graphs; the base corpus's value oracle (below) compares such graphs. Beside a full `==` pin, a unit test calls `expectDifferentialValuesAgree`. Both skip under `SAFEDI_SKIP_COMPILE_CHECK`. A graph that `judgesRetention` also has each probe's describer run the retention experiments `fuzzer-seam-oracles.md` describes, whose lines the comparator reads apart from the description (`DescribedProbe.retentionLines`) into `DifferentialValueComparison.retentionJudgments`, one per probe (`DifferentialValueRetention.Judgment`): each type the feature path keeps more instances of alive than the known-right path in an experiment both paths ran, how many experiments holding a wrapper both ran, and how many only one ran.
- **Reported issues' shapes.** A roll after the mock vocabulary, on a stream of its own (`repeatedAncestorRandom`, base corpus only, one graph in twenty-five), draws the shape of a reported generator defect, so that its fix stays gated: `addingRepeatedAncestorShapes` (#720) builds `RepeatBadge` only beneath `RepeatFlow`'s instantiator of `RepeatScreen`, an ancestor it repeats, under a hand-written `mockOnly` mock of `RepeatScreen` that omits it three times in four, so the mock compiles only when `RepeatBadge`'s configuration is generated from a node beneath the repeated ancestor, and `RepeatBadge` builds `RepeatBadgeDetail`, which builds `RepeatBadgePart`, so it compiles only when the configuration `RepeatBadge`'s nests is generated too. Its mask keeps it off every smoke seed. `RepeatScreen` and `RepeatFlow`, a two-type lazy cycle, show the lazy cycle's configuration-field shape under a renaming (`repeatedAncestorLazyCycleSeeds`), each seed combined with its other shapes in `knownIssues` (`addingReportedIssueShapes`); the seam corpus inherits `knownIssuesBesideReportedIssueShapes`, since it does not draw the roll.
- **A type built twice with differing pins.** The base corpus's last pass, on a stream of its own (`differingPinsRandom`, one graph in twenty-five, 199 of 5000; `SafeDIToolGraphFuzzerDifferingPinsTests` pins each shape), draws `addingTypeBuiltTwiceWithDifferingPins`: `PinScreen`'s mock builds `PinLeaf`, which receives `pinToken: PinToken?` only if available or aliases it so, in two places. In `PinSource`'s tree a required `pinToken: Instantiator<PinToken>` above it (on `PinSource` or `PinHolder`, optionally through `PinMaker`'s instantiator) pins the declaration, so production passes it `nil`; in `PinScreen`'s own tree or `PinOther`'s, `PinReader` requires `pinToken: PinToken` beside it. The mock binds both forms (`twoFormsOfOneLabel`), so the plan adds `pinnedPlacePair`: `PinScreen.mock()` against `ZPinRoot().pinHost.pinMiddle.pinScreen`, a root only the value-oracle fixture declares, since a root's mock rejects `PinHost`'s tree by design and the oracle mocks every root of the graph. `corpusValueOracleCounts.pinnedPlacePairCount` pins the compared pairs, floored at ten.
- **A type built again through a second lazy cycle.** The base corpus's last pass, on a stream of its own (`nestedCycleRandom`, 179 of 5000; `SafeDIToolGraphFuzzerNestedCycleTests` pins each shape), draws `addingTypeBuiltAgainThroughSecondLazyCycle`: `NestRoot` builds `NestOuter`, which builds `NestInner` and `NestReader`, which receives `nestLabel`; `NestInner` builds `NestOuter` again and `NestRedeclarer`, which declares its own `nestLabel` and builds `NestInner` again (through `NestThird`, a third cycle, one graph in three; received only if available one in four). A mock and production pass the label by one rule, so the plan adds `nestedCyclePair`: `NestRoot()` against `ZNestMirror.build()`, the tree built by hand to the Manual's nearest-declaration rule, which only the value-oracle fixture declares. `corpusValueOracleCounts.nestedCyclePairCount` pins the compared pairs, floored at ten.
- **One label received as both wrapper kinds.** After it, on a stream of its own (`wrapperKindsRandom`, base corpus only, about one mixed graph in six), `addingLabelReceivedAsBothWrapperKinds` draws `WrapKindsHost`'s mock, whose tree receives `wrapKindsToken` as a `LazilyInstantiated` (`WrapKindsPinner`, required) and as a `SendableLazilyInstantiated` (`WrapKindsLeaf`), beside `WrapKindsSource`, which receives it by value. Where the leaf requires its wrapper, the mock root promotes a wrapper of each kind and must declare both before the by-value receiver (`lazilyInstantiatedSiblingIndicesByInstanceProperty`, `lazily-instantiated.md`); no root reaches the tree and the mirror would hold two forms of one label, so the compile is the oracle: with each by-value receive waiting on one wrapper sibling, seeds 78 and 317 crash Swift 6.2.4 compiling the mock. Where the leaf receives its wrapper only if available, the pinner's required wrapper provides the instance the source reads, so the mock promotes no wrapper of the leaf's kind (`mock-root-promotion.md`), and passes the leaf `nil` where the pinner, building the source, pins it, or offers it an override beside a pinner that does not; the mirror model's count of what the mock builds and of its overrides is the oracle.
