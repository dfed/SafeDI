# Graph fuzzer: value oracles

- **Base corpus value oracle.** Every base corpus graph the tool accepts runs again as its value-oracle fixture (`GraphFuzzerValueOraclePlan`, `Tests/SafeDIToolTestSupport/GraphFuzzerMockMirrors.swift`): the graph with `generateMock: true` on every root and a mirror root, `S<seed>_ZMirror<k>`, in a file of its own, for each mocked type whose generated `mock()` takes no required parameter. A mirror declares what the mock builds beside the mocked type – the type's own children and aliases in its declaration order, an own property its tree receives lazily rebuilt as that wrapper, then the dependencies the mock promotes, in the order its tree first receives them – and builds the mocked type from them by hand (`differentialMirrorValue`), passing a wrapper's `.instance`, the non-optional declaration to an optional receive, and `nil` for an alias or a receive only if available that it does not declare. It copies the mocked type's aliases, but writes an alias of the optional form of a property the mock promotes and builds non-optional with the non-optional type (`ofType: X.self`), since the mirror declares that property itself and production reads a rename of a type's own property as a rename of exactly that property; the mock hands such an alias the non-optional value it binds. A model in the harness (`GraphFuzzerMockMirrorModel`) decides only which siblings exist and their base order, by the rules of `createMockRootScopeGenerator` and `inOrderTheMockTreeFirstReceives`; the production generator decides what each receiver is handed. The comparator compares, in one path (a graph of probe pairs, one compile and one link per batch), each root's `mock()` with `Root()` – a root receives nothing, so its mock builds its production tree – and each mirrored `mock()` with its mirror's `differentialMirrorValue`, never the mirror itself, with no exemption: a difference is `mockBuildsOtherValuesThanProduction`. Before the tool runs again, and before any mirror is skipped, since every skip reads the model, the model is cross-checked against every mocked type's generated `SafeDIOverrides` – what it builds beside the mocked type, as a multiset of concrete type names (`AnyT<n>` read as `T<n>`, as every erasure of the corpus erases), and how many `onlyIfAvailable` overrides it takes – and a disagreement is `mirrorModelDisagreesWithMock`, so a change to what `createMockRootScopeGenerator` promotes or to `inOrderTheMockTreeFirstReceives` changes the model in the same pull request; a model left behind on the promoted set or the override count fails at once, while one left behind on the base order, which the cross-check cannot read from generated code, shows only where the order decides a value (promoted siblings that receive each other only if available) or where production rejects the mirror. The tool's rejection of the fixture is `valueOracleFixtureRejected` (an error naming a mirror is judged against the model first; one naming a root or a drawn type is a finding), a fixture that does not compile or run is `valueOracleFixtureDoesNotCompile`, and a root's `mock()` taking any parameter but its overrides is `rootMockTakesParameter`. The oracle judges the corpus's mocks: each drawn type's `<T>+SafeDIMock.swift` must equal the corpus run's (`valueOracleFixtureChangesDrawnMocks`), but for its blocks that declare a type's configuration, which a root mock can need where no drawn mock did, and for a default-valued configuration field read through its `@Sendable` autoclosure, which a root mock that builds the type inside a `Sendable` builder makes of every read (`GraphFuzzerMockOverrides.comparableWithAnotherRunsMocks`), and the drawn mock files that match only after that normalization are counted and pinned, so that the allowance stays visible when a generator change widens it; and each mirror's name must sort after every type name of the graph, so that `computeCycleEdges`, which walks types alphabetically, adds no back-edge. The tool runs the fixture as drawn and the comparator compiles it drawn storing every parameter, which changes nothing the tool generates; the fixture only feeds the oracle, so it is never renamed or run twice (the drawn graph already pins determinism and rename invariance). A mirror is skipped, by a counted reason (`GraphFuzzerMirrorSkip`), where the mock takes a required parameter, or where by a mock rule the Manual and this file state no production scope builds the mock root's tree as the mock does: two forms of one label in the mock root's scope; a required receive or required alias of an optional form whose closest declaration is the non-optional form, the mocked type's own aliases included, which production does not fulfill with it; and a required receive of an `onlyIfAvailable` alias production does not create, which a mock creates from the override it binds for the alias's fulfilling property. A receive whose closest declaration of its label has another type is no reason to skip: production passes `nil` for one received only if available, as the mock's override of its own type does, and a mirror production rejects is a finding. A seed whose known issue has a `valueOracleFixtureDoesNotCompile` signature is compared on its own, outside the value batch (`Corpus.isolatedValueOracleSeeds`), so that its known failure does not make the batch compile each graph again on its own. The long run reports per shard, and the combine job adds up and checks against `corpusValueOracleCounts`, the compared root pairs and mirrored pairs, each as a count and a set sum over `<seed>:<type>`, the skips by reason, the compared pairs that show each `GraphFuzzerValueOracleShape` (read from the model for mirrored pairs and from the root's tree for root pairs), and the drawn mock files R6's normalization alone makes match; the inspected graphs are `corpusValueOracleInspectedGraphCount`, every graph the tool accepts. The smoke batch must compare a root pair and a mirrored pair and show every shape. What it does not see, beyond the comparator's limits: an override passed to a mock, a mock with a required parameter, the tree behind an instantiator with forwarded properties, a hand-written mock (production has none to compare with), what production and a mock share – sibling order, availability, alias creation – which a regression changes in both alike, and a change to the promoted set made in the generator and in `GraphFuzzerMockMirrorModel` together, which the cross-check and the mirror then both follow, so that the kept unit tests alone judge it (a transitive `onlyIfAvailable` receive left to an override is pinned by the model and by the direct form's kept tests).
- **Differential value comparator.** `DifferentialValueOracle` (`Tests/SafeDIToolTestSupport/DifferentialValueComparator.swift`) judges two paths that build one graph, a feature's and one known to be right, by the values they build, which a differential that compares acceptance alone and a full `==` pin of generated code both pass: `nil` for a declared value, a second instance where one was shared, an initializer's default where the mock's was due, an ignored field, an `Instantiator` that hands out one instance or captures one built outside its builder. Each path (`DifferentialValuePath`: modules in dependency order, each with its fixture files and generated files) is compiled with `-enable-testing` against the SafeDI runtime and the describer module, which the comparator compiles once per process, and linked into an executable of its own whose `main.swift` `@testable import`s every module and writes, with `write(2)` rather than through Glibc's `stdout`, which Swift 6 rejects as a mutable global, a canonical description of each probe (`DifferentialValueProbe`, a Swift expression such as `Root()` or `Feature.mock()`, with another for the known-right path where the two take one value through different declarations, such as a public mock's parameter and an inline mock's override): stored properties in declaration order, a superclass's first; class instances numbered by first visit within the probe (`<2> A`, then `<2> A (seen)`), with `(seen in probe …)` on an instance an earlier probe of the same graph held; leaves by dynamic type and `String(reflecting:)`, except an `AnyHashable`, described as the value it wraps, `Data`, by its bytes, and a pointer or `ObjectIdentifier`, as `(address)`; the values of a set or dictionary in the order of their own descriptions; types without a leading qualifier that names one of the path's modules or the `(extension in <module>):` of one, and with `(private)` where the runtime prints an address. An `Instantiator` with no forwarded properties is called twice (`instantiate()`, `instantiate() again`), each instantiator once beneath a second call; a `LazilyInstantiated`'s instance is read after the rest of the probe, under the calls on the path where its wrapper was met. Where the probe's value is a class that stores a creation stamp, that instance's line says `(built before the probe's value)` when it is a class instance stamped before the probe's value that the value does not hold through stored properties, which catches an instance a wrapper's closure captures, built up front, and an early read of either wrapper kind, wherever the description first showed the instance (the probe's own instantiator calls can read it first). Generated code stamps the probe's value after everything it builds for it, and the describer builds everything after the value. Otherwise, a `LazilyInstantiated`'s line says `already instantiated` when its instance was read before the describer met it (read from `Mirror`; a `SendableLazilyInstantiated`'s `Mutex` hides its state). Stamps follow `DifferentialValueCreationStamp`, the one contract fixtures follow: one counter per path, and every class storing `let differentialValueCreationStamp = <Counter>.next()`, which the describer never prints. Only the lazily built class instance itself is judged, never its dependencies or what a non-class lazy value holds: a mock builds the dependencies its tree receives up front and hands them to lazily built instances (`let x = X(); LazilyInstantiated { B(x: x) }`), so judging those would mark correct paths. Two lines that differ only by these marks still pair, so one early build is one difference at one line, and what lies beneath it and later references are compared; a wrapper whose owner type and property are on the path twice already is not traversed, so a cycle is unrolled once and its closing builder called. A probe traverses at most `DifferentialValueLimits.traversalsPerProbe` wrappers, so a description cannot grow exponentially with the builders each type holds, and the describer sets an alarm per probe, so a probe that runs past `probeTimeLimitInSeconds` fails its path, never hangs the test. Stated limits: an `ErasedInstantiator`, or an instantiator with forwarded properties, is not traversed; a closure is described as `(Function)`, so closures compare only as present or `nil`; a set, or a dictionary whose keys or values hold class instances, is described as `(not compared: set of 3 class instances)` and compared by kind and count only, since which of several alike instances is described first would follow hash order; an instance an earlier probe held is identified by that probe alone; any other leaf whose debug description holds an address or a hash-ordered collection is not canonical; how often and in what order instances were built is not seen, so an instance built and discarded, or a reordering, passes; a lazily built instance's dependency built up front passes, as does an instance built early inside an instantiator the probe calls (stamped after the probe's value); and a fixture without stamps (a hand-written one that does not follow the contract), or a probe whose value is not a stamped class (a struct), gets no stamp marks, so there an instance a wrapper's closure captures, built up front, and a `SendableLazilyInstantiated` read early pass too, unless something else holds the instance, whose identity then shows it. `compare` reports every node whose line differs and nothing beneath it, pairing the identities the two paths number at the same node, so an added or missing instance renumbers nothing after it; an exemption is a `DifferentialValueDifference`, passed to `compare`, a `DifferentialValueGraph`, or `expectDifferentialValuesAgree`, and removes exactly the differences equal to it, each with everything beneath its node, such as the contents of a second instance. A compared node where a probe spent its traversals, on either path, fails the graph with a `DifferentialValueOracleError` (nothing beneath it is described), unless an exemption equal to that node's two lines accepts it; one beneath a difference is part of that difference. The comparator sees only stored properties, so a fixture it can judge stores every dependency and every default-valued parameter (what a closure determines, not the closure), and an extension's `instantiate(…)` passes its parameters to the type it returns, which stores them, and each class stores a creation stamp; `GraphFuzzerGenerator.fixture(forSeed:storingEveryParameter: true)` gives a fuzzer graph that shape (the counter at the end of its first file), and must compile wherever the default does, which is what the corpus and its pins are of. A feature wires it in by batch, not one compile per seed: for each accepted seed, a `DifferentialValueGraph` of its feature and known-right paths (`DifferentialValuePath(fixture:generatedFiles:)`) and `fixture.differentialValueProbes(generatedFiles:)` (each root, each generated mock without a required parameter, and each root's `spellSeamBuilder`, `spellHostBuilder` and `aliasSeamBuilder`, which only the seam corpus draws, called with a sample value), compared together by `DifferentialValueOracle.compare(graphs:filesToDelete:)`, which compiles the graphs of one layout into one executable per path, describes each graph's probes as on their own (numbering and every `(seen …)` mark start afresh at each graph), and, when a batch fails to compile or run, compares each of its graphs on its own; each graph's differences or `DifferentialValueOracleError` become a `GraphFuzzerFailure` of a `Kind` the feature adds. A graph may instead hold both ways in one path (`DifferentialValueGraph(name:path:probePairs:)`, each `DifferentialValueProbePair` a feature expression and a known-right expression described under one name): its batch compiles that path once and links one executable, which describes each pair's two expressions one after the other, and paired graphs batch only with paired graphs; the base corpus's value oracle (below) compares such graphs. Beside a full `==` pin, a unit test calls `expectDifferentialValuesAgree`. Both skip under `SAFEDI_SKIP_COMPILE_CHECK`.
