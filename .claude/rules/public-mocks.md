# Public mocks

- **Public mocks (`generateMock: .public`).** `Instantiable.generateMock` is a `MockGeneration` (`.none`, `.internal`, `.public`; the macro reads a boolean literal as `.internal` or `.none`), with the argument's range in `mockGenerationArgumentRange`, where every public mock diagnostic points. The declaring module generates one through the internal mock's path, branched where they differ (`generateMockRootCode`'s `publicMock`, `generateMockBodyBindings`' `PublicMockEmission`), so an internal mock's output is byte-identical with no public mock in the module; the public parts live in `PublicMockGeneration.swift`. A parameter's and a member's access is `TypeAccessProof`'s, read through one `PublicMockContext` per module with the mocked type's module and each label's receivers' modules admitted. Whether a public mock can be generated (a narrower enclosing type, or a narrower declaration of the type an enclosing extension extends, read from `extendedTypeAccessNeeds` as constructions read it; a narrower type itself, which the macro rejects, reported plainly at the declaration; a required parameter no `public` tier can take) is decided for one root by `ScopeGenerator.publicMockFindings`, which `generateMockCode` and the query both run. A configured type in a public mock's tree is built by a construction function in its own extension (`__safeDI_init`/`__safeDI_mock`), which mirrors `Initializer.spelledIsolation`, from one module-level configuration per type shared by the module's public mocks; never nest a public configuration in the configured type's extension, where two modules that declare one make its name ambiguous. The module-level configuration is named `__safeDI_<Module>_<Type>_MockConfiguration`, or `__safeDI_<Type>_MockConfiguration` when the build names no module, with the type spelled by `asIdentifier`. A public mock also declares an empty `public enum __safeDI_<Type>_mock_<hash>` whose hash is FNV-1a over its signature (`guardTypeName`); every generated call names it, so a call generated against an out-of-date signature fails to compile at the call. The Manual says only that much and never names either type. A consumer in another module calls the public mock of a type it cannot build inline (`publicMockCalls(in:)`: the type's mock tree has an inaccessible construction, other modules' `.public` types in it left out), through a leaf scope (`Scope.publicMockCall`, `publicMockLeafInstantiable`) that declares the mock's whole signature, which the consumer computes as the declaring module did, with a `DependencyTreeGenerator` over that module's visible declarations (`SeamResolution.foreignPublicMocks`, `publicMockPlan(ofOwnType:)`): the reached tier's received parameters as receives (`T? = nil` ones only if available) and the parameters it omits, and a public mock's no-tier parameters, as receives only if available, which order the leaf and reach the trees that call it as inline receivers would. Only-if-available receives only leaves make are never mock parameters or overrides (`receivedOnlyByPublicMockCalls`; a leaf passes them where the tree provides them, as production would, `NearestDeclarations.binding(of:)`), except on a `.public` consumer, which takes those a call passes as its own `T? = nil` parameters (`passedByPublicMockCalls`), a call inside a fill included: `collectReceivedProperties` walks a leaf's fills after its children and keeps what their calls pass that the fill's fields do not provide (`ScopeGenerator.fieldForms(of:)`, which the fill's generator declares), so the mock binds every parameter the generator surfaces, and `inOrderTheMockTreeFirstReceives` walks the fills it met last, so a dependency built when passed `nil` that only a call inside a fill receives is promoted and ordered. `publicMockTierOmissions` (modeled on `seamTierOmissions`), the mock-condition agreement and the by-name check run over every mock root before any code is generated; both walk each call's fills too, each with the `propertiesGeneratedLater` `prepareFillCode(propertiesGeneratedLater:)` generates it with, a fill's fields hiding the caller's declarations of their labels: a call a fill makes is reported under its mock condition at the dependency that leads to the call the fill is passed to, and a value a fill's field provides is located there too, as the called mock's; `noTierParameters` walks the calls in a node's fills (`publicMockCallsInFills(of:)`) after the node's own, so a public mock whose fill calls a mock that omits a parameter records it as one no tier takes. A public mock's builders are a seam's, through the seams' hole machinery ("Seams: holes, builders, fills"): the public mock's map is built with `buildsHoles` (`MockScopes.publicMockTypeDescriptionToScopeMap`, `forMockRoot`), so a hole (an `@Instantiated` property nothing the module sees fulfills) is a site, a `MockAliasNode.holeSite`; `createMockRootScopeGenerator` reads the root's generator with `holes(of:)`, shapes the places into builders with `shapedBuilders(…scopeTypeNames: .publicMock)`, named apart from the mock's other parameters per tier as a seam's are from its parameters (`otherParameters`, the names and accesses the plan of the tree built without builders gives them; a builder's per-tier names are `PublicMockParameter.narrowerTierNames`, which `parameters(ofTier:)` applies) – `SafeDIMockScope_`, `SafeDISendableMockScope_`, `SafeDIStagedMockScope_`, which a builder spells qualified by the mocked type, since a caller's leaf receives it as a module that does not declare it spells it – and builds the tree again with them (`mockBuilders`, which `SeamHoles` reads as a seam's tree reads its signature's, and `MockRootParameters.mockBuilders` hands the plan). A call of another module's public mock in its tree is a call as a seam call is (`ScopeGenerator.calledBuilders`, `PublicMockCall.holes`, `builders`, `scopeEnums`), whose unfilled places (`Scope.HoleArgument.passUp`) `holesPassedUp` and `placesAndCalls` read, so a route that reaches one is a case of the caller's enum. The builders are parameters after the uncovered ones, in builder order; the guard hashes each as a parameter, then `SeamSignature.combine(scopeEnums:holes:into:)`, which a seam's guard ends with too. Fill or pass up is decided per place, not per hole type: `holesFilled(byCallsOf:in:)` starts from every place of a call whose fulfilling declaration's tree reads nothing but the struct's fields and the builders of public mocks whose every place is filled, every construction in it reachable – the fulfilling scope is the one the inline mock would build the hole's property with (`fulfillingMockScope(of:in:)`, from the mock scope map, so a hand-written mock or a `mockOnly` fake that alone fulfills the hole fills it), judged with `isMock: true` – and drops a place whose fill reads anything else until none is dropped, so a fill never passes a place up. An internal mock's fills and a public mock's are decided apart (`unfilledInstantiationsAreHoles`): a fulfiller whose tree instantiates a property no scope builds (`instantiatesWhatNothingFulfills`) fills a public mock's place, whose tree makes that property a place of the mock's own, and an internal mock passes the place up, since its fill would read a value nothing binds. An enum's case holds a called mock's whole enum, of whose places the calling public mock can fill some itself: `PublicMockPlan.unpresentedHoles` lists those, and a caller's `PublicMockCall.holes` appends them to the places the mock hands its builders, so the caller's dispatchers switch over every case, filling each such place it can and passing the rest up – an internal caller then takes a builder for a place no call ever hands it, the cost of holding the whole enum. The leaf scope's `holeArguments` hold a fill per filled place and a pass-up per other place; `FillDispatcher.dispatchers(of:filledSites:…)` declares a dispatcher for each enum that reaches a filled place, which takes `passUp` (`FillDispatcher.passUpParameterName`) where it reaches a place it does not fill, and `builderCallArguments` passes each builder its dispatcher, a route closure into the caller's own enum (a `.public` caller), the leaf's dependency of the builder's label (an internal caller, whose leaf receives each builder that reaches an unfilled place, `PublicMockCall.passedUpBuilders`, as a flat parameter typed by the called enum, `@Sendable` where a `@Sendable` builder function captures it; no declaration the person wrote can fulfill that receive, so neither hidden-receive walk judges it (`PublicMockCall.passesUpBuilder(receivedAs:)`), and `mockRootParameterNames(of:)` names its parameter apart instead: from the other flat parameters and the root's bindings as any flat parameter is, and from every label a scope enclosing a leaf that reads it declares (`passedUpBuilders(in:)`), and a builder so named is named after the type whose mock it is passed to, `serviceBuilder_Panel`, unless another such builder would share the name or a parameter, binding or label of the tree has it, when it keeps the flat parameters' name; the leaf's builder function binds it under the label, as a renamed flat receive is), or the dispatcher handed a closure that passes the whole scope up to either; a `.public` caller's leaf receives no builder (`publicMockLeafInstantiable(…takesBuildersFromOwnEnums:)`). The fills are generated by `ScopeGenerator.prepareFillCode(propertiesGeneratedLater:)` with production emission before the mock's emission, with the `propertiesGeneratedLater` of the body of the calling node's builder function (`MockParameterNode.fillPropertiesGeneratedLater`), as production generates a seam call's fills, so a receive inside it of a sibling the caller builds after the call is passed `nil`, every scope of its tree built as the inline mock builds it – with its hand-written mock where `mockReturnTypeIsCompatible` says the mock builds it (`buildsWithHandWrittenMocks` in `Scope.createScopeGenerator`, `ScopeGenerator.constructsWithHandWrittenMock`) – and no override reaches it; a call inside it passes the enclosing fill. A node whose call passes a fill or a dispatcher (`ScopeGenerator.fillsABuilder`) is built in a builder function of its own, as a seam call is in production, with its fills, dispatchers and guard inside it (`callPreamble(of:indent:)`), so two calls of one mock, or a fill and a `.public` caller's own builder of one label, never share a scope; fills and dispatchers are named as a seam's caller names them, and matched to places by site. A leaf passes `<label>.instance` for a by-value parameter whenever the calling tree holds a wrapper of the label – promoted or instantiated – as `dependencyArgument` reads it, and as a leaf inside a fill does, which production emission builds; availability is decided from the same declarations (the wrapper's nearest declaration binds its by-value form, `CycleParameter.forms(providedBy:)`, read by `NearestDeclarations.binding(of:)`). A dependency a called public mock builds when passed `nil` is promoted at the caller's root, as the inline mock promotes it, wherever the caller can construct it (`builtWhenNilByPublicMockCalls`, M8.8b), so every call – each one an `Instantiator` makes included – is passed one instance; a lazily instantiated one is promoted as the wrapper the called mock builds (`PublicMockParameter.builtWrapper`), whose instance each call is passed. A `mock()` bound to a global actor (`Instantiable.generatedMockIsGlobalActorIsolated`, from `declarationIsolation` and `mockAttributes`) takes the type's own optional-typed defaults as parameters with providers of its isolation, never as `SafeDIOverrides` fields, whose nonisolated initializer cannot call them. SafeDI cannot see isolation a type takes from a conformance or a superclass, which is the user's opt-in through `mockAttributes` (decision 53): every other public mock keeps those defaults as fields with `nonisolated` providers, above which a generated comment names the opt-in. A `.public` caller's fill whose fulfiller instantiates a type `canBeHole` rejects (`[any Gizmo]`), which no declaration can fulfill, reads a value nothing binds, so its mock does not compile; this is a deliberate gap, not a finding: production fails at every root whose tree reaches that fulfiller anyway. A module that declares a public mock computes it again over its callers' view (`callersViewFinding(of:)`), as `computeSeamRoots` does for seams; the declarations it can name are the types the tree reaches as their fulfillers, so a protocol's fulfiller that builds a place of the mock, or of a public mock it calls, is named.
- **A default-valued `@autoclosure` parameter in a public mock** is a closure the caller passes, `(() -> T)? = nil`, as a root parameter (`optionalParameter` with `{ <default> }`) or as a field of a type's public configuration (`publicDefaultParameters`, which returns each parameter's `publicMockForm`), and the construction calls it, so the default is evaluated in the declaring module, once per construction; `@autoclosure` cannot be optional, which is why the caller passes a closure rather than a value.
- **A module whose declarations default to the main actor** (`-default-isolation MainActor`; SwiftPM's `defaultIsolation(MainActor.self)`; a new Xcode 26 app target) puts on the main actor every declaration nothing else isolates. An `@Instantiable` type is nonisolated there, since `Instantiable` refines `SendableMetatype`, and so is everything in its extensions, including a type nested in one; a type on the main actor puts the types nested in its extensions there. A public mock's module-level configuration, at file scope, and its `SafeDIOverrides`, nested in a type that may be on the main actor, hold only `nil`, `.init()` of each other and calls of `nonisolated` providers, and nonisolated code builds and reads them (`mock()`, another module's configuration, which holds a called mock's `SafeDIOverrides`), so both are declared `nonisolated public struct` (`publicConfigurationDeclarations`, `publicSafeDIOverridesStruct`). In a module without that default the keyword changes nothing, Sendable inference included; with it, they are no longer `Sendable` through the main actor, as in a module without it. An internal mock's `SafeDIOverrides` and `SafeDIMockConfiguration` keep the isolation of the type they are nested in, since a configuration's initializer spells the defaults the configured type's declaration spells, which may read that actor's state; so a configuration of a type on the main actor cannot be the default of a nonisolated `SafeDIOverrides` there, which a module without the default accepts. The compile verifier compiles a module with that default through `VerificationCompilerSettings.defaultIsolation` (`SafeDIToolPublicMockDefaultIsolationTests`).
- **Attributes for generated declarations are resolved once.** The `@Instantiable` macro has two overloads: one takes `generatedInitializerAttributes:` and `mockAttributes:`, the other `generatedAttributes:` (no default, which is what selects it), so no declaration spells `generatedAttributes` beside either. `InstantiableVisitor` resolves them into `Instantiable.generatedInitializerAttributes` and `Instantiable.mockAttributes` (`generatedAttributes` when given, else the specific argument), and generators read only those fields, never the macro's arguments. Each is written verbatim before its generated declaration's modifiers, on the same line (`@MainActor public convenience init()`, `@MainActor static func mock(`); a new kind of generated initializer reads `generatedInitializerAttributes`, and a new kind of generated mock `mockAttributes`. A `mockOnly` declaration merged into a production declaration contributes neither: `mergedWithMockProvider` copies only the hand-written mock's fields.
- **Types a public configuration spells.** A public mock's module-level configuration (`publicConfigurationDeclarations`), and the construction function and providers in the configured type's extension (`publicConstructionFunctions`), spell the type's default-valued parameter types and builder parameter types outside its declaration, where a type nested in it, or in a type enclosing it, is not in scope: an extension of `Outer.Child` sees `Child`'s members but not `Outer`'s. They spell the types normalization qualified (see "Nested-type qualification"), as every mock and configuration does, so the mocked type's own `mock()` spells them qualified too, and the access proof and the comment on types SafeDI reads no declaration of (`UnreadTypeComment`) read the same qualified type.
