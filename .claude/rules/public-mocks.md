- **An override closure for a call of another module's public mock.** Where the called mock takes no `SafeDIOverrides`, the calling mock's struct holds a closure that builds the called type, handed the builders the called `mock()` takes, which it passes on to `mock()`; it is generated only where the mock root whose body makes the call can hand each as a function a person could write (`ScopeGenerator.publicMockOverrideBuilders`, `MockLowering.PublicMockCallNode.overrideClosureType`): an internal mock passes up its own parameter, and a call that fills a builder whose places one fill fills (one place: a fill is generated per place) hands a function over that fill, `{ fill(session: session) }`, whose function then takes each value it reads by itself (`fillTakesPayloadFields`) and is handed what the call passes the called mock's parameter of that label. Not where a public mock's body passes a place of the call up, since that body holds only the struct its caller built, nor where a fill reads a value the called mock binds itself (another of its places, or a value it renames), which no value at the call site holds: a written call of `mock()` would drop the called mock's values; nor where a call inside the call's fills re-enters one of its level functions and a fill reads a value of the caller's scope, which the fill then takes from the level function (`PublicMockLevelFunctions.Reentry`), so no function over the fill alone builds it. - **A default-valued `@autoclosure` parameter in a public mock** is a closure the caller passes, `(() -> T)? = nil` (`optionalParameter` at the root), since `@autoclosure` cannot be optional: "A default-valued `@autoclosure` parameter is evaluated where the mock builds the type" in `mock-generation.md`.
- **A module whose declarations default to the main actor** (`-default-isolation MainActor`; SwiftPM's `defaultIsolation(MainActor.self)`; a new Xcode 26 app target) puts on the main actor every declaration nothing else isolates. An `@Instantiable` type is nonisolated there, since `Instantiable` refines `SendableMetatype`, and so is everything in its extensions, including a type nested in one; a type on the main actor puts the types nested in its extensions there. A public mock's module-level configuration, at file scope, and its `SafeDIOverrides`, nested in a type that may be on the main actor, hold only `nil`, `.init()` of each other and calls of `nonisolated` providers, and nonisolated code builds and reads them (`mock()`, another module's configuration, which holds a called mock's `SafeDIOverrides`), so both are declared `nonisolated public struct` (`publicConfigurationDeclarations`, `MockLowering.publicOverridesStruct`). In a module without that default the keyword changes nothing, Sendable inference included; with it, they are no longer `Sendable` through the main actor, as in a module without it. An internal mock's `SafeDIOverrides` and `SafeDIMockConfiguration` keep the isolation of the type they are nested in, since a configuration's initializer spells the defaults the configured type's declaration spells, which may read that actor's state; so a configuration of a type on the main actor cannot be the default of a nonisolated `SafeDIOverrides` there, which a module without the default accepts. The compile verifier compiles a module with that default through `VerificationCompilerSettings.defaultIsolation` (`SafeDIToolPublicMockDefaultIsolationTests`).
- **Attributes for generated declarations are resolved once.** The `@Instantiable` macro has two overloads: one takes `generatedInitializerAttributes:` and `mockAttributes:`, the other `generatedAttributes:` (no default, which is what selects it), so no declaration spells `generatedAttributes` beside either. `InstantiableVisitor` resolves them into `Instantiable.generatedInitializerAttributes` and `Instantiable.mockAttributes` (`generatedAttributes` when given, else the specific argument), and generators read only those fields, never the macro's arguments. Each is written verbatim before its generated declaration's modifiers, on the same line (`@MainActor public convenience init()`, `@MainActor static func mock(`); a new kind of generated initializer reads `generatedInitializerAttributes`, and a new kind of generated mock `mockAttributes`. A `mockOnly` declaration merged into a production declaration contributes neither: `mergedWithMockProvider` copies only the hand-written mock's fields.
- **Types a public configuration spells.** A public mock's module-level configuration (`publicConfigurationDeclarations`), and the construction function and providers in the configured type's extension (`PublicConstructionRecord.constructionFunctionLines(requiresSendable:)`), spell the type's default-valued parameter types and builder parameter types outside its declaration, where a type nested in it, or in a type enclosing it, is not in scope: an extension of `Outer.Child` sees `Child`'s members but not `Outer`'s. They spell the types normalization qualified (see "Nested-type qualification"), as every mock and configuration does, so the mocked type's own `mock()` spells them qualified too, and the access proof and the comment on types SafeDI reads no declaration of (`UnreadTypeComment`) read the same qualified type.
