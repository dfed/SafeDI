# Seams: fills

Continues `seam-holes.md`.

A fill (`ScopeGenerator(fill:key:functionName:boundLabels:child:)`) declares the fields it binds from its struct as its properties (`fillStructBoundLabels`, `fillBoundFields`), so a receive they provide is not received from the call's enclosing scopes, and emits a binding only for a field its tree reads or a site inside it carries from that binding (`fieldsCarriedBySites`, which each scope above the site leaves a label it declares out of, as Swift's lookup would), under a parameter named `scope`, with `_` appended while a field, a value its tree receives, or a value a site inside carries has that label, which the parameter would hide (a carrier's place: the run struct and extras, `fillCarrierUse`); the one exception is a label a declaration on the path to a call inside a fill of the same seam call that passes this fill on hides (`fillDeferredLabelsHiddenByReenteringCalls`, from `hiddenByReenteringCalls(ofFills:)` over the pass before's tree, another pass of `createScopeGenerator` running while it changes, `fillStructBoundLabelsChangedInTree`), which the fill, one function, binds from the struct's field at its top – the one place a fill reads a deferred value early, which the Manual states; A fill is keyed by the site it fills; a call inside it of the seam that holds the site, or of a seam that passes the site up, passes the fill, and a fill is never declared inside itself. A fill of a case is named `__safeDI_<label>_<seam stem>_<case>` (`_<enum>_<case>` for a case of a nested enum); every place of a case nested by type is filled by ONE emitted fill, the first place's in builder order (`fillCaseKey(of:)`;
