# Generator design

- **No feature that can crash an accepted tree.** If static analysis cannot rule out that an accepted tree plus ordinary user code crashes, hangs or recurses at runtime because of a feature, the feature is disqualified; removing a trap does not satisfy this. Misuse inside a user's own initializer (reading the `LazilyInstantiated` being created) is the user's: it behaves like the Swift feature it mirrors, never a trap.
- **Build type spellings through `TypeDescription`.** Generated code computes type names and call targets with `TypeDescription` (`asSource`, `asInstantiatedTypeSpelledAsDeclared`), never by joining strings such as a type name, `"."` and a method name, which loses generics, nesting and module qualification.
- **Spell an existential with its `any`.** Swift 6 adopters enable the `ExistentialAny` upcoming feature, under which a protocol spelled as a type without `any` warns, and they build with warnings as errors. `asInstantiatedType` drops `any` (it names the type a scope builds, for maps and comparisons), so code that declares a value of the built type spells `asInstantiatedTypeSpelledAsDeclared`, which keeps `any P` and spells an opaque parameter's `some P` as `any P`. A spelling the person wrote without `any` is copied as written: the warning is then their code's too. `==` reads `any P` and `P` as one type, so where two declarations spell one value apart, a set keeps whichever it met first. A dependency the mocked type receives, directly or through an alias, its mock binds in the mocked type's own spelling, in every form it does not build itself: a promoted dependency's override and binding, a flat `mock()` parameter, an `onlyIfAvailable` override or parameter, and a `LazilyInstantiated` of it (`ScopeGenerator.MockedTypeSpellings`). An alias spells the dependency as its property's type does, where that type is the one `ofType:` names, and never as `ofType:` does: `Service.self` is an expression, which the feature does not flag. A direct receive decides over an alias, whichever the type declares first (`SafeDIToolMockExistentialAnyTests`). Every other value – one the mocked type does not receive, and a seam's pass-through – takes the most explicit of its receivers' spellings over all its forms (`ValueSpellings`, `TypeDescription.mostExplicitSpelling(among:)`), an alias's receive spelled as its property is, so a receive by value and a `LazilyInstantiated` of one dependency are spelled one way: every set of received properties keeps the more explicit spelling on each merge (`insertKeepingMostExplicitSpelling(_:)`), so neither a walk's order nor a set's decides (`SafeDIToolMockExistentialAnyTests`, `SafeDIToolSeamExistentialSpellingTests`). One deliberate gap, commented at its sites: the override closure of a type the mock builds, and the bindings of its arguments in that type's builder function, take that type's initializer's parameters as declared (`MockParameterNode.init`, `emitReceiverBindings`), since an argument reads the nearest declaration of its label, which a type between it and the mock root can spell its own way. Every compile check and every graph fuzzer compile enables the feature (`existentialAnyFeature` in `SafeDICompileVerifier.swift`). A warning in generated code is excused only when the module's own fixture draws the same message, or, for a missing `any` alone, the fixture of a module it imports (`warnings(_:excludingExistentialAnyMessagesIn:)`), since generated code copies the spellings of the declarations it reads and of nothing else; so a generated spelling that drops an `any` the fixture spells fails its test or its graph (`SafeDIToolMockExistentialAnyTests`, `SafeDIToolCompileVerifierTests`).
- **No hand-kept list of system frameworks.** Where logic or wording must tell system modules from the user's, use a signal SafeDI has (the modules it read, or was given module info for), or drop the feature. A curated list is always incomplete and goes stale with every SDK.
- **Runtime speed of generated code over compile time.** Generated trees run in adopters' apps; compile time costs only developers, and release compile time matters least. Never make a tree slower in order to compile faster (`@inline(never)` on seam initializers, heap-allocated payloads) without a runtime measurement beside the compile numbers, and rank compile-cost work by debug builds. A small constant cost per tree build, such as one allocation per seam, is fine: trees are not built in tight loops.
- **A cost every build pays needs the case's frequency.** More `generate` time is paid by every user on every build; a rare compile error with a documented fix is paid once by the few who hit it. Measure how often the case occurs in a real app before trading API, capability or build time for it, and keep it documented when it is rare, fails at compile time (never with a wrong value) and has an easy fix. Where SafeDI cannot see something (isolation, another module's sources), a documented opt-in or spelling comes before generator work. Erasure (`fulfilledByType:`, `erasedToConcreteExistential:`, `ErasedInstantiator`) is first-class: a real app's tree that does not use it yet is no evidence a shape is rare.
- **Measure the compile cost of a change to generated code.** Before review of a change that alters what seams, public mocks or builders emit, run `Scripts/compile-time-check.py BASE_TOOL HEAD_TOOL BUILD DIRECTORY --base-build BASE_BUILD` with tools built from the change and from the commit it is based on: it generates wide graphs (40 and 200 screens) with each tool and fails when a module's generated lines grow by a quarter or `swiftc`'s CPU time on it by half. A change that grows either on purpose says so, with the table, in its pull request. CI times no compile: "Check Generate Time on Linux" runs the script's self-test and its `--lines` mode, which reports a module's generated lines more than 5% from `Scripts/compile-time-baseline.txt` (a warning, `--warn-only`, until the generator's output settles; then a failure). A change that alters generated output rewrites the file with `--write-baseline` from its own tool, in a commit of its own, and says why in a comment above each moved number.
- **No function the compiler takes long over.** "Check Function Compile Time on Linux" (`Scripts/function-compile-time-check.py`) fails when one function of SafeDICore takes over 10 s in the optimizer or 5 s in the type checker in a release build: the optimizer's cost grows faster than a function's length, and one 646-line initializer was 40% of the module's compile. Split the function (a block of a long initializer into a private static function, a long joined expression into sequential appends); never turn the optimizer off for it, since the generator's hot path runs through such code. `Scripts/function-compile-time-waivers.txt` lists the functions known to be over, each with a ceiling and what removes it; never add a line for new code.
- **`generate` time grows with the code it generates.** A step that runs once per place, fill, builder or scope must not build or scan a collection holding every place's, fill's or name's entries: build it once and share it (`GenerationWork.Shared`), or ask each set in turn (`NamesConsultedInTurn`) instead of joining them. A seam reached along thousands of paths did each of these, and took minutes to generate. Each such step counts its work where each taker takes what it consults (`GenerationWork.taking(_:by:)`): a plain collection counts every element, so rebuilding or scanning it for each taker counts that work whatever the step reports. `SafeDIToolSeamGenerationWorkTests` fails when a counted step's work grows more than 1.1 times as fast as the paths to the places of shape E: its places in the seam's own tree, in the fills of a seam it calls at each path, and there with every path opening types of its own, so that the names grow with the paths. A new step of that kind is counted there too. The observer is task-local, and `Scope.startCodeGeneration(of:)` hands it to the detached task that emits a scope's code, so it sees every step; `identifierSafeNames` counts only for a seam's signature. Two sites still do such work, uncounted, and are left for the performance work after 2.3.0: a call walks the enums of the inner seams on each of its places' routes, once for each place (`InnerScopeReaders.labelsSomeInnerRouteLacks(of:)`), so its work grows with its places times the inner seams' places; and a call nested in a fill of another call copies the enclosing calls' fill map and fill names.
- **Benchmarks are lifelike.** A synthetic module takes its shape from a real app's measured statistics: module count and sizes, the share of files with `#if` and mock text, where `#SafeDIConfiguration` lives, received-chain depth and fan-out. Never copy a private app's source into the repository, a fixture or the fuzzer's seeds; reproduce its shape with invented names.
- **Generated code captures only what it reads.** A generated closure, `@Sendable` or not, never captures a value nothing in it reads; that failure is SafeDI's (`seam-and-mock-contract.md`, "No retain cycles"). A non-`Sendable` value the user's own declarations capture is the user's, left to the compiler.
- **Parallel generator work reads only `Sendable` values.** No `@unchecked Sendable`, `nonisolated(unsafe)`, or lock-wrapped sharing of a mutable reference type in the generator: build immutable value snapshots (structs of what each task needs, keyed by index) once, serially, and keep `Scope` and the other classes actor-isolated or task-local. If that needs a type that does too much split in two, split it. `SourceRuleTests` fails on either under `Sources` and `Plugins` (`uncheckedConcurrency`, `source-rules.md`), and only a waiver citing Dan's OK for that one site admits one.
- **Text transforms at every node go over bytes.** A tree has a node per path, so a transform of generated text that runs at every node (re-indenting a subtree, spelling an override path) goes over UTF-8 bytes through `GeneratedCodeText` rather than splitting into `Character`s or rewriting through Foundation, and returns the same bytes as the expression it replaces, which `GeneratedCodeTextTests` checks on every string of a few tokens; where it deliberately differs, because the old expression wrote code that did not compile, a test there spells the case out.
- **Share work by construction.** Work that several places, types or roots would repeat belongs to an object that owns its result: a view computed once per type or per context and handed to every taker (as `GenerationWork.Shared` hands a collection built once), or a node of the tree that holds its own state. It is never a skip flag or a memo table that a walk consults on its way: such a walk does the right work only when every path through it remembers to ask, its result depends on which caller arrived first, and the unshared path stays in the tree beside the shared one. Each such object states what memory it holds and for how long, in a comment at its declaration, since an object that outlives its last taker costs every build. Four deliberate exceptions, each stated at its site: a cache read only to word an error report; a set of the nodes one building walk has already seen, which dies with that walk; a seam walk whose result depends on the path that reached it, so that no one result can be owned; and a pass over a whole tree that looks for cycles.
- **One driver builds each layer once.** `DependencyTreeGenerator.generate(_:)` is the one call that generates a module: it validates and builds the trees of the roots and seams once, which their code, their warnings and the DOT graph read, and then the mocks, and returns all four. No stored property of an actor is a memo whose computation awaits: once a memo filled by check-then-set awaits between the two, two callers both compute and the later wins, and a stored in-flight task is banned (below). A value computed once is a local of the driver, or of the one entry-point call that needs it (`fileHeaders(for:)` reads the module's own files at most once, `requirements(of:)` builds each view's mock scope map once, for every type `query needs` asks about, and keeps nothing after it returns), handed down as a parameter; a module whose public mocks a run calls computes every plan the run asks of it in one call (`publicMockPlans(ofOwnTypes:)`), which the caller keeps in `PublicMockPlans`. `SourceRuleTests` fails on an `async` function, or `async` accessor, of an actor under `Sources/SafeDICore` that assigns a stored property of that actor (`ActorStateRuleCheck`), every actor but `ScopeGenerator`, whose code memo and mock parameter tree task go with the rewrites of production and mock output; it cannot see an `async` function that calls a synchronous one that sets a property, so `SafeDIToolGenerationLayerTests` counts each layer (`GenerationLayerObservation`): each declaration map's seam signatures and each root's tree once per run, the access proof of the run's own declarations at most once per run (the public mock context and the module's own seam signatures share it through `ownAccessProof()`, built when first read, so a module with neither builds none), and each module's mock scopes once for its mocks, once for the plans of its own public mocks, and once for every plan a calling run asks of it.
- **A generator keeps finished code, never a finished task.** A Swift task keeps the memory its async frames took until the task is released, so a cache of a scope's code holds the code's plan once it is generated and drops the task (`ScopeGenerator.generateCode`); and only scopes of large subtrees start their code as soon as the tree exists (`ScopeGeneratorUnderConstruction.scopeCountOfLargeSubtree`), each on a detached task of its own that builds the scope's plan, with the small subtrees directly beneath them in groups of at least as many scopes, one task each, which builds its subtrees' plans one after another (`groupsOfLargeSubtreeSize(_:)`; a task per small subtree held about 27 KB of frames per scope beneath a root with hundreds of small children, most of a wide tree's peak memory). A group's task also spells each of its plans and caches the text with the plan (`GeneratedCode.spelled(_:)`, `ScopeGenerator.generateSpelledPlan()`), which the root's spelling copies in place of walking the plan, so most of the spelling overlaps generation, while a large subtree's task spells nothing, since a large subtree can hold another and would copy its text again; every other scope's code starts on a task created when the scope above asks for it. Keeping every finished task, with every scope's code started early, held 13 to 18 KB for each generated line. `SafeDIToolCodeTaskTests` counts the code tasks still held once a tree's code is generated (`HeldCodeTasks`), and the tasks started (`CodeTaskStart`), and forces the order in which the early starts finish (`CodeTaskStart.ordering`, which holds the roots' code until every start has finished), checking that the code is the same in every order; neither is a `GenerationWork` step, whose every step must grow with a seam's paths.
- **A shared generator is built as each place would build it.** `Scope.createScopeGenerator` reuses a generator between places whose key and read log match (`construction-memo.md`). A new input to a place's build, a new read of the context above it, or a new field a generator stores goes into the memo's key, its log, or its exclusions, and onto that file's list, in the same change; a new argument of `generatePropertyCode` goes into `UnavailablePropertiesCacheKey`.
