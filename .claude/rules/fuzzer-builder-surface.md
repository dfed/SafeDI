# Graph fuzzer: the builder-surface oracle

Continues `fuzzer-seam-oracles.md`.

The builder-surface oracle (`Tests/SafeDIToolTestSupport/GraphFuzzerBuilderSurface.swift`) judges what a person writes against the seam and public mock corpora's accepted graphs, by "Builders a person writes" in `seam-and-mock-contract.md`, from the tool's output alone, without a compile. The base check (`builderSurfaceFailure`, `builderSurfaceNamesGeneratedType`): no parameter of a seam's readable initializer, any tier, or of a generated `mock()` names a scope enum, a `…_Values` struct or a `__safeDI_Builder` type, and no builder a hand-written caller passes takes a scope: a `{ _ in … }` the call passes is judged by the type each generated `mock()` of the called type gives its label (`GraphFuzzerPublicMockBuilders.takesForwardedValue(builderType:)`), and takes the forwarded value, not a scope, only where every tier takes the label as an `Instantiator`'s `Builder` (whose `T.ForwardedProperties` the module cannot see) or an erased instantiator's over a value other than `()`; the label check (`builderLabelFailure`, `builderLabelBreaksContract`): each builder's label is rule 8's for its filling type, returned type and family (`Sendable` before `Builder`); an `@autoclosure`, an instantiator a mock passes on unread, is no builder (`isBuilder`, seed 3855). Both corpora draw a hole whose place forwards a value, each on a stream of its own: the seam corpus's `holeTicketBuilder`, an `ErasedInstantiator<Int, any HoleTicketService>` or its `Sendable` twin on `HoleSeam` (`HoleRolls.forwardingPlace`, `holeForwardingPlace`), and the public mock corpus's `ErasedInstantiator<Int, AnyHole>` hole (`publicMockHoleForwardingRandomSeedMask`, `holeForwardsValue`), whose builders take `(Int) -> B` (`BuilderForm.forwardingClosure`). Then each graph with a hole is edited after every other draw (`GraphFuzzerBuilderSurfaceEdit`, `GraphFuzzerGenerator.fixture(forSeed:features:builderSurfaceEdit:)`), the tool runs again, and calls `C` written against the drawn surface (`calls(against:seed:)`: every required parameter, one builder per builder parameter in the contract's label and a Manual form, no `SafeDIOverrides`) are judged against the edited surface by one function, `accepts(parameterType:facts:form:)`, through `problems(of:against:)`. The seam corpus draws the edits that move or add places across modules, through `HoleSurfaceInner`, an inner seam in `FuzzSession` that the seam builds as it builds the hole's holder; the public mock corpus draws the edits of a place's wrapper. (i) Same supply adds no problem (`sameSupplyCallStopsCompiling`): in the seam corpus a second place in another type, a second place in the inner seam, the holder moved into the inner seam (its graph lists every module beneath a root, the remedy the tool states when a root's only route to the fill passes beneath the seam's module), and a place behind `LazilyInstantiated`; in the public mock corpus a place behind `LazilyInstantiated`, an `Instantiator` place moved to a plain place and back, an `Instantiator` changed to an `ErasedInstantiator` and back (each reverse pair judges the edited graph's calls against the drawn one, as `lazilyInstantiatedPlaceMovedBack` does for the place behind `LazilyInstantiated` in both corpora), and the `@Sendable` twins of the first two and their reverses, judged against the graph whose `Instantiator` is made `SendableInstantiator`. That graph moves the place into the `@Sendable` family, which is no same-supply edit, and the tool rightly rejects it where the place's tree receives a value that is not `Sendable`, such as a consumer's `LazilyInstantiated` (public mock corpus seed 333), or where its fill reads a value declared outside the `@Sendable` function that now builds the place (seed 2486): the twins are then unjudged and pass (`rejectsOnlyValuesNotSendable`); any other rejection of it fails. Likewise a place moved into the inner seam, by the second place there or the holder moved there, moves past where its fill's value is bound when the type that calls the inner seam binds that value, which that call passes up from its own caller: the tool rightly rejects the edited graph with its pass-up error and remedy (seam corpus seeds 1331, 1524 and 1972), and the pair is then unjudged and passes (`rejectsOnlyValuesBoundAbovePassedUpPlace`), as is part (iii)'s remedy in the inner seam; any other rejection, or one beside another error, fails. (ii) A new builder of an existing filling type keeps every existing builder's label, type and order (`addedBuilderChangesExistingBuilder`): the public mock corpus's second erasure and the seam corpus's `holeGadgetOther` and a new builder in the inner seam, judged against the graph with its second place; so does, in the seam corpus, a place of `HoleServiceSendable`, a hole type of its own whose plain builder label is `HoleService`'s `@Sendable` one, beside `HoleService`'s place (`placeOfHoleTypeNamedAfterSendableLabel`), judged against the drawn graph. (iii) A second place forwarding other values is rejected in the module where the places meet (`placesForwardingOtherValuesAccepted`), in both corpora and, in the seam corpus, from the inner seam: the module whose `generate` rejects the graph, which the multi-module harness names (`GraphFuzzerOracle.toolRun`'s `rejectingModuleName`), not the module a diagnostic's path names, where a declaration lives; which error it reports is left to the slice that writes it; its remedy must be accepted (`remedyOfPlacesForwardingOtherValuesRejected`) with exactly the drawn graph's builders (`remedyAddsBuilder`), kinds of their own that no known issue lists. (iv) The public mock corpus's second call of a public mock (`t6Twin`, `t6Second`) is a second place of the first call's filling type, returned type and family, so it is judged as same supply: the calls written against the calling mock without it compile against the calling mock with it, which takes no builder more (`callingMockChangesBuilder`). An edit the tool rejects is a failure ("The tool rejects the edited graph"; `sameSupplyEditRejected` for part (i), the part's own kind for part (ii)); a legitimate rejection is a pass, never a known issue, judged so by the check (as the `@Sendable` twins' base is), and its pair, whose calls were never judged, counts toward no floor. Each judged pair counts toward its kind's floor of ten whether it passes or fails, as does each hole kind the base check judges a builder of (`builderSurfaceFloorKinds`): plain and `@Sendable` by the family of a judged builder parameter, lazy and forwarding where a judged builder returns the type of a place the draw recorded beneath a lazy wrapper or forwarding a value (`GraphFuzzerGenerator.drawnHolePlaces`), never from the fixture's text; the long run reports them as `builder-surface`, which the combine job adds up and checks against the kinds each corpus floors, every kind it draws (`Corpus.builderSurfaceFlooredKinds`). A known builder-surface failure masks no later failure the entry does not list, and a listed kind the graph does not show is a misfiled seed (`staleBuilderSurfaceSignature`); no known failure of an earlier oracle, such as a hole name that changes with a second place, masks a failure of the builder surface, the remedy's two kinds included (`GraphFuzzerFailure.builderSurfaceKindsNeverMasked`), since each judges only the tool's output. A signature names a part's failure kind, not the pair kinds it joins: a seed listed for one pair of a part is not told apart from a new failure of another pair of that part on the same seed, which every unlisted seed still reports. Which graphs count as passing: until the builder structs, a graph that fails only the builder surface's known kinds, listed or not, counts as passing wherever passing graphs are read, since every other oracle judged it – the smoke batches' output features and the long run's spellings, where a leak a known issue lists passes too (`passes(butForRetentionDocumentedBy:butForBuilderOrderDocumentedBy:)`), and the cross-process sample, which runs the executable in two processes for every 50th seed among such graphs (`GraphFuzzerResult.passesBesidesBuilderSurface`). On main every graph with a hole fails the base check, so the parts' seeds are known issues of their own, each part's list apart (`seamBuilderSurfaceSeeds`, `publicMockBuilderSurfaceSeeds`, and `seamSmokeKnownIssues` for the smoke seeds beyond the corpus), which the builder-struct work empties, but for same supply's, a shape that stays for 2.x: an internal mock keeps the flat parameters 2.2.0 gave it, and a builder added later comes with a default beside the flat parameter ("A seam's own internal mock" in `public-mock-builders.md`), so a same-supply edit that moves a place behind `LazilyInstantiated` changes that parameter's type. Its reason differs by corpus (`BuilderSurfaceSeeds.sameSupplyReason`): in the public mock corpus an internal calling mock takes the called mock's hole as a value or wrapper (`callingMockTakesHoleValueReason`), and in the seam corpus the internal mock of a type that is not a seam, such as `HoleOwner`, does (`seamMockTakesHoleValueReason`). Where the surface judgment could disagree with a compile of `C`: escaping, `@Sendable` and isolation, a labeled tuple of several forwarded values, whether an `Instantiator<T>`'s `T.ForwardedProperties` is `Void`, `any` spelling, the wrappers' `Builder` aliases and the label of a `@Sendable` family, which the contract does not settle; for a builder that takes a builder struct, the compile of `C` ("The compile of the call a person writes" in `fuzzer-gating-checks.md`) backs `accepts`. The builder-surface oracle has floors and no exact pins: its per-part known-issue seed lists (`seamBuilderSurfaceSeeds`, `publicMockBuilderSurfaceSeeds`) are copied from a corpus run's report, never edited by hand, and a change that moves them moves them from CI's output.

## Wide carrier levels

- **What the roll draws.** Two hole graphs in five draw a wide level (`HoleRolls.wideLevel`), whatever the base draw. `HoleWideSeam` is a leaf seam that the root builds beside the rest. It binds `holeWide1`… before its one place of `HoleWideService`, which `HoleWideImpl` fills beside the roots, reading the last value. So its level holds 7, 8, 9 or 12 values, both sides of `SeamCarrierValues.maximumPositionalValues`. The seam draws nothing else, so it is declared with carriers whatever else the graph draws, and no other draw widens its level.
- **Narrower values.** Never with the fillers in another package:
  - On a `public` seam, half the time one value is `package`, which only a run struct carries (`holeLevelWithPackageValueOnPublicSeam`).
  - On a `package` seam, every value is `package`. That is as visible as the carrier's members, so the values stay positional (`holeLevelOfPackageValuesOnPackageSeam`).
  - An `internal` seam cannot have a hole, because its filler is in another module. So the `package` seam stands in for "a seam's values at its own access".
- **What catches a mistake.** The compile oracle catches a value passed positionally that is narrower than its member. Both forms of a level within the count compile and build the same values, so the threshold itself is covered by hand-written tests, not by an oracle.

## A seam's property instantiated only if available

- **What the draw adds.** `addingOptionalPlaceShapes` (`optionalPlaceRandom`, six in ten split graphs, after `addingCarrierShapes`) gives `OptionalPlaceSeam`'s tree `@Instantiated(onlyIfAvailable: true) let optionalPlaceAnalytics: (any OptionalPlaceAnalytics)?`, a protocol only the roots' module may fulfill. So the seam takes `optionalPlaceAnalyticsOptionalBuilder`, a builder returning the optional.
- **Its rolls.** The root fills that builder with `OptionalPlaceAnalyticsImpl` or with `nil`. The place sits on the seam or on `OptionalPlacePanel`, built by value or through an instantiator. `OptionalPlaceOuter` may pass the builder up. The holder may also instantiate the protocol required, so the optional builder sits beside the required one. Where nothing fulfills the protocol, the seam may generate its mock: that mock is internal to the seam's module, which sees no fulfiller, so it binds `nil` where the visible build builds the fulfiller.
- **How it is judged.** Each shape is an `optionalPlace…` draw feature: a gating draw (`isOptionalPlaceShape`) whose accepted counts are pinned and floored. The value comparator judges each graph against its inline build and its visible build. The label check reads the `Optional` stem (`expectedLabel(of:facts:)`).
