# Seams: carriers and builder structs

Continues `seam-generation.md`.

**Carriers.** Which seam hole types hand their levels to their builders as carriers is in `seam-carriers.md`; every other one, and every public mock's, keeps the builder structs below.

A seam's builders of a hole type that keeps builder structs (above), both families together, take a builder struct whatever places they reach (an `.inner` case, the seam's own where its tree builds it again, or a `.fill` case), so every enum declares one and every builder takes one (`SeamBuilderFamilies`); a public mock's builders take it by the same rule (`public-mock-builders.md`). A seam's tree calls a carrier's members, and a caller's level functions return carriers, as for structs (`RouteStep.Member`, `FillDispatcher.returnsBuilderStruct`); carried routes and re-entering calls below arise only with builder structs. Each such enum declares, after its payload structs and nested enums, `__safeDI_Builder<__safeDI_Built>` (`ReservedName.builderStructTypeName`, `builderStructGenericParameterName`): one stored function per case, named as the case, taking the case's payload struct, or, for a `@Sendable` enum's case, an empty `Sendable` struct named as a payload struct (`ScopeEnum.Case.memberValuesTypeName`), and returning `__safeDI_Built` for a plain or lazy place, the erased wrapper's `Builder` over it for a place held in an instantiator (`ErasedInstantiator<F, __safeDI_Built>.Builder`, `SendableErasedInstantiator` in a `@Sendable` enum, `F` the forwarded value the case carries, or `()`), or the held enum's struct; its memberwise initializer; and, for a public mock's struct only, `init(__safeDI_noScope __safeDI_builder:)`, every member of which calls the one builder (a seam's level declares none: its callers build it without a scope in local functions of their own, `seam-carriers.md`). A `@Sendable` enum's struct is `Sendable` with `@Sendable` members. The enums, payload structs and structs of such a hole type are `nonisolated`. The generated-only initializer takes the root's struct (`Builder.parameterType`, which the guard hashes) and the readable one the type its places' forwarded values give it (`Builder.readableParameterType`, from `DependencyTreeGenerator.builderForm(ofPlaces:)`, which the two diagnostics that print a builder's type print): `() -> T` or `@Sendable () -> T` where every place is plain or lazy or forwards nothing (`ErasedInstantiator<(), T>`, or `T.ForwardedProperties` beside such a place), else the wrapper's `Builder` or its `Sendable` twin's, or the erased wrapper's where the places spell one value through other wrappers or spellings, over the most explicit of their spellings (`TypeDescription.mostExplicitSpelling(among:)`: the longest name-erased spelling, `withNamesErased`, then its text, then the spelling's), never by where the places are, since a location's file path is a name; the location order (`sortedByForwardingLocation`) chooses only which place an error about other forwarded values names; building the levels through local functions (`ScopeGenerator.LevelsWithoutScope`). The seam's tree calls one member per step of a place's route (`RouteStep.Member`), bound `__safeDI_<builder label>_<case>` on the struct the step before returned, the root builder's for the first: before the step's property's builder function, as a payload is bound, or, for a `@Sendable` enum's step whose property is built in a `@Sendable` function, at the top of that function (`SeamHoles.memberCallsInsideFunction(at:)`), since what it returns can be a plain struct that function could not capture, and, for a call's case for a fill whose fulfiller builds its type in a `@Sendable` builder function of its own (the case carries no inner scope), at the top of the fulfiller's function, where the places inside the fill read it; the place calls its own member on the last. Each `@Sendable` local function generated code declares, here as everywhere, is `@Sendable nonisolated` (`ScopeGenerator.localFunctionPrefix(isSendable:)`). For a place held in an instantiator, the seam builds the wrapper around its member's result, `Instantiator<T>(<struct>.<member>(<values>))`, with no builder function of its own for the place. The struct's no-scope builder (a public mock's initializer, or a seam caller's level function) is typed per level by the places at and beneath it, in the level's family, but takes a `@Sendable` builder where it hands its builder to a struct whose no-scope initializer takes one, as a plain level does whose call's case re-enters an enclosing fill through a `Sendable` wrapper and returns the called seam's `@Sendable` struct (`LevelBuilderForms.takesSendableBuilder(atLevel:)`; that fill is built in a `@Sendable` function, so the root above is of the `@Sendable` family), and adapts a builder of another form: `{ _ in { _ in __safeDI_builder() } }` for an instantiator member, which takes `()` or `T.ForwardedProperties`, under a builder that takes nothing; a level member of another form is handed the next level built from the same adapter. A caller fills such a place with a place function, `<level function>_<member>`, which takes each field of `values` the fill reads and the reads handed down, declares the fill's builder function inside it, and returns `{ forwarded in <builder function>(…) }` as the wrapper's `Builder` (spreading a labeled tuple by label, `{ _ in … }` where the fulfiller forwards nothing), so the closure the wrapper keeps captures no `values`. Such a place function is handed each struct of its own level as the function the inner seam's member returns for the place (`@escaping ErasedInstantiator<F, S>.Builder`, `SendableErasedInstantiator` in a `@Sendable` enum), and the builder function calls it at its top with what it was forwarded, `()` for nothing, one value as itself, several as the labeled tuple the wrapper forwards, binding the struct under the parameter's name (`innerScopesCalledWithForwardedValue`); a builder the place function returns that called the member itself would capture the payload fields the place function's other arguments read. A fill that builds its type in a `@Sendable` builder function of the type's own is handed no struct of its level, and binds none (`ScopeGenerator.readsFillInnerScopes`): its case carries no inner scope, and its places read the call's member bound at the top of that function. On a carried route, the member of an instantiator's place returns `{ _ in <level>(…) }`, or `{ [level = <level>(…)] _ in level }` where the level reads the payload (`Case.returnsWrapperBuilder`), and the no-scope builder of a struct whose case for a filled builder returns the called seam's struct hands that struct's no-scope builder `{ _ in … }` where the called seam's root takes a value, every place it reaches an instantiator that forwards one (`calledRootsTakingValue`). A caller of a public mock converts nothing: it hands the called mock the member of its own struct as it is, or the struct a level function returns (`PublicMockLevelFunctions.Member`). A loop's level re-entered through a cycle-closing scope re-enters the function built at its first opening, with the struct bound there, as the enum form re-enters with that payload; the member at the reopening property that would carry what was bound above it is not generated yet, a deliberate gap kept safe by `declarationBoundOnCycleReentry`, which rejects every read whose value would differ.

A caller writes, for each enum a builder struct's root reaches, a function that returns the level's struct (`FillDispatcher.returnsBuilderStruct`, keyed apart from the enum-form dispatcher of the same enum, `FillDispatcher.key(of:returnsBuilderStruct:)`), taking the values its targets read that the cases do not carry, its members calling the next level's function, a fill by name, or holding an inlined fill's body, which declares no function (`ScopeGenerator.fillDeclaresFunction`; one that does is called by name, since a function declared inside the struct's closure would not take the isolation of the code around it), and the call passes the root's function called. Only a public mock's calls keep dispatchers in enum form: every seam's builders take carriers or builder structs, so no seam's call keeps a dispatcher over an enum for a call inside its fills to reuse, and no tree holds both a seam's call and a public mock's, since only the trees of the seam world call seams (`createSeamScopeMapping`) and only mock trees call public mocks (`createMockTypeDescriptionToScopeMapping`). An enum the call reaches only as the value a public mock's case carries keeps its dispatcher. Where a call hands a struct-taking seam's places on, it decides that when generating, never by converting an enum at run time. A place it passes up is handed the caller's own builder, or a member of the caller's builder struct, as it is. Where the call carries the scope it hands its fills (`SeamHoles.innerScope(at:innerKey:)`), its dispatchers return their level's builder struct (`FillDispatcher.returnsBuilderStruct`). Each carried level is one function that returns the called seam's struct over the struct of the fill's own level (`CarriedLevel`, in `FillDispatcher.dispatchers(of:filledSites:…)`).

A seam's or a public mock's enum that declares a builder struct is a namespace with no case and no `@frozen` (`ScopeGenerator.scopeEnumDeclaration`): no generated code builds or switches over a case of it. A carrier's enum is declared not at all.

A fill that holds places of several hole types or families of the calling seam is handed one struct of its own level per type (`SeamHoles.innerScopes(at:innerKey:)`), each named `__safeDI_<call>_<builder>_<label of the builder whose route leads there>` (one alone keeps `__safeDI_<call>_<builder>`), and each level function on the call's carried route takes the caller's struct of its level once per type, in the order of the fill's parameters' names, which the fill and every level function declare and are called with (`FillDispatcher.carriedInnerScopes`), each under `up_` and the fill's parameter's name without its `__safeDI_` prefix (one alone under `up`): a positional name would move to another type when the types are renamed. Each is claimed apart from every label a carried level's cases hold, which a level function takes as values beside it, without reserving those labels. The levels of a seam the called seam calls on the way to its fill of that seam's place (the call's carried dispatchers, `CarriedLevel`) take the caller's struct too, nested inside the structs of the fills' levels they return over (`FillDispatcher.carried(_:through:)`); and a carried level that fills a deeper seam's place leads on through that seam's levels, whose places return the struct of the fill's level, carried in turn (`CarriedLevel.fillLevelKeys`, nearest first), so a place inside a fill of a place inside a fill gets a level function at every level. A carried level's function is named after the builder label of the nearest fill's level, that level's seam and its own, and its enum where that is nested; where the enums of two levels would take one name, as two root enums of one seam do under one fill's builder, each level takes its enum's name, root then nested, and none keeps the bare one, so which one is named apart never follows the order of the builder labels.

A fulfilling call that hands up its plain enum from a `@Sendable` fill is a plain place to the place graph (`SeamDeclarationGraph.PlacesOfEveryHoleType`): the fill's edge already says the call is built in that function, so the fill's case is of the `@Sendable` family and holds the plain enum, as a child call's own case does.

**Forms of one label at a dispatcher.** The root dispatcher hands each target the caller's declaration in the form that target takes, found by its parameter's property (`callerArgumentByParameter`, and `memoArgumentByMemo` for a memo), so two fills of one call that take a label in different forms each get their own, and no spelling is chosen among another's (`SafeDIToolSeamCallerArgumentFormTests`). A nested enum's dispatcher likewise takes a label once per form its targets take (an optional form beside its unwrapped one taken as that one), each named apart where a label has several (`FillDispatcher.parameterNames(of:)`, `<label>_<type identifier>`), and hands each target the parameter of its form (`parameter(handing:among:)`), so places beneath a level that binds none of the label, one of them beneath a type that binds it lazily and one beneath a type that binds it by value, each get their own form.

A values struct declares a deferred parameter's memo (`__safeDI_<label>`, a `LazilyInstantiated` or its `Sendable` twin) at its field's access. A fill that reads such a field from the struct (a place a seam passes up, its fill inside a called seam's included, and a fill whose call re-enters the seam beneath another declaration of the label) binds every such field's memo under the label (`SeamSignature.Hole.Field.bindingItsMemo`; but a `LazilyInstantiated` its tree reads inside a `@Sendable` function, which it binds by value: `seam-holes.md`) and reads its instance where its tree reads the value, optional fields included, so the value is created when the tree reads it, as inline; a level function hands the memo on, never the instance (the value, for a label bound by value), and never captures the payload. So does a place a caller fills inside a fill of a passed-up place: its field is a level's by-value field in the passing-up seam's signature, but where some route reaches it through a level on a carried route whose field of the label is a deferred parameter's (`FillDispatcher.memosHanded(toFillOf:labels:readingSendableWrapper:among:)`, a fixed point over the dispatchers), the fill takes a memo: that field's, in the form the route hands, which can differ from the place's field of a level further out (`SeamSignature.Hole.Field.handedAsMemo(_:)`, `Scope.Fill.labelsHandedAsMemo`), where every route hands one memo, or every route that hands a memo hands one `SendableLazilyInstantiated` and the fill's tree reads that wrapper too (`ScopeGenerator.fillSendableWrapperReads`, which the pass before finds), so the tree reads one wrapper where it reads the wrapper and the value, as inline reads one declaration both ways, the root dispatcher handing the caller's declaration of the wrapper itself (`FillCallerReads.memoArgumentByMemo`) – where some route hands a seam's `LazilyInstantiated` instead, which no `@Sendable` function can capture, the fill takes a `LazilyInstantiated`, and `memosHanded` finds those routes (`HandedMemos.plainMemoRoutesOfSendableWrapperReads`), which `validateFills` reports at the wrapper's reader (`sendableWrapperReadBesidePlainMemo`, `seam-hole-fills.md`); else, where routes hand memos that differ only in deferral, or another route hands the value (the calling seam's own route to the place's level, which hands the caller's declaration, or a level's by-value field), a `LazilyInstantiated`. Each level function on the route takes and hands the memo (`dispatcherParameters(of:fillReads:)` takes a form some target takes as the memo as the memo, a `SendableLazilyInstantiated` before a `LazilyInstantiated`: `handsForm(_:inPlaceOf:)`), and a case that hands another form makes the target's memo of it, `LazilyInstantiated<T>({ [handed = values.__safeDI_<label>] in handed.instance })` of another memo or a type's wrapper, `({ [handed = values.<label>] in handed })` of a value, and `({ <caller's declaration> })` at the root dispatcher (`FillDispatcher.HandedSource`), so the value is created where the fill's tree reads it on every route; the by-value exception above applies to it alike (`SafeDIToolSeamPassedUpDeferredFieldTests`' `levelFunctionHandsMemoOn` and `fillTakesMemoOnEveryRoute` and `fillTakesSendableMemo` cells). Memos of one label that differ in form (`T` and `T?`) are left out: the fill takes the value. So is a label the fill's tree reads only as the place's own field of it, the wrapper a type further out declares, never as the value nor at a site of its tree (`ScopeGenerator.fillLabelsReadOnlyAsPlaceField`, which the pass before finds): the fill takes that field, and the levels hand it on past a deferring seam's level, whose deferred field carries the value and its memo but not that wrapper (`FillDispatcher.Case.handsOn(_:)`), so the fill reads the declaration inline reads (`SafeDIToolSeamCarriedWrapperReadTests`' `levelFunctionsHandCarriedWrapper` cells). A fill that takes a handed memo declares the label, for the places inside it, as the place's own field (`fields(of:)` in `SeamBuilderParameters`), not the memo's value: a seam passing such a place up records that wrapper, which the fill one module up reads alone. A member of a level's builder struct hands the next level the memo its own case's payload carries wherever that level binds it, also a deferred field no route to the case carries (`FillDispatcher`'s `structDeclaration`): below the root of a seam built again inside a fill that declares the label again, the enclosing value is that other declaration, so a place there reads the memo of the seam built again, as inline (`SafeDIToolCallingMockMirrorsProductionTests`' `whenFillBuildingCalledTypeAgainDeclaresValueAgain`). The field's own property decides what it satisfies, as for any field; the memo decides only when the value is created: `Scope.fillUnderConstruction` registers the field's unwrapped property as read through the memo, as `DependencyTreeGenerator.seamRootGenerator` registers a deferred parameter of the seam's own tree, its sibling. Public mocks hold the value by value.

The error about a declaration a seam binds on its path to calls whose places it passes up (`boundByPassingUpSeam`) takes every part a place decides from every place it names: the seams whose calls present them, the builders, and each remedy, once per kind of place (built in a `@Sendable` function or not). Two findings of one reader that differ only in their places merge into one that names both (`FillFinding.adding`), so no place is picked by where it is declared. In the same form, the error about a declaration on the path to a call inside a fill that re-enters the seam (`declarationBoundOnPathToReenteringCall`) names every path that hides the label (`FillReentryHidings.pathDeclarations` keeps each path's), one clause per declaration and call in name order, since which fill's path a walk meets first follows the order of the files that declare the places. Its notes, each a diagnostic of its own, follow source order. Of one key's findings (kind and reader location, `FillFinding.key`), those that print the same apart from their places, the fulfilled types their remedy names included, merge, and every one that remains is reported (`validateFills`): none is chosen. Findings that name different declaring types are different facts with their own remedies, so each stays its own error. So, too, where calls inside the fills of one seam call pass a fill on to several seams that pass its place up, the fill gets a finding per seam whose copy of the hole does not carry a label it reads (`FillReentryHidings.calledCopyDeclarations` keeps every copy's), never the copy the walk meets first.

A seam's call made inside a fill whose own fill is the reuse by name of an enclosing call's level function that takes a carried struct (`ScopeGenerator.holdsCallReenteringEnclosingFill`, `enclosingFillsPassed`) takes that struct from a member `<call>_<builder>` of its own case, keyed by the called seam's root: the member is on the level of the type that makes the call, nested by type under the level of the enclosing fill, and returns the called seam's struct over the struct of the type the reused fill builds. The declaration graph enters the enclosing fill, which becomes a level with its own root member and carried route (`SeamScopeEnumsByType.leadsToPlace(_:reenteringFills:)`), and adds a reuse edge from the calling type to the node of the type the reused fill builds (`FillEdge.reusesEnclosingFill`), which the walk never visits again, the dominators never see, and the cycle rule never removes, since the tree closes there by name. The call's route ends on that case (`CallRoute.reentersEnclosingFill`), and the call hands each struct the reused level function takes, under its `up` label, the member's binding for that struct's type (`SeamHoles.carriedStruct(at:innerKey:carrying:)`, from `enclosingCarriedInnerScopes`). In the plain family the member is bound before the calling property's builder function, never inside the called type's function, where its forwarded properties would shadow the labels the values read; in the `@Sendable` family, where the call is built in a `@Sendable` function, it is bound at the top of that function from the root `_Sendable` member and carries neither values nor a level. Where the reused fill is the one that encloses the call, or one above it, the member is recursive: `DefaultSecond_Scope.subBBuilder_secondBuilder` returns `SubB`'s struct over `DefaultSecond_Scope`'s own (`SafeDIToolSeamReenteredFillTests`). Where the call is of a seam that calls the re-entered seam and passes its place up (`Relay`), the call declares the level functions of the seams on the way and reuses the enclosing call's from the re-entered seam's root on: a case that leads to a reused level function hands it, under that function's name for each struct it takes, this call's struct of the same type (`FillDispatcher.Case.Target.reusedCarriedInnerScopes`), so each level function on the way takes its struct too, as it would for a fill of its own call. Such a case refers to the reused level function by name, as a dispatcher a call passes by name does (`ScopeGenerator.referencedFillNamesByKey`), so no builder function declared between the two calls takes its name, which would hide it from the case (`builderFunctionNames`: a property `secondBuilder_SubB` of the calling type is built in `__safeDI_secondBuilder_SubB_X`), and where the call is made inside a `@Sendable` function that does not enclose the reused function (a `SendableInstantiator`'s builder function, at the call or above it, or a `@Sendable` fill), the reused function is `@Sendable` too (`generate_marksReusedLevelFunctionSendable_…` in `SafeDIToolSeamReenteredFillTests`). A public mock's call does the same. The member carries no value bound on the path to the call, so a read of one in the fill the call passes on stays rejected (`declarationBoundOnPathToReenteringCall`), in the visible build and, through the place's `reenteringCallDeclarations`, where a caller fills a place inside that fill, a field of the label bound above the seam call included: the fill reads one value on every route (`seam-hole-fills.md`).
