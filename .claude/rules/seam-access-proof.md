# Seams: tiers and access proofs

Continues `seams.md`.

Tiers: a parameter's `access` is the proof of the narrowest type its type names (`TypeAccessProof`, computed once per declaration map a signature is computed over, so the seam's module and every caller compute the same proofs; an outer seam proves an inner seam's carried parameter again over its own map), its `tierAccess` that capped at `parameterAccess(seam.effectiveTypeAccess)`, which decides the tiers and the guard; the tiers are that type level plus each narrower `tierAccess`, widest first, the seam's own initializer's level is no tier, and nothing is deduplicated (each narrower tier takes a parameter the next wider omits); the narrowest tier takes every parameter and calls the seam's own initializer, which may be narrower than it; a wider tier passes `nil` for the parameters it omits, and a required one narrower than the type level is one `tierOmitsRequiredParameter` at the seam, worded by `SeamAccessExplanation` from how the narrowest type is proven (`TypeAccessProof.Cause`), what receives it, and the error; the seam's own `@Received(onlyIfAvailable: true)` property is received only if available; no parameter of any tier has a default, so every call, generated or hand-written, writes every argument; a caller takes the narrowest tier `AccessLevel.required(toConstructFrom:declaredIn:isOwnFile:)` lets it reach, and a seam's own module (`isOwnFile`) the narrowest tier `internal` code reaches; a caller that reaches none cannot construct the seam's type, and its call (`Construction.isSeamLeaf`) is reported at the type and the types enclosing it, never at a generated or own initializer. The proof reads only the declaration map and the plain type declarations of the modules it holds (`PlainTypeDeclaration`), its mentions dependency-bound only – an argument of the construction initializer, `instantiate(…)` or hand-written mock whose inner label names a dependency of the entry it is recorded on – never a name, iteration order, `otherInitializers`, a result type or a type-name string: a type declaration outside every extension is exact at its spelled chain; one inside an extension is exact, capped by the extended type's own exact entry of the same module (same `moduleName`, or both in the run's own files), or else by the extended type's exact plain declaration as a mention from the entry's module resolves it, or by `public` when no declaration SafeDI reads declares the extended type nor a type enclosing it (`unreadExtendedTypesByEntry` remembers that type for the comment), and otherwise starts at the extension's bound (its spelled level for a top-level extended type, `internal` otherwise), as does an extension-based declaration whose type's plain declarations are not exact (one with an exact plain declaration is exact at it, so the README's unspelled `mockOnly` extension of a `public` type proves it `public`, and one whose type nothing SafeDI reads declares is exact at `public`), both raised by every mention of their type at the mentioning member's level capped by its entry's proof, a least fixed point. An extension-based declaration of a nested type SafeDI reads no exact declaration of starts instead at the level its extension spells capped by the exact proof of the type directly enclosing it, when SafeDI reads that type's declaration exactly (`exactEnclosingType`: its exact entry of the same module, or its exact plain declarations): Swift requires the extended type's own level to reach the extension's, checking no type further out, so a type between that SafeDI reads no declaration of could cap it, and `exactEnclosingType` never walks past one. It is exact at that proof when the spelled level reaches it, and its cause is then `enclosedBy` the enclosing type; otherwise the cause's `enclosingTypeLevel` says whether a spelled level counts, and the remedy that spells the extension's level is offered only where it does, with the enclosing type widened too when it is narrower than the level needed. `unreadTypes(namedBy:mentionedFrom:)` follows such an entry to the enclosing type, so a generated `public` declaration that names it carries the comment naming an enclosing type SafeDI counts `public` unread (an entry of a type no module it reads declares). An entry inside an extension of a type SafeDI reads no declaration of, but a type enclosing which it reads, is exact at that enclosing type's exact proof (`exactProofOfNearestEnclosingType`; the cause carries it as `extendedTypeEnclosingType`, and its sentence names it), as a nested type SafeDI reads no declaration of counts as the type enclosing it. A type with no entry is in one of two states (decision 54). RECORDED: its plain declarations as a mention from the seam's module resolves them (`TypeAccessProof.PlainTypeDeclarations.candidates(named:mentionedFrom:)`: generic arguments stripped; `M.T`, with `M` a module of the view and no type `M`, names `M`'s declarations of `T`; otherwise the seam's module's own, else other modules' declared `package` or wider that the mentioning module can name (`TypeAccessProof.ModuleReach`, the one rule `distinguishingTypesUnnameable` reads a mention by too, which returns what SafeDI knows and what it cannot tell (`Reach.undetermined`), each reader settling the second its own safe way: the proof drops a module's declarations only when SafeDI knows the mentioning module cannot name them – narrower than `package`, `package` in a package SafeDI knows differs, or, under the target graph (`ModulesRead.includesEveryModuleItCanImport`), of a module it does not depend on, directly or not – and otherwise counts them, since a module of a run given module info files can import a module beneath one it lists, which its run does not read (`modulesRead(byRunOfModuleNamed:)`); the view's own module reads every module of the view; a module's declarations count or not together, by the narrowest; an entry counts by the same rule at the level its type has by itself, `open` for an extension's (`ModuleReach.cannotName(_:from:)`: `entryKind(of:mentionedFrom:)` and the init's `nameableEntry`, so neither a lookup nor a member's mention that raises an entry binds to one its module cannot name); a module that cannot name them reads the type as unread) – one whose module SafeDI does not know, read from an unnamed `.safedi` or an additional directory, counting at its declared level when it is not in the run's own files – a declaration `private` or `fileprivate` anywhere in its chain, or directly inside such an extension, never counting) – a `struct`, `class`, `actor`, `enum`, `protocol` or `typealias`, a typealias's level being exact because Swift caps it at its underlying type's – each, outside every `#if` block or in a clause `FileVisitor` scans, exact at its `levelBeforeExtendedTypeCap`, capped, when it is directly inside an extension, by the proof of the extended type (the record's chain popped `enclosingTypeAccess.count + 1` times, resolved by `cause(of:)` from the record's module; a narrowing cap is `.declarationInExtensionOfRecordedType`, carrying the extended type's plain declarations for the notes, or `.enclosedBy` when the extended type is itself proven otherwise); of several candidates, the narrowest (two clauses of a platform-conditioned block can each declare a type, and the compiler may select either), and the cause, `.plainDeclaration`, lists those its extended type does not cap, each module once at its narrowest in the sentence (`declarationLevelsByModule`). A spelling SafeDI cannot read (`.unknown`) is the one type proven by mentions: from the seam's module and its receivers' modules (a mention elsewhere is tied to the parameter by name alone, which a name collision would make fail open, so `.signatures` carries the mentioning module and its sentence says which mentions count, "SafeDI cannot read its spelling"); its remedies offer no `mockOnly` mock. Without a candidate, the nearest enclosing type with an entry or a candidate proves a nested type (`.enclosedBy`: a protocol body's `typealias`, a macro-generated member). UNREAD: otherwise no declaration SafeDI reads declares the type, which counts as `public` (`cause(of:)` returns `nil`): a framework's, a fetched package's, a binary target's, or a first-party module's that does not run SafeDI – exact for all but the last, whose `package` type then fails to compile at the generated declaration. A module's own declaration of a standard type's name precedes the standard type; the list of standard types (`isAllowlisted`) only keeps those out of the comment. Every view a proof is computed over carries the plain declarations of the modules whose declarations it holds (`ForeignSeam`/`ForeignPublicMock.visiblePlainTypeDeclarations`, `SeamResolution.callersVisiblePlainTypeDeclarations`, which keeps only declarations with a module). A diagnostic whose cause is a plain declaration narrower than needed carries a note at each narrower declaration in its chain with a fix-it (`SeamAccessExplanation.declarationNotes(for:neededLevel:)`), since a fix-it edits only the file its diagnostic points at. What a parameter's proof depends on (`declarationsProving(typesNamedBy:admittedModules:)`) is computed after the fixed point, and is the second tier of the declarations the callers'-view check names.
