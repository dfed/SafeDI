# Seams: holes, builders, fills

- The configuration that governs a module's own generation (imports, directories, additional mocks, its mock condition) comes only from that module. A dependency module's configuration is read only for its `mockConditionalCompilation`, to check a call of its seam or public mock (`GenerateCommand.seamResolution`, `publicMockUnderOtherMockCondition`; see `seams.md`).
- **An erased rename of an optional dependency is mapped.** `ScopeGenerator.aliasValue` binds an alias with `erasedToConcreteExistential: true` to `(x as X?).map { AnyX($0) }` whenever its `ofType:` is optional or its binding may be (`fulfillingValueMayBeOptional`), required or `onlyIfAvailable`, and it is the one site production, mocks, and seams share. Never decide the wrapping from the binding alone: a required rename of `x: X?` reads a forwarded optional, a mock's optional parameter or override, or the non-optional value a promoted node or a lexically enclosing `let` holds, and the mapped expression compiles over each.
- **Seams: holes, builders, fills.** In a seam's tree as the seam map builds it, an `@Instantiated` property whose instantiated type (`Dependency.asInstantiatedType`) no production declaration the map holds fulfills (none, or only `mockOnly`) is `Scope.PropertyToGenerate.hole`, unless its spelling is one no nominal type can be (`DependencyTreeGenerator.canBeHole`, by spelling: a closure, tuple, array, dictionary, metatype, `Void`, optional, opaque or attributed type stays `noInstantiableFound`; a typealias of a closure is a hole, which only hand-written code fills). A hole is a build site – a place – a node of the seam's generator tree (`ScopeGenerator(holeProperty:…)`): a property built at k sites is k places, each with its own payload and its own fill; a cycle-closing scope builds nothing and so holds no site. `SeamSignature.holes` lists every place a seam's builders reach, its own and each inner seam's it passes up, one per site, in the order the builders reach them, and is what fills, the hidden-label walks and validation read; `SeamSignature.builders` and `scopeEnums` are what the initializer takes (`shapedBuilders`, `SeamBuilderFamilies.swift`, read after the places and fields are computed). A hole type is (instantiated type, type the builder returns), spelled canonically (`Hole.holeType`, `TypeDescription.spelledCanonically`). Per hole type a seam takes a plain builder over `SafeDIScope_<Stem>`, for its places built in plain code, and a `@Sendable` builder over `SafeDISendableScope_<Stem>`, for those built inside a `@Sendable` function – a builder function that is `@Sendable`, a `@Sendable` fill, or the `Sendable` wrapper a place is held in – each only if its root has a case; order is per hole type in label order, then plain, `@Sendable`. A hole type's stem depends only on what it builds (`stems(of:)`): its instantiated type, followed by `_<returned type>` where the two differ canonically, from the first place on. Only hole types whose stems or labels coincide (`Box<Int>` beside `Box_Int`, `Impl_Api` beside (`Impl`, `any Api`), `URLThing` beside `UrlThing`, `ServiceSendable` beside `Service`'s `@Sendable` family, where only the stem whose plain label it is, `ServiceSendable`, is named apart, so a hole type's own labels never follow another type's name) are named apart, by their types (`ScopeGenerator.identifierSafeNames`), then trailing underscores. The stem names the root enums and payload bindings. A tier's label is the stem's, `_` appended while a parameter label the tier takes, its own or a wider tier's, equals it (`TierNames.label(ofStem:isSendable:)`), per family and for `mock()` against its own parameters, so a parameter renames no stem or enum and a narrower one never relabels a wider tier's builder; a builder's label can differ between tiers (`Builder.narrowerTierLabels`, `Hole.narrowerTierBuilderLabels`, which the guard hashes where set); a call takes the signature at its tier (`atTier`). Names derived from a label (internal name, a caller's dispatchers and fills, a called seam's fill case) follow the widest tier's, `_` included; builders are ordered by its plain labels, and a seam declares one enum per hole type and family whatever tier takes it. A seam's enums are nested by type for its places and calls outside every fill (`seam-generation.md`). Which types have an enum and which cases is a fact of the declaration graph of that hole type (`SeamDeclarationGraph.PlacesOfEveryHoleType.placeHolding(of:)`, one walk of the tree shared by every hole type, every build of a declaration read, its edges joined: a place is a site of the hole type, or a call that hands up an inner seam's enum of it – a passed-up place counts as holding a place here, though not in the start order, and is no place of the levels oracle, which reads the places the seam builds: by ruling of 2026-11-14, an `.inner` case holds the inner seam's root enum and no payload, as in the `@Sendable` family: a payload built at the call is inside the called type's builder function, where its forwarded parameters hide the calling type's labels, and the builder the called type holds would capture every field, read or not (a retain cycle inline lacks, and values times cases times hole types of generated code); no generated fill could read one, since an inner seam's root dispatcher takes no parameters, and a fill reading what the passing-up seam binds before the call stays `boundByPassingUpSeam`; a fill leading to a place is an edge to the type it builds, a public mock's as a seam's), never of paths: a case per place-holding property in the type's declaration order – `.place(sites:)` (every site of the property, one case however many paths), `.nested(enumKey:enumType:isIndirect:)` holding the built type's enum, `.inner` holding the inner seam's root enum and nothing else – each but `.inner` carrying `Case.values`, what the type binds before the property (`levelDeclarations(of:…)`, read from the type's first build: the seam's parameters then its children, or the type's forwarded properties, the cycle parameters of any of its builds (`seam-generation.md`), then its children), in a payload struct `<label>_Values` (a carrier's member takes them in run structs instead, `seam-carriers.md`). A public mock's enums, a place inside a fill included, are nested by type the same way (`public-mocks.md`, whose caller decides per route); a call of an inner seam whose hole type this module cannot fill (`fulfillingInstantiable(of:in:)`, decided per instantiated type per module, so all of an enum's places are filled or none are) holds that seam's enum, of the plain enum in plain code over a plain inner enum and of the `@Sendable` enum otherwise. The enums never join; a fill is one function per place, `@Sendable` as `Hole.isSendable` (set for a place the `@Sendable` builder builds) and the walk below say. An enum's case is `indirect` exactly when the enum it holds is in its own strongly connected component (`markingIndirectCases`, Tarjan on an explicit stack after signatures settle; every enum of a cycle is generated by one module). A case that holds an enum of its own seam carries that enum's type as the extension spells it (`ScopeEnum.Case.Kind`'s `enumType`, set where `scopeEnumsByType` builds the case), never a lookup the declaration could miss: a public mock's tree that builds the mocked type again inline (itself, through a child, in a `@Sendable` function, or as a called mock's fill) holds the root enum, while a seam's tree calls the seam's initializer (`.inner`). Every tier takes every builder, after the parameters, and a place whose tier access is narrower than a tier is `tierOmitsBuilder`, once per declaration, naming the first builder in builder order whose enum reaches the place (`ShapedBuilders.builderBySite`), the `@Sendable` one where no plain one does, explained by `SeamAccessExplanation` as a required parameter's omission is, with the builder's remedy (`ParameterKind.builder`) in a pass-through's place, and a builder narrower only because of an inner seam whose enum it holds is `tierOmitsBuilderHoldingInnerSeam`. A place's tier access is `TypeAccessProof`'s over the property's type, the forwarded type among those it names, the hole's owner admitting its module, with a passed-up builder's scope struct counting as the type of the seam that declares it, capped at the seam's type; a builder's is the narrowest of its places and the inner seams whose enums it holds; a field's access is the proof of its type, the declaring type admitting its module, capped the same way (a pass-through keeps its parameter's); each keeps the proof's cause (`Hole.accessCause`, `Field.accessCause`), which `fieldNotReadable` explains with the shared formatter too. `SeamBuilderParameters.swift` computes the holes from the seam root's generator tree, in this order: sites in generation order (`buildSites`, which walks only subtrees whose `containsBuildSite` holds, ordering each scope's children with `orderedChildrenComputedAfresh`, the order generation will use), then each site's fields, then names; `SeamSignature` hashes the guard from the result. A label is a field exactly when its nearest declaration on the site's path – the seam's parameters, then each path scope's forwarded properties, the parameters of its builder function when a lazy cycle closes on it (`CycleParameter`, by value, declared by the first type in the function's body that receives it), the wrappers its builder function makes again as a member of a loop of instantiators (`ScopeGenerator.reboundProperties`, bound first in the function, at the member's level of the path, so `cycleReentryDeclarations` counts them inside the function, and declared by the scope that declares the loop; see `ReceivedBuilderLoops` in `cycle-generation.md`), and its children, an `onlyIfAvailable` alias bound to `nil` included – is bound before the site, so a cycle parameter hides a deferred parameter's memo and the field holds the value the function was passed, as inline's site reads it; a nearer declaration bound later hides a farther bound one (`UncarriedDeclaration`), since Swift would bind the farther one. The lazily instantiated instance form is never a field: the field is the wrapper. A label bound outside the innermost `@Sendable` function on the site's path – a builder function (`buildsInSendableFunction`), a `@Sendable` fill (`ScopeGenerator.buildsInSendableFunction(ofFill:)`), or the `Sendable` wrapper the place is held in – is no field but an uncarried declaration (`UncarriedDeclaration.Reason.boundOutsideSendableFunction`), and a generated fill reading it, required or only if available, is `declarationBoundAfterSite` with that reason, whose remedies are to receive the value on the seam from its caller, offered only where the seam declares the value itself, since a declaration by a type of its tree or by a seam it calls stays bound outside the function, and where the seam's caller can build it (`isBuildableAboveSeam`, `seam-hole-fills.md`) (for an alias, to drop it, and inside the tree to instantiate the label outside: `AliasOrigin`) or to forward it to the type the function builds (for a forwarded one, for an instantiated one where the receive is not offered, and for a parameter of a builder function a lazy cycle closes on, named with what the cycle passes: `CycleParameterOrigin`); a parameter of the seam is no field of such a place, and its fill reads the caller's own declaration, so SafeDI never hands over a value it cannot tell is `Sendable`. A public mock binds at its root, from the optional parameter its caller passes its own declaration to, each received value it promotes; such a declaration bound outside the function is uncarried too, marked `isBoundFromCallersArgument`, and a calling mock's fill reads its own declaration of it, as the twin's fill reads the seam's parameter, where the declarations enclosing the call bind that form (`Scope.fillUnderConstruction` drops it from the fill's hole). A deliberate gap: where they bind another form or none, as for a receive only if available of a value the caller does not instantiate, the mock may build a value of its own, so the fill is an error whose remedies are to instantiate the value above the call or to fill the place in the called type's module, while the twin takes the value as a parameter; both sites say so. A seam or public mock that calls such a mock and passes the place up keeps the mark, since the mock is passed what that type's caller passes, unless the path to the call binds the label, whose declaration then stands in its place (`SiteAdditions.presenting`). A builder is always `@escaping` and returns the property's declared type without its wrapper, around which the seam builds a wrapper (`seam-generation.md`). A fill runs inline's `ErasedInstantiatorForwardedPropertiesMismatchError` (`fillUnderConstruction`), seeing through the fulfiller's module and, for a hole the seam's own module declares the owner of and no seam passes up (`Hole.declaringModuleNames`), the seam's, only for a type no other module SafeDI read declares a type of the name of (`DeclaredTypeNames.isDeclared(_:outsideModuleNamed:)`): generated code spells the hole's type in the module that generates the fill, where a bare name can mean a type of that module, which a `.safedi` records only when a declaration of that module mentions it, so a hole that crosses another module keeps inline's check, whose error names a spelling that compiles. A builder is also `@Sendable` where the seam's tree passes it on from inside a `@Sendable` function, a fill's included, a passed-up one or its own handed to a call that re-enters the seam, or passes it to a call that takes it `@Sendable`: one builder per site joins the hidden labels and the sendability of every route that presents the site. In `orderedPropertyToGenerateIndices`, a child that holds a place (a carrier, `ScopeGenerator.startsAsCarrier(_:)`) starts after every child that is no carrier and depends on none through the final edges; every edge is computed exactly as without holes, so no availability changes, and a tree without a carrier keeps the index order. A public mock's `SafeDIOverrides`, and every configuration it nests, takes its members in the order without the carriers' start (`ScopeGenerator.inlineOrdered(_:property:)`), the internal mock's and the inline build's, so no change to the start order moves an initializer a person calls (`SafeDIToolPublicMockOverridesOrderTests`; the public mock corpus's `drawCarrierBeforeSiblingPublicMock`). Whether a child holds a place is a fact of its parent's type, read from the tree's declaration graph (`SeamDeclarationGraph`: a node per declaration as the cycle check keys it, the edges whose target dominates their source removed, since they close a cycle on every build), so every build of a type starts its children in one order, a build on which a child closes a cycle included; it equals "its subtree holds a site on this path" except in a tangle of cycles no type always encloses, or for a type that one declaration builds outside a cycle and another builds inside one, whose edge for the property is removed, where `Scope.createScopeGenerator` creates the tree once more with each type's place-holding properties. A fill's tree starts each type's children in that order too: the start-order graph enters a fill as the type it builds. Each place's levels – what each scope on its path binds before the next property – are computed beside its fields (`SeamPlaceLevels`, handed only to a test's observer): read nearest first they hold the place's fields, which `executeSafeDIToolTest` checks for every test, and the seam corpus fails a graph two builds of whose type give other levels, cycle parameters aside (`placeLevelsDifferBetweenBuildsOfType`). A sibling that depends on a carrier and is declared after a later carrier is built after it: a fill reading it is reported (`FillFinding.Kind.declarationBoundAfterSite`), a deliberate gap a finer order could close later. A caller's seam leaf gets `Scope.holeArguments`: `.fill` where its declarations hold a production fulfiller (`fulfillingInstantiable(of:in:)`), else `.passUp`, which a seam's tree turns into a builder parameter of its own per inner site, shared by every call, and which in a root's tree is `unfilledHoles`, reported at the root's dependency with a note at the hole where its file is readable. A hole is identified by its site (`scopeSeamType`, `sitePath`), which a passed-up hole keeps, and a site inside a fill has, where the fill sits on its path, the filled site's own path, after the seam that holds it when the seam called passes it up (`Hole.pathBeforePropertyInItsFill`), since two holes of one call can share a label and type, and each fill's places are places of their own – the seam that holds it being a stand-in on that path, no declaration, so generated names read `sitePath` and a diagnostic reads `Hole.declaredSitePath`, which in its place walks the calls that passed the hole up (`Hole.passedUpRoute`) and names the type that declares each hop (`DeclaredProperty.declaringType`), a fulfiller where a fill builds a protocol; a seam never takes a site it already takes, and a call that presents one passes the seam's builder by its internal name (`SeamHoles.hole(taking:)`); `SettledContent.Hole` carries a hole's hidden labels, which only accumulate, so a cycle of seams settles. Fills: `seam-hole-fills.md`. Before any field match `validateFills` reports a receive, required or only if available, of a label in `Hole.cycleReentryDeclarations` (`declarationBoundOnCycleReentry`), which `fields(of:)` fills, for each scope on the site's path whose builder function a cycle-closing scope in the seam's tree calls, with each label a scope between the two declares (`declarationsBetween(closedOnScope:closedOnDeclaration:)`, the labels inline makes the function's parameters, less the scope's own property and declarations and the hole's label; a label a scope between takes as a parameter of a function a cycle nested inside closes on is reported as the declaration that cycle passes it, through every nested parameter, with `parameterTakingType` naming the scope; so is one a nested cycle declares again that no function takes) whose nearest declaration at the site is outside the function (`fields(of:)` declares the function's own parameters at its level of the path, a deferred parameter's memo included, so a field bound from one is bound at each level), which a passed-up hole keeps, with those of cycles around its call (`holesPassedUp`): inline, the type built again reads that declaration; a fill reads one scope struct or caller's scope at every level. `validateReachableTypeDescriptions` reports a missing fulfiller only outside every seam's tree (the fills this module generates for foreign seams entered), and a hole in a seam this run generates (`generatedSeamTypes`) while its module is unnamed (`EmittingModule.identity` names no module) is `holesInSeamsOfUnnamedModule`, whose message leads with declaring a fulfilling type, then declaring the seam without `generateDependencyTree: true`, then how SafeDI comes to know the module under the only runs that reach it (the Xcode project plugin: a local Swift package; What the guard hashes of the builders: `seam-generation.md`. Mocks never see holes: they build every seam inline and take a flat parameter for a type they cannot build, but for a type a fill of a call of another module’s public mock instantiates, for which an internal mock takes a builder, binding it where a seam would call its hole’s builder (`public-mock-builders.md`). - **A memo a `@Sendable` function in a fill would capture is bound by value.** Of the deferred fields a fill binds from its struct (`seam-builder-structs.md`), one whose memo is a `LazilyInstantiated` and whose label the fill's tree reads inside a `@Sendable` function, or hands a nested seam that takes it `@Sendable` (`ScopeGenerator.labelsReadInsideSendableFunction(among:)`), is bound from the struct's by-value member (`fillDeferredLabelsReadInsideSendableFunction`, from the pass before), creating the value where the fill, or a level function on its route, is handed the struct, not where the tree reads it. A `SendableLazilyInstantiated` memo the fill takes, the one every route hands where its tree reads that wrapper too included, is bound as the memo, which the function captures (`Scope.fillUnderConstruction`'s `isBoundByValue`; `SafeDIToolSeamPassedUpDeferredFieldTests`' `fillBindsSendableMemo` cells). A deliberate gap against inline, commented at `Scope.fillUnderConstruction` and that property: the seam's signature is settled in its own module, which sees no fill, and deferring it `@Sendable` would narrow the seam's initializer to a type SafeDI cannot tell is `Sendable`.
