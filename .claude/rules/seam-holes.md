# Seams: holes, builders, fills

- The configuration that governs a module's own generation (imports, directories, additional mocks, its mock condition) comes only from that module. A dependency module's configuration is read only for its `mockConditionalCompilation`, to check a call of its seam or public mock (`GenerateCommand.seamResolution`, `publicMockUnderOtherMockCondition`; see `seams.md`).
- **An erased rename of an optional dependency is mapped.** `ScopeGenerator.aliasValue` binds an alias with `erasedToConcreteExistential: true` to `(x as X?).map { AnyX($0) }` whenever its `ofType:` is optional or its binding may be (`fulfillingValueMayBeOptional`), required or `onlyIfAvailable`, and it is the one site production, mocks, and seams share. Never decide the wrapping from the binding alone: a required rename of `x: X?` reads a forwarded optional, a mock's optional parameter or override, or the non-optional value a promoted node or a lexically enclosing `let` holds, and the mapped expression compiles over each.
- **Seams: holes, builders, fills.** In a seam's tree as the seam map builds it, an `@Instantiated` property whose instantiated type (`Dependency.asInstantiatedType`) no production declaration the map holds fulfills (none, or only `mockOnly`) is `Scope.PropertyToGenerate.hole`, unless its spelling is one no nominal type can be (`DependencyTreeGenerator.canBeHole`, by spelling: a closure, tuple, array, dictionary, metatype, `Void`, optional, opaque or attributed type stays `noInstantiableFound`; a typealias of a closure is a hole, which only hand-written code fills). A hole is a build site – a place – a node of the seam's generator tree (`ScopeGenerator(holeProperty:…)`): a property built at k sites is k places, each with its own payload or stages and its own fill; a cycle-closing scope builds nothing and so holds no site. `SeamSignature.holes` lists every place a seam's builders reach, its own and each inner seam's it passes up, one per site, in the order the builders reach them, and is what fills, the hidden-label walks and validation read; `SeamSignature.builders` and `scopeEnums` are what the initializer takes (`shapedBuilders`, `SeamBuilderFamilies.swift`, read after the places and fields are computed). A hole type is (instantiated type, type the builder returns), spelled canonically (`Hole.holeType`, `TypeDescription.spelledCanonically`). Per hole type a seam takes a plain builder over `SafeDIScope_<Stem>`, a `@Sendable` builder over `SafeDISendableScope_<Stem>`, and one staged builder per place built inside a `@Sendable` function or held in a `Sendable` wrapper (or passed up from an inner seam), each only if it has a case; order is per hole type in label order, then plain, `@Sendable`, staged. A hole type's stem is its instantiated type, followed by `_<returned type>` where a label it gives collides with another hole type's or with a parameter the tier takes (`stems(of:parameterLabels:)`). Each tier names its builders apart only from the parameters it takes, its own and every wider tier's (`tierNames`), so a narrower parameter never renames a wider tier's builder, and a builder's label can differ between tiers (`Builder.narrowerTierLabels`, `Hole.narrowerTierBuilderLabels`, which the guard hashes where set); a call takes the signature at its tier (`atTier`). The enums, the staged scope types and the builder order follow the widest tier's stems, so a seam declares one enum per hole type and family whatever tier takes it. Cases are in the order the seam's generated code first reaches them. A place in plain code is a case of the plain enum named by the labels on its path, with payload `<case>_Values`; a call of an inner seam whose hole type this module cannot fill (`fulfillingInstantiable(of:in:)`, decided per instantiated type per module, so all of an enum's places are filled or none are) is a case holding that seam's enum: `<path>` of the plain enum in plain code over a plain inner enum, and of the `@Sendable` enum otherwise, `<path>_Sendable` for an inner `@Sendable` enum. The enums never join; a staged builder and a fill do: a passed-up staged builder's first stage is `@Sendable` when any route presents it from a `@Sendable` function, and a fill is one function per place, `@Sendable` as `Hole.isSendable` and the walk below say. An enum's case is `indirect` exactly when the enum it holds is in its own strongly connected component (`markingIndirectCases`, Tarjan on an explicit stack after signatures settle; every enum of a cycle is generated by one module). Every tier takes every builder, after the parameters, and a place whose tier access is narrower than a tier is `tierOmitsBuilder`, once per declaration, naming the first builder in builder order whose enum reaches the place (`ShapedBuilders.builderBySite`), the `@Sendable` one where no plain one does, explained by `SeamAccessExplanation` as a required parameter's omission is, with the builder's remedy (`ParameterKind.builder`) in a pass-through's place, and a builder narrower only because of an inner seam whose enum it holds is `tierOmitsBuilderHoldingInnerSeam`. A place's tier access is `TypeAccessProof`'s over the property's type, the forwarded type among those it names, the hole's owner admitting its module, with a passed-up builder's scope struct counting as the type of the seam that declares it, capped at the seam's type; a builder's is the narrowest of its places and the inner seams whose enums it holds; a field's access is the proof of its type, the declaring type admitting its module, capped the same way (a pass-through keeps its parameter's); each keeps the proof's cause (`Hole.accessCause`, `Field.accessCause`), which `fieldNotReadable` explains with the shared formatter too. `SeamBuilderParameters.swift` computes the holes from the seam root's generator tree, in this order: sites in generation order (`buildSites`, which walks only subtrees whose `containsBuildSite` holds, ordering each scope's children with `orderedChildrenComputedAfresh`, the order generation will use), then each site's fields, then names; `SeamSignature` hashes the guard from the result. A label is a field exactly when its nearest declaration on the site's path – the seam's parameters, then each path scope's forwarded properties, the parameters of its builder function when a lazy cycle closes on it (`CycleParameter`, by value, declared by the first type in the function's body that receives it), and its children, an `onlyIfAvailable` alias bound to `nil` included – is bound before the site, so a cycle parameter hides a deferred parameter's memo and the field holds the value the function was passed, as inline's site reads it; a nearer declaration bound later hides a farther bound one (`UncarriedDeclaration`), since Swift would bind the farther one. The lazily instantiated instance form is never a field: the field is the wrapper. Each `@Sendable` function on the path starts a stage – a builder function (`buildsInSendableFunction`), or a function of a fill the seam's tree generates for a seam it calls (`ScopeGenerator.sendableStages(ofFill:)`), also where the builder is `@Sendable` already or nothing is bound since the stage before, because SafeDI cannot tell which bound values are `Sendable`, a stage called before the function is the only way to hand one over, and a builder's stages follow only from the functions on the path, so binding a value there never adds a closure to what a caller writes – and what it binds goes in that stage (`Hole.stageName(at:)` names the stage structs, which are nested side by side, `Stage1`, `Stage2`, … with `_` appended while a field's type, or the built type the last stage's alias spells, names the struct's name, a generic argument of a type enclosing it included (`TypeAccessProof.mentionedTypes(in:)`), or that type would resolve to the struct; `Hole.stageFunctionName(at:ofFunctionNamed:)` spells a stage's function as one identifier): the seam calls each stage but the last just before declaring that function (`SeamHoles.stageCalls(at:)`, and `fillStageCalls(at:)` for a fill's, by the fill's stage: before the fill when its first function is `@Sendable`, and inside it, before that stage, for a later one), binding the returned `@Sendable` function, and calls the last at the site. A builder is always `@escaping` and returns the property's declared type without its wrapper (`Hole.builtType`); the seam builds a wrapper that forwards no value (`ScopeGenerator.buildSiteCode`) around a function named as inline's builder function, which makes the last stage's call, `@Sendable` for a `Sendable` wrapper, whose function starts a stage of its own that carries nothing, the builder function of a wrapper hole taking part in `builderFunctionNames` so that a cycle-closing scope beneath a sibling never resolves to it; an instantiator's forwarded value is the last stage's second argument (`Hole.forwardedType`: `ErasedInstantiator`'s first generic unless spelled `()` or `Void`, and always `T.ForwardedProperties` for `Instantiator<T>`, since the seam cannot always see whether `T` forwards anything). That `T.ForwardedProperties` can be a function type only `T`'s module sees, which spelled in a parameter list would not escape and cannot be written `@escaping` where it is no function; so can an erased instantiator's first generic spelled as a name, a typealias of a function type its fulfiller declares `@escaping` (`TypeDescription.nameDeclaredEscaping`). A case's payload always escapes; a staged place's last stage, of either kind (`Hole.spellsLastStageThroughAlias`), is spelled by a generic typealias generated inside the place's scope type (`Hole.lastStageAliasName(isSendable:)`, `SendableLastStage<__safeDI_Forwarded>`: a staged place's last stage is always `@Sendable`, which cannot be written on an alias's use), whose generic parameter the forwarded type substitutes, which escapes (probe p15, on Swift 6.2 and 6.4); every wrapper that forwards a value is built around a closure, whose `$0` the wrapper's generic signature types, instead of a function, since an `ErasedInstantiator`'s first generic can be a typealias of a function type, which a function's parameter would not let escape into the case, and a fill, which sees its fulfiller, writes `@escaping` when the fulfiller forwards one function, written out or a name its subtree declares `@escaping` (`ScopeGenerator.typesDeclaredEscaping`). `Hole.stageFunctionType` holds each later stage as its spelling, so a staged builder's type has one stage's depth however many `@Sendable` functions are on the path (`SafeDIToolSeamDeepStageTests`), and the guard, a seam's or a public mock's, hashes `builderTypeWithoutAny`, which strips `any` stage by stage. One allocation of names serves each generated Swift scope (`GeneratedNameAllocator`): a seam's initializer body claims its builders' internal names with the stage bindings each makes, then the function that builds each wrapper place; a filler's body around one seam call claims its fills with their later stages, then its dispatchers; no site names anything with a loop of its own. A fill runs inline's `ErasedInstantiatorForwardedPropertiesMismatchError` (`fillUnderConstruction`), seeing through the fulfiller's module and, for a hole the seam's own module declares the owner of and no seam passes up (`Hole.declaringModuleNames`), the seam's, only for a type no other module SafeDI read declares a type of the name of (`DeclaredTypeNames.isDeclared(_:outsideModuleNamed:)`): generated code spells the hole's type in the module that generates the fill and in a staged builder of every module that passes it up, where a bare name can mean a type of that module, which a `.safedi` records only when a declaration of that module mentions it, so a hole that crosses another module keeps inline's check, whose error names a spelling that compiles. A builder is also `@Sendable` where the seam's tree passes it on from inside a `@Sendable` function, a fill's included, a passed-up one or its own handed to a call that re-enters the seam, or passes it to a call that takes it `@Sendable`: one builder per site joins the hidden labels and the sendability of every route that presents the site. In `orderedPropertyToGenerateIndices`, a child whose subtree holds a site (a carrier) starts after every child that is no carrier and depends on none through the final edges; every edge is computed exactly as without holes, so no availability changes, and a tree without a carrier keeps the index order. A sibling that depends on a carrier and is declared after a later carrier is built after it: a fill reading it is reported (`FillFinding.Kind.declarationBoundAfterSite`), a deliberate gap a finer order could close later. A caller's seam leaf gets `Scope.holeArguments`: `.fill` where its declarations hold a production fulfiller (`fulfillingInstantiable(of:in:)`), else `.passUp`, which a seam's tree turns into a builder parameter of its own per inner site, shared by every call, and which in a root's tree is `unfilledHoles`, reported at the root's dependency with a note at the hole where its file is readable. A hole is identified by its site (`scopeSeamType`, `sitePath`), which a passed-up hole keeps, and a site inside a fill has, where the fill sits on its path, the filled site's own path, after the seam that holds it when the seam called passes it up (`Hole.pathBeforePropertyInItsFill`), since two holes of one call can share a label and type, and each fill's places are places of their own – the seam that holds it being a stand-in on that path, no declaration, so generated names read `sitePath` and a diagnostic reads `Hole.declaredSitePath`, which in its place walks the calls that passed the hole up (`Hole.passedUpRoute`) and names the type that declares each hop (`DeclaredProperty.declaringType`), a fulfiller where a fill builds a protocol; a seam never takes a site it already takes, and a call that presents one passes the seam's builder by its internal name (`SeamHoles.hole(taking:)`); `SettledContent.Hole` carries a hole's hidden labels, which only accumulate, so a cycle of seams settles. A fill (`ScopeGenerator(fill:key:functionName:boundLabels:child:)`) declares the fields it binds from its struct as its properties (`fillStructBoundLabels`, `fillBoundFields`), so a receive they provide is not received from the call's enclosing scopes, and emits a binding only for a field its tree reads or a site inside it carries from that binding (`fieldsCarriedBySites`, which each scope above the site leaves a label it declares out of, as Swift's lookup would), under a parameter named `scope`, with `_` appended while a field, a value its tree receives, or a value a site inside carries has that label, which the parameter would hide; it binds every field but one from a deferred parameter, which it reads from the caller's scope – the declaration the call passed the parameter – as inline, so the seam analysis (`fields(of:)`, `receivers(in:)`, `declarationsBound(by:…)`) treats that label as the caller's, and the capture walk's fill branch (`fillCaptures`, with `NonSendableWrapperCapture.capturingFillSeamType` for a `@Sendable` stage) reports a `@Sendable` function in the fill that would capture a non-`Sendable` wrapper the caller declares, with inline's error (`capturingFillIsPassedOn` says when the fill is `@Sendable` only for where it is passed on, since the filled seam's tree then has no `@Sendable` function to name); the one exception is a label a declaration on the path to a call inside a fill of the same seam call that passes this fill on hides (`fillDeferredLabelsHiddenByReenteringCalls`, from `hiddenByReenteringCalls(ofFills:)` over the pass before's tree, another pass of `createScopeGenerator` running while it changes, `fillStructBoundLabelsChangedInTree`), which the fill, one function, binds from the struct's field at its top – the one place a fill reads a deferred value early, which the Manual states; its child is the fulfiller's scope, built as the declared property, wrapper included, so a repeat of it equals the stack entry, but a wrapper's child (`isBuiltByFill`) declares only the builder function and returns what it builds, spreading the fill's forwarded parameter as the wrapper's closure spreads `$0`, and leaves the wrapper to the seam; the child is built with the stack the seam whose tree holds the site has at the site (`Hole.fillPropertyStack`, the owner's stack, which inside a seam's own fill is the filled seam's), never the filler's path, while a value it takes from the caller's scope is available as to a pass-through of the call, so one the caller's path is still building is passed `nil`; a site inside a seam's own fill carries every field of the filled seam's struct, which the fill binds: a repeat of the hole's property closes on the fill's own builder function, and a repeat of a property of the seam's path, built for the same concrete type (`Hole.fillConcreteTypeStack`, beside the stack), is reported (`FillFinding.Kind.closesCycleInSeamTree`), never a rebuild; a property of that label and type built for another fulfiller is built again, as inline builds it, and a hole's fulfiller, a type the seam's module cannot build, can never be the type of a stack entry, so a fill's root never closes on the path (`InstantiableResolution`'s duplicate fulfillment error rejects the one spelling that would make a type the seam's module builds fulfill the hole only in the filler's module). A fill is keyed by the site it fills; a call inside it of the seam that holds the site, or of a seam that passes the site up, passes the fill, and a fill is never declared inside itself. A fill of a case is named `__safeDI_<label>_<seam stem>_<case>` and a staged fill `__safeDI_<staged label>`; one dispatcher per enum that reaches a filled place, `__safeDI_<label>_<seam stem>`, is a one-level switch handing each case to its fill or the inner enum's dispatcher, in first-reach order (a fill exactly one case calls is generated as that case's body, under the conditions `seam-generation.md` states), so a cycle is ordinary mutual recursion (`FillDispatcher.dispatchers(of:filledSites:…)`, which a public mock's caller shares; its `passUp` never arises for a seam, whose caller fills every place of an enum or none, and the route test of `shapedBuilders` – an enum reaching a place the call passes up – is the hole-type test for a seam). Each is named apart from a fill or dispatcher of an enclosing call, its siblings, a builder the enclosing seam takes, and a later stage that seam's stage calls bind (`SeamHoles.namesBoundForBuilders`, `ScopeGeneratorUnderConstruction.Fill`, by the allocator above), so the closer declaration never shadows the one a call inside it passes. `HoleCallArgument` stays per place, so `enclosingFillsPassed`, `referencedFillNamesByKey`, the hidden sets and `Hole.isSendable` see every fill a passed dispatcher reaches; `BuilderCallArgument` is what the call passes. A fill passed to such a call reads the outer call's values, so a label declared on the path from the root of any fill of the same seam call to a call inside it that passes this fill hides every read the fill resolves from the caller's scope (`FillFinding.Kind.declarationBoundOnPathToReenteringCall`, naming the fill whose tree holds the path, as `boundByPassingUpSeam` hides the labels a passing-up seam binds), and a fill passed to a call of a seam that passes the site up honors that seam's copy of the hole too: the labels it does not carry hide the reads (`declarationBoundAfterSite`), and its sendability makes the fill `@Sendable`; the hidden sets are computed per seam call, over every fill's tree, in `hiddenByReenteringCalls(ofFillsOf:)`. A fill made `@Sendable` that way and capturing a non-`Sendable` wrapper of the caller is reported by the capture walk's fill branch; one capturing another non-`Sendable` value fails to compile, as the inline tree does inside that seam's `@Sendable` builder function. A fill's first function is `@Sendable` when a `@Sendable` function that does not enclose the fill refers to it, the seam the fill is passed to takes it `@Sendable`, or a call inside any fill passes it to a seam that takes it `@Sendable` (`HoleCallArgument.hole`); a fill made `@Sendable` that way is itself such a function, so `ScopeGenerator.sendableFills(of:referencedFromSendableFunctions:)` finds the set with a worklist, once per seam call and bottom-up, like `buildsInSendableFunction` for cycle closers; every later stage is `@Sendable` always. It reads only the call's subtree and the settled signatures of the seams it calls, a filled seam always being in another module, so a seam's signature can use the result without a circle, and generation, the capture walk, `fields(of:)`, `holesPassedUp` and `receivers(in:)` all ask `sendableStages(ofFill:)`. A dispatcher is `@Sendable` when a `@Sendable`-family argument reaches it or a `@Sendable` function that does not enclose it refers to it (`SendableFillNode`, a node of the same worklist as the fills). A site's reads of the seam's parameters are at the call of its first stage, before the first `@Sendable` function on its path, so a site never makes a parameter `@Sendable`. Before generation `validateFills` (`DependencyTreeGeneratorError.fillFindings`) reports each receive in a fill's tree that a field does not give inline's value – except a receive only if available of the hole's own property or its instance, which inline and the fill's tree both pass `nil` – the nearest declaration of its label is bound after the site (`declarationBoundAfterSite`, which also covers a label a passing-up seam binds on a path to its call of the inner seam, inside the seams and fills on that path included, a parameter of a builder function a lazy cycle closes on along it too, as `fields(of:)` counts one: `boundByPassingUpSeam`, which names the place that call presents, so a place inside a fill of it gets the remedy on that place's seam), the field is at an access the filler cannot read (`fieldNotReadable`), or held only optionally while the receive requires it (`fieldHeldOnlyOptionally`), or a scope of a fill of the same seam call declares its label on the path to a call that passes the fill on (`declarationBoundOnPathToReenteringCall`) – and each cycle closed on the seam's path (`closesCycleInSeamTree`, read from what generation found, `ScopeGenerator.closedOnFillPathDeclarationsBeneath`, never worked out a second time: only a closer whose nearest enclosing fill's stack holds the entry is that fill's finding, a fill nested in it judging its own, and the rename remedy is offered only where the declaration closed on builds the type that declares the hole), keyed by kind and location; the finding is read on the filler's generator tree, where a seam is a leaf, while the cycle walk below inlines every seam; and `rootScopeGenerators` walks, for cycles only, every foreign seam with holes from its own root over the validated scopes (`validateCyclesFromRootsOfForeignSeamsWithHoles`), which reports the seam's own cycle diagnostic where a fill would close a cycle with no instantiator along it that the filler's walk closes earlier. Before any field match it reports a receive, required or only if available, of a label in `Hole.cycleReentryDeclarations` (`declarationBoundOnCycleReentry`), which `fields(of:)` fills, for each scope on the site's path whose builder function a cycle-closing scope in the seam's tree calls, with each label a scope between the two declares (`declarationsBetween(closedOnScope:closedOnDeclaration:)`, the labels inline makes the function's parameters, less the scope's own property and declarations and the hole's own label; a label a scope between takes as a parameter of a function a cycle nested inside closes on is reported as the declaration that cycle passes it, followed through every nested parameter, with `parameterTakingType` naming the scope) whose nearest declaration at the site is outside the function (`fields(of:)` declares the function's own parameters at its level of the path, nearer than every other declaration of their labels, a deferred parameter's memo included, so a field bound from one is bound again at each level), and which a passed-up hole keeps: inline, the type built again reads that declaration, while a fill reads the same scope struct or caller's scope at every level. `validateReachableTypeDescriptions` reports a missing fulfiller only outside every seam's tree (the fills this module generates for foreign seams entered), and a hole in a seam this run generates (`generatedSeamTypes`) while its module is unnamed (`EmittingModule.identity` names no module) is `holesInSeamsOfUnnamedModule`, whose one message leads with declaring a fulfilling type, then declaring the seam without `generateDependencyTree: true`, then how SafeDI comes to know the module under the only runs that reach it (the Xcode project plugin: a local Swift package; a run by hand: `--module-name`); never reading a module that depends on this one; a seam in neither `generatedSeams` nor `foreignSeams` — an added directory, a file no target lists — is built inline by every tree and has no hole. The guard hashes, after the parameters, each builder's label, the type its signature spells without `any` (`Builder.parameterTypeWithoutAny`, made by the function that spells the signature, attributes included, so nothing can be emitted and not hashed) and tier access, then every enum its builders reach in key order, each case's name and payload (fields and forwarded type, or the inner enum's key), then each staged place's stages; with no hole the input is unchanged. Mocks never see holes: they build every seam inline and take a flat parameter for a type they cannot build, as before. Diagnostics are keyed by declaration, so k sites report once.
