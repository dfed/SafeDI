# Seams: holes, builders, fills

- The configuration that governs a module's own generation (imports, directories, additional mocks, its mock condition) comes only from that module. A dependency module's configuration is read only for its `mockConditionalCompilation`, to check a call of its seam or public mock (`GenerateCommand.seamResolution`, `publicMockUnderOtherMockCondition`; see `seams.md`).
- **An erased rename of an optional dependency is mapped.** `ScopeGenerator.aliasValue` binds an alias with `erasedToConcreteExistential: true` to `(x as X?).map { AnyX($0) }` whenever its `ofType:` is optional or its binding may be (`fulfillingValueMayBeOptional`), required or `onlyIfAvailable`, and it is the one site production, mocks, and seams share. Never decide the wrapping from the binding alone: a required rename of `x: X?` reads a forwarded optional, a mock's optional parameter or override, or the non-optional value a promoted node or a lexically enclosing `let` holds, and the mapped expression compiles over each.
- **Seams: holes, builders, fills.** In a seam's tree as the seam map builds it, an `@Instantiated` property whose instantiated type (`Dependency.asInstantiatedType`) no production declaration the map holds fulfills (none, or only `mockOnly`) is `Scope.PropertyToGenerate.hole`, unless its spelling is one no nominal type can be (`DependencyTreeGenerator.canBeHole`, by spelling: a closure, tuple, array, dictionary, metatype, `Void`, optional, opaque or attributed type stays `noInstantiableFound`; a typealias of a closure is a hole, which only hand-written code fills). A hole is a build site, a node of the seam's generator tree (`ScopeGenerator(holeProperty:…)`), never a type: a property built at k sites is k holes, each with its own builder and scope struct, never grouped, intersected or merged; a cycle-closing scope builds nothing and so holds no site. `SeamSignature.holes` is kept apart from `parameters`, so a builder is never receivable in its own seam's tree, and every reader of `parameters` is unchanged; every tier takes every builder, after the parameters, in builder-label order, and a hole whose tier access is narrower than a tier is `tierOmitsBuilder`, once per declaration, explained by `SeamAccessExplanation` as a required parameter's omission is, with the builder's remedy (`ParameterKind.builder`) in a pass-through's place. A builder's tier access is `TypeAccessProof`'s over the property's type, the hole's owner admitting its module, with a passed-up builder's scope struct counting as the type of the seam that declares it, capped at the seam's type; a field's access is the proof of its type, the declaring type admitting its module, capped the same way (a pass-through keeps its parameter's); each keeps the proof's cause (`Hole.accessCause`, `Field.accessCause`), which `fieldNotReadable` explains with the shared formatter too. `SeamBuilderParameters.swift` computes the holes from the seam root's generator tree, in this order: sites in generation order (`buildSites`, which walks only subtrees whose `containsBuildSite` holds, ordering each scope's children with `orderedChildrenComputedAfresh`, the order generation will use), then each site's fields, then names; `SeamSignature` hashes the guard from the result. A label is a field exactly when its nearest declaration on the site's path – the seam's parameters, then each path scope's forwarded properties and children, an `onlyIfAvailable` alias bound to `nil` included – is bound before the site; a nearer declaration bound later hides a farther bound one (`UncarriedDeclaration`), since Swift would bind the farther one. The lazily instantiated instance form is never a field: the field is the wrapper. Each `@Sendable` builder function on the path (`buildsInSendableFunction`) starts a stage: the seam calls each stage but the last just before declaring that function (`SeamHoles.stageCalls(at:)`), binding the returned `@Sendable` function, and calls the last at the site. A builder is always `@escaping` and returns the property's declared type; a builder is also `@Sendable` where the seam's tree passes it on from inside a `@Sendable` builder function, a passed-up one or its own handed to a call that re-enters the seam, or passes it to a call that takes it `@Sendable`: one builder per site joins the hidden labels and the sendability of every route that presents the site. In `orderedPropertyToGenerateIndices`, a child whose subtree holds a site (a carrier) starts after every child that is no carrier and depends on none through the final edges; every edge is computed exactly as without holes, so no availability changes, and a tree without a carrier keeps the index order. A sibling that depends on a carrier and is declared after a later carrier is built after it: a fill reading it is reported (`FillFinding.Kind.declarationBoundAfterSite`), a deliberate gap a finer order could close later. A caller's seam leaf gets `Scope.holeArguments`: `.fill` where its declarations hold a production fulfiller (`fulfillingInstantiable(of:in:)`), else `.passUp`, which a seam's tree turns into a builder parameter of its own per inner site, shared by every call, and which in a root's tree is `unfilledHoles`, reported at the root's dependency with a note at the hole where its file is readable. A hole is identified by its site (`scopeSeamType`, `sitePath`), which a passed-up hole keeps; a seam never takes a site it already takes, and a call that presents one passes the seam's builder by its internal name (`SeamHoles.hole(taking:)`); `SettledContent.Hole` carries a hole's hidden labels, which only accumulate, so a cycle of seams settles. A fill (`ScopeGenerator(fill:key:functionName:boundLabels:child:)`) declares the fields it binds from its struct as its properties (`fillStructBoundLabels`, `fillBoundFields`), so a receive they provide is not received from the call's enclosing scopes; it binds every field but one from a deferred parameter, which it reads from the caller's scope – the declaration the call passed the parameter – as inline, so the seam analysis (`fields(of:)`, `receivers(in:)`, `declarationsBound(by:…)`) treats that label as the caller's, and the capture walk's fill branch (`fillCaptures`, with `NonSendableWrapperCapture.capturingFillSeamType` for a `@Sendable` stage) reports a `@Sendable` function in the fill that would capture a non-`Sendable` wrapper the caller declares, with inline's error; the one exception is a label a declaration on the path to a call inside a fill of the same seam call that passes this fill on hides (`fillDeferredLabelsHiddenByReenteringCalls`, from `hiddenByReenteringCalls(ofFills:)` over the pass before's tree, another pass of `createScopeGenerator` running while it changes, `fillStructBoundLabelsChangedInTree`), which the fill, one function, binds from the struct's field at its top – the one place a fill reads a deferred value early, which the Manual states; its child is the fulfiller's scope built with the stack the seam whose tree holds the site has at the site (`Hole.fillPropertyStack`, the owner's stack, which inside a seam's own fill is the filled seam's), never the filler's path, while a value it takes from the caller's scope is available as to a pass-through of the call, so one the caller's path is still building is passed `nil`; a site inside a seam's own fill carries every field of the filled seam's struct, which the fill binds: a repeat of the hole's property closes on the fill's own builder function, and a repeat of a property of the seam's path is reported (`FillFinding.Kind.closesCycleInSeamTree`), never a rebuild. A fill is keyed by the site it fills; a call inside it of the seam that holds the site, or of a seam that passes the site up, passes the fill, and a fill is never declared inside itself. A fill is named `__safeDI_<builderLabel>`, with `_` appended while a fill of an enclosing call, or a builder the enclosing seam takes, has that name (`ScopeGeneratorUnderConstruction.Fill`), so the closer declaration never shadows the one a call inside it passes. A fill passed to such a call reads the outer call's values, so a label declared on the path from the root of any fill of the same seam call to a call inside it that passes this fill hides every read the fill resolves from the caller's scope (`FillFinding.Kind.declarationBoundOnPathToReenteringCall`, naming the fill whose tree holds the path, as `boundByPassingUpSeam` hides the labels a passing-up seam binds), and a fill passed to a call of a seam that passes the site up honors that seam's copy of the hole too: the labels it does not carry hide the reads (`declarationBoundAfterSite`), and its sendability makes the fill `@Sendable`; the hidden sets are computed per seam call, over every fill's tree, in `hiddenByReenteringCalls(ofFillsOf:)`. A fill made `@Sendable` that way and capturing a non-`Sendable` wrapper of the caller is reported by the capture walk's fill branch; one capturing another non-`Sendable` value fails to compile, as the inline tree does inside that seam's `@Sendable` builder function. A fill a `@Sendable` function that does not enclose it refers to is `@Sendable` (`referencedFillKeys`, `sendableFillKeys`, like `buildsInSendableFunction` for cycle closers), as is one a call inside it passes to a seam that takes it `@Sendable` (`HoleCallArgument.hole`). Before generation `validateFills` (`DependencyTreeGeneratorError.fillFindings`) reports each receive in a fill's tree that a field does not give inline's value – the nearest declaration of its label is bound after the site (`declarationBoundAfterSite`, which also covers a label a passing-up seam binds on a path to its call of the inner seam, inside the seams and fills on that path included: `boundByPassingUpSeam`), the field is at an access the filler cannot read (`fieldNotReadable`), or held only optionally while the receive requires it (`fieldHeldOnlyOptionally`), or a scope of a fill of the same seam call declares its label on the path to a call that passes the fill on (`declarationBoundOnPathToReenteringCall`) – and each cycle closed on the seam's path (`closesCycleInSeamTree`), keyed by kind and location; its membership test runs on the filler's generator tree, where a seam is a leaf, while the cycle walk below inlines every seam; and `rootScopeGenerators` walks, for cycles only, every foreign seam with holes from its own root over the validated scopes (`validateCyclesFromRootsOfForeignSeamsWithHoles`), which reports the seam's own cycle diagnostic where a fill would close a cycle with no instantiator along it that the filler's walk closes earlier. `validateReachableTypeDescriptions` reports a missing fulfiller only outside every seam's tree (the fills this module generates for foreign seams entered), and a hole in a seam this run generates (`generatedSeamTypes`) while its module is unnamed (`EmittingModule.identity` names no module) is `holesInSeamsOfUnnamedModule`, whose one message leads with declaring a fulfilling type, then declaring the seam without `generateDependencyTree: true`, then how SafeDI comes to know the module under the only runs that reach it (the Xcode project plugin: a local Swift package; a run by hand: `--module-name`); never reading a module that depends on this one; a seam in neither `generatedSeams` nor `foreignSeams` — an added directory, a file no target lists — is built inline by every tree and has no hole. The guard hashes, after the parameters, each hole's builder label, builder type without `any`, tier access and every field of every stage (label, type without `any`, access); with no hole the input is unchanged. Mocks never see holes: they build every seam inline and take a flat parameter for a type they cannot build, as before. Diagnostics are keyed by declaration, so k sites report once.
