# Graph fuzzer: calling mocks mirror production

A *calling mock* is a generated `mock()` (`generateMock: true` or `.public`) whose tree calls another module's public mock. Contract rule 7's calling-mock clause (`seam-and-mock-contract.md`) says it fills a place wherever the same tree built for production fills it, reports production's error wherever production reports one, and passes a place up as a required builder only for a permanent reason: its module sees no implementation of the place's type (reason 1), or the implementation reads a name the mock's tree hides (reason 3, which has no computable definition yet). Reason 2, an implementation that receives what nothing in the mock's tree builds, is withdrawn for internal and `.public` mocks alike: production takes that value as a parameter and fills the place, so the mock must too.

- **The check** (`GraphFuzzerCallingMockCheck`, `Tests/SafeDIToolTestSupport/GraphFuzzerCallingMocks.swift`) runs a graph twice through the module-info flow, without compiling: as drawn, and as its *production twin*, the same sources with the caller's `@Instantiable(generateMock: …)` line replaced by `@Instantiable(generateDependencyTree: true)` (the seam form, never `isRoot: true`, since a root rejects the holes and unprovided receives a seam passes up; an internal caller stays internal, which the tool accepts as a seam). Where the twin rejects the graph, the mock must be rejected at the same sites: each error's and note's file, line and declaration (`GraphFuzzerDiagnosticSite`), never the text, which a fix may reword. Where the twin is accepted, the mock must be too, and every parameter of its `mock()` but `safeDIOverrides` and the flat parameters the graph names is a place it passes up, classified by the graph's facts: reason 1, else unclassified, which fails (reason 3 is never assigned until it has a definition). A twin whose outcome is not the one the graph is drawn for is a drawing defect, never a mirroring requirement. The failures are `GraphFuzzerFailure.Kind`'s `callingMock…` kinds; a known issue documents two of them (`.callingMockAcceptedWhereTwinReportsShapeError`, `.callingMockPassesUpUnclassifiedPlace`).
- **The draw** (`GraphFuzzerCallingMockDraw`, its own stream, `callingMockRandomSeedMask`, so no other corpus graph changes) fills all 28 cells (`GraphFuzzerCallingMockCell`): six shapes and one control, each with an internal and a `.public` caller and a plain place or a deferred one (`ErasedInstantiator<Int, any P>`, whose fill forwards `id: Int`). The shapes: a fill receiving a value the outer seam builds; an app-only screen in a loop of the seam's screens; a seam built again whose fill reads a value of the level between; a loop through an inner seam's builder (the outer seam holds `innerBuilder` and a sibling that receives it, and the fill receives the sibling); a fill receiving the caller's own value, which the twin fills; and an implementation that receives a value nothing in the tree builds, which the twin takes as a parameter and fills from. The control: no visible implementation. A plain app-only screen is built by value, so its loop is a constant cycle, which the twin reports as a dependency cycle at the screen's receive of the feed's builder, and the mock must report too. Seed `s` draws `drawnCells[s % 28]`; seeds `0..<280` give each cell ten graphs, which differ in names and in a leaf the caller declares before or after its property.
- **Known issues.** `SafeDIToolGraphFuzzerCallingMockTests.callingMockKnownIssues` lists one entry per cell that fails on main: all 24 shape cells. Only the four cells of the control pass. The mock work empties them; a seed that passes is reported stale. The hand-written tests pin each shape's twin sites and wrap the failing contract assertion in `withKnownIssue`; the seam built again also compiles main's mock, which fails (`missing argument for parameter 'logger'`).
- **Not drawn yet:** lazy and `@Sendable` places, a second hole type, a caller that forwards a value. Each joins the cells when drawn.
- **Report only.** `publicMockCorpusCallingMocks_reportTwinsShapeErrors`, run with `SAFEDI_GRAPH_FUZZER_CALLING_MOCK_TWIN_REPORT` set, runs each mocked consumer of the public mock corpus's accepted graphs as its twin and prints the consumers whose twin reports a shape error (`GraphFuzzerCallingMockTwinReport.shapeErrorMarkers`) or another error. It fails nothing: the rule for mirrored rejections is applied to its count before the mock work lands.
