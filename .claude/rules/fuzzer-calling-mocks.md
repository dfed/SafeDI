# Graph fuzzer: calling mocks mirror production

A *calling mock* is a generated `mock()` (`generateMock: true` or `.public`) whose tree calls another module's public mock. Contract rule 7's calling-mock clause (`seam-and-mock-contract.md`) says it does what its production twin does: it fills a place where the twin fills it, reports the twin's error where the twin reports one, and passes a place up only where the twin takes a builder for it, which is where its module sees no implementation of the place's type. An implementation that receives what nothing in the mock's tree builds is no reason to pass a place up, for internal and `.public` mocks alike: production takes that value as a parameter and fills the place, so the mock must too. One outcome differs by rule 7's list: where the called type's tree builds that type again, or a call inside a fill re-enters the called mock's root level, the twin reports that its caller cannot hand the place the value nearest it, and the mock, which builds the called type inline, hands it that value and is accepted. That outcome is agreed only when the mock's values equal those of the same types built inline (`SafeDIToolCallingMockMirrorsProductionTests`' value cells, and the check below); no pass-up reason, flag or list entry stands for it.

- **The check** (`GraphFuzzerCallingMockCheck`, `Tests/SafeDIToolTestSupport/GraphFuzzerCallingMocks.swift`) runs a graph twice through the module-info flow: as drawn, and as its *production twin*, the same sources with every `@Instantiable(generateMock: …)` of the caller's module (the draw declares one, the caller's, besides a mocked intermediate type, below), or the plain `@Instantiable` of a caller the module lists in `additionalMocksToGenerate` (the graph's `mockConfiguration`, a `SafeDIConfiguration.swift` beside the caller's file in the mock form only), replaced by `@Instantiable(generateDependencyTree: true)` (the seam form, never `isRoot: true`, since a root rejects the holes and unprovided receives a seam passes up; an internal caller stays internal, which the tool accepts as a seam). Where the twin rejects the graph, the mock must be rejected at the same sites: each error's and note's file, line and declaration (`GraphFuzzerDiagnosticSite`), never the text, which a fix may reword. But where the tool skips the twin's error in the mock (`mockSkipsTwinsError`: the graph's twin error is one the tool checks only where the generated mocks compile, a plain implementation's fill that instantiates a type no declaration can fulfill, `twinErrorIsCheckedOnlyWhereMocksCompile`, and its `mockBuild` leaves the mock condition inactive), the mock must be accepted (`callingMockRejectedWhereMockConditionIsInactive` otherwise), passing up the place. The one exception is rule 7's outcome above, recognized by the twin's text: where every error the twin reports is that a seam built again passes its builder on unchanged (`reportsOnlySeamBuiltAgain`, `seamBuiltAgainMarker`) and the mock is accepted, the graph must state probes, and, where values are compared, the mock must compile and its probes build what they build of the same types built inline (`inlineModules`: the twin's files in one module named after the caller's, imports of the graph's modules dropped, the caller's module's seams roots, every other seam and public mock a plain `@Instantiable`), each known-right expression calling the caller's root initializer there (`callingMockBuildsOtherValuesThanInline`); a graph without probes fails as `callingMockAcceptedWhereTwinReportsShapeError`, and an inline build the tool rejects or that does not compile throws, as a twin that does not compile does. Where values are not compared (a seed the cell test does not compare, or compile verification off), nothing more is judged of that outcome, as of an accepted twin's. Where the twin is accepted, the mock must be too, and every parameter of its `mock()` but `safeDIOverrides` and the flat parameters the graph names is a place it passes up; a generated file that declares no `mock()` in an extension of the caller throws, so a mock the parser misses never reads as one that passes nothing up. Each flat parameter the graph names must be among the `mock()`'s parameters (`callingMockLacksFlatParameter`, judged after the pass-ups, so main's known issues keep their kind). A pass-up is classified only when its label is among the places the graph says its module sees no implementation for, or the tool skips the twin's error for (`expectedPassUpLabels`, reasons `noVisibleImplementation` and `mockConditionIsInactive`); every other is unclassified, which fails, since a hidden name is never assigned until it has a definition. Where the twin is accepted, the check also reads the twin's seam initializers' parameters (`__safeDI_` stripped) and requires those the graph is drawn for (`expectedTwinInitializerLabels`: none where production fills the place, the value nothing builds, or the control's builder), so a fill the twin was meant to make is observed. A twin identical to its mock, or rejected while a module other than the caller's generates, is a drawing defect; a form the tool accepts without a generated file for the caller's module throws. A twin whose outcome is not the one the graph is drawn for is a drawing defect, never a mirroring requirement. Where both forms are accepted and the mock passes up no place without a reason, the check compiles both with the differential value comparator and compares what the graph's probes build (`valueFailure`, `valueProbes`): the calling mock against the twin's seam initializer, or, where the graph `comparesValuesWithInline`, against the caller's root initializer in the same types built inline (`inlineModules`, `callingMockBuildsOtherValuesThanInline`), each type qualified by its module (Foundation declares `Host` on macOS), and for a deferred place one tuple of the caller and what the place's builder builds for `id` 7 (`callerAndFill(of:place:)`), since the comparator calls no `ErasedInstantiator` and numbers identities per probe, so the fill's received value shows as the caller's own or a second one. A mock path that does not compile fails, as does one whose probe traps or does not finish, and other values; any other comparator failure, such as a twin that does not compile or run or a probe that names no declaration, throws. The seam built again's cells state probes against that inline module (`seamBuiltAgainValueProbes`; a deferred place's probe holds the outer fill, the level between and the inner fill it builds again, since the comparator calls no `ErasedInstantiator`). The cell test compares the first graph of each cell with each leaf position it draws, and, in the shape whose fill receives the caller's lazy value below the called type's root, with each call it draws (`comparesValues(ofSeed:)`, at most 150 graphs of the forty-two probed cells, the seam built again's six among them), and fails a passing, unlisted compared seed that compared nothing (`comparisonProblems`). The failures are ten of `GraphFuzzerFailure.Kind`'s kinds, `callingMockAcceptedWhereTwinReportsShapeError`, `callingMockReportsOtherErrorThanTwin`, `callingMockRejectsWhereTwinAccepts`, `callingMockRejectedWhereMockConditionIsInactive`, `callingMockPassesUpUnclassifiedPlace`, `callingMockLacksFlatParameter`, `callingMockDoesNotCompile`, `callingMockFailsWhenRun`, `callingMockBuildsOtherValuesThanTwin` and `callingMockBuildsOtherValuesThanInline`, and a self-test makes each of the ten fire with files any tool judges alike, so none depends on main's defects: a mock rejected one line below its twin's error (`.callingMockReportsOtherErrorThanTwin`); a mock rejected in a release build for an error every build reports, its fill's read of the outer seam's value, which the graph says the tool skips (`.callingMockRejectedWhereMockConditionIsInactive`); a mock rejected where its twin is accepted (`.callingMockRejectsWhereTwinAccepts`); a mock whose fill reads nothing, accepted where its twin's fill reads the outer seam's value, and a seam built again's graph that states no probes (`.callingMockAcceptedWhereTwinReportsShapeError`); a mock of a seam built again whose fill builds the `Logger` inline's fill receives, and a mock whose accepted twin's graph compares it with inline and whose fill builds the `Database` inline's fill receives from the caller (`.callingMockBuildsOtherValuesThanInline`); a graph with no visible implementation that says one is visible (`.callingMockPassesUpUnclassifiedPlace`); a graph that names a flat parameter its mock does not take (`.callingMockLacksFlatParameter`); a mock whose module holds an expression that does not compile (`.callingMockDoesNotCompile`); a mock whose fill traps (`.callingMockFailsWhenRun`); and a mock whose fill builds the `Database` its twin's fill receives from the caller (`.callingMockBuildsOtherValuesThanTwin`, in a plain and a deferred place).

- **Known issues.** `SafeDIToolGraphFuzzerCallingMockTests.callingMockKnownIssues` lists one entry per cell that fails: every cell passes, the seam built again's by building what inline builds, but those of the fill that receives the caller's lazy value below the called type's root, whose compared seeds' mocks do not compile until that defect's fix (`.callingMockDoesNotCompile`, which the fix removes with the entries). A listed seed that passes is reported stale, except one whose every signature is `.callingMockDoesNotCompile` in a run with compile verification off, which compiles nothing. Each entry lists seeds of one shape cell, never the control's, in increasing order (`callingMockKnownIssueListProblems`), and no count is required, so a fix deletes the seeds and entries it mends and nothing else. The hand-written tests pin each shape's twin sites, require the twin's intended outcome and that the mock mirrors it; the seam built again's test (`callingMock_buildsInlineValues_whenFillReadsValueOfLevelBetweenBuildsOfSeam`) also requires that the twin's error is recognized as that outcome, and compares the mock's values with inline's, and `callingMock_compiles_whenFillReadsValueOfLevelBetweenBuildsOfSeam` compiles its mock. The twin's seam initializer labels are read from the initializers of an extension of the caller itself, never of a type nested in one, such as the builder struct a seam's enum declares.
