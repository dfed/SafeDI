# Graph fuzzer: calling mocks mirror production

A *calling mock* is a generated `mock()` (`generateMock: true` or `.public`) whose tree calls another module's public mock. Contract rule 7's calling-mock clause (`seam-and-mock-contract.md`) says it fills a place where production fills it, reports production's error where production reports one, and passes a place up only when its module sees no implementation of the place's type, or the implementation reads a name the mock's tree hides, which has no computable definition yet. An implementation that receives what nothing in the mock's tree builds is no such reason, for internal and `.public` mocks alike: production takes that value as a parameter and fills the place, so the mock must too.

- **The check** (`GraphFuzzerCallingMockCheck`, `Tests/SafeDIToolTestSupport/GraphFuzzerCallingMocks.swift`) runs a graph twice through the module-info flow, without compiling: as drawn, and as its *production twin*, the same sources with the caller's `@Instantiable(generateMock: …)` line replaced by `@Instantiable(generateDependencyTree: true)` (the seam form, never `isRoot: true`, since a root rejects the holes and unprovided receives a seam passes up; an internal caller stays internal, which the tool accepts as a seam). Where the twin rejects the graph, the mock must be rejected at the same sites: each error's and note's file, line and declaration (`GraphFuzzerDiagnosticSite`), never the text, which a fix may reword. Where the twin is accepted, the mock must be too, and every parameter of its `mock()` but `safeDIOverrides` and the flat parameters the graph names is a place it passes up. A pass-up is classified only when its label is among the places the graph says its module sees no implementation for (`expectedPassUpLabels`); every other is unclassified, which fails, since a hidden name is never assigned until it has a definition. Where the twin is accepted, the check also reads the twin's seam initializers' parameters (`__safeDI_` stripped) and requires those the graph is drawn for (`expectedTwinInitializerLabels`: none where production fills the place, the value nothing builds, or the control's builder), so a fill the twin was meant to make is observed. A twin identical to its mock, or rejected while a module other than the caller's generates, is a drawing defect; a form the tool accepts without a generated file for the caller's module throws. A twin whose outcome is not the one the graph is drawn for is a drawing defect, never a mirroring requirement. The failures are four of `GraphFuzzerFailure.Kind`'s kinds, `callingMockAcceptedWhereTwinReportsShapeError`, `callingMockReportsOtherErrorThanTwin`, `callingMockRejectsWhereTwinAccepts` and `callingMockPassesUpUnclassifiedPlace`; a known issue documents two of them (`.callingMockAcceptedWhereTwinReportsShapeError`, `.callingMockPassesUpUnclassifiedPlace`), and two self-tests make the other two fire (a mock rejected one line below its twin's error, `.callingMockReportsOtherErrorThanTwin`; a mock rejected where its twin is accepted, `.callingMockRejectsWhereTwinAccepts`).
- **The draw** (`GraphFuzzerCallingMockDraw`, its own stream, `callingMockRandomSeedMask`, so no other corpus graph changes) fills all 28 cells (`GraphFuzzerCallingMockCell`): six shapes and one control, each with an internal and a `.public` caller and a plain place or a deferred one (`ErasedInstantiator<Int, any P>`, whose fill forwards `id: Int`). The shapes: a fill receiving a value the outer seam builds; an app-only screen in a loop of the seam's screens; a seam built again whose fill reads a value of the level between; a loop through an inner seam's builder (the outer seam holds `innerBuilder` and a sibling that receives it, and the fill receives the sibling); a fill receiving the caller's own value, which the twin fills; and an implementation that receives a value nothing in the tree builds, which the twin takes as a parameter and fills from. The control: no visible implementation, whose mock's pass-ups must be exactly the hole's builder. The app-only screen's loop closes only through builders, so its plain place is the canonical one, a builder that forwards nothing (`ErasedInstantiator<(), any SettingsPage>`); a screen built by value, whose loop is a constant cycle, has a hand-written test only. Seed `s` draws `drawnCells[s % 28]`; seeds `0..<280` give each cell ten graphs, which differ in names and in a leaf the caller declares before or after its property.
- **Known issues.** `SafeDIToolGraphFuzzerCallingMockTests.callingMockKnownIssues` lists one entry per cell that fails on main: all 24 shape cells. Only the four cells of the control pass. The change that makes a calling mock mirror its production tree, which lands before 2.3.0, empties them; a seed that passes is reported stale. Each entry lists seeds of one shape cell, never the control's, in increasing order (`callingMockKnownIssueListProblems`), and no count is required, so a fix deletes the seeds and entries it mends and nothing else. The hand-written tests pin each shape's twin sites and wrap the failing contract assertion in `withKnownIssue`; the seam built again also compiles main's mock, which fails (`missing argument for parameter 'logger'`).
- **Not drawn yet:** lazy and `@Sendable` places, a second hole type, a caller that forwards a value, and a deferred place that forwards nothing (`Instantiator<T>`, `ErasedInstantiator<(), any P>`) outside the app-only screen's loop: elsewhere a plain place is held by value and a deferred one forwards `id`, so for the outer seam's value, the loop through an inner seam's builder, the seam built again and the accepted shapes, forwarding and deferral change together. Each joins the cells when drawn.
- **Report only.** `publicMockCorpusCallingMocks_reportTwinsShapeErrors` runs only by hand: `SAFEDI_GRAPH_FUZZER_CALLING_MOCK_TWIN_REPORT=1 swift test --traits sourceBuild --filter SafeDIToolGraphFuzzerCallingMockTests/publicMockCorpusCallingMocks`. It runs each mocked consumer of the public mock corpus's accepted graphs as its twin and prints the consumers whose twin reports a shape error (`GraphFuzzerCallingMockTwinReport.shapeErrorMarkers`) or another error. It fails nothing: the rule for mirrored rejections is applied to its count before that change lands.
