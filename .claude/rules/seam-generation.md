# Seams: leaves, calls, and the callers' view

Continues `seam-access-proof.md`.

Every call of a seam's tier builds a leaf over the WHOLE signature (`seamLeafInstantiable`): the tier's parameters as the tier takes them, and each parameter the tier omits or no tier takes as a `@Received(onlyIfAvailable: true)` dependency, which the emitted call never passes (`SeamCall.parameters` stays the tier's) but which orders the leaf among its siblings and reaches the trees that call it as inline receivers would. A caller whose tree would hand such a parameter a binding is `seamTierOmitsProvidedValue`, found by `ScopeGenerator.seamTierOmissions(ofTreeRootedAt:)`, a walk over each root's finished generator tree modeled on `nonSendableWrapperCaptures` (generation's `unavailableProperties` and `propertiesGeneratedLater`, the closest declaration of each label), run for every root before any code is generated and reported for every root in source order – never at emission, never from a side channel of `generateCode` – at the provider's declaration, or, when the provider's file cannot be read (`EmittingModule.isReadableFile`), at `SeamTierOmission.referenceLocation`, the closest own-file dependency on the path to the call as the construction check finds it, with the provider's module named; its notes are the parameter's receivers, or, for the seam's own property, of which a signature records no receiver, the call's leaf's own receive. A receive that reaches an outer seam only through a nested seam call that omits it is a no-tier receive, and a label all of whose receivers are no-tier is a parameter on no tier (`SeamSignature.noTierParameters`: received only if available, taken by no tier, ignored by the guard and `CallShape`, part of `SettledContent`, declared by every leaf of the outer seam, and never receivable inside its own seam's tree). A mock never calls a seam tier. The seam map's scopes carry `builtInlineSeamComment(for:)` as the validated maps' do, a leaf's from its instantiable. In a module that holds a seam, `rootScopesThisModuleGenerates` checks every construction where it is generated: each root's seam-world tree, in which a seam is a leaf constructed with the tier its caller reaches, and each generated seam's tree, which compiles in the seam's module (`checkingSeamTrees`, reported together with the roots'); the validated inline scopes decide nothing about access there, since they would report constructions beneath a foreign seam that the module never emits. A root declared outside the module's own files is never generated there, so the tier a module calls (an own seam at the narrowest tier, a foreign one at the narrowest the caller reaches) is always the one its own roots' trees call. A `fileprivate` or `private` tier is therefore never generated: `parameterAccess` counts those levels as `internal`, since the receiver such a tier would take a parameter from, or the seam's own type at that level, is constructed in a tree that check rejects. The guard enum `__safeDI_<Seam>_<FNV-1a of labels, types, tier access, isOnlyIfAvailable>` is generated beside the initializers and referenced on the line before every generated call (`seamGuardLines`, which makes the leaf's construction a builder function), with a comment on that line (`SeamCall.comment`, a `SeamCallComment`) on every call to another module's seam: under the SwiftPM plugin it says to add the SafeDI plugin to the target that declares the seam; in a `.safedi` flow, where the seam's module ran SafeDI, it says to compile the code SafeDI generated for that module into it, naming how under Bazel, Tuist and a custom build. The graph fuzzer's multi-module oracle excuses both as integration-specific (`integrationSpecificTrailingComments`). A run given neither `--swift-manifest` nor `--output-directory` – Bazel's, Tuist's, a custom script's, never a build tool plugin's, whose fallback passes `--output-directory` – writes one more comment per generated file (`SeamResolution.carriesUnreadTypeComment`, `UnreadTypeComment`): each `public` declaration it generates that names a type SafeDI reads no declaration of (`TypeAccessProof.unreadTypes(namedBy:mentionedFrom:)`: no entry, no record a mention resolves to, no recorded enclosing type, and not one of the standard types `isAllowlisted` lists; plus the unread type an entry or record is declared in an extension of) – a seam's `public` tier, by its parameters and the types its builders return, a `public` field of a scope struct or case payload, a public mock's `public` tier, provider and `SafeDIMockScope` struct – carries a marker line, and the emitter of the combined file replaces the first marker with one comment naming every marker's types, ordered by spelling, and drops the rest, so the comment sits above the first declaration the compiler can report a `package` type of an unscanned module at. A `package` tier never carries one: a type its module can name is at least `package` there. Every tier carries the seam's `generatedInitializerAttributes` (the macro's `generatedAttributes` when given), as a root's generated `init()` does, since a caller can reach any tier and a wider tier calls the next narrower one; the guard hashes no attributes, since no call depends on them. Both sides compute from the seam's module's visible declarations (`SeamResolution.ForeignSeam.visibleInstantiables`, normalized and resolved as a subset): the module's entry plus its `dependencyModuleNames`' entries, every one present by construction in the views of the `.safedi` files this run was given (`MergedModuleInfoView`, which reads a module given twice once and rejects two entries of one module that differ, `ModuleInfoDisagreementError`; a module this run was given is read from its own file, with positions, and one only a view carries without them), or, under the plugin, every target reachable from it in the target graph (`ModuleMembership.dependencyModuleNames(ofModuleNamed:)`); a declaration the callers cannot see – under the plugin's target graph an additional directory's – is an error at a seam only when it changes the seam's signature (below). A seam whose module SafeDI does not know (an additional directory's file, a file no target lists) is in neither `generatedSeams` nor `foreignSeams` and is built inline everywhere, with no call; each production construction of it ends in a comment saying so (`builtInlineSeamComment(for:)`, before the `package`-assumption comment when both apply, whatever the declarations' access); when some declaration this run sees is one the callers cannot see, `GenerateCommand.seamResolution` builds the callers' view (`SeamResolution.callersVisibleInstantiables`, only under the target graph (`callersComputeFromTargetGraph`): the files the graph attributes to this module and its transitive dependencies, without the directories the configuration adds – resolved as the callers resolve them), `seamRoots` computes each generated seam's signature over it a second time (`seamSignatures` returns a `SeamSignatureComputation`: each seam's signature, the errors of each component's last pass, and the seams those errors belong to), and a seam whose `SeamSignature.callShape` – what a call depends on and the guard hashes: each parameter's label, type spelled without `any`, tier access and whether it is received only if available, and the tiers; never the receivers or the parameter's `access` before the seam's type caps it, which an unseen declaration's wider mention can change without changing any call – the callers compute otherwise, or whose callers'-view computation throws (a seam is reported on its own call shape, so one that passes through parameters of a seam its callers cannot compute is reported too, as when that seam's computation merely differs), is `SeamError.Kind.treeReachesDeclarationCallersCannotSee` under the target graph and `treeReachesDeclarationOfUnnamedModuleInfo` under the `.safedi` flow, naming a declaration the callers cannot see (`unseenDeclarationToName`), in tiers, the first by source location within each: one that declares a receiver of a parameter the callers would not take as such – where their computation threw, one whose label the thrown error names – else one that fulfills such a parameter's type (a received nested type they qualify otherwise), else one the seam's tree reaches; where none is, the earliest plain declaration of a module SafeDI knows no name of, or of a directory the configuration adds, that proves such a parameter's access (`earliestUnseenPlainDeclaration(provingAnyOf:)`, through `Cause.provingPlainDeclarations`), reported at that declaration as `treeReachesPlainDeclarationCallersCannotSee`, since without it the callers count the type as unread and so `public` – the callers' view is built when either kind of declaration lacks a module, and a public mock's callers' view names such a declaration the same way (`PublicMockFinding.callersCannotSeePlainDeclaration`); a seam whose call shape the callers compute the same, whatever its tree instantiates or who else receives its parameters, is not reported, a seam this run could not compute is reported with its own error alone, and a module whose own name is unknown is never checked, since its callers build its seams inline. The view is built only when a seam is generated, so a project without seams pays nothing. Mocks never see seams (`createMockTypeDescriptionToScopeMapping` inlines). Scan plans the seam's file among the module's own files only, named in the same `outputFileNames` call as the root files.

A fill that exactly one case of one of its call's dispatchers calls is generated as that case's body, not as a function of its own (`ScopeGenerator.inlinableFillKeys`, `FillDispatcher.InlinedFill`), since a function per place, beside the dispatcher's case, is most of what a caller compiles. It is one when its place has one stage, the seam's tree makes no stage call before it (`fillStageCalls`), nothing else refers to it by name (`namedFillKeys`, gathered bottom-up: an argument of a seam call that passes a fill or dispatcher by name – a staged builder, or an enclosing fill or dispatcher a call inside a fill passes as it re-enters the seam – and a dispatcher's case, of the call's own dispatchers or of a call inside any of its fills), it is `@Sendable` exactly when the dispatcher is, and its scope parameter is spelled `scope` (`inlinedFill(of:code:leadingMemberWhitespace:)`): a fill whose place carries a field, or whose tree reads a value of the caller's, labeled `scope` names its parameter apart, which the dispatcher's own parameter would hide, and keeps its function. The case binds only what the body reads – `case .x:`, `case let .x(scope):`, `case let .x(_, __safeDI_forwarded):` – since a bound value no one reads draws a warning (a fill reads no forwarded `Void`), and every other case returns its call, so the switch is a statement. Fills and dispatchers claim their names before any is inlined, so whether a fill is inlined never renames anything; the graph fuzzer's `holeOutputFeatures` reads a case that ends its line at its colon as a fill.
