# Seams: leaves, calls, and the callers' view

Continues `seam-access-proof.md`.

Every call of a seam's tier builds a leaf over the WHOLE signature (`seamLeafInstantiable`): the tier's parameters as the tier takes them, and each parameter the tier omits or no tier takes as a `@Received(onlyIfAvailable: true)` dependency, which the emitted call never passes (`SeamCall.parameters` stays the tier's) but which orders the leaf among its siblings and reaches the trees that call it as inline receivers would. A caller whose tree would hand such a parameter a binding is `seamTierOmitsProvidedValue`, found by `ScopeGenerator.seamTierOmissions(ofTreeRootedAt:)`, a walk over each root's finished generator tree modeled on `nonSendableWrapperCaptures` (generation's `unavailableProperties` and `propertiesGeneratedLater`, the closest declaration of each label), run for every root before any code is generated and reported for every root in source order – never at emission, never from a side channel of `generateCode` – at the provider's declaration, or, when the provider's file cannot be read (`EmittingModule.isReadableFile`), at `SeamTierOmission.referenceLocation`, the closest own-file dependency on the path to the call as the construction check finds it, with the provider's module named; its notes are the parameter's receivers, or, for the seam's own property, of which a signature records no receiver, the call's leaf's own receive. A caller's declaration is matched to a parameter its tier omits by label and type spelling (the parameter's `Property`), so a tree in another package that holds a value of that label whose unrelated type has the same name (another module's `Theme`) is reported too. A receive that reaches an outer seam only through a nested seam call that omits it is a no-tier receive, and a label all of whose receivers are no-tier is a parameter on no tier (`SeamSignature.noTierParameters`: received only if available, taken by no tier, ignored by the guard and `CallShape`, part of `SettledContent`, declared by every leaf of the outer seam, and never receivable inside its own seam's tree). A mock never calls a seam tier. The seam map's scopes carry `builtInlineSeamComment(for:)` as the validated maps' do, a leaf's from its instantiable. In a module that holds a seam, `rootScopesThisModuleGenerates` checks every construction where it is generated: each root's seam-world tree, in which a seam is a leaf constructed with the tier its caller reaches, and each generated seam's tree, which compiles in the seam's module (`checkingSeamTrees`, reported together with the roots'); the validated inline scopes decide nothing about access there, since they would report constructions beneath a foreign seam that the module never emits. A root declared outside the module's own files is never generated there, so the tier a module calls (an own seam at the narrowest tier, a foreign one at the narrowest the caller reaches) is always the one its own roots' trees call. A `fileprivate` or `private` tier is therefore never generated: `parameterAccess` counts those levels as `internal`, since the receiver such a tier would take a parameter from, or the seam's own type at that level, is constructed in a tree that check rejects. The guard enum `__safeDI_<Seam>_<FNV-1a of labels, types, tier access, isOnlyIfAvailable>` is generated beside the initializers and referenced on the line before every generated call (`seamGuardLines`, which makes the leaf's construction a builder function), with a comment on that line (`SeamCall.comment`, a `SeamCallComment`) on every call to another module's seam: under the SwiftPM plugin it says to add the SafeDI plugin to the target that declares the seam; in a `.safedi` flow, where the seam's module ran SafeDI, it says to compile the code SafeDI generated for that module into it, naming how under Bazel, Tuist and a custom build. The graph fuzzer's multi-module oracle excuses both as integration-specific (`integrationSpecificTrailingComments`). A run given neither `--swift-manifest` nor `--output-directory` – Bazel's, Tuist's, a custom script's, never a build tool plugin's, whose fallback passes `--output-directory` – writes one more comment per generated file (`SeamResolution.carriesUnreadTypeComment`, `UnreadTypeComment`): each `public` declaration it generates that names a type SafeDI reads no declaration of (`TypeAccessProof.unreadTypes(namedBy:mentionedFrom:)`: no entry, no record a mention resolves to, no recorded enclosing type, and not one of the standard types `isAllowlisted` lists; plus the unread type an entry or record is declared in an extension of) – a seam's `public` tier, by its parameters and the types its builders return, a `public` field of a scope struct or case payload, a public mock's `public` tier, provider and `SafeDIMockScope` struct – carries a marker line, and the emitter of the combined file replaces the first marker with one comment naming every marker's types, ordered by spelling, and drops the rest, so the comment sits above the first declaration the compiler can report a `package` type of an unscanned module at. A `package` tier never carries one: a type its module can name is at least `package` there. Every tier carries the seam's `generatedInitializerAttributes` (the macro's `generatedAttributes` when given), as a root's generated `init()` does, since a caller can reach any tier and a wider tier calls the next narrower one; the guard hashes no attributes, since no call depends on them. Both sides compute from the seam's module's visible declarations (`SeamResolution.ForeignSeam.visibleInstantiables`, normalized and resolved as a subset): the module's entry plus its `dependencyModuleNames`' entries, every one present by construction in the views of the `.safedi` files this run was given (`MergedModuleInfoView`, which reads a module given twice once and rejects two entries of one module that differ, `ModuleInfoDisagreementError`; a module this run was given is read from its own file, with positions, and one only a view carries without them), or, under the plugin, every target reachable from it in the target graph (`ModuleMembership.dependencyModuleNames(ofModuleNamed:)`); a declaration the callers cannot see – under the plugin's target graph an additional directory's – is an error at a seam only when it changes the seam's signature (below). A seam whose module SafeDI does not know (an additional directory's file, a file no target lists) is in neither `generatedSeams` nor `foreignSeams` and is built inline everywhere, with no call; each production construction of it ends in a comment saying so (`builtInlineSeamComment(for:)`, before the `package`-assumption comment when both apply, whatever the declarations' access); when some declaration this run sees is one the callers cannot see, `GenerateCommand.seamResolution` builds the callers' view (`SeamResolution.callersVisibleInstantiables`, only under the target graph (`callersComputeFromTargetGraph`): the files the graph attributes to this module and its transitive dependencies, without the directories the configuration adds – resolved as the callers resolve them), `seamRoots` computes each generated seam's signature over it a second time (`seamSignatures` returns a `SeamSignatureComputation`: each seam's signature, the errors of each component's last pass, and the seams those errors belong to), and a seam whose `SeamSignature.callShape` – what a call depends on and the guard hashes: each parameter's label, type spelled without `any`, tier access and whether it is received only if available, and the tiers; never the receivers or the parameter's `access` before the seam's type caps it, which an unseen declaration's wider mention can change without changing any call – the callers compute otherwise, or whose callers'-view computation throws (a seam is reported on its own call shape, so one that passes through parameters of a seam its callers cannot compute is reported too, as when that seam's computation merely differs), is `SeamError.Kind.treeReachesDeclarationCallersCannotSee`, naming a declaration the callers cannot see (`unseenDeclarationToName`), in tiers, the first by source location within each: one that declares a receiver of a parameter the callers would not take as such – where their computation threw, one whose label the thrown error names – else one that fulfills such a parameter's type (a received nested type they qualify otherwise), else one the seam's tree reaches; where none is, the earliest plain declaration of a module SafeDI knows no name of, or of a directory the configuration adds, that proves such a parameter's access (`earliestUnseenPlainDeclaration(provingAnyOf:)`, through `Cause.provingPlainDeclarations`), reported at that declaration as `treeReachesPlainDeclarationCallersCannotSee`, since without it the callers count the type as unread and so `public` – the callers' view is built when either kind of declaration lacks a module, and a public mock's callers' view names such a declaration the same way (`PublicMockFinding.callersCannotSeePlainDeclaration`); a seam whose call shape the callers compute the same, whatever its tree instantiates or who else receives its parameters, is not reported, a seam this run could not compute is reported with its own error alone, and a module whose own name is unknown is never checked, since its callers build its seams inline. The view is built only when a seam is generated, so a project without seams pays nothing. Mocks never see seams (`createMockTypeDescriptionToScopeMapping` inlines). Scan plans the seam's file among the module's own files only, named in the same `outputFileNames` call as the root files.

A fill that exactly one case of one of its call's dispatchers calls is generated as that case's body, not as a function of its own (`ScopeGenerator.inlinableFillKeys`, `FillDispatcher.InlinedFill`), since a function per place, beside the dispatcher's case, is most of what a caller compiles. It is one when nothing else refers to it by name (`namedFillKeys`, gathered bottom-up: an argument of a call of a seam or another module's public mock that passes a fill or dispatcher by name – an enclosing fill or dispatcher a call inside a fill passes as it re-enters the seam – and a dispatcher's case, of the call's own dispatchers or of a call inside any of its fills), the dispatcher takes no `passUp` (whose parameter would hide a `passUp` the fill's tree reads from the caller), it is `@Sendable` exactly when the dispatcher is, and its scope parameter is spelled `scope` (`inlinedFill(of:code:leadingMemberWhitespace:)`): a fill whose place carries a field, or whose tree reads a value of the caller's, labeled `scope` names its parameter apart, which the dispatcher's own parameter would hide, and keeps its function. The case binds only what the body reads – `case .x:`, `case let .x(scope):`, `case let .x(_, __safeDI_forwarded):` – since a bound value no one reads draws a warning (a fill reads no forwarded `Void`), and every other case returns its call, so the switch is a statement. Fills and dispatchers claim their names before any is inlined, so whether a fill is inlined never renames anything; the graph fuzzer's `holeOutputFeatures` reads a case that ends its line at its colon as a fill.

A seam's enums are NESTED BY TYPE (`scopeEnumsByType`, `SeamScopeEnumsByType.swift`) for its places and calls outside every fill: the root `SafeDIScope_<Stem>` describes the seam, and each type of its tree that leads to a place has `<Type>_Scope` nested in the root (`ScopeEnum.Key.describedType`, `rootTypeName`), the type spelled as the seam's module spells it (a caller computes the seam's tree over the seam module's own view, so a caller that declares a `Store` of its own still names `Store_Scope`; two types of one stem are both named apart, by module, then `_` in spelling order). Every generated type nested in the root (a nested enum, a payload struct) takes `_` while a case, another generated type, or a type spelled inside the root (a field's, a forwarded value's, an inner enum's) has its name. The seam's tree binds each wrapping case's payload just before building its property (`__safeDI_<stem>Values_<label>`, `valuesBindingNames`, one per path prefix that a plain case leads through, apart from the names bound above it and beside it, `SeamHoles.valuesBindings(at:)`), and a site or a passed-up call (`SeamSignature.CallRoute`) wraps its own case in them (`Hole.EnumPlace.route`). The `@Sendable` enum nests by the same rule: a type's case `p` holds the plain enum of the type `p`'s own `@Sendable` builder function builds (`case p(SafeDIScope_<Stem>.<U>_Scope)`), the inner plain enum a call made in that function hands up, or is a place held in a `Sendable` wrapper (`case p`, `case p(Forwarded)`); its case `p_Sendable` holds the `@Sendable` enum of the type `p` builds, or an inner `@Sendable` enum, named apart while another case of its enum has the name (a case keeps its label); its cases carry no values, so a place built in a `@Sendable` function is handed only what the innermost such function binds, and the plain root is declared with no case of its own where only the `@Sendable` enum leads to a plain enum, taking no builder (`ScopeEnumsByType.enums`, `Hole.EnumPlace.isBuiltBySendableBuilder`).

A builder is always `@escaping` and returns the property's declared type without its wrapper (`Hole.builtType`); the seam builds a wrapper that forwards no value (`ScopeGenerator.buildSiteCode`) around a function named as inline's builder function, which calls the builder, `@Sendable` for a `Sendable` wrapper, the builder function of a wrapper hole taking part in `builderFunctionNames` so that a cycle-closing scope beneath a sibling never resolves to it; an instantiator's forwarded value is the case's last value (`Hole.forwardedType`: `ErasedInstantiator`'s first generic unless spelled `()` or `Void`, and always `T.ForwardedProperties` for `Instantiator<T>`, since the seam cannot always see whether `T` forwards anything), which a case's payload lets escape whatever it is; every wrapper that forwards a value is built around a closure, whose `$0` the wrapper's generic signature types, instead of a function, since an `ErasedInstantiator`'s first generic can be a typealias of a function type, which a function's parameter would not let escape into the case, and a fill, which sees its fulfiller, writes `@escaping` when the fulfiller forwards one function, written out or a name its subtree declares `@escaping` (`ScopeGenerator.typesDeclaredEscaping`).

A level nested by type carries, after its type's forwarded properties, the parameters of its builder function that a lazy cycle closes on (`CycleParameter`) which any build of the type declares, inside a seam's fill whose code is generated or a `@Sendable` function too (`cycleParametersOfAnyBuild(inTreeRootedAt:)`, by label, in the order builds first declare them). A build whose function takes the parameter binds the field from it, so a place built inside such a function hands its fill the value the function was passed, as inline does, never the value of the chain the first build reports (`SafeDIToolSeamDeferredCycleParameterTests`). A build whose function does not take it binds the field as the type's tree reads the label there, so it holds what inline reads: the label, or the instance of the `LazilyInstantiated` it names where that is the seam's deferred parameter or a lazily instantiated declaration (`SeamHoles.valuesArguments(of:readingInstancesOf:)`, also for the place's own payload). That is the tangle of the graph fuzzer's seed 605, where `T`'s reader makes the function `Hub` builds `T` with take `mark` and the `T` that `Hub`'s `C` builds reads `C`'s (`SafeDIToolSeamHoleOnCycleTests`). Every build takes a label in one form, since a parameter's form follows from the receivers in the type's own tree. After them it carries each label any build of the type's builder function wraps again as a member of a loop of builders (`reboundPropertiesOfAnyBuild(inTreeRootedAt:)`, `ScopeGenerator.reboundProperties`): a build that rebinds the label binds the field from the wrapper it made, so a place built inside that function is handed what inline hands it, and any other build binds it from the label as its tree reads it there. Where every receiver in the type's tree receives the label only if available, the field takes the optional form, since a build outside the loop can bind it from an optional declaration. A loop member's payload holds no member of its own loop, which is still being built where the payload is bound: any member's function can call another's, so the payloads of every member are bound before the loop's first function (`BuilderFunctionNames.loopValuesBindingLines`), and the member's own level carries the wrapper its function makes again (`SafeDIToolSeamReceivedBuilderCycleTests`).

A root scope enum declares the enums nested in it in the order its cases first lead to their types, breadth first, each enum's cases in its type's declaration order (`ScopeEnumsByType.enums`), never in the order of the types' names, which the graph fuzzer's rename oracle would catch (seed 93 of the seam smoke batch, with the draw of types shared under a hole); only the names of two types of one stem, and the guard's key order, read spellings.

When every place of a hole type is in the `@Sendable` family, the plain root `SafeDIScope_<Stem>` has no case and the seam takes no plain builder, yet the root is still declared, as an empty namespace for the `<Type>_Scope` enums the `@Sendable` cases hold (`SafeDIToolSeamHoleOnCycleTests`' cycle closing on a function built by value); accepted, since moving the enums would make a type's enum name depend on which families exist.

A place inside a fill is nested by type too. The declaration graph enters each fill whose code is generated and whose tree builds a place or a call that passes one up, as an edge from the call's declaration to the declaration of the type the fill builds (`SeamDeclarationGraph.FillEdge`, `ReachedStep.filledBuilder`), and the calling type's enum has, after the call's own case, one case per call and builder filled, `<call>_<builder>`, the builder the called seam's (`ScopeEnum.Case.Kind.fill`; the labels keep their names and it takes `_` while another case has its name). It holds the type's level, the scope value of the root enum of the seam whose tree holds the filled place (`ScopeEnum.rootKey(of:)`), and the enum of the type the fill builds. For a place the called seam passes up, that is the deeper seam's root enum, in a case of its own named after that seam, `<call>_<builder>_<Seam>`, so adding a call to the called seam renames no case. It cannot be the called seam's: a call inside a fill of a seam that holds the site, or passes it up, passes that seam's dispatcher by name (`enclosingFills`), and the scope value such a call hands is the deeper seam's alone. What the passing-up seam binds is no level, as `boundByPassingUpSeam` rules. In the `@Sendable` family the case of the innermost `@Sendable` function carries the scope value and no level, and a `_Sendable` case carries neither. A fill that builds its type in a `@Sendable` builder function of the type's own (the filled place is held in a `Sendable` wrapper) binds nothing it was handed, so its case carries no scope value: the builder's fills that differ in this take a case each (`SeamDeclarationGraph.FilledBuilder.carriesInnerScope`), the one that carries it first, so each case's payload has one type on every route. The seam's tree binds the case's payload before the call (`__safeDI_<stem>Values_<case>`, keyed by path and case, `ValuesBindingKey`) and hands the scope value to each fill whose tree builds such a place, and to each dispatcher on the way, as a parameter named `__safeDI_<call>_<builder>`, apart from every name bound above it (`innerScopeNames`, `SeamHoles.innerScope(at:innerKey:)`, `FillCallerReads.innerScopeParameters`); the root enum's dispatcher names its own parameter so. A site inside such a fill carries only what the cases inside the innermost fill on its route hold (`fieldsCarried(by:)`), so the fill binds no field nothing reads. One fill of a case of the inner seam's nested by type stands for every place of the case (`ScopeGenerator.fillCaseHoles`): a place inside it takes the fields every place carries, and a label uncarried on one route, with no nearer field there, is uncarried for it. A caller reads a label that some route of the inner enum a case carries holds and another does not, where no level of the outer seam's on the route holds it, from its own scope on the other route, as for a label one place of a case carries and another does not (`InnerScopeReaders.labelsSomeInnerRouteLacks(of:)`, `Fill.callerReadLabels`): the fill's parameter is optional where no read requires it, and the root dispatcher's fallback is the caller's declaration or `nil`. A caller's dispatcher of such a case passes each value its target takes from the nearest of the inner seam's levels, through one reader per enum of the inner seam's that leads to a level holding the label (`InnerScopeReaders`: a one-level switch whose cases return, nearest first, what the enum they hold finds, then what the inner scope they carry finds, then their payload's field; non-optional where every route holds the label, the greatest such set of the recursive enums; named by the call's allocator after its dispatchers, `@Sendable` where a `@Sendable` dispatcher calls it), and else the case's payload's field or its own value (`reader(scope) ?? value`), binding the payload only where the reader falls back to it; a place's case binds `_` for the value an instantiator forwards, which the site's path says it carries, whichever seam's tree holds the place. One function fills every place of an inner case, and the dispatchers on the way pass it one scope value, so a case both of the inner seam's root enums reach (it builds the type both inside and outside a `@Sendable` function) whose fill's tree builds a place or passes one up is reported (`FillFinding.Kind.placeInsideFillOfCaseOfBothRootEnums`), by ruling for 2.3.0: a case per root enum, with the dispatchers both reach emitted per root, can accept the shape later and break no caller. Per-place validation (`validateFills`) stays the check. Public mocks keep a case per path for a place inside a fill.

One allocation of names serves each generated Swift scope (`GeneratedNameAllocator`): a seam's initializer body claims its builders' internal names, then the function that builds each wrapper place; a filler's body around one seam call claims its fills, then its dispatchers; no site names anything with a loop of its own.

A seam's guard hashes, after the parameters, each builder's label, the type its signature spells without `any` (`Builder.parameterTypeWithoutAny`, made by the function that spells the signature, attributes included, so nothing can be emitted and not hashed) and tier access, then every enum its builders reach in key order, each case's name and payload (fields and forwarded type, or the inner enum's key); with no hole the input is unchanged.
