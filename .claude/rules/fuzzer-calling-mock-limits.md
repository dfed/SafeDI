# Graph fuzzer: the calling-mock check's limits

The known issues, cost, undrawn shapes and report-only run of the calling-mock check and draw that `fuzzer-calling-mocks.md` describes.

- **Known issues.** `SafeDIToolGraphFuzzerCallingMockTests.callingMockKnownIssues` lists one entry per cell that fails, and is empty: every cell passes, the seam built again's by building what inline builds. A listed seed that passes is reported stale, except one whose every signature is `.callingMockDoesNotCompile` in a run with compile verification off, which compiles nothing. Each entry lists seeds of one shape cell, never the control's, in increasing order (`callingMockKnownIssueListProblems`), and no count is required, so a fix deletes the seeds and entries it mends and nothing else. The hand-written tests pin each shape's twin sites, require the twin's intended outcome and that the mock mirrors it; the seam built again's test (`callingMock_buildsInlineValues_whenFillReadsValueOfLevelBetweenBuildsOfSeam`) also requires that the twin's error is recognized as that outcome, and compares the mock's values with inline's, and `callingMock_compiles_whenFillReadsValueOfLevelBetweenBuildsOfSeam` compiles its mock. The twin's seam initializer labels are read from the initializers of an extension of the caller itself, never of a nested type such as a seam enum's builder struct.
- **Cost.** In the ordinary suite the check compiles only in `callingMock_compiles_whenFillReadsValueOfLevelBetweenBuildsOfSeam` (a compile per module), in the value tests `callingMock_buildsTwinsValues_whenFillReadsNothing`, its deferred twin, `callingMock_buildsInlineValues_whenFillReadsValueOfLevelBetweenBuildsOfSeam` and `callingMock_buildsInlineValues_whenDrawnFillReceivesCallersLazyValueBelowCalledRoot`, in the self-tests `check_reportsOtherValues_…`, `check_reportsOtherValuesThanInline_…`, `check_throws_whenSameTypesBuiltInlineDoNotCompile` and `check_reportsMockDoesNotCompile_…` (a compile of each module and a probe link per path), in `drawnValueProbes_describeKnownRight_inFirstGraphOfEachProbedCell` (the known-right half, the twin's or inline's, of each drawn probe in the first graph of each of the forty-eight probed cells), and in the cell test's first graph of each probed cell and leaf position, and of each cell, call and later variation of the fill that receives the caller's lazy value below the called type's root that states probes, and of each cell, builder and value wrapper of the fill that holds a builder of the enclosing called type, at most COMPAREDMAX; its other tests run the tool alone.
- **Not drawn yet** (each test named here covers its shape for each caller kind): a fill of a call nested in a re-entered fill that reads what the called mocks' copies leave uncarried, the twin's error (`SafeDIToolCallingMockCrossCallReentryTests`); a fill that re-enters its called type through another public mock where the type nothing fulfills is instantiated by a sibling place's fill, by a place of the third module's type, or around or inside a call nested in another call's fill (`SafeDIToolCallingMockReentryStructTests` covers each, and each beside a `SendableInstantiator` of the called type, as `SafeDIToolSeamReenteringSendableFillTests` does for the twin); a builder of the enclosing called type held on a level beneath the called mock's root (`whenCalledMockBuildsTypeHoldingBuilderOfFilledType`); lazy places of the called mock, `@Sendable` places outside the shape whose fill reads the called type's received value, a second hole type of it, a caller that forwards a value, and a deferred place that forwards nothing (`Instantiator<T>`, `ErasedInstantiator<(), any P>`) outside the app-only screen's loop: elsewhere a plain place is held by value and a deferred one forwards `id`, so for the outer seam's value, the loop through an inner seam's builder, the seam built again and the accepted shapes, forwarding and deferral change together. Each joins the cells when drawn. Nor is rule 7's second outcome: a call inside a fill that re-enters the called mock's root level, where the fill reads, only if available, a value a level between the two builds holds (an implementation of `Checkout`'s `payments` that reads `CartScreen`'s `cart` and builds `Checkout` again). Neither this draw nor the public mock corpus's re-entering fill (`HoleFill`'s lazy cycle, on `T6`'s own level, receiving nothing) draws it; `SafeDIToolCallingMockMirrorsProductionTests`' re-entry cells cover it, and drawing it needs the check to recognize the twin's `fieldOfReenteringPlace` error as rule 7's outcome, as it recognizes the seam built again's. Nor are two of the fill gates' shapes (`DependencyTreeGenerator.holeTypesTheFillGatesPassUp(of:in:lazilyHeldValues:)`): two places of one hole type whose fills read different lazy values, and a call re-entered only through the fills of the calls its fills make; `SafeDIToolCallingMockMirrorsProductionTests`' `whenPlacesOfOneHoleTypeReadDifferentLazyValuesBesideTheirFields` and `whenCallReadingCallersLazyValueIsReenteredThroughAnotherCallsFill` cover them, and each joins the last block's variations with a seed range of its own. Nor is a fill that builds the called type again and reads the value only if available, less than the re-entered call's root level function takes it, where the called type holds no copy of the value (`Scope.labelsHandedToReenteredFunctions(by:)`); `whenFillBuildingCalledTypeAgainReadsLessOfValueThanReenteredFunctionTakes` covers it, and it joins the last block's variations, as a second place's fill that reads the value only if available, with a seed range of its own. The variation that draws a fill reading none of it while the caller holds it lazily (`fillReadsInstanceCalledTypeDoesNotHold`) reads the instance by value only: `whenFillBuildingCalledTypeAgainReadsNoneOfValueCallerHoldsLazily` covers the read only if available, a child of the fill building the called type again and re-entry through another call's fill.
- **Report only.** `publicMockCorpusCallingMocks_reportTwinsShapeErrors` runs only by hand: `SAFEDI_GRAPH_FUZZER_CALLING_MOCK_TWIN_REPORT=1 swift test --traits sourceBuild --filter SafeDIToolGraphFuzzerCallingMockTests/publicMockCorpusCallingMocks`. It runs each mocked consumer of the public mock corpus's accepted graphs as its twin and prints the consumers whose twin reports a shape error (`GraphFuzzerCallingMockTwinReport.shapeErrorMarkers`) or another error. It fails nothing: the rule for mirrored rejections is applied to its count before that change lands.
