# Source rules

`SourceRuleTests` fails on a trap in `Sources` or `Plugins` (a force unwrap, in an expression or a key path, an implicitly unwrapped optional or `init!`, `unsafelyUnwrapped`, `try!`, `as!`, `fatalError`, `precondition`, `preconditionFailure`, `assert`, `assertionFailure`, `Dictionary(uniqueKeysWithValues:)`, `Dictionary(dictionaryLiteral:)`, or a dictionary literal whose keys are not distinct literals), on `try?` under `Sources/SafeDICore/Generators`, on a trap spelled in a literal in `Sources` (`generatedTrap`: one of those five functions’ names or `unsafelyUnwrapped` as a whole word, `try!` or `as!`), on `__safeDI_` in a literal in `Sources` outside `ReservedName.swift`, on a lone backtick literal in `Sources` outside `IdentifierSpellingExtensions.swift`, on a straight apostrophe between letters in a literal in `Sources`, `Plugins` or `TuistPlugins`, on a mock, override, configuration, seam, hole or fill named in a type key file (`TypeKeyBody*.swift`) or `PlaceRecord.swift`, on `String`, `Property` or `TypeDescription` named in a fold of the per-type facts (`typeFactsFoldModelName`: `OrderedGraph.swift`, `ReadsFromAbove.swift`, `SiblingOrder.swift`, `TypeFactsColumns.swift`, `TypeFactsVariants.swift`, `TypeFactsOutcomes.swift`, which work on IDs and bit sets; a reader fold that still reads a declaration's `Property` is left out until the graph answers what it reads: `TypeFactsImports.swift`, which hands each declaration's type to `FulfillerImports`, until the frozen table holds each declaration's fulfiller modules), on an error type declared under `Sources/SafeDICore` that `ErrorReportingSite.byErrorType` does not list with the code that reports it, on an `async` function or `async` accessor of an actor under `Sources/SafeDICore` that assigns a stored property of that actor (`ActorStateRuleCheck`, matched by what an assignment assigns, with the bindings in scope, never by a property's name; every actor but `ScopeGenerator`, which `actorsNotYetCovered` lists with its reason; no waiver lifts it), on `nonisolated(unsafe)` or `@unchecked Sendable` in `Sources` or `Plugins`, a field only `deinit` mutates included (`uncheckedConcurrency`: an owner that releases the next level of a tree holds it in a `DeferredReleaseSlot`, `cycle-generation.md`), on a task group in `Sources` or `Plugins` whose `of:` type is a tuple or an optional tuple (`taskGroupTupleElement`: 2.3.1’s release builds miscompiled one; return a struct), on a scan of a string’s characters under `Sources/SafeDICore/Generators` (`stringScan`: `split`, `replacingOccurrences` or `components(separatedBy:)` on anything, or `contains` given a string literal, since a generator’s code runs per place or per node, but not a call on a string’s `utf8` view, which compares bytes; a text transform there goes over UTF-8 bytes through `GeneratedCodeText`, and a site that runs a bounded number of times, or tests membership in a few elements, is waived with how often it runs), and on a `@testable import` in `Tests/SafeDIToolTestSupport` (`testableImport`; `test-infrastructure.md` says why). The rule finds `@testable` anywhere in an import’s attributes, inside `#if` too, and reports it at the line of the `import` keyword, so a waiver of it goes at the end of that line. A safe site is waived by a comment on its line or on the lines just above it, `// safedi-source-rule: allow <rule> — <the invariant that makes it safe>`; a waiver that names no rule, gives no reason, or waives no site fails the test. No stated invariant waives `uncheckedConcurrency`: only Dan admits such a site, one at a time, and its waiver's reason begins with where he did, `// safedi-source-rule: allow uncheckedConcurrency — Dan’s OK: <where he gave it>`, or the test fails.

## Compiler workarounds

These apply to any new code:

- **An actor's `lazy var` initializer reaches nothing isolated through a closure.** In an actor, a `lazy var` whose initializer contains a closure or a local function that calls an isolated method or reads an isolated property fails to compile with Xcode 26's Swift 6.2 ("actor-isolated default value in a actor-isolated context"), although Linux's Swift 6.2 and Swift 6.4 accept it. Keep the value in a stored optional instead, filled on first use by an isolated method that returns it.
- **Build long arrays and strings with sequential appends.** A long expression that joins arrays or strings with `+` and contains ternaries makes Linux's Swift 6.2 time out type-checking it. Declare a `var` and append each part, with an `if` where a ternary chose a part.
