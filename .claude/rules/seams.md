# Seams: two scope maps, one signature, a guard

- **Seams: two scope maps, one signature, a guard.** A type declared with `generateDependencyTree: true` (a seam) is generated by the module whose own files declare it (`SeamResolution.generatedSeams`, decided in `GenerateCommand.seamResolution` by `ownFilePaths`: the files the build system attributes to the module, else the module's own files as the access check's `isOwnFile` reads them: the manifest's `mockScopedFilePaths` or else the input files (`ownProjectFilePaths`, the one definition both read, since `scan` plans a seam's output for a mock-scoped file alone), found only when some visible declaration is a seam, because without the build system's word it normalizes every input path, which the lifelike benchmark showed costs more than generating a module) and called by every tree that reaches it. `DependencyTreeGenerator.rootScopeGenerators` validates the FULL inlined map as always — cycles through a seam, hidden labels, `generateWarnings`, `validateReachableTypeDescriptions` (relaxed, in a module that holds or calls a seam, to the types reached outside every seam's tree, `typesReachableOutsideSeamTrees`) — with each generated seam a validation root whose tree receives its pass-throughs (`ValidatedRootScope.receivedFromOutside`), and only when `seams` is non-empty builds a SEAM MAP (`createSeamScopeMapping`) in which every reach of a seam with a signature is a leaf `Scope` carrying a `SeamCall` and an `Instantiable` whose dependencies are the called tier's parameters (`seamLeafInstantiable`: own `@Received`/`@Forwarded` kept as declared, pass-throughs as `.received(onlyIfAvailable: isOnlyIfAvailable)`); generation starts in `createScopeGenerator`'s detached task, so the map is built between validation and the per-root `createScopeGenerator` calls, never by rewriting generators. The signature (`SeamSignature`, `seamRoot(of:rootScope:generator:)`) is read from the seam's root `ScopeGenerator` built over that map with `startsCodeGeneration: false`: own `@Received`/`@Forwarded` parameters in declaration order, then pass-throughs in label order from `receivedProperties` minus what the seam's own properties provide (a non-optional wrapper provides its instance's by-value forms and its own optional form, as a forwarded one does; an optional one only itself; `formsProvided(by:)`), required when in `requiredReceivedProperties` only — a property required through an `onlyIfAvailable` alias of it (`requiredAliasFulfillingProperties`) stays `T?`, received only if available, since the alias reads it only if available, and carries `SeamSignature.Parameter.requiredThroughAlias` (in the call shape and the guard, hashed only when set), which the caller's leaf scope adds to its `requiredAliasFulfillingProperties` (`SeamCall.requiredThroughAliasProperties`), so the caller builds the provider first, exactly as inline orders the alias's fulfilling property before the receiver's branch, while validation, which builds every seam's tree inline, reports a sibling cycle through it at the alias's receiver — (`SeamSignature.Parameter.isOnlyIfAvailable` is stored, never derived from the type: a required pass-through keeps the optional type where every receiver that requires it declares it optional, since the caller's tree may declare a forwarded `x: X?`, and takes the unwrapped form only where a receiver requires a non-optional form), one label's forms visited in sorted order so the spelling chosen among `any`-equal types is deterministic. Forms of one label are grouped by what provides them (`formsProvided(by:)`): a required non-optional `LazilyInstantiated`/`SendableLazilyInstantiated` receive is a parameter of exactly that type and provides every by-value form beneath (`seamRootGenerator` lists its instance in `lazilyInstantiatedInstanceProperties`) and the optional form of its kind; otherwise the by-value forms are one parameter (`x: X`, a required `x: X?`, or an `x: X?` received only if available) and an optional wrapper is its own parameter that provides nothing but itself; the seam's own `@Received`/`@Forwarded` properties are parameters as declared and provide forms by the same rules; an alias's fulfilling property counts as a form of the label it aliases (an `onlyIfAvailable` alias's, spelled non-optional, as its optional form). Every other mix – a by-value form beside an optional wrapper, two wrapper kinds, the seam's own receive beside a form it does not provide – is `SeamError.parametersShareLabel`, whose remedy (`SeamError.LabelCollisionRemedy`, decided in `seamRoot` by `labelCollisionRemedy(among:requiredProperties:)`) names the providing form spelled as a receiver spells it (`@Received let x: LazilyInstantiated<any X>`, or `x: X`), says to receive the label the same way alone where no form the inlined validation accepts provides the others (a required `x: X?` beside a wrapper, whose instance is non-optional), says to receive one wrapper kind, or says to rename for forms of different by-value types, an `Instantiator<X>` or `ErasedInstantiator` form being another type than `X`, which no form of `X` provides. Callers pass what `createInitializerArgumentList` passes any receiver: the exact property, the non-optional form for an optional parameter, `.instance` for a by-value parameter where the chain holds a non-optional wrapper of either kind, and `nil` for an optional parameter the chain does not hold, which a deferred parameter's autoclosure wraps: a tier that defers a parameter has two initializers, a plain one for people, whose parameters are values under their readable labels and whose body forwards them, so its closures capture its own parameters and a call cannot retain its caller (`plainSpelling`), and one only generated code calls, every parameter and builder of which is labeled `__safeDI_<label>` (`ReservedName.seamGeneratedOnlyArgumentLabel(of:)`, `generatedOnlySpelling`, `Initializer.Argument.outerLabel` on the leaf, `SeamCall.callsGeneratedOnlyInitializer`), and which a wider tier's last initializer calls too; a tier that defers nothing keeps one initializer under its readable labels. The prefixed labels keep the two initializers apart and replace the guard argument an earlier design gave the second one; the guard enum stays, since labels name no type and no availability, so a stale call with the right labels still compiles (a call passing `nil` where the tree now requires a value) without the enum. No plain parameter has an underscored name, which would keep the initializer out of the symbol graph: a tier with one initializer and a hole binds `let __safeDI_<builder> = <builder>` first, which the tree reads. The initializer only generated code calls takes each by-value pass-through (`SeamSignature.Parameter.deferral`, decided in `seamRoot` for the by-value branch by `propertyType.isConstant`, so an `Instantiator` form, a wrapper and the seam's own `@Received`/`@Forwarded` stay by value) as `__safeDI_x: @autoclosure @escaping () -> X` (an implicitly unwrapped type spelled as its optional form, `deferredValueType`; the internal name renamed past every builder function name of the tree, and the holes' internal names past it) and binds it in the narrowest tier's body as a `LazilyInstantiated` memo under its label – always the memo, never a read at the top, except that a by-value pass-through no read reaches (a declaration inside the tree hides its label from every receiver, `ParameterReads.reads(_:)`) stays by value, so no memo goes unread – seeding its unwrapped form into `lazilyInstantiatedInstanceProperties`, so receives, aliases, nested seam arguments and cycle-closing arguments read `.instance` where inline reads the caller's wrapper; the memo provides only the by-value forms. The one exception is the seam's own alias that keeps a deferred parameter's label (`SeamRoot.autoclosureCallByLabel`): it is the parameter's only reader and is bound where inline binds it, so it reads `__safeDI_x()` and no memo is bound, which it would redeclare. A wider tier passes `__safeDI_x()` into the narrower tier's autoclosure. A hole's struct field bound from a deferred parameter (`Hole.Field.deferral`) holds the memo – `LazilyInstantiated`, or `SendableLazilyInstantiated` for a `@Sendable` parameter, in an internal `__safeDI_<label>` (`memoName`) beside the public computed field that reads its instance, with the struct's initializer the seam's tree calls – and the site and each stage call hand it the memo, so a hand-written fill creates the value when it reads the field; a generated fill reads the caller's own declaration instead (see `seam-holes.md`), so a fill creates the value where inline would and the value comparator holds seams with holes to parity with no exemption. A parameter read inside a `@Sendable` function where the label's nearest declaration is the parameter – a builder function by `buildsInSendableFunction`, a fill by `ScopeGenerator.sendableStages(ofFill:)`, the predicates the emitters decorate from – or handed to a nested seam that takes it `@Sendable`, is a `@Sendable` autoclosure held in a `SendableLazilyInstantiated` (`receivers(in:)`' `ParameterReads`, `labelsReadInsideSendableFunction`; a site reads the parameters it carries at the call of its first stage, before any `@Sendable` function on its path), the production twin of the mocks' `@Sendable` autoclosures; the caller's capture walk counts a leaf's `@Sendable` deferred parameter as one more `@Sendable` builder (`NonSendableWrapperCapture.capturingSeamType`), and the seam root's walk seeds a deferred parameter as its memo, so a read the decision missed is reported rather than miscompiled; no instance is read through the other wrapper kind, no edge joins a wrapper parameter to an instance sibling, and a required wrapper the chain lacks is the inlined validation's error, so a seam call never captures a value a receiver would not; a parameter's receivers are the receives of its forms that leave the seam, whose modules' declarations the type proof admits and at which its errors' notes point, while its access is the proof of its type (`receivers(in:)` walks the seam root's generator tree, which is per path and closes every cycle, threading what each scope provides, so a receive fulfilled inside proves nothing while a type reached under two parents, only one of which provides the label, is a receiver on the other path; the `Scope` graph, which a tree reaches a scope once in, cannot say that; a receive that leaves the seam on several paths is kept once, by declaration – declaring type, declaration location, property – where the tree first reaches it, so an error names it once, and a cycle-closing scope, built for a property on the stack and so of an ancestor's type, needs no skip of its own. A lazy cycle that re-enters a seam calls its generated initializer again with the nearest declarations, as the Manual's `@Received` rule says and as inline's cycle-closing scope passes them to the function it closes on (`CycleParameter`); an alias of a property its own scope provides (as `ScopeGenerator.init` decides) is no receiver at all; nothing in a seam's tree is hidable: a receive the tree does not provide whose label a scope between it and the seam root declares with a property that does not provide it (`ScopeGenerator.provides`) – instantiated, aliased, or forwarded, the seam's own included; its own `@Received` are parameters and hide nothing, so another form under their label is a collision – is the inlined hidden-label error from the seam's chain on every path, whatever its optionality and whatever any caller holds, because the seam's validation root has every property its tree receives from outside receivable (`ValidatedRootScope.receivedFromOutside`) and nothing prunes it beneath a declaration, so `receivers(in:)` and generation never meet a hidden receive; in the seam's module, a chain that passes through a seam the module generates is not reported again when that seam's own walk reaches the receive along the same path below it (`reportingEachSeamsChainOnce`, which matches the chain's scopes by their concrete types, since the chain names each by its property's type – `ScreenProtocol`, `AnyScreen` – and only against a strictly shorter chain, so every receive keeps a report), so nested seams report the innermost seam's chain, sibling seams each their own, and a chain that reaches the receive without passing through such a seam keeps its own; a caller in another module, whose validation inlines the seam's tree, reports the same receive from the caller's chain when the caller provides the property; a `@Sendable` builder inside the seam that reads a non-Sendable wrapper parameter is a capture whatever the caller would pass, since the generated initializer declares the parameter outside every builder (seed 840), a seam's own error the oracle counts as such by its wording; a nested seam's pass-through stands for the receivers its signature carries, `SeamSignature.Parameter.receivers`, so an outer seam's `tierOmitsRequiredParameter` names the receive inside the nested seam, not the nested seam, and the outer seam proves the parameter's type again over its own computation's declarations); the guard hash covers labels, `withoutAny` type spellings, tier access, `isOnlyIfAvailable` (hashed as the token `= nil`, the default the parameter once had, so that no guard moved when the defaults went), and, only for a deferred parameter, its deferral (`deferred`, `deferred @Sendable`); the `@Sendable` capture walk of a seam root is seeded with its parameters; Pass-throughs are sorted by label (kept by ruling: a parameter order that follows label order is how mocks and initializers already work), so the rename-invariance oracle's label reversal reorders them in the seam corpus's graphs with two or more; that is expected, not a defect, and those seeds are a seam known-issue shape of their own, as the mock's label-sorted parameters are in the base corpus. Parameters are in scope throughout the seam's tree (each the nearest declaration of its label in `NearestDeclarations`, providing both forms, plus the instance of a non-optional wrapper; the seam root's own forwarded properties prune as any scope's do): an `onlyIfAvailable` alias of a parameter is generated as everywhere, bound from the parameter with the parameter's optionality, or to `nil` where its fulfilling property is still being built or generated later, and every type beneath reads that binding, as inline reads the caller's nearest declaration of the label, so a seam rejects no read of an alias. Because a seam's parameters change what its tree receives, `seamSignatures(forSeams:in:…)` settles a module's seams inner first: each strongly connected component of the seam-reaches-seam graph (`stronglyConnectedComponents`, Tarjan on an explicit stack), in reverse topological order, sees the final signatures of the seams it reaches outside it, and only seams that reach one another are computed again until none changes, in one fixed point in which every input to `seamRoot` only grows (a tree built with more parameters in scope receives no less from outside it, each label's form only strengthens – `X?` received only if available, then a required `X?`, `X`, a wrapper – a parameter that stops being received only if available never is again, and each parameter's receivers only accumulate; nothing else a pass finds feeds the next); a pass changes a signature only in its `SeamSignature.settledContent` – each parameter with its receivers as a set, never their order, which a tree carrying the receivers of a seam that carries its own meets differently on every pass – and `seamSignatureComputationLimit(forComponentOf:)`, 8 × (seams + 1) passes, guards the argument: a component that reaches it is `signaturesDidNotSettle`, which no input reaches, so its test lowers the limit through the task-local `seamSignatureComputationLimitOverride`, which nothing else sets; a change that lets one of them shrink breaks the argument the bound guards. Every seam error – each label collision, each tier omission, each redeclaration, per seam, per module – is collected and reported with `reportingAll(of:)`, so which are reported never depends on name order. `foreignSeamRoots` computes only the foreign seams this module's trees reach, before the inlined trees are validated (so a module info this run lacks is reported with its remedy, not as the dependencies its declarations would have fulfilled), each module from what it sees, with the modules whose seams a module's visible trees reach computed first, from an explicit stack that pushes a module back under the modules it needs; a module that a computed module's trees reach is found in that module's own view of the seams it depends on (`SeamResolution.foreignDeclarations(seenByModuleNamed:)`), never in this run's global `foreignSeams`, and computed with `SeamResolution.resolution(seenByModuleNamed:)`, so a seam this run reads only in a view is never matched against this module's own types; an unreached one costs nothing. A foreign public mock's plan (`foreignPublicMockPlan`) is computed the same way, and its nested resolution carries `foreignDeclarationsSeenByModule` on, so each level of a chain of public mocks reads what its own module saw: without it, a public mock three modules beneath the caller is found in no map, built inline, and the call names an enum its module never generated. Before any is computed, `validateCalledSeamModulesShareMockCondition` walks the trees this module generates – its own roots' and its own seams', never entering another module's seam – and reports `seamModuleMockConditionDiffers` once per foreign seam whose `ForeignSeam.declaringModuleMockCondition` differs from `SeamResolution.currentModuleMockCondition`, at the first dependency in source order that instantiates it: `GenerateCommand.seamResolution` sets that condition only under the target graph, where this run read the seam module's mock-only declarations under its own condition, from the configuration among `module.configurations` in a file the graph attributes to that module (`DEBUG` when none, `nil` a spelling of its own); a caller reading the module's `.safedi` reads them as the module did and is not checked. Reached keys are looked up through the module's own map (a seam reached as one of its additional types counts; a key the map lacks reaches nothing), and a module's reached modules are pushed only on its first visit, so the loop ends whatever the module infos claim; computing a reached module's seams fails only from a module info a failed run, or a run given other declarations, wrote, which is collected with the other seam errors. A seam with no `@Instantiated`/aliased dependency and no pass-through is trivial: no code, no `SeamCall`, callers use its own `init`; a hand-written `init` (`Instantiable.otherInitializers`) that a call with a tier's argument labels can reach – its labels hold the tier's, builders included, in order, every other argument defaulted – is `initializerCollides`, whatever its types, since beside an optional parameter an existential, generic, defaulted, or `Any` twin takes the call from a caller holding the value, and no type comparison tells it from one that loses.
