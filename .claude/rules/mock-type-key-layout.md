# Laying a mock's body out by the type key

**Every place has a plan node of its own.** Only `sharingNode(ofBuiltPlaceAt:nodesByKey:)` merges two places, by `MockLowering.SharedRecordKey`, which holds every field of the record and its children's. A key made of the generator and the place's own reads merged two places whose children's records differed (the same siblings declared in other orders beneath two `SendableInstantiator`s; a rename only one parent declares), and a field left out of the key because "no test fails without it" merged an actor's `@Sendable` closure parameter with a class's. A field leaves the key only with a value test of two places that differ in it alone.

**An internal mock's tree is walked for records, and again for text only where its layout falls back.** `lowerMockRootWithTree(of:context:)` walks an internal mock root's tree (`MockLowering.Walk`), recording a place for each node, and the type key lays the body out from the records (`typeKeyRootLines(declaredAtRoot:)`). That walk writes no statement (`Walk.writesText` is off): a tree has a statement or more for each path, so writing them only for the layout to replace them held a root's largest text beside its records. A place whose record is made of its text, a call of another module's public mock, is written to lines of its own, which the record copies. A root whose layout falls back is walked again, from a copy of the walk taken before the first, recording nothing and writing every statement, so its body is the one a root the type key never lays out gets (a public mock's, or any with `laysOutWithTypeKey` off). Such a root pays for two walks, so a reason to fall back that a real shape meets often is decided before the first walk, never found by it. A new statement the walk writes is written only where `writesText` is set: `SafeDIToolMockTypeKeyWalkTextTests` counts the statements each walk of a root writes (`MockLowering.rootWalkObserver`).

**`laidOut` means the records carried the whole body.** A place whose record cannot say something the walk writes of it refuses its root where the record is made, with a reason of its own (`Walk.unrecordedReasons`, reported as `unrecorded:<reason>`), so that no caller of the layout has to know which roots it may lay out: the root then keeps the walk's body. A public mock's body is laid out only behind a test's switch (`MockLowering.laysOutPublicMocksWithTypeKey`), and four of its facts are refused so (`SafeDIToolPublicMockTypeKeyRefusalTests`, `SafeDIToolMockSubtreeSharingTests`' `mock_sharesNothing_whenRootIsPublicMock`): a node it promotes, which reads its caller's value first (`promotedParameter`); a configured node, which it builds with the type's construction function (`publicConstructionFunction`); an override read inside a `@Sendable` builder function, which the walk reads into a local before that function, since a public mock's overrides are never `Sendable` (`overrideLocal`); and its overrides, which its records read by the path from the root, so its root shares no subtree (`sharesSubtrees(of:)`). `laidOut` promises code that builds what the walk's builds, not the walk's bytes: a laid out public mock calls another module's public mock in a builder function that holds the call's retention line, and annotates a constant's type, as a laid out internal mock does. A change that makes a record carry one of these lifts that refusal in the same change, with the test moved to `laidOut`. A new statement or read the walk writes for a place is recorded, or refused there.

**A loop of builders is recorded as production records it.** Each member is a built place (`MockLowering+LoopPlaces.swift`), whose function begins with a closer on the function of each member its tree receives (`ClosingPlaceRecord.rebindsLoopMember`), which the type key resolves among its level's statements; a mock lays out every loop it holds (`TypeKeyBody.statements(…laysOutEveryLoop:)`), since its layout replaces the walk's body however many places a member's view stands for. Every turn of a loop reads the overrides of the members its level declares, so a member's function takes, beside its own configuration, its level's (`loopMemberConfigurations()`, under a name the root's table claims for the level's type, `ConfigurationParameterNames.name(ofLoopLevelConfigurationOf:builtWithHandWrittenMock:)`), which its level hands and each closer hands on with the callee's field of it: passed arguments, as the nearest configurations of a cycle's closers are, but never optional and never by lap, and one per function whatever the loop's size (`SafeDIToolSeamReceivedBuilderCycleTests`' `generate_growsLinearly_…` fails on one per member reached). A loop the mock root declares reads `safeDIOverrides`, so its members take no level parameter. Where the level's configuration cannot cross into the `@Sendable` functions of its members (`safeDIOverrides` never does, as the walk reads it into locals before each), each member's function takes the configuration of each member it reaches instead, all `Sendable`: a known gap, n parameters in each of n functions of a loop whose members reach each other, and in each function a closer per member it receives that hands n arguments, so the text grows with the cube of the loop (4.7 MB at 32 members, where the walk writes 132 KB), which ends when a level's configuration can be read there without capturing what is not `Sendable`. A member keeps the walk's body, with a reason of its own, where production keeps the path key's (payload bindings, a `_received` function, a rename or a rebinding it does not plan), where a public mock rebinds a member it promotes as the caller's own, and where its level binds no wrapper of it (`unboundLoopMember`, only a mock root's). `SafeDIToolMockTypeKeyLoopValueTests` compares the values on several turns, with an override at every place.

**A laid out body's names are claimed, never spelled from a type alone.** A builder function takes its type's configuration under one name per mock root, concrete type and way of building it (`MockLowering.ConfigurationParameterNames`), which only `Walk.configurationParameter(ofPlaceOf:builtWithHandWrittenMock:configurationType:)` hands out: a record that hands a configuration asks it, and never spells `__safeDI_<Type>_configuration`. The name is spelled as one identifier, so a type named with backticks joins it (`` `default` ``), and claimed in the order the walk first reaches the types, with its `_nearest` name, apart from the names claimed before it (`Outer.Inner` beside `Outer_Inner`) and from the locals `mock()` reads its `@Sendable` autoclosure parameters into. The layout reserves every parameter its functions take before it claims a function or a local (`TypeKeyLayout.computeDecoratorsAndNames`), so the function of a property labeled as a parameter is named (`Aa_configuration` beside the type `Aa`) is named apart. `SafeDIToolMockTypeKeyConfigurationNameTests` compiles each meeting and compares its values with the walk's; each piece reverted fails one of them.

**A place instantiated only if available lays out by a `nil` alternative, beside its override read.** Where a declaration fulfills the property, the place's record holds the read of its entry, `<binding name>IsUnavailable` of its parent's configuration (`BuiltPlaceRecord.nilAlternative`, from `Walk.nilAlternatives`): the body that holds the place binds it `if <entry> { nil } else { <its call or construction> }`, annotated with the property's optional type, so nothing of the place is built where the entry is set, as the walk writes it. The read is made where the place is bound: the calling body's structural key holds it, the place's own function's does not, and `SharedRecordKey` holds it, so every place of one plan node reads one (`nilAlternative(ofStatementAt:inBody:)`). It is never a `ConstructionAlternative`, which gives a value from inside the function a place bound to `nil` never calls. Where nothing fulfills the property, the place is written as text that reads no declaration of a body (an `AliasPlaceRecord` with no reads): `nil`, or `mock()`'s override of it. `SafeDIToolMockTypeKeyOnlyIfAvailableTests` compares each cell's values with the walk's; each piece reverted fails one of them.
