# Laying a mock's body out by the type key

**An internal mock's tree is walked for records, and again for text only where its layout falls back.** `lowerMockRootWithTree(of:context:)` walks an internal mock root's tree (`MockLowering.Walk`), recording a place for each node, and the type key lays the body out from the records (`typeKeyRootLines(declaredAtRoot:)`). That walk writes no statement (`Walk.writesText` is off): a tree has a statement or more for each path, so writing them only for the layout to replace them held a root's largest text beside its records. A place whose record is made of its text, a member of a loop of builders with every place beneath it and a call of another module's public mock, is written to lines of its own, which the record copies. A root whose layout falls back is walked again, from a copy of the walk taken before the first, recording nothing and writing every statement, so its body is the one a root the type key never lays out gets (a public mock's, or any with `laysOutWithTypeKey` off). Such a root pays for two walks, so a reason to fall back that a real shape meets often is decided before the first walk, never found by it. A new statement the walk writes is written only where `writesText` is set: `SafeDIToolMockTypeKeyWalkTextTests` counts the statements each walk of a root writes (`MockLowering.rootWalkObserver`).

**`laidOut` means the records carried the whole body.** A place whose record cannot say something the walk writes of it refuses its root where the record is made, with a reason of its own (`Walk.unrecordedReasons`, reported as `unrecorded:<reason>`), so that no caller of the layout has to know which roots it may lay out: the root then keeps the walk's body. A public mock's body is laid out only behind a test's switch (`MockLowering.laysOutPublicMocksWithTypeKey`), and four of its facts are refused so (`SafeDIToolPublicMockTypeKeyRefusalTests`, `SafeDIToolMockSubtreeSharingTests`' `mock_sharesNothing_whenRootIsPublicMock`): a node it promotes, which reads its caller's value first (`promotedParameter`); a configured node, which it builds with the type's construction function (`publicConstructionFunction`); an override read inside a `@Sendable` builder function, which the walk reads into a local before that function, since a public mock's overrides are never `Sendable` (`overrideLocal`); and its overrides, which its records read by the path from the root, so its root shares no subtree (`sharesSubtrees(of:)`). `laidOut` promises code that builds what the walk's builds, not the walk's bytes: a laid out public mock calls another module's public mock in a builder function that holds the call's retention line, and annotates a constant's type, as a laid out internal mock does. A change that makes a record carry one of these lifts that refusal in the same change, with the test moved to `laidOut`. A new statement or read the walk writes for a place is recorded, or refused there.
