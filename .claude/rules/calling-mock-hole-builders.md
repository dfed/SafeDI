# A calling mock's builders for the places its calls fill

Continues `public-mock-builders.md`. Kept apart so that the generator files this does not govern do not load it.

- **Optional builders for filled places.** A calling mock takes one optional builder, `(() -> T)? = nil`, per hole type and family whose places its calls of other modules' public mocks fill, at the mock root's level or inside fills (`ScopeGenerator.FilledCall`, `filledFamilies(of:)`), so the builder a test writes is never ignored. Family: a filled builder's is the one a passed-up builder of it would take, `@Sendable` where the called builder is or the call is made inside a `@Sendable` function. Labels: the label a required builder of the hole type would take, from `stems(of:)` over every hole type of the mock's builders in a lifted gate's order (own places, fill places, then passed-up and filled builders in the sorted order of the properties they would be received as), unless that pass renames a required builder's stem, when the optional ones are named among themselves (`stemsOfOptionalBuilders`); claimed after every required label, so no existing label moves, and `_` on collision. The one check site is the call's struct (`FillPlaceBindings.HoleBuilder.structValue`): `<name>.map { .init(__safeDI_noScope: $0) } ?? <root level call>`, read at the root-level call (`publicMockCallArguments`) and inside fills (`constructionArgumentList`); level functions, dispatchers and inlined fills gain nothing. An override of the called type is handed `{ if let <name> { <name>() } else { <fill>(…) } }` (`overrideValue`). A call that re-enters an enclosing call (a call inside a fill whose argument holds no builder struct and names the enclosing call's root dispatcher, `FilledCall.reenteredBuilders`) reads the enclosing call's builder for that argument, in its family, or the `@Sendable` twin where the re-entering call is inside a `@Sendable` function; within one family the read changes no value, since the enclosing fill runs only where the builder is `nil`, but every place of the hole type then reads it the same way. An override of a called type wrapped in a builder (`PublicMockOverrideBuilder`'s wrapper case) is handed `<name> ?? <call>` (`wrapperBuilderValue`). No adapter: a place whose builder takes a value is an instantiator of a type that conforms to `Instantiable` by hand, which no type a caller declares can fulfill, so no call fills it (comment at `structValue`). A known gap, planned as the pull request stacked on this one: a public mock whose initializer the calling module can call is built inline, and its places read no builder. The join: a family the internal mock also takes a required builder for (a passed-up place, its own places, a fill place) adds no parameter; its calls hand `.init(__safeDI_noScope: <required>)` and overrides `{ <required>() }`. A public mock takes each as a `PublicMockParameter` of `Role.optionalBuilder` after its required builders, on `mock()` and `__safeDI_mock` (under an internal name apart from every name of its tree and fills); a joined one appears on `__safeDI_mock` only, under the `_` label, and `mock()` passes the required builder to it. Generated callers never pass one (`PublicMockCall` drops the role), so the called mock's fills build those places. The per-root channel is `FillPlaceBindings.holeBuildersByCall`, keyed by the call's generator, so fill code is cached by (`propertiesGeneratedLater`, `FillPlaceBindings`). `query needs` lists none. A B5 exception: in the fallback a later gate lift can relabel an optional builder from `x_` to the stem the union pass gives.
